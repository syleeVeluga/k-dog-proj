## 1. 구현 결과

화면을 단순하게 줄이는 것보다 다음 작업을 찾고, 근거를 비교하고, 입력과 결과 버전을 보존하는 데 초점을 맞췄다. 기존 역할 권한과 부분 결과 조회·출력 흐름을 유지한다.

| 점검 ID | 반영 내용 |
|---|---|
| UX-01 | 원본 근거를 현재 화면의 고정 재생 패널에서 확인한다. 파일명·카메라·원본 시간·관찰문을 표시하고 Esc로 닫으면 호출 버튼으로 포커스를 돌린다. |
| UX-02 | 참가자 목록을 3초 주기로 갱신한다. 마지막 조회 시각·연결 실패를 표시하고 검색·선택을 유지한다. |
| UX-03·08 | 분기 처리 완료와 유효 채점 수를 분리한다. 영역별 유효/대상 수, 부분 평균, 근거 부족·충돌·규칙 미정, 행동·설문 척도 방향과 한글 영역명을 표시한다. |
| UX-04 | 선택 참가자·행사·모든 행사 범위를 명시한다. 생성 전 참가자·입력/수정 버전·부분 결과를 확인하고 미리보기 해시로 생성 시점의 변경을 거절한다. 생성된 파일별 수동 전달 방법·메모·작성자·시각을 기록한다. |
| UX-05 | 파일별 카메라와 대기/등록 중/저장됨/실패 상태를 제공한다. 첫 실패에서 중단하고 재시도는 성공 파일을 건너뛴다. 실제 저장·실패·대기 수를 알린다. |
| UX-06 | 설문·참가자 정보·촬영 정보·점수·설명 편집의 기준 버전을 각각 유지한다. 배경 갱신과 다른 편집기의 저장이 초안을 초기화하지 않는다. 이동·재촬영 시 미저장 입력을 확인하고 충돌은 초안을 보존한 채 거절한다. |
| UX-07 | 모바일 참가자 표를 카드로 배치해 ID·상태·열기 버튼을 가로 스크롤 없이 표시한다. 주요 버튼의 최소 높이는 44px이다. |
| UX-09 | 행사·예약일·자료 보완·분석 미실행·대기/진행·실패 조치·결과 준비 필터와 현재 목록 일괄 선택을 제공한다. |
| UX-10 | 항목 검색·상태·영역 필터와 선택 항목의 수정 폼을 같은 작업 공간에 배치한다. 항목의 ‘검토하기’에서 직접 수정 대상으로 전환한다. |
| UX-11 | 표지·각 영역·교차 해설·각 팁의 근거를 독립적으로 유지한다. 새 설명 수정 이력에 전후 본문을 저장하고 항목/문단별 전후 값·근거·수정 사유를 화면에서 대조한다. |
| UX-12 | 표준 파일 외에 사용자 열 이름 연결과 원본 가로 설문의 응답 열→등록 참가자 연결을 지원한다. 원본 30문항의 번호·문구를 확인하고 세션·버전·변경 문항·오류 위치를 미리 보여 준다. 오류 안내를 내려받을 수 있다. |
| UX-13 | 교수는 운영 대상 세션을 변경하지 않고 이전 촬영을 열람한다. 실행 이력에 촬영 차수·시각을 표시한다. 대표 이미지 선택은 파일명·카메라와 재생 위치를 사용한다. |
| UX-14 | 파일 확인·실패 단계 재시도·개발자 연결 설정 요청을 구분한다. 진행 중 분석의 중복 시작을 막고 성공 결과의 보존과 재사용 조건을 안내한다. |

운영자는 참가자 ID·반려견 이름·예약 시각을 버전 검사 후 정정할 수 있다. 촬영 정보에는 입장·분리·훈련·놀이·퇴장의 미확인/실시/미실시/재촬영 필요 기록을 추가했다. 이 기록은 관찰 입력과 재사용 비교에 포함되며 평가 점수를 자동 결정하지 않는다.

## 2. 버전·권한과 호환성

- 입력 변경은 기존 입력 revision 및 표시 실행 무효화 규칙을 따른다. 과거 분석·파일의 내용은 바꾸지 않는다.
- 내보내기 미리보기는 파일이나 감사 이력을 저장하지 않는다. 생성은 확인했던 대상·결과가 그대로인지 검증한 뒤 불변 스냅샷을 저장한다. 기존 API 호출은 미리보기 해시 없이도 기존 계약대로 사용할 수 있다.
- 파일 전달 기록은 운영자/운영 관리자만 저장한다. 교수는 결과 수정·출력과 이력 열람 권한을 유지하며 참가자/촬영/전달 정보 쓰기는 허용하지 않는다.
- ‘전달 이후 변경’은 해당 과거 파일과 현재 결과의 차이다. 최신 파일의 재전달 기록을 함께 확인한다. 자동 발송, 배달/읽음 확인 또는 정정 업무의 자동 완료 상태가 아니다.
- 촬영 체크리스트가 없는 기존 manifest는 빈 기록으로 읽는다. 빈 기록은 기존 재사용 해시를 바꾸지 않는다. DB 테이블 추가나 마이그레이션은 없다.
- 기존 설명 수정 이력에는 전후 본문이 없을 수 있다. 과거 내용을 추정해서 채우지 않으며 새 수정부터 기록한다.

## 3. Cold review 및 수정

구현 이후 변경 diff와 실제 요청·응답 흐름을 다시 읽고 권한, 기준 버전, 비동기 갱신, 부분 실패를 검토했다. 별도 검토 에이전트는 사용하지 않았다.

| 발견 사항 | 조치·검증 |
|---|---|
| 연속 파일 선택에서 React 상태 갱신 전에 파일 입력을 비우면 두 번째 선택이 누락됨 | File 목록을 먼저 복사한다. 등록→추가 영상→설문→재촬영 브라우저 시험 통과. |
| 다른 운영자가 새 분석을 시작하면 자동 갱신이 편집 중인 실행을 교체할 수 있음 | 보고 있는 실행을 고정하고 이전 실행 경고를 표시한다. 새 실행 도착 뒤에도 선택 실행과 점수 초안이 유지되는 회귀 시험 추가. |
| 재촬영 추가가 설문·업로드 초안을 제거할 수 있음 | 세션 변경과 같은 이탈 확인을 적용한다. 취소 시 기존 세션·설문 초안 보존 확인. |
| 내보내기 미리보기 요청 중 선택 범위가 바뀌면 이전 미리보기가 뒤늦게 표시될 수 있음 | 미리보기의 요청 키와 현재 범위를 비교해 표시·생성을 제한한다. 서버는 생성 시 해시를 다시 검사한다. |
| 닫힌 내보내기 영역도 목록을 반복 조회하며 전달 기록 없는 파일의 최신 리포트를 계산함 | 영역이 열려 있을 때만 폴링한다. 전달 이력을 파일당 한 번 읽고 전달된 대상만 변경 여부를 계산한다. |
| 가로 원본 설문 오류가 변환 후 행 번호로 표시됨 | 실제 시트·응답 열 범위(예: 데이터입력 F6:F35)와 문항을 표시한다. 정상·오류 위치 시험 추가. |
| 전후 수정 값을 원시 JSON으로 보여 주면 검토 부담이 큼 | 항목명·선택지·상태·사유·문단·근거로 표시한다. 내보내기 및 열 목록 응답 모델도 명시한다. |
| 표지만 수정해도 다른 문단의 규칙 미정 안내가 중복 추가됨 | 기존 안내가 있으면 다시 붙이지 않는다. 다른 영역·교차 해설·팁과 전후 이력의 보존을 백엔드·브라우저에서 검증한다. |

## 6. 후속 관찰 범위

- 실제 운영자·교수의 작업 시간, 20명 이상 목록에서의 사용성, 실제 공급자 품질·비용은 이번 UI 수정 시험으로 검증했다고 주장하지 않는다.
- 초안 보호는 현재 페이지 수명 동안 제공한다. 새로고침을 확인해 진행하거나 탭을 강제로 종료한 뒤 복원하는 서버 초안 기능은 없다.
- 업로드 응답 자체가 유실되면 기존 파일 목록에서 저장 여부를 확인한다. 동일 파일 중복 등록은 기존 서버 해시 검사로 거절한다. 바이트 단위 진행률과 중단 지점 업로드 재개는 포함하지 않는다.
- 전달/정정 전용 통합 작업함, 검토 구간·수정 여부 필터, 다음 항목 자동 이동은 후속 사용성 측정 후 결정한다.
- 4영역 대응·②④ 유형·q23/C-2·DOG-12·OWN-14의 미정 규칙은 유지한다. 승인 게이트·참가자 포털·총점/순위·자동 전송은 추가하지 않았다.
