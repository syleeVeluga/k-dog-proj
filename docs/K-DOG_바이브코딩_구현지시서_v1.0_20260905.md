## 1. 문서 해석과 작업 원칙

### 1.1 충돌 시 적용

현재 작업에 적용되는 시스템·도구·저장소 지침을 따른다. 제품 요구사항 안에서는 최신 사용자 요청을 우선하며 다음 기준으로 조정한다.

1. 확정 행동 55항목·설문 30문항의 원문은 첨부 Excel을 기준으로 한다.
2. 초기 UI·DB·구현 범위는 이 지시서와 AI 파이프라인의 최소 구성으로 한다.
3. 상세 기능·리포트 내용·사용자 역할은 PRD v0.4를 따른다.
4. Excel의 셀 배치·안내 문구·과거 수식이 실제 확정 항목 또는 최신 사용자 요구와 충돌하면 그대로 복제하지 않는다.

PRD의 많은 개념 엔터티를 모두 별도 테이블로 구현하지 않는다. 운영자·교수의 검토를 승인·반려 절차로 바꾸지 않는다. 이 문서에 들어 있는 예시 ID·형식·기본값은 실제 참가자 데이터나 검증된 점수 경계가 아니다.

### 1.2 에이전트 작업 방식

- 먼저 현재 저장소 구조와 실행·검증 방법을 확인한다. 기존 구현이 있으면 통째로 재생성하지 않고 필요한 부분을 수정한다.
- 코딩을 시작하기 전 확정/미정 요구와 현재 구현의 차이를 짧게 기록한다. 이후 작은 기능 단위로 구현·검증한다.
- 일반적인 파일명·모듈 분리·컴포넌트 배치는 스스로 정한다. 이미 답변받은 참가자 접속·키 관리·승인 여부를 다시 질문하지 않는다.
- 새 기능을 임의로 늘리지 않는다. 원본 평가 기준이나 외부 비용·배포처럼 결정이 필요한 사안은 가정으로 강행하지 않는다.
- 원본 자료와 `sources/` 등 읽기 전용 자료는 수정·이동·삭제하지 않는다.
- API 키·실제 개인정보·영상은 소스 저장소에 넣지 않는다. 디버깅을 위해 키 값을 출력하지 않는다.
- 도중에 컨텍스트가 바뀌어도 완료 기능을 다시 만들지 않도록 진행 기록에 현재 상태·다음 단계·검증 결과를 남긴다.
- 테스트는 수치·접근 권한·중단 복구·핵심 사용자 흐름 중심으로 작성한다. 단순 문구나 스타일마다 구현을 복제하는 테스트를 만들지 않는다.

## 2. 구현할 제품

K-DOG 운영자용 웹 앱이다. 참가자 ID에 사전 설문과 현장 촬영 영상을 연결한다. Gemini가 영상·음성을 관찰하고, 단계별로 선택한 Gemini·GPT·Claude가 반려견·보호자를 병렬 평가한다. 평가·리포트 설명의 초기 기본 공급자는 Gemini다. 프로그램이 집계하고 리포트를 만든다. 운영자·교수가 결과를 즉시 조회·검토·수정하고 파일로 내보내 참가자에게 전달한다.

### 반드시 유지할 조건

| REQ-02 | 최소 계획 정보는 참가자 20명·카메라 2대·영상 약 3분. 최대치·납기 미정 |

### 이번에 만들지 않을 것

참가자 포털·본인 인증·공개 결과 URL, 예약 결제·설문 제작 서비스, 자동 이메일/메신저 발송, 실시간 CCTV·카메라 제어, 네이티브 모바일 앱, 다중 카메라 전문 편집기, 범용 프롬프트 노드 편집기, 순위·단일 종합 100점, 모델 학습, 운영 클라우드 자동 배포.

Redis·Celery·Kubernetes·벡터 DB·RAG·에이전트 프레임워크는 초기 필수 의존성으로 추가하지 않는다. 이 프로젝트는 고정된 단계 호출로 구현한다.

## 3. 기술 기본안

기존 저장소에 적절한 선택이 있으면 우선 재사용한다. 새 저장소라면 다음 구성을 기본으로 시작한다. 구체적인 버전은 구현 시 공식 문서를 확인하고 호환되는 버전을 잠금 파일에 고정한다.

| 계층 | 기본안 |
|---|---|
| UI | React + TypeScript, 단순한 CSS와 재사용 가능한 작은 컴포넌트 |
| 개발·빌드 | Node.js 기반 프런트엔드 빌드 도구 |
| API | Python + FastAPI, 명시적 입력·출력 타입 검증 |
| 작업 실행 | 별도 Python worker 1개, DB 대기 작업 조회 |
| DB | SQLite, 짧은 트랜잭션·외래키·필요한 고유 제약 |
| 결과 | 버전 있는 JSON 파일, DB에는 상태·참조 경로 |
| 미디어 | FFmpeg/ffprobe 검사·필요한 변환·프레임 추출 |
| 공급자 | 공식 지원 API/SDK를 감싼 작은 어댑터 |
| 출력 | 서버에서 실제 PDF·XLSX·CSV 생성. 화면 캡처만으로 Excel을 대신하지 않음 |
| 배포 | 로컬 실행 관리자, FastAPI가 React 빌드 파일 제공 가능 |

운영 PC에 개발용 Node 서버와 Python 명령을 각각 입력하도록 요구하지 않는다. 설치·실행 스크립트 또는 실행 아이콘으로 API·worker를 시작하고 브라우저를 열도록 한다. Node.js는 빌드에 사용하며 완성된 로컬 앱의 상시 서버로 중복 실행하지 않아도 된다.

로컬 기본 접속은 loopback으로 제한한다. 내부망 접속은 명시적 운영 설정으로 활성화하고 인증을 적용한다. 클라우드 대비는 파일 저장·DB·실행 설정 경계를 분리하는 수준으로 시작하며 초기부터 두 환경의 모든 인프라를 만들지 않는다.

### 디렉터리 예시

```text
project/
  docs/                       # 요구사항·구현 기록·실행 안내
  frontend/                   # React
  backend/
    app/
      api/                    # 직원·개발자 API
      domain/                 # 항목·점수·권한·출력 타입
      pipeline/               # S0~S7 단계 함수
      providers/              # Gemini/GPT/Claude 어댑터
      storage/                # DB·파일·비밀 참조 접근
      exports/                # PDF/XLSX/CSV
      worker/                 # 작업 점유·실행·복구
    tests/
  resources/
    catalogs/                 # 원본에서 확인한 읽기 전용 항목집
    prompt_defaults/          # 기본 프롬프트·비밀 없는 설정
  scripts/                    # 설치·시작·종료·검증
```

폴더 이름은 예시이며 기존 저장소와 맞춰도 된다. 실제 참가자 데이터·운영 설정·로그·API 키는 이 소스 트리와 분리한다. 필요하지 않은 추상 클래스·빈 계층을 폴더 예시에 맞추기 위해 만들지 않는다.

## 4. 최소 UI 구현 계약

### 4.1 목록 화면

표시 열은 참가자 ID, 반려견 이름, 설문 준비, 영상 수, 분석 상태, 결과 열기다. 핵심 동작은 자료 가져오기, 분석 실행, 전체 내보내기다. 검색·상태 필터는 단순하게 제공한다.

### 4.2 상세 화면

기본정보·연결 자료·처리 상태·결과 요약을 먼저 표시한다. 55개 항목·설문 원응답·관찰 근거는 필요한 때 펼친다. 미관찰·충돌 항목을 찾기 쉽게 표시한다.

- 영상 파일 또는 폴더 선택 → 참가자·카메라·세션 확인 → 등록.
- 설문 Excel/CSV 선택 → 필요한 열·문항 매핑 → 검증 → 저장.
- 결과에서 근거 시점을 누르면 해당 원본 구간을 재생한다.
- 점수는 허용 선택지 또는 미관찰 상태로 수정하고 사유를 저장한다.
- 결과가 준비된 즉시 열리고 설명·PDF 생성 중 상태는 별도로 표시한다.
- 부분 결과의 미완료 항목을 0점·정상으로 채우지 않는다.
- 리포트 미리보기와 개별·전체 파일 다운로드를 제공한다.

### 4.3 개발자 설정 화면

별도 인증된 개발자만 접근한다. 단계 선택, 프롬프트·설정 편집, 샘플 실행, 버전 차이 보기, 운영 적용, 복원과 키 관리를 작은 화면으로 제공한다. 운영자 화면의 ‘설정’에 개발 기능을 섞지 않는다.

한국어 UI, 최소 360px 반응형, 읽기 쉬운 표·여백·상태 문구를 사용한다. 장식용 대시보드·애니메이션·그래프를 추가하지 않는다. 4영역 리포트 그래프는 필수 내용이므로 유지한다.

## 5. DB·파일·버전 구현 계약

### 5.1 핵심 테이블

| 테이블 | 필수 역할 |
|---|---|
| users | 인증, 역할, 활성 상태. 평문 비밀번호 금지 |
| cases | event_id+participant_id 고유 연결, 이름·현재 입력 revision·manifest |
| runs | case/session, 입력·설정 스냅샷, 상태·결과 참조, 점유 토큰·만료·시각 |
| steps | run·단계·카메라/분기·시도, 상태·사용량·출력·재시도 시각 |
| changes | 사용자·시간·대상, 수정·설정 적용·내보내기의 비밀 없는 변경 이력 |

라이브러리가 필요한 내부 migration 메타데이터를 사용하는 것은 허용한다. 별도 업무 테이블을 대량 생성하지 않는다. 실제로 필요해지는 조회가 생길 때만 분리한다.

참가자 ID는 문자열로 저장한다. Excel 파일의 1~20번은 파일 내부 순번이며 event_id+participant_id를 대신할 수 없다. 한 보호자의 여러 반려견은 평가 쌍마다 구분한다. 재촬영은 session_id를 새로 부여하고 서로 다른 세션을 자동 합치지 않는다.

### 5.2 저장 파일

- 입력 manifest: 참가자·세션·영상 ID·해시·설문 원응답·동선·버전.
- 실행 manifest: 입력 revision·항목집·파이프라인·프롬프트·설정·모델 버전.
- 관찰·근거: 카메라별 JSON과 검증된 통합 근거 JSON.
- 평가·점수: 반려견·보호자 결과와 프로그램 집계 JSON.
- 리포트·수정: AI 원결과와 사람 수정 revision을 분리.
- 내보내기: export_id별 snapshot과 실제 PDF/XLSX/CSV.

참조 ID·해시·스키마 버전을 검증한다. 원본 파일명을 경로로 직접 사용하지 않는다. 외부 파일은 앱 관리 위치에 복사를 끝낸 뒤 등록하며, 등록 후 원래 SD카드가 없어도 사용할 수 있어야 한다.

### 5.3 변경 원칙

입력·설정 수정은 진행 중 run을 변형하지 않는다. 새 분석 또는 새 결과 revision을 만든다. 내보내기는 당시 저장된 결과 버전을 고정하는 동작이며 별도 승인 과정이 아니다. 이미 내보낸 파일은 이후 수정으로 바꾸지 않는다.

## 6. 확정 항목과 미정 규칙

### 6.1 항목집 이관

첨부 Excel을 읽어 아래 개수와 실제 원문·구간·선택지를 대조한다. 헤더·안내·빈 행을 항목으로 세지 않는다.

| 그룹 | 개수 | 제안 ID |
|---|---:|---|
| 바디시그널 | 16 | BS-01~BS-16 |
| 개행동 | 20 | DOG-01~DOG-20 |
| 보호자 행동 | 19 | OWN-01~OWN-19 |
| 설문 | 30 | q01~q30 |

선택지는 고유 option_id와 원문·점수·방향 태그를 가진다. 정의되지 않은 2점·4점 선택지를 생성하지 않는다. 행동 분기 합은 36+19=55다. 프롬프트가 항목을 추가·삭제해도 서버 검증에서 거절한다.

항목집의 원본 위치·파일 해시·생성 버전을 남긴다. 원본이 없으면 이름·선택지를 꾸며서 55개를 채우지 않는다. 항목 이관과 실제 채점을 미완료로 기록하고, 입력·화면·권한·worker·파일 출력 등 독립적인 작업은 계속한다.

### 6.2 계산 책임

모델은 선택지를 선택하고 프로그램이 점수·방향을 조회한다. 평균·최고·역채점·분모·반올림·방향 집계는 프로그램 코드에서 계산한다. LLM의 평균값이나 자유 문장에서 숫자를 추출해 최종 점수로 사용하지 않는다.

초기 원본 매핑은 EDU 7, SOC_P 1, SOC_D 1, SOC_E 9, ATT 14, CON 12, TRN 6, 참고 5개다. 총 55개 중 집계 대상은 50개이며 무반응 기준선·퇴장 적응 5개는 참고다. 설문과 행동 원점수의 방향이 반대임을 유지한다.

설문은 원응답·환산값·층을 분리한다. 문항 내용 확정과 수식·그래프 집계 확정은 다르다. 구체적인 초기 계산안과 역채점은 파이프라인 S5를 따른다.

### 6.3 추측하지 않을 내용

| 미정 내용 | 구현 상태 | 계속 구현할 내용 |
|---|---|---|
| q23의 C-2 포함·환산 충돌 | 계산 규칙 pending, 원응답 유지 | 다른 설문·행동 점수 |
| 4영역 번호·통합·가중치 | mapping_pending | 4영역 자리·원자료·근거 설명 |
| ②④ 교차 유형·경계·명칭 | type_rule_pending | 보류 사유·근거 기반 설명 |
| 대표 행동 선택·시간 경계가 애매한 항목 | insufficient_evidence 또는 명시적 초안 규칙 | 다른 판단 가능한 항목 |
| 모델명·한도·API 키 | 개발자 설정 필요 | 키 없는 단위·통합 테스트 |
| 최대 인원·영상 길이·전달 마감 | 설정/문서에 미정 표시 | 최소 계획 시나리오 검증 |

미정 값을 정상값이나 임의 등급으로 채우지 않는다. pending 상태가 있다는 이유로 전체 시스템 조회를 막거나 평가 항목 자체를 삭제하지 않는다. 운영자가 확인하지 않은 리포트에 ‘교수 검토 완료’를 붙이지 않는다.

## 7. AI 파이프라인 구현 계약

파이프라인 문서의 S0~S7과 같은 단계 이름을 사용한다. 단계 함수·스키마를 먼저 만들고 공급자 호출을 연결한다.

| 단계 | 구현 | 저장·노출 조건 |
|---|---|---|
| S0 입력 검사 | 참가자·세션·삭제 요청 여부·설문·파일·활성 설정 확인, run 스냅샷 생성 | 대기 상태 저장 |
| S1 미디어 준비 | 해시·길이·코덱·오디오 검사, 필요한 변환만 실행 | 원본·분할 시간 변환·품질 정보 저장 |
| S2 Gemini 관찰 | 카메라별 영상·음성에서 구간·사실·횟수·시간·가림 추출 | 카메라별 완료 관찰 저장 |
| S3 근거 통합 | 구조·시간·ID 검사, 원본 시간 환산, 확인 가능한 사건 그룹화 | 검증된 근거 ID·항목 연결 저장 |
| S4-D 반려견 평가 | BS+DOG 36항목 선택지 판단 | 독립 완료·저장 |
| S4-O 보호자 평가 | OWN 19항목 선택지 판단 | S4-D와 병렬, 독립 완료·저장 |
| S5 계산 | 선택지→점수, 행동 영역·설문 규칙 계산 | 완료된 점수·부분 결과 즉시 조회 |
| S6 설명 | 계산값·대조 상태·근거에서 6개 리포트 구성의 설명 생성 | 설명 준비 상태 별도 갱신 |
| S7 내보내기 | 수정 revision과 결과를 고정하고 PDF/XLSX/CSV 생성 | AI 재호출 없이 동일 snapshot 재출력 가능 |

### 7.1 공급자 어댑터

영상 관찰과 구조화 텍스트 평가를 작은 인터페이스로 분리한다. 실제 함수명은 저장소에 맞춰도 된다.

| 인터페이스 예시 | 반환에 필요한 정보 |
|---|---|
| observe_video(video, checklist, config) | 관찰·구간·품질, 공급자 요청 ID·모델·사용량 |
| evaluate_items(evidence, catalog_subset, config) | 항목별 상태·선택지 ID·근거 ID·이유, 호출 메타데이터 |
| write_report(scores, comparisons, evidence, config) | 코멘트·관계 설명·팁·근거 ID, 호출 메타데이터 |

Gemini 실제 영상·오디오 입력을 구현한다. 반려견 평가·보호자 평가·리포트 설명은 모두 Gemini를 초기 기본값으로 사용하며, 개발자가 단계별로 Gemini·GPT·Claude 중 공급자와 모델을 선택할 수 있게 한다. 설정 변경으로 교체할 수 있도록 세 공급자의 평가·설명 어댑터를 구현한다. 모델명 문자열만 바꾸어 서로 다른 공급자의 API를 호출하지 않는다. 각 단계는 선택 공급자 하나만 호출하며 다중 심사 흐름을 자동 추가하지 않는다. 평가 요청 전에 필요한 입력 크기·스키마·모델 지원 옵션을 검증한다.

S2에는 설문 응답이나 기존 점수를 주지 않는다. S4 두 분기에도 설문 응답과 다른 분기의 점수를 주지 않는다. 필요한 반려견·보호자 상호작용 근거는 공유할 수 있다. 설문 대조는 평가 후 S6에서 수행한다.

### 7.2 필수 타입

실제 구현에서는 타입 모델로 작성하고 요청·응답·저장 파일 모두 검증한다. 다음 필드는 최소 요구다.

| 타입 | 필드 |
|---|---|
| RunInput | run_id, case_id, session_id, input_revision, catalog/pipeline/scoring/report 버전, survey, videos |
| VideoReference | video_id, camera_id, sha256, 저장소 참조, duration, audio 상태, clip offset·동기화 정보 |
| Evidence | evidence_id, video_id, camera_id, segment_id, 원본 start/end, subject, modality, observation, 관련 item_ids, quality_flags |
| ItemEvaluation | item_id, status, selected_option_id 또는 null, evidence_ids, reason |
| ScoreResult | 항목별 원점수·방향·상태, 영역별 평균·최고·유효 수·대상 수, 계산 규칙 버전 |
| ReportResult | 4영역 표시·pending 상태, 설명·근거 ID, 교차 유형 상태, 팁, 안내 |

모델이 반환한 근거 로컬 번호는 프로그램이 부여한 evidence_id에 매핑한다. 알 수 없는 참조·다른 참가자 자료·원본 범위 밖 시간·중복 항목·정의되지 않은 선택지는 거절한다.

평가 상태는 scored, not_visible, audio_unusable, not_performed, not_applicable, insufficient_evidence, conflicting_evidence를 기본으로 한다. scored만 유효한 선택지·점수를 가진다. 나머지는 null이다. 근거가 없는 ‘없음’과 관찰해서 확인한 ‘없음’을 구분한다.

### 7.3 다중 카메라

- 동일 참가자·세션 안에서만 통합한다.
- 동기화 표식·운영자 보정값이 있을 때만 시간 비교를 수행한다.
- 주 카메라의 횟수·지속 관찰을 기준으로 하고 다른 카메라는 보조 근거로 사용한다.
- 문장 유사성만으로 사건을 합치거나 카메라별 횟수를 더하지 않는다.
- 해소하지 못한 충돌은 상태로 남긴다. 별도 LLM 토론·무제한 재관찰로 해결하려 하지 않는다.

### 7.4 병렬 실행·즉시 조회

초기 동시 참가자는 1건, 카메라 관찰 동시 요청은 1개, 반려견·보호자 평가는 2개 요청을 병렬 실행한다. 한 분기가 실패해도 성공 분기를 저장하고 화면에서 볼 수 있게 한다. 두 요청을 하나의 성공/실패로 묶어 성공 결과를 버리지 않는다.

화면 상태 갱신은 3~5초를 기본으로 한다. 이는 AI 응답 속도 보장이 아니다. 점수 준비됨·설명 생성 중·파일 생성 중을 구분하고 하나의 전체 완료 플래그로 조회를 막지 않는다.

### 7.5 실패·재시도·비용

- 키 없음·401/403은 개발자 설정 필요로 중단한다. 운영자에게 키를 요구하지 않는다.
- 429·일시 장애는 공급자 대기 지시와 점진적 지연을 적용한다.
- 최초 요청 포함 최대 3회, 스키마 수정 최대 1회를 초기 제안으로 사용하되 동일 시도·비용 한도 안에서 관리한다.
- 한 분기 실패는 해당 단계만 재시도한다. 설명 실패는 점수 유지, 파일 출력 실패는 AI 호출 없이 재생성한다.
- 응답이 유실된 요청은 이미 과금되었을 수 있음을 기록한다. 공급자가 중복 방지를 보장하지 않는데 정확히 한 번 과금된다고 주장하지 않는다.
- 예산·재시도 한도는 개발자가 정한다. 더 비싼 모델·다른 공급자에 자동 전환하지 않는다.

## 8. 개발자 권한·비밀·설정

### 8.1 역할 분리

| 역할 | 허용 | 금지 |
|---|---|---|
| 운영자·교수 | 전체 참가자 조회, 분석·수정·내보내기 | 키 원문·프롬프트 편집·모델/파이프라인 변경 |
| 운영 관리자 | 직원 관리·행사/보관 설정·백업 | 자기 계정을 개발자로 승격, 개발자 설정 변경 |
| 개발자 | 키 관리·프롬프트/설정 시험·적용·복원 | 개발자 역할만으로 참가자 데이터 무제한 접근 |

프런트엔드 메뉴 숨김만 구현하지 않는다. 서버의 모든 관련 API에서 권한을 검사한다. 데이터 접근이 필요한 개발자는 별도 직원 권한이 있어야 한다. 개발자 계정은 배포·관리 경로에서 발급하고 기본 공개 비밀번호를 만들지 않는다.

### 8.2 키 관리

키 등록·연결 시험·교체·폐기만 제공한다. 등록된 원문을 다시 반환하는 조회 API는 만들지 않는다. 개발자가 등록하는 입력란 외에는 키를 화면 데이터에 포함하지 않는다. 관찰·평가·리포트 설명에서 실제로 사용하는 공급자의 키만 요구한다. 기본 구성은 Gemini 키 하나로 실행하고, 특정 단계에 GPT·Claude를 선택했을 때만 해당 공급자의 키를 추가로 요구한다.

키는 비밀 저장소에 둔다. 코드·프런트엔드 번들·browser storage·일반 SQLite·JSON manifest·프롬프트·로그·설정 내보내기·자료 백업·결과 파일에 넣지 않는다. `.env.example` 등을 제공한다면 비밀 참조 설정이나 빈 예시만 둔다. 운영용 키를 저장소의 `.env`로 배포하지 않는다.

로컬은 신뢰 가능한 서비스 계정과 OS 비밀 보호를 사용할 수 있다. 운영 PC 관리자에게도 실제 공급자 키를 숨겨야 하면 개발자 관리 중계 또는 클라우드에 키를 둔다. exe 패키징이나 문자열 난독화를 완전한 키 보호로 설명하지 않는다. 중계 도입·외부 배포는 별도 결정이며 이번 작업에서 자동 개설하지 않는다.

### 8.3 설정 버전

현재 버전 복제 → 초안 편집 → 스키마·샘플 시험 → 개발자 운영 적용 → 필요 시 복원을 구현한다. 초기에는 하나의 전용 화면과 버전 파일로 충분하다.

- Gemini 관찰, 반려견 평가, 보호자 평가, 리포트 설명 프롬프트를 분리한다.
- 단계별 모델·지원 옵션·출력 한도·동시성·재시도·비용 설정을 검증한다.
- 초안 저장으로 운영 버전을 바꾸지 않는다.
- run을 접수할 때 입력·설정 버전을 고정한다. 대기·진행 중 run에 새 설정을 주입하지 않는다.
- 적용·복원은 신규 run부터 사용한다. 과거 결과를 조용히 재계산하지 않는다.
- 키 교체 참조 버전과 프롬프트 버전을 구분한다. 키 자체는 manifest에 없다.
- 업로드 JSON/YAML·프롬프트를 코드로 실행하지 않는다. 새로운 단계·공급자·도구를 추가하는 것은 코드 변경이다.

## 9. 리포트·내보내기 계약

아래 구성을 화면 미리보기와 참가자용 PDF/Excel에 반영한다.

| 구성 | 조건 |
|---|---|
| 표지 요약 | 반려견 이름·관계 요약 한 줄·대표 이미지 |
| 4영역 비교 | 자기인식 vs AI관찰, 기본 쌍 막대 그래프. 미정/결측은 0점으로 그리지 않음 |
| 영역별 코멘트 | 영역당 2~3문장 + 관찰 근거 한 줄 |
| ②④ 교차 해설 | 한 단락. 분류 규칙 미정이면 상태·이유 표시 |
| 오늘의 팁 | 근거 기반의 실천 가능한 1~2개, 완충 표현 |
| 안내 | ‘진단이 아닌 관찰 기반 제안’, 필요한 경우 전문 상담 권유 |

대표 이미지는 해당 참가자의 실제 영상 프레임 또는 제공 사진을 사용한다. 관계 문구 예시 ‘조용하지만 깊은 유대형’을 모든 참가자의 고정 결과로 쓰지 않는다.

점수 수정 후 프로그램 집계·그래프를 갱신한다. 기존 설명이 새 점수와 다르면 설명 갱신 필요를 표시하고 재생성 또는 수동 수정 저장을 지원한다. 오래된 설명을 새 결과처럼 내보내지 않는다.

- 개별 PDF·XLSX에는 해당 참가자만 넣는다.
- 전체 XLSX에는 전체 요약·영역 비교·행동 55항목·설문·근거·수정 이력·규칙 설명을 넣을 수 있다. 최소한 모든 참가자의 요약과 항목 상세를 실제 데이터로 제공한다.
- 전체 PDF는 참가자별 파일 ZIP을 기본으로 한다. 합본 PDF는 핵심 흐름 후 필요 시 추가한다.
- CSV는 행 기반 결과·설문·근거를 제공한다. 그래프·이미지를 CSV로 대체하지 않는다.
- Excel은 실제 숫자·문자열 ID·날짜 형식을 사용한다. 파일명을 `.xlsx`로 바꾼 CSV를 만들지 않는다.
- PDF 한글 글꼴·페이지 잘림, Excel 그래프·텍스트·이미지, 개별/전체 데이터 범위를 시각적으로 확인한다.
- 파일 snapshot·export_id·생성자·시간을 기록한다. 재다운로드는 AI를 호출하지 않는다.

## 10. 구현 순서와 단계별 완료 기준

각 단계가 끝날 때 동작 증거를 남기고 다음 단계로 진행한다. 한 단계 완료가 전체 MVP 완료를 뜻하지 않는다.

| 단계 | 구현 작업 | 완료 증거 |
|---|---|---|
| M0 저장소·계약 | 기존 코드 확인, 범위 기록, 항목 이관·타입·미정 규칙 정의 | 원본 항목 대조 결과, 실행 구조, 고정된 정상·결측 사례 |
| M1 최소 입력 | 인증·5개 테이블·목록·상세·표준 입력·영상 저장 | 1명·2개 영상·설문 등록 후 앱 재시작해 조회 |
| M2 관찰 | FFmpeg 검사·Gemini 어댑터·관찰 스키마·근거 저장 | fixture 계약 시험과, 가능하면 실제 영상 근거 시간 확인 |
| M3 병렬 평가 | Gemini/GPT/Claude 어댑터·두 분기·집계·부분 결과 | Gemini 기본값·단계별 공급자 선택, 한쪽 지연/실패 중 다른 쪽 조회, 점수 고정 사례 일치 |
| M4 설명·출력 | 리포트 설명·수정·이미지·PDF/XLSX/CSV | 실제 생성 파일의 내용·시각 검증, 개별 데이터 분리 |
| M5 개발자 편집·복구 | 설정 편집·시험·적용·복원, 재시도·파일/DB 복구 | 권한 거절 시험, 버전 고정 시험, 강제 중단 후 재개 |
| M6 패키징·파일럿 준비 | 원클릭 실행·백업/복원·설치 안내·전체 부하 시험 | 새 환경 실행 기록, 20명·2대·각 3분 계획 시나리오 결과 |

권한·비밀 분리는 M1부터 적용한다. M5까지 인증·키 보안을 미루지 않는다. 각 마일스톤을 가로지르는 핵심 API·파일 오류 처리도 기능과 함께 구현한다.

### API 키·샘플이 없는 경우

실제 공급자 어댑터와 설정 검증을 구현하되 실호출은 실행하지 않는다. 테스트용 provider는 명시적인 test/demo 모드에만 연결하고 UI·출력에도 테스트 자료임을 표시한다. 키가 없다고 자동으로 demo로 전환하지 않는다.

원본 Excel이 없으면 실제 항목 이관을 완료했다고 하지 않는다. 실제 영상이 없으면 영상 관찰 품질을 검증했다고 하지 않는다. 이러한 외부 조건이 필요한 작업과 독립적인 구현을 분리하고, 마무리 보고에 미검증 범위를 명시한다.

공급자별 어댑터를 구현했더라도 실제로 호출하지 않은 공급자는 ‘실 API 미검증’으로 기록한다. 필요한 개발자 설정이 완료되고 허용된 시험 자료·호출 범위가 있을 때만 실호출 시험을 한다.

## 12. 산출물과 완료 판정

### 12.1 저장소 산출물

- 실행 가능한 프런트엔드·API·worker 소스와 의존성 잠금 정보.
- 원본에서 확인한 읽기 전용 항목집과 출처·버전.
- 단계별 프롬프트·설정 기본값, 키가 없는 샘플 설정.
- 최소 입력 템플릿과 실제 PDF/XLSX/CSV 출력 기능.
- 설치·시작·종료·백업·복원·개발자 계정/키 설정 안내.
- 의미 있는 테스트와 실제 수행 결과.
- 구현된 기능·미정 규칙·외부 조건·실 API 검증 상태를 담은 진행 기록.

문서·설정·원본 자료·코드를 구분한다. 샘플 결과 파일이 실제 참가자 결과와 섞이지 않게 한다. 런타임 참가자 자료와 비밀을 커밋하지 않는다.

### 12.2 완료 수준을 분리해서 보고

| 수준 | 충족 조건 |
|---|---|
| 개발 흐름 구현 완료 | UI·DB·단계 함수·실제 공급자 어댑터·권한·출력·복구 기능이 구현되고 핵심 테스트 통과 |
| 실제 API 연결 검증 완료 | 개발자 설정으로 허용된 실제 영상·설문을 처리하고 근거·결과·사용량 확인 |
| 현장 사용 준비 완료 | 실제 촬영 품질·계산/리포트 규칙·부하·장비·자료 보관 조건까지 확인 |

미정 리포트 규칙을 pending으로 구현하는 것은 가능한 개발 결과다. 그러나 해당 유형·그래프 계산이 확정되었다고 표시하거나 현장 평가 검증까지 완료했다고 주장하면 안 된다.

### 12.3 완료로 인정하지 않는 상태

- 화면만 있고 저장·재조회·실제 파일 출력이 없음.
- 버튼이 alert나 임의 지연 후 성공 메시지만 보여 줌.
- 키가 없을 때 가짜 평가를 실제 AI 완료로 표시함.
- 항목 수만 맞추고 원문·선택지는 임의로 생성함.
- 평가 결과를 메모리에만 두어 새로고침·재시작으로 사라짐.
- 인증이 메뉴 숨김뿐이거나 키가 브라우저·소스에 포함됨.
- PDF/Excel 생성이 설명 예시나 빈 파일에 그침.
- 한쪽 평가 실패 시 성공 결과도 삭제하거나 모든 AI 단계를 다시 호출함.
