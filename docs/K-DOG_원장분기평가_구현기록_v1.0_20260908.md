# K-DOG 사건 원장·분기 분할과 Gemini 영상 API 구현 기록

버전: v1.0 · 2026-09-08

## 구현 범위

[영상별평가 변경 계획 v1.1](K-DOG_영상별평가_변경계획_v1.1_20260908.md)과 [Gemini 영상 API 적용 계획 v1.0](K-DOG_Gemini영상API_적용계획_v1.0_20260907.md)을 구현했다. 영상 1개당 호출이 "전체 55항목 1회"에서 "사건 원장 1회 + 반려견 분기 1회(36항목) + 보호자 분기 1회(19항목)"로 바뀌었다. 영상별 독립 평가, 항목별 병합, 불일치 항목의 한 차례 재검토, 미해결 보류 구조는 유지한다.

## 사건 원장

`backend/app/ledger.py`가 평가 순서표와 프로그램 계산을 소유한다.

- `STEPS`는 PRD 촬영 구간 순서(입장 → 무반응 10초 기준선 → 분리 → 재회 → 지시① → 지시② → 지시③ → 지시④ → 놀이 → 퇴장) 10개 순번을 고정한다. R-09에 따라 지시②는 기록만 하며 `scored=false`로 전달하고 계산에서 제외한다.
- 사건은 `step`·`kind`·시각·`subject`·`modality`·`command`·`observation`·`quality_flags`만 담는다. 횟수·합계·점수·선택지 필드는 스키마에 없다. 프롬프트도 횟수를 적지 말고 발화 1회를 사건 1건으로 기록하도록 지시한다.
- `validate_events`가 거절하는 것: 영상 길이를 넘는 시각, 끝이 시작보다 빠른 구간, 보호자 음성 근거 없는 `command_utterance`/`play_cue`, 무음 영상의 발화 사건, `skipped` 구간의 사건, 시행에 맞지 않는 지시어 귀속. 귀속이 불확실한 사건은 `step: unknown`으로 남고 계산에 들어가지 않는다.
- `command_counts`는 순번별로 해당 지시어의 보호자 발화를 세고, 시행에 수행 사건이 있으면 첫 수행까지만 센다. 놀이 구간은 단일 시행 경계가 없어 절단 없이 구간 전체를 센다.
- 보상 간격·진정 시간은 계산하지 않았다. 그 값을 쓰는 OWN-14·DOG-12는 원문 시간 경계 규칙이 미정이어서 계속 `rule_pending`으로 보류하므로 계산해도 채점에 쓰이지 않는다. 해당 사건 종류는 사실로 기록만 한다.
- `LedgerArtifact.measures`는 저장 시와 조회 시 모두 자신의 `events`에서 다시 유도되는지 검사한다(`validated_ledger`). 사후 편집된 계산값은 채택하지 않는다.

## 분기 분할과 원장 일관성

- `observe`·`review_video` 단계의 `branch_key`가 `{video_id}/dog`·`{video_id}/owner`가 되고 `ledger` 단계는 `video_id`를 쓴다. `analysis.branch_key`/`split_branch_key`가 이 규칙을 소유한다.
- 분기 호출은 자기 분기 항목만 받고 `context`에 `branch`와 원장을 함께 넣는다. `validated_observation`은 항목 집합·분기 표기·재검토 범위를 대조하여 상대 분기 항목을 담은 산출물을 거절한다.
- 공유 사실 검사: `COUNT_ITEM_STEPS`가 DOG-13→지시①, DOG-14→지시③, DOG-15→지시④, OWN-11→훈련 네 시행, OWN-18→놀이로 항목을 시행에 귀속한다. 분기가 보고한 `command_count`는 측정 구간이 속한 시행의 원장 계산값과 같아야 한다. 어느 시행에도 귀속되지 않거나 값이 다르면 **그 항목만** 보류하고 사유에 원장 계산값을 남긴다. 시행 간 합산 규칙은 원문에 없으므로 만들지 않았고, 합산값은 어느 시행과도 일치하지 않아 자연히 보류된다.
- 기존 검사(측정 구간의 관찰 범위 포함, 원문 선택지 횟수 조건, 보호자 음성 근거)는 그대로 앞서 적용된다. 원장 검사는 그다음이다.
- 재검토는 분기별로 그 분기에 속한 불일치 항목만 받는다. 어느 분기에도 불일치가 없으면 그 분기의 재검토 호출은 만들지 않는다.
- 병합·`BranchEvaluation` 산출·`program_merge` 표시는 변경하지 않았다. 병합은 AI 호출이 아니며 과금 집계에서 계속 제외된다.

## Gemini 요청 계약

- 영상 파트의 `processing`이 `{"type": "static", "fps": N}` 또는 문자열 `"agentic"`이다.
- `generation_config`에 `thinking_level`(`low|medium|high`)과 `media_resolution`(`low|medium|high`)을 조건부로 넣는다. 미지정 시 키를 보내지 않아 공급자 기본값을 쓴다. `minimal`은 설정 enum에서 배제했다(gemini-3.8-flash가 오류로 반환).
- `Api-Revision: 2026-05-20` 헤더를 `interactions` 호출에 고정하고, 그 호출의 소켓 타임아웃만 900초로 올렸다. 업로드·상태 조회는 120초를 유지한다.
- `store=false`, 호출 후 원격 파일 삭제, `temperature`/`top_p`/`top_k` 미전송을 유지한다. `background=true`는 `store=false`와 비호환이므로 채택하지 않았다.
- 단계별 업로드를 유지했다. 원장이 올린 파일 URI를 분기가 재사용하는 방안은 채택하지 않았다. 단계는 각각 독립적으로 재시도·중단·복구되므로 단계 간 원격 파일 수명은 다른 실행 회차의 재시도에서 무효가 되고, 단계별 `remote_cleanup_pending` 회계와 "참가자 영상을 공급자에 남기지 않는다"는 보장을 단계 단위로 유지할 수 없다. 절감분은 업로드 대역폭뿐이며 토큰 비용은 같다.

## 샘플링 계약

`fps`를 전제한 세 곳을 처리 방식 기준으로 바꿨다.

| 위치 | 이전 | 현재 |
| --- | --- | --- |
| 프롬프트 컨텍스트 | `sampling_fps: 1.0` | `sampling: {"mode": "static", "fps": 1.0}` 또는 `{"mode": "agentic"}` |
| 근거 품질 플래그 | `sampling_1fps` | `sampling_static_1fps` · `sampling_agentic` |
| 프롬프트 문구 | `sampling_fps` 설명 2줄 | 방식 무관 문구 + agentic의 자율 확인·미확인 구간 `coverage` 기록 지시 |

`processing_mode`가 `agentic`일 때 `fps` 지정을 설정에서 거절한다. 저장된 기존 초안은 필드 부재 시 `static`으로 읽어 검증된 동작을 유지한다.

## 기본값 결정

`agentic`과 구조화 출력(`response_format` 스키마 강제)의 병용은 공급자 문서에 기재가 없다. 두 방식을 모두 구현하고 **운영 기본값은 검증된 `static`으로 두었다.** 실호출 없이 미검증 경로를 기본값으로 배포하지 않는다. 개발자 설정의 `합성 샘플 API 시험`으로 원장·분기 단계에서 병용을 확인한 뒤 기본값을 바꾼다. 모델 ID도 코드가 임의 선택하지 않으며 `gemini-3.8-flash`는 개발자 설정 또는 `KDOG_GEMINI_MODEL`로 지정한다.

## 사용량·비용

- `ledger` 단계를 과금 집계 대상에 넣었다. 정상 호출 수는 영상 N개 × 3 + 리포트 1회이며 충돌 시 분기별 재검토가 추가된다.
- `agentic`이 만드는 `total_thought_tokens`·`total_tool_use_tokens`는 `token_meters`가 이미 자동 수집한다. 여기에 더해, 단가 파일에 없는 token 계량이 기록되어 있으면 `unpriced_meters`로 보고하고 `complete_meter_cost_estimate`를 비운다. 이전에는 미등록 계량이 조용히 제외되어 추정액이 과소 계상되면서도 완전한 추정으로 표시될 수 있었다. 공급자 총합 `total_tokens`는 청구 범주가 아니라 롤업이므로 미등록 판정에서 제외한다.
- `gemini/gemini-3.8-flash` 단가는 운영자가 단가 파일에 등록한다. 도입가는 2026-12-31까지이며 2027-01-01부터 표준 단가이므로 `as_of`와 함께 명시한다.

## 화면

- `영상별 평가 결과`가 영상별 사건 원장(시행별 계산된 구령 횟수, 사건 목록, 미확인 사항)과 분기별 결과를 각각 펼쳐 보여준다. 근거 재생은 그대로 동작한다.
- 개발자 설정에 `영상 처리 방식`·`추론 수준`·`미디어 해상도`를 추가했다. `agentic` 선택 시 FPS 입력을 비활성화한다. 편집 단계에 `사건 원장`을 추가했고, 원장 프롬프트는 프로그램 소유이므로 편집란 대신 안내를 표시하며 모델·출력 한도는 영상별 직접 평가 단계 값을 쓴다.

## 자동 검증

저장소 밖 합성 자료로 수행했다. 실제 AI 정확도 시험과 구분한다.

| 검증 | 결과 |
| --- | --- |
| `backend/`: `uv run --locked python -X utf8 -m unittest discover -s tests` | 164개 통과 (기존 145 + 신규 19) |
| `backend/`: `uv run --locked python -X utf8 -m app.import_catalogs --check` | 행동 55·설문 30 및 원본 해시 일치 |
| `frontend/`: `npm run build` | TypeScript·Vite production build 통과 |
| `frontend/`: `npm run test:e2e` | 16개 통과 |
| 저장소: `git diff --check` | 통과 |
| `backend/`: `uv run --locked python -X utf8 -m tests.pilot_scenario --participants 3 --cameras 2 --seconds 2` | 통과 · 영상 호출 18 = 3참가자 × 2카메라 × 3, 리포트 3 |

`pilot_scenario`의 예상 호출 수식을 `참가자 × (카메라 + 3)`에서 `참가자 × (카메라 × 3 + 1)`로 고쳤다. 과거 M6 구현기록의 측정값은 그때의 파이프라인 기록이므로 다시 쓰지 않는다. `M2`·`M3` 구현기록의 `KDOG_GEMINI_MODEL` 안내도 당시 기록이므로 유지하며, 모델 지정 기준은 본 문서와 적용 계획이 갖는다.

신규 시험: `tests/test_ledger.py` 13개(순서표·스키마·무음/무근거 발화 거절·체크리스트가 사실을 거절하지 않음·대응 지시어 수행에서만 시행 종료·혼합 지시어와 놀이 지시·말 계량·지시 없는 구간의 계량 행 제외·미확정 귀속 제외·원장 대조·귀속 실패와 다중 시행 거절·분기별 계량 선택·놀이 발화의 무음 채점 차단·원장 버전 게이트), `test_video_evaluation.py` 2개(구버전 파이프라인 run은 결과 없이 scored가 되지 않음, 연쇄 재사용이 원장을 항상 동반), `test_settings.py` 2개(상호배타 설정 거절과 허용, 두 방식 모두에서 추론 설정의 실행 버전 분기), `test_observation.py` 1개(agentic 요청 본문·헤더·타임아웃·샘플링 플래그), `test_packaging.py` 1개(미등록 token 계량의 미계측 계상과 총합 단가 처리).

기존 시험 갱신: 3시야 시나리오의 호출 수가 영상당 3회 구조로, 항목 수가 분기별 36/19로, 샘플링 플래그가 `sampling_static_*`로 바뀌었다. 분기 산출물이 상대 분기 항목 기대값으로 검증되면 거절되는 것도 확인한다. `test_invalid_options_are_rejected_before_pending_normalization`은 잘못된 선택지를 담은 분기만 실패하고 다른 분기의 결과가 보존되는 것을 확인한다.

## 독립 cold review와 수정

두 독립 reviewer가 코드만 보고 검토했다. 제기된 22건 중 17건을 수용해 수정했고 2건을 근거와 함께 반려했다(나머지는 수용 항목과 중복). 아래는 수용한 결함이다.

- **놀이 구간 지시·말이 계산되지 않아 보호자가 "말 없음·방치"로 채점될 수 있었다.** `command_counts`가 `command_utterance`만 세는데 프롬프트는 놀이 지시·말을 `play_cue`로 기록하게 한다. 원장이 항상 0을 계산하므로 원장을 따르는 분기가 OWN-18:S4를 통과시킬 수 있었다. `play_cue`를 계량에 포함했다.
- **반려견 항목과 보호자 항목이 같은 계산값을 공유했다.** DOG-13/14/15는 그 지시어의 발화 수를, OWN-11/18은 원문 선택지가 말하는 "지시·말 반복"을 묻는다. 다른 지시어가 섞인 발화를 빼면 OWN-11:S3(4회 이상·지시어 뒤섞임)이 도달 불가능해진다. 시행별로 `count`(같은 지시어)와 `talk_count`(보호자 지시·말 전체)를 함께 계산하고 항목 분기에 따라 대조한다.
- **귀속 실패 시 모든 시행 중 아무 값이나 맞으면 통과했다.** `counted_steps`의 `inside or rows` 폴백이 귀속 검사를 무력화했다. 지시② 구간에 걸친 측정이나 훈련 전체에 걸친 합산값이 통과했다. 겹치는 시행이 정확히 하나일 때만 대조하고, 없거나 여러 개면 그 항목을 보류한다.
- **한 시행이 무관한 수행에서 끊겼다.** `dog_performance`의 지시어를 확인하지 않아 다른 행동이 시행을 종료시켰다. 대응 지시어가 일치하는 수행에서만 끊고, 프롬프트에 수행·반응의 `command` 기록을 명시했다.
- **체크리스트가 관찰된 사실을 거절했다.** `skipped` 구간의 사건을 오류로 처리해 원장 전체가 실패하고 그 영상의 분기가 실행되지 않았다. "체크리스트는 실시 계획·운영 기록이며 성공·행동 부재의 근거가 아니다"라는 프로젝트 규칙에 정면으로 어긋난다. 검사를 제거하고 불일치는 `quality_flags`로 남기도록 프롬프트를 바꿨다.
- **연쇄 재사용에서 원장이 빠져 공유 사실 검사가 우회되고 조회가 영구 실패했다.** 재사용 manifest에 로컬 실행 원장만 내보내, 원장을 재사용한 run을 다시 재사용하면 분기 판단만 전달되었다. 새 원장이 다른 값을 계산하면 병합은 통과하고 이후 모든 조회가 500으로 실패했다. `ledger_references`로 재사용을 한 단계 따라가 실효 원장을 내보내고, 원장 없는 분기 판단은 재사용하지 않으며, 조회·병합 경로에서 원장 없는 분기 판단을 409로 거절한다.
- **구버전 파이프라인 run을 재개하면 구조가 섞이고 결과 없이 "점수 준비됨"으로 표시됐다.** 분기 없는 기존 `observe` 산출물이 완결 검사의 여분 원소가 되어 병합이 영구히 막히는데, 모든 단계가 성공이므로 상태가 `scored`가 되었다. 스냅샷의 `pipeline_version`이 현재와 다르면 단계 생성 전에 중단하고, `integrate` 없는 실행은 절대 `scored`로 표시하지 않는다.
- **계산 규칙을 바꾸면 저장된 원장이 모두 무효가 됐다.** `validated_ledger`가 현재 코드로 항상 재유도해, 규칙 수정만으로 과거 run의 조회가 깨졌다. `measures`에 기록된 원장 버전이 현재와 같을 때만 재유도한다. 이번 수정으로 `ledger-1.1`이 되었다.
- **단가 미등록 계량이 있는 호출이 `unpriced_or_uncertain_calls`에 계상되지 않았다.** 전체 추정은 올바르게 비었지만 "미계측 호출 0"이라고 단정했다. 해당 호출을 미계측으로 계상한다. 반대로 공급자 총합(`total_tokens`)만 단가에 등록한 경우에는 모든 범주가 그 안에 포함되므로 미등록으로 보지 않는다.
- **기존 방식에서는 추론 설정이 실행 버전에 반영되지 않았다.** 기존 관찰 경로도 `sampling`을 읽는데 `config_version`은 영상별 경로에서만 갈라졌다. 두 경로 모두 반영한다.
- **원장 단계가 화면에서 "영상별 직접 평가"로 표시되고, 어느 영상·분기의 호출인지 알 수 없었다.** 단계 이름과 파일명·분기를 함께 표시한다.
- **분기 결과가 없으면 원장이 화면에서 사라졌다.** 원장만 성공한 실행에서 유일한 산출물이 보이지 않았다. 원장이 있으면 표시한다.
- **지시가 없는 구간에도 "계산된 구령 N회"가 표시됐다.** 계량 행을 지시 시행과 놀이 구간에만 만들고, 채점 행이 없는 지시②는 그 사실을 함께 표시한다.
- **사건 원장 편집 단계에서 모델·출력 한도 입력이 영상별 평가 단계를 조용히 수정했다.** 해당 입력을 비활성화했다.
- **원장 합성 시험이 사건을 하나라도 반환하면 실패로 처리했다.** 원장 프롬프트는 빈 결과를 요구하지 않으므로 정상 응답이 실패로 보고될 수 있었고, 이는 agentic 전환의 유일한 게이트다. 실제 계약인 `validate_events`로 검사하도록 바꿨다.

반려한 지적:

- **한 영상의 원장 실패가 전체 병합을 막는다.** 이번 변경 이전에도 모든 영상이 평가되어야 병합하는 설계였다(카메라 간 합산 금지의 귀결). 원장은 실패 경로를 하나 늘렸을 뿐이며, 부분 병합은 별도 결정이 필요하다.
- **합성 시험이 반려견 분기만 확인한다.** 보호자 분기 시험 단계를 새로 만들어야 하고, 무음 회색 영상에서는 보호자 음성 규칙을 의미 있게 확인할 수 없다.

## 유지된 제약

원문 55항목·선택지·점수를 변경하지 않았다. DOG-12·OWN-14는 `rule_pending`을 유지한다. 지시②에 채점 행을 만들지 않았다. 시행 경계·시행 간 합산 등 원문에 없는 채점 규칙을 만들지 않았고, 확정할 수 없는 것은 보류와 `unknown` 귀속으로 남겼다. 평균·다수결·자신감 가중치·카메라 간 합산을 사용하지 않는다. 기존 run의 설정 스냅샷·산출물·플래그·버전 문자열은 재작성하지 않으며, 과거 `sampling_1fps` 플래그를 가진 근거는 그대로 조회된다.

## 남은 작업

1. 개발자 설정의 `합성 샘플 API 시험(provider)`으로 원장·분기 단계와 `agentic` 병용을 실호출 확인한다. 병용이 확인되면 운영 기본값을 `agentic`으로 바꾼다.
2. 허용된 실제 3영상으로 `static` 단일 호출 대비 세 호출 구조의 항목 일치율·보류율·토큰·지연을 측정한다. 이 측정 없이는 토큰 3배 여부를 단정할 수 없다.
3. 단가 파일에 `gemini/gemini-3.8-flash`와 `total_thought_tokens`·`total_tool_use_tokens`를 등록한다.
4. 지시 단위 순서 변경·재촬영 기록은 운영자 입력(`checklist`가 구간 단위) 확장이 필요하므로 별도 범위다. 현재는 `unknown` 귀속과 보류로 처리한다.
5. 훈련 시행 경계의 원문 규칙(다른 지시어 혼입, 긴 침묵 후 재발화, 수행 후 추가 발화)을 확인하면 `ledger.command_counts`의 절단 규칙을 그 근거로 교체한다.
6. 독립 cold review.
