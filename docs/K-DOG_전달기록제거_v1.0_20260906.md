# K-DOG 전달 기록 제거 기록

작성일: 2026-09-06

범위: 앱 내 수동 전달 이력·정정 필요 표시 제거, 파일 내보내기 유지, 기존 SQLite/백업 호환

## 운영 계약

보고서는 파일 내보내기까지만 담당한다. 앱은 이메일·메신저 등 어떤 채널로도 파일을 보내지 않으며, 보낸 사실을 기록하지도 않는다. 운영자는 PDF·Excel·CSV를 내려받아 기존 외부 수단으로 직접 전달하고 그 이력은 앱 밖에서 관리한다.

기존에 있던 것은 실제 발송 기능이 아니라 **수동 전달 기록**이었다. 파일별로 이메일·메신저·기타 채널과 메모를 남기고, 기록 이후 결과가 바뀌면 ‘전달 이후 변경’을 표시했다. 이 기능 전체를 제거한다.

내보내기의 나머지 계약은 그대로다. 대상 미리보기, 미리보기 해시 검증, 결과 버전 고정, 생성 실패 시 같은 스냅샷 재출력, 권한·삭제 요청 검사는 변경하지 않았다. 이전에 만든 파일은 이후 수정에도 바뀌지 않는다. 정정이 필요하면 현재 결과로 새 파일을 만들어 다시 전달한다.

## 변경 범위

- 프런트엔드: 채널 라벨(이메일·메신저·기타), 전달 기록 입력 폼, 전달 이력 목록, 전달 상태 문구를 제거했다. 파일별 접이식 영역은 `대상·버전`만 남는다. 전달 기록 폼만을 위해 존재하던 `canRecord` 속성을 `Exports`·`Reports`·`Observations`·목록 화면에서 제거했다. 목록 안내 문구의 ‘결과 전달’을 ‘결과 내보내기’로 바꾸었다.
- API: `POST /api/exports/{export_id}/deliveries`를 제거했다. `DeliveryRecord`·`DeliveryView` 모델과 `ExportMember`의 `deliveries`·`correction_needed` 필드도 함께 제거했다. 내보내기 생성·미리보기·목록·생성 재시도·다운로드 경로는 그대로다.
- 서버: `exports.record_delivery`를 제거했다. `export_view`는 전달 이력 조회와 최신 결과 재계산을 하지 않으므로 `store`·`db` 인자가 필요 없어졌고 스냅샷만 읽어 응답을 만든다. 목록 조회에서 참가자별 리포트를 다시 계산하던 경로가 사라진다.
- 테스트: 전달 기록 회귀 시험을 파일 고정 검증으로 대체했다. 결과를 수정해도 이미 생성된 파일의 바이트가 같고 응답에 전달 필드가 없으며 제거된 경로가 라우트 목록에 없고 성공 응답을 돌려주지 않는 것을 확인한다.
- 문서: PRD의 기능·역할·화면·데이터 모델·인수 시험 항목과 AI 처리 파이프라인, 바이브코딩 구현지시서를 갱신했다. UI/UX 점검·개선 검증 기록은 당시 이력으로 보존하고 현재 계약 링크를 머리말에 추가했다. 원본 Excel과 평가 규칙은 변경하지 않았다.

## 기존 DB와 백업

SQLite 스키마·user_version은 변경하지 않았다. 마이그레이션도 없다. 과거에 기록된 `export.delivery` 감사 행은 삭제하지 않고 그대로 둔다. 읽는 코드가 없으므로 화면·파일·API 응답에 나타나지 않으며, 감사 원장에서 과거 기록을 지우지 않는 기존 방침을 따른다.

자료 삭제 시 해당 내보내기 대상의 `changes` 행을 일괄 삭제하는 기존 동작이 과거 전달 행에도 그대로 적용되므로 삭제 요청 처리에는 영향이 없다. 백업 파일 참조 수집은 파일 경로·해시 키만 훑으며 전달 상세에는 그런 키가 없다.

구버전 앱과 신버전 앱을 같은 데이터 폴더에 동시에 실행하지 않는다. 서버와 worker를 함께 종료한 뒤 프런트엔드를 빌드하고 새 코드로 재시작한다. 실제 운영 DB는 이번 검증에서 열지 않았다.

## 의존성 확인

확인일: 2026-09-06. 새 의존성을 도입하지 않았고 `backend/pyproject.toml`·`uv.lock`·`frontend/package.json`·`package-lock.json`을 변경하지 않았다. 이번 작업은 기존 API·모델·화면에서 기능을 제거하는 범위이므로 라이브러리·프레임워크 선택이나 버전 판단이 개입하지 않는다. 검증 환경은 Python 3.14 / Node.js 24이며 기존 고정 버전(FastAPI 0.141.1, Pydantic 2.13.5, React 19, Vite 8.2.2, Playwright 1.63.0)을 그대로 사용했다.

## 검증과 cold review

실행 명령은 `backend/`에서 `uv run --locked python -X utf8 -m unittest discover -s tests -v`와 `uv run --locked python -X utf8 -m app.import_catalogs --check`, `frontend/`에서 `npm run build`와 `npm run test:e2e`다. 저장소 루트에서 `git diff --check`를 수행한다.

- Python 127개 통과.
- 브라우저 16개 통과. 내보내기 선택·미리보기·생성·다운로드 흐름과 모바일 화면을 포함한다.
- production build(`tsc --noEmit && vite build`) 통과.
- 행동 55항목·설문 30문항의 원본 카탈로그 대조 통과.

Cold review는 구현·시험 후 변경 diff와 인접 호출부를 다시 읽어 수행했다. 확인 항목과 결과는 다음과 같다.

- 제거된 모델·함수·속성의 잔존 참조를 저장소 전체에서 검색해 없음을 확인했다. 남은 ‘전달’ 표현은 모두 앱 밖 수동 전달을 가리킨다.
- `exports.py`의 `json`·`report_view`·`run_row` import가 다른 경로에서 계속 쓰이는 것을 확인했다. 화면의 `writable`도 다른 편집 권한 판정에 계속 쓰인다.
- 감사 원장·백업 참조 수집·자료 삭제 경로가 과거 전달 행 때문에 실패하지 않는지 대조했다. 허용 액션 목록이나 스키마 제약이 없어 영향이 없다.
- 처음 작성한 회귀 시험은 제거된 경로에 대한 POST가 405를 돌려주는 것에 의존했다. 이 값은 프런트엔드 빌드 산출물이 정적 마운트로 붙어 있을 때만 나오므로 환경에 따라 404가 될 수 있다. 라우트 목록에 해당 경로가 없고 응답이 2xx가 아닌 것을 확인하도록 고쳤다.

## 남는 한계

파일 생성 이후 결과가 바뀌었는지 알려 주는 표시는 함께 사라졌다. 이 표시는 전달 기록이 있는 대상에만 계산되던 것으로, 전달 기록 없이 유지하려면 목록을 열 때마다 모든 대상의 최신 리포트를 다시 계산해야 하고 이는 이전 점검에서 성능 문제로 피했던 경로다. 운영자는 최신 결과가 필요하면 새 파일을 만들어 대조한다.

앱 밖으로 나간 파일은 회수할 수 없다. 누구에게 무엇을 언제 보냈는지는 이제 앱에 남지 않으므로 외부 절차에서 관리해야 한다. 실제 참가자 데이터·운영 DB·공급자 실 API는 이번 검증에 사용하지 않았다. HTTPX TestClient에 대한 기존 Starlette 폐기 예정 경고는 그대로 남아 있으며 이번 범위에서 의존성을 교체하지 않았다.
