# PR-S02 설문과구글폼등록

버전: v1.0 · 2026-10-03 · 상태: 구현 전 · 선행: S01 · 기준: main 3654596

상위: [전체 계획](K-DOG_개발반영계획_v1.0_20261003.md). 공통 검증·리뷰·버전 확인·저장 보호는 상위 §7을 적용한다.

브랜치 제안: `veluga/s02-forms-intake` · 권장 PR 제목: `feat: 설문 파일로 참가자와 응답 등록`

## 문제와 결과

현재 참가자 import와 설문 import가 분리되고 설문은 기존 대상 ID를 요구한다. Google Forms CSV/XLSX를 확인하여 사전·현장 참가자 등록과 설문 연결을 한 흐름으로 처리하고 S1 결측 상태를 적용한다.

근거: 운영 요청 4항, 통합명세 10절·부록 D·D05/D06. 인수: T14·T25. 실시간 Google Forms API 연동은 범위에 넣지 않는다.

## 구현 순서와 입력 계약

1. 실제 폼 내보내기의 원헤더·시트·응답 문자열을 표준 프로필과 s01~s28에 연결한다. 파일 bytes/hash·원행·선택 판본·매핑 버전을 저장한다. 문항명 일치만으로 척도를 추정하지 않는다.
2. 미리보기에 대상 신규 생성 또는 명시적 기존 참가자/회차 연결을 표시한다. 원파일에 안정적인 ID가 없으면 서버 발급 ID를 미리보기에서 고정한다. 보호자명·개 이름·타임스탬프만으로 동일인 확정 금지.
3. 같은 import 재시도는 같은 결과를 돌려주고 중복 참가자를 만들지 않는다. 기존 응답 변경은 전후 값을 보여준 후 새 revision으로 반영한다. 행 오류·ID 충돌은 확정 전에 표시하며 일부 성공을 조용히 숨기지 않는다.
4. 참가자 생성과 해당 설문 반영은 같은 확정 작업으로 묶는다. 영상보다 설문이 늦은 경우 S03 수신 파일을 이후 대상에 연결한다. 동의 열이 없으면 미확인으로 보존한다.
5. 현재 v3 28문항 원문·척도·역채점·8영역+Q25를 재사용한다. Q10~11/Q12~14는 하나라도 결측이면 해당 묶음 null, 다른 영역은 독립 계산한다.
6. Q7~9를 포함한 나머지 부분 결측 정책은 확인 대기다. 완전 응답만 명시 산식으로 계산하고 부분값을 임의 평균·0 대체하지 않는다. Q24/25는 단일 원값으로 취급한다.
7. 예비 9월 정리표의 행/열 전치는 별도 입력 프로필로 처리하되 실제 원문 판본을 보존한다. 지원하지 않는 과거 척도는 원자료 참고 상태로 보관하고 S1 설문 결과·비교집단에 넣지 않는다.
8. API 응답에 설문 등록 상태와 산출/비교 가능 상태를 분리한다. 등록 완료 조건 미확정을 임의 ‘전문항 필수’로 바꾸지 않는다.

## 검증과 완료 조건

- 사전 응답 등록→현장 추가→같은 파일 재업로드→응답 수정 시 참가자 중복 없이 변경 이력이 남는다.
- 동명이인/같은 개 이름을 다른 대상으로 유지하며 모호한 연결은 확정 전 사용자 선택이 필요하다.
- Q10=0,Q11=2와 Q12=0,Q13=1,Q14=2는 각각 1.0. 하나가 null이면 해당 묶음만 미산출.
- Q26~28의 1/3/5는 역채점 5/3/1. 원응답은 유지한다. Q1~6 부분응답과 두려움 완전응답을 함께 시험한다.
- 예비 1~5 편안함은 0~4 두려움으로 자동 환산되지 않는다. 중복열·잘못된 라벨·숫자 아닌 값·수식 셀·판본 충돌을 검출한다.
- 확정 중 대상 삭제/revision 변경, 권한 변경을 검사한다. 신설 시험 두 모듈과 importer/survey 브라우저 회귀를 수행한다.

## 경계와 인계

S13에 원응답·역채점·집계 정책·유효 n과 중복 대상 식별자를 전달한다. 실제 폼 파일이 없으면 합성 형식으로 구조 구현을 검증하고 실제 매핑 검수는 대장에 남긴다. 과거 참가자 자료를 저장소 fixture로 복사하지 않는다.
