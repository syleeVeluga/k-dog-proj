## 문제와 결과

현재 참가자 import와 설문 import가 분리되고 설문은 기존 대상 ID를 요구한다. Google Forms CSV/XLSX를 확인하여 사전·현장 참가자 등록과 설문 연결을 한 흐름으로 처리하고 S1 결측 상태를 적용한다.

근거: 운영 요청 4항, 통합명세 10절·부록 D·D05/D06. 인수: T14·T25. 실시간 Google Forms API 연동은 범위에 넣지 않는다.

## 구현 순서와 입력 계약

1. 실제 폼 내보내기의 원헤더·시트·응답 문자열을 표준 프로필과 s01~s28에 연결한다. 파일 bytes/hash·원행·선택 판본·매핑 버전을 저장한다. 문항명 일치만으로 척도를 추정하지 않는다.
2. 미리보기에 대상 신규 생성 또는 명시적 기존 참가자/회차 연결을 표시한다. 원파일에 안정적인 ID가 없으면 서버 발급 ID를 미리보기에서 고정한다. 보호자명·개 이름·타임스탬프만으로 동일인 확정 금지.
3. 같은 import 재시도는 같은 결과를 돌려주고 중복 참가자를 만들지 않는다. 기존 응답 변경은 전후 값을 보여준 후 새 revision으로 반영한다. 행 오류·ID 충돌은 확정 전에 표시하며 일부 성공을 조용히 숨기지 않는다.
4. 참가자 생성과 해당 설문 반영은 같은 확정 작업으로 묶는다. 영상보다 설문이 늦은 경우 S03 수신 파일을 이후 대상에 연결한다. 동의 열이 없으면 미확인으로 보존한다.
5. 현재 v3 28문항 원문·척도·역채점·8영역+Q25를 재사용한다. Q10~11/Q12~14는 하나라도 결측이면 해당 묶음 null, 다른 영역은 독립 계산한다.
6. Q7~9를 포함한 나머지 부분 결측 정책은 확인 대기다. 완전 응답만 명시 산식으로 계산하고 부분값을 임의 평균·0 대체하지 않는다. Q24/25는 단일 원값으로 취급한다.
7. 예비 9월 정리표의 행/열 전치는 별도 입력 프로필로 처리하되 실제 원문 판본을 보존한다. 지원하지 않는 과거 척도는 원자료 참고 상태로 보관하고 S1 설문 결과·비교집단에 넣지 않는다.
8. API 응답에 설문 등록 상태와 산출/비교 가능 상태를 분리한다. 등록 완료 조건 미확정을 임의 ‘전문항 필수’로 바꾸지 않는다.

## 검증과 완료 조건

- 사전 응답 등록→현장 추가→같은 파일 재업로드→응답 수정 시 참가자 중복 없이 변경 이력이 남는다.
- 동명이인/같은 개 이름을 다른 대상으로 유지하며 모호한 연결은 확정 전 사용자 선택이 필요하다.
- Q10=0,Q11=2와 Q12=0,Q13=1,Q14=2는 각각 1.0. 하나가 null이면 해당 묶음만 미산출.
- Q26~28의 1/3/5는 역채점 5/3/1. 원응답은 유지한다. Q1~6 부분응답과 두려움 완전응답을 함께 시험한다.
- 예비 1~5 편안함은 0~4 두려움으로 자동 환산되지 않는다. 중복열·잘못된 라벨·숫자 아닌 값·수식 셀·판본 충돌을 검출한다.
- 확정 중 대상 삭제/revision 변경, 권한 변경을 검사한다. 신설 시험 두 모듈과 importer/survey 브라우저 회귀를 수행한다.

## 경계와 인계

S13에 원응답·역채점·집계 정책·유효 n과 중복 대상 식별자를 전달한다. 실제 폼 파일이 없으면 합성 형식으로 구조 구현을 검증하고 실제 매핑 검수는 대장에 남긴다. 과거 참가자 자료를 저장소 fixture로 복사하지 않는다.

### 2026-10-04 구현·검증 기록

`forms_v4.py`에서 CSV/XLSX 시트와 전치 배치의 원헤더, 문항별 원라벨, 명시적 대상/회차를 검증한다. 원파일·매핑·원행·미리보기는 불변 파일과 해시로 고정하고, ID가 없는 신규 참가자의 ID도 미리보기에서 발급한다. 확정은 미리보기 ID/hash만 받으며 참가자와 설문을 한 DB 트랜잭션으로 반영한다. 같은 요청/원파일 반복은 같은 결과를 반환하며 역할·삭제·회차·revision은 재검사한다. 원척도가 다른 과거 자료는 참고 원행으로만 보관한다.

`survey_v4.py`와 `survey-policy-v4.json`은 두려움 두 묶음의 결측과 나머지 묶음의 미확정 정책을 구분한다. Q10=0,Q11=2 및 Q12=0,Q13=1,Q14=2는 각각 평균1, Q26~28=1/3/5는 변환5/3/1이다. 원응답은 유지하며 Q24/Q25는 각각 원값으로 표시한다. 등록 완료 기준과 외부 비교 D06 승인은 산출 여부와 분리한다.

API에는 `/api/forms/columns`, `/preview`, `/commit`을 연결했다. 최대32MiB 파일만 허용하며 원자료는 URL에 넣지 않는다. `FormsImporter.tsx`에서 신규/기존 회차, 전후 응답·빈칸 사유, 전체 오류와 일괄 확정을 확인한다. 파일·시트·배치가 바뀌면 대상과 라벨 연결을 초기화한다. revision 충돌 시 최신 상태로 다시 연결하여 새 미리보기를 만든다. 접수/설문 메뉴에서 동일 흐름을 사용한다.

독립 cold review에서 다음 항목을 수용·수정했다.

- 오류행과 참가자 생성 전 미리보기도 명시한 case 또는 행사/참가자 ID로 삭제 대상과 연결한다. 이름으로 동일인 추정은 하지 않는다.
- 여러 시트의 같은 원파일은 source hash로 모든 참조를 함께 정리한다. 남은 참가자의 독립 원행 기록은 유지한다.
- 참가자 생성 전 백업을 복원해도 현재 삭제 대장을 적용하여 원본 미리보기가 부활하지 않는다. 서버 발급 ID와 원파일 ID 모두 시험했다.
- `ref`, `storage_ref`, `*_json`이라는 원헤더·응답 라벨은 사용자 데이터로 취급하고 백업 파일 참조로 해석하지 않는다.
- 시트/배치 변경 후 이전 대상 연결이 남는 문제와 revision 충돌 뒤 재확인이 불가능한 화면을 수정했다.

자동 시험: `uv run --locked python -X utf8 -m unittest tests.test_forms_import_v4 tests.test_forms_api_v4 tests.test_survey_v4 tests.test_settings -v` **58개 통과**(Forms30/API4/설문11/백업·권한13). 원척도0/null, 수식·중복열·잘못된 라벨, 동명이인, 반복 요청, 대상 삭제/권한 철회/revision 충돌, 원본 손상, 부분 실패 원자성, 삭제·복원까지 검증했다. 프론트는 `npm run build`와 `KDOG_TEST_INTAKE_SPEC=20261002`에서 importer/survey 브라우저 시험을 실행한다. 최종 실행 결과·commit은 [실행 기록](K-DOG_구현실행기록_v1.0_20261003.md)에 기록한다.

2026-10-03 확인한 기존 Pydantic/FastAPI/openpyxl/React/Playwright 잠금 버전을 유지했다. 최신 안정판·선택 이유·공식 문서 링크는 실행 기록의 의존성 표를 적용하며 신규 패키지는 도입하지 않았다. 실제 Forms 파일의 매핑 검수는 [후속 대장](K-DOG_실측및확인후속대장_v1.0_20261003.md)에 남기고 D05/D06은 미확정 상태를 유지한다. S13에는 원응답·변환값·정책 판본·영역별 유효 상태를 제공한다.
