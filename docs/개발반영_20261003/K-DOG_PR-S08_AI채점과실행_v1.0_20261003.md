## 구현 순서와 실행 계약

1. S1 설정/프롬프트/hash를 만들고 기존 분석 설정을 교체한다. 구판 설정을 계속 실행하는 호환 모드는 만들지 않는다. 모델·API·지원 FPS/음성/구조화 출력은 구현 시 공식 최신 자료로 재확인하고 기존 고정 버전을 유지할 경우 이유를 기록한다.
2. 숫자83개와 메모3개의 경로를 명시한다. 자동4개·개59 연결메모·폐기·미사용 코드는 숫자 채점 응답 집합에 넣지 않는다. 메모는 관찰 근거만 작성하며 G 검토메모나 사람 독립 점수를 입력하지 않는다.
3. 같은 관찰창·조건의 항목군을 재구성한다. 선택한 카메라 view들의 공통시각/시야를 제공하고 같은 행동을 각 카메라 점수로 따로 더하지 않는다. 단순히 기존 37호출을 새 목표 호출 수로 고정하지 않는다.
4. 숫자·null·사유·기회·전체 관찰량·클립 내부 근거를 검증하고 앱이 원본 hash/camera/시각으로 변환한다. 복수 view 같은 사건은 공통 사건 식별로 연결한다. 영상 밖 시각·타대상·존재하지 않는 사건 참조·부족한 전체 관찰량은 채택하지 않는다.
5. 채점→S07 계산→기본 판정→게시로 연결한다. 고정 애착 수치 분기식은 없으며 D04 미확정 세부 계약을 승인된 것으로 활성화하지 않는다. 해당 해석은 보류하되 다른 유효 원자료/계산은 게시할 수 있다.
6. `scoring_v4`는 공통 runs/steps·claim token·불변 attempt·호출 예약·수리 상한·중지/삭제 검사를 재사용한다. 초기화 전 실행·token·구판 종류의 요청을 거절하고 대체된 구판 실행 분기는 제거한다. 요청 ID로 응답 유실 뒤 중복 실행을 막는다.
7. 한 항목군 실패는 해당 항목 null+실패 사유로 남기고 다른 결과를 보존한다. 재생성은 새 실행이며 초기화 이후 생성한 S1 결과 중 카탈로그·창·영상·offset·모델·설정 hash가 맞는 명시적 reuse만 허용한다. 기존 앱의 AI 출력·전처리 캐시는 재사용하지 않는다.
8. 업로드/공급자 처리 대기/추론/수리/계산/게시 시간을 분리해 계량한다. 같은 원격 클립 재사용을 최적화한다면 수명·해시·삭제 소유권을 검증한 범위에 한정한다. 초기 실행은 직렬로 유지하고 병렬 속도 개선을 완료 기준으로 약속하지 않는다.

## 검증과 완료 조건

- 합성 응답에서 새 코드 집합·범위·자동값 거절·일부/전체 관찰·음성·선택 꼬리·미정 개21을 검사한다.
- 3CAM의 동일 행동이 횟수3으로 늘지 않고 모든 채택 근거가 실제 원본으로 역추적된다.
- 구판/다른 대상/다른 설정 재사용, 같은 크기 clip 변조, 입력 변경 중 실행을 거절한다.
- 공급자 429/timeout/잘린 응답/schema 오류, 원격 파일 삭제 실패, 예약 후 응답 유실의 과금 미확인을 시험한다.
- 점유 만료·옛 token·worker 재시작·사용자 중지·동의 철회·삭제 중 결과 채택을 검사한다.
- 공개 제한이 UI/API/원자료 다운로드에서 유지된다. 독립 사람 시트를 모델에 전달하지 않는다.
- 실제 참가자 자료 없이 계약 시험을 완료할 수 있으나 실제 정확도·시간은 S16 미실행으로 남긴다.

## 경계와 인계

S09에 기본 결과 snapshot, S12에 공통 실행·계량 패턴, S16에 설정/단계별 측정 로그를 전달한다. 참가자 영상의 유료 호출은 해당 작업의 동의·호출 범위가 확인된 실행에서만 수행한다. 단순 조회가 enqueue하지 않아야 한다.
