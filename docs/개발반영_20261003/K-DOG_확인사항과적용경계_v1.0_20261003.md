# K-DOG S1 확인사항과 적용 경계

버전: v1.0 · 2026-10-03 · 갱신: 2026-10-07 · 상태: 회신 수용안 계획 작성, 구현·교수 테스트·외부 비교 기준표 및 실측 대기

**회신 수용 후속:** 사용자가 대화로 전달한 회신을 반영한 [리포트 수용안 적용 계획](../리포트개편_20261007/K-DOG_리포트수용안적용계획_v1.0_20261007.md)을 작성했다. §0은 회신 수령 전 재확정 기록으로 보존한다. 이후의 설문 완전응답 방향·문장은행 없이 AI 작성·AI 애착 우선 판단은 새 계획을 따르고, 외부 비교는 교수님의 두 기준표를 받은 후 적용한다. 원메일 파일 수령·추가 문의 발송·구현 완료를 뜻하지 않는다.

상위: [전체 계획](K-DOG_개발반영계획_v1.0_20261003.md), 근거: [통합명세](K-DOG_원본자료목록_v1.0_20261003.md) 부록 G, [변경 검토](../K-DOG_개발기준변경검토_v1.0_20261003.md). 본 대장은 확정 개발을 진행하면서 확인이 필요한 기능의 활성 조건을 분리한다. 고객 원문 D/G와 아래 운영 계획 항목을 혼동하지 않는다.

2026-10-03 사용자는 기존 점수 등을 제거하고 다시 진행해도 된다고 지시했다. 기존 앱 결과의 보존·이관은 확인 대기가 아니라 **제외하기로 결정된 범위**다. [S01](K-DOG_PR-S01_초기화와S1전환_v1.0_20261003.md) 전환을 구현하고 2026-10-04 S15에서 실제 로컬 초기화를 적용했다. 원입력·영상 hash 보존, 사후 백업 복원과 초기화 이전 백업 차단을 [인수 검증 대장](K-DOG_인수검증대장_v1.0_20261003.md) O14에 기록했다. 모든 S1 점수는 새로 채점하며, 이 결정으로 원문 자체의 D/G 미확정 규칙까지 확정되는 것은 아니다.

S00~S15의 실측 외 확정 범위는 구현·자동 검증·cold review를 완료했다. 최종 전체 backend685개(780.886초)·브라우저41개(3.7분)와 현재 Windows의 실제 ZIP 새 설치 검증을 통과했다. S16 준비 도구와 S17 승인 조건부 종단 경로도 구현했지만 실제 영상 실측·깨끗한 OS/물리3PC·연구 승인은 후속이다. 아래 D/G는 자료·정책별 남은 경계이며 앱 전체의 미구현 목록이 아니다. 실제 실행과 후속 입력은 각각 [구현 실행 기록](K-DOG_구현실행기록_v1.0_20261003.md), [후속 대장](K-DOG_실측및확인후속대장_v1.0_20261003.md)에 연결한다.

## 0 2026-10-07 리포트 요구사항 재확정 기록

사용자는 리포트 검토와 확인 요청 이메일 초안 작성 후, 요구사항이 불명확하고 상당수 항목이 취소될 수 있으므로 이를 요구사항에 기록하도록 지시했다. 현재 상태는 **리포트 요구사항 재확정 필요 — 상당수 항목의 축소·취소 가능, 구체적인 대상과 범위는 미정**이다. 이미 확정된 변경과 향후 취소 가능성을 구분하며, 리포트 관련 요구사항 전체가 취소됐다고 해석하지 않는다.

기준 우선순위는 **사용자의 후속 결정 → 통합명세 SRC02의 확정 본문 → 산출근거 SRC03 → 예시 자료**다. 통합명세 9절·10절·부록 E/G를 준용하되, 문서가 제안·미확정으로 표시한 내용을 확정 규칙으로 올리지 않는다. 2026-10-07 SRC02·SRC03·SRC10의 SHA-256을 [원본 자료 목록](K-DOG_원본자료목록_v1.0_20261003.md)과 재대조했다. 고객 원본은 수정하지 않는다.

따라서 이번 재검토는 **대부분 리포트와 연결되지만, 모두 화면·문구만의 문제는 아니다.** 설문 계산·애착 판정·비교 통계에 연결된 요구는 리포트에서 표시를 빼더라도 자동으로 취소되지 않는다. 접수·원본 영상 보관·확정 관찰/채점·실행 및 결과 이력 보호를 일괄 취소하는 지시는 없다.

이번에는 요구사항 상태만 기록한다. 의뢰자의 회신 또는 사용자의 후속 결정으로 각 항목을 유지/변경/축소/취소로 구분한 뒤, 관련 R/D/G·S·T/O와 기대 결과를 연결하여 별도 구현 계획을 문서화한다. 그 전에는 미정 항목을 필수 구현 범위로 확장하거나 임의로 기능을 삭제하지 않는다. D04의 최종 자동화 승인 요청에 앞서 개발 측 반환 항목·실패 처리·출력 예시를 구체화한다. 이메일은 초안이며 발송·회신 수령으로 기록하지 않는다.

기존 S10~S13/S17 계획과 T22/O10 등의 장면·6쪽 관련 문구 및 완료 기록은 **당시 구현·검증 이력**이다. 이를 새 리포트 요구사항의 확정 또는 개편 완료로 간주하지 않는다. 이번 기록으로 앱 코드·산출물·운영 설정을 변경하지 않았으며, 확정된 장면 제거도 구현 완료와 구분한다.

## 4 기존 확인대장과의 관계

9월30일 Q번호와 10월2일 문서 Q번호는 별도다. 구 Q03의 개32 잠재기 문제는 S1 폐기로 종료한다. 구 Q01(상태/API 명칭과 조합)은 S00 및 후속 v4 계약의 구현·검증 기록으로 관리하고, 구 Q02(대표값/최소 관찰량)는 D03, 구 Q04(부분응답)는 D05, 구 Q05(중단 영향)는 확정 배점 제외와 D05 추가 무효 조건으로 나누어 관리한다. 구 Q06은 확정 의견 완료 조건 및 D04, 구 Q08은 D01/D02, 구 Q10은 D06, 구 Q12의 문장 부분은 G02와 연결한다. 구 Q07/Q09/Q11 및 연구 수용 조건은 이번 자료만으로 해소됐다고 표시하지 않는다.

## 5 회신과 변경 기록 형식

`ID / 확인 결과 / 적용·미적용·미확인 / 근거 파일·hash·위치 / 결정 주체·확인일 / 적용 PR·앱·모델·기준 버전 / 영향받는 기존 결과 / 검증 근거 / 남은 사항`을 사용한다.

고객 확인 결과는 원문 및 사용자가 대화로 전달한 회신의 명시 범위까지만 기록한다. 회신의 원메일 파일 수령이나 추가 기준표 수령·고객 메시지 발송을 의미하지 않는다. 수용 방향·구현·실제 검증을 구분한다.
