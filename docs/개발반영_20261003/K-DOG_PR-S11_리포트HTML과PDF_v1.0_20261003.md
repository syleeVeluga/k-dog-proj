# PR-S11 리포트HTML과PDF

## 문제와 결과

제공된 매거진형 HTML과 6쪽 PDF를 실제 대상 데이터로 렌더하는 새 출력기를 만든다. 현재 구형 리포트 모듈의 채점 의미는 재사용하지 않고 자산·파일 처리 기반만 필요한 만큼 활용한다.

근거: 제공 HTML/PDF·포맷 안내, 통합명세 10절. 인수: T16·T21~T24·T31의 화면/인쇄.

## 구현 순서와 출력 계약

1. 제공 자료에서 레이아웃·색·그래프 의미를 추출한다. 참가자 이름·사진·예비 점수는 템플릿 자산에 하드코딩하지 않는다.
2. 1쪽4카드→2쪽장면/시간→3쪽설문→4쪽설문/영상 비교→5쪽관계/걷기/환경→6쪽실천/총평/출처의 기본 구조를 구현한다. 별도 몸 영역·전문가 의견 상자를 만들지 않는다.
3. 청록=영상·코랄=설문, 등급색이 아님을 유지한다. 서로 다른 척도의 수치를 같은 축에 겹치지 않고 단위·결측·집단 n을 표시한다. 외부 비교는 기본 미승인 상태로 렌더한다.
4. 서버 PDF는 기존 PDF 생성 기반과 폰트를 활용하는 별도 S1 렌더러를 우선한다. HTML/PDF가 같은 ReportContent와 차트 수치를 사용하도록 한다. 라이브러리 교체가 필요하면 버전/호환성을 먼저 확인하고 범위를 기록한다.
5. 사진은 S10이 선택한 실제 시각의 승인된 장면에서 추출하고 원본 hash/시각을 출력 이력에 남긴다. 사진이 없으면 안내 공간으로 바꾸며 임의 대체 이미지를 만들지 않는다.
6. HTML은 휴대폰에서 카드1열, 읽기 가능한 글자·그래프를 제공한다. 인쇄용 페이지 규칙과 다운로드한 독립 HTML의 자산 포함 방식을 구현한다. 외부 네트워크가 없어도 필수 글꼴/그림이 보이게 한다.
7. 텍스트·메모·파일명을 escape하고 사용자 문장을 HTML/스크립트로 실행하지 않는다. 사진·민감 원본 경로를 공개 정적 URL로 노출하지 않는다.
8. 기본 사례는 6쪽으로 검수한다. 긴 설명은 근거를 유지한 출력 요약으로 조정하고 페이지 밖으로 자르거나 필수 사유를 몰래 생략하지 않는다. 더 많은 페이지가 필요한 예외는 명시해 검토하며 고정2~3쪽 제한은 넣지 않는다.
9. 고객이 추가 UI 디자인을 제공하면 4카드·6쪽/모바일·빈값/긴문장 사례, 글꼴·이미지 사용 조건, 차트 단위, 구성 요소 대응표를 전달 항목으로 사용한다. 현재 HTML/PDF로 구현을 시작할 수 있으며 추가 디자인을 필수 선행으로 만들지 않는다. 향후 분량 축소는 실제 제외 요청의 요소/적용 템플릿 버전을 기록해 반영하고 이번 기본 출력에서 미리 항목을 삭제하지 않는다.

## 검증과 완료 조건

- 정상/일부결측/전체결측/선택꼬리없음/의견유형변경/장면0~3/외부비교차단 fixture를 렌더한다.
- HTML과 PDF의 모든 수치·유형·분모·출처가 중간 데이터와 일치한다.
- PDF 전 페이지를 이미지로 렌더해 제공 견본과 구성·한글·색·축·표·페이지 나눔·잘림을 확인한다.
- 긴 이름·긴 한국어·기호/음수·사진없음·원척도 다름을 검증하고 데스크톱/360px·브라우저 인쇄를 확인한다.
- 자산 누락·폰트 대체·오프라인 HTML·위험 문자열을 검사한다. 사용자 데이터로 코드가 실행되지 않는다.
- 코드 시험 통과 외에 대표 화면과 PDF 시각 검수 결과를 실행 기록에 첨부한다.

## 경계와 인계

생성 큐·최신 출력 선택·재발급·권한은 S12가 담당한다. S11은 렌더 입력을 고정한 파일 생성기까지다. 새 라이브러리/브라우저 설치를 암묵 전제로 하지 않고 실제 배포 의존성은 S15 패키지에 명시한다.
