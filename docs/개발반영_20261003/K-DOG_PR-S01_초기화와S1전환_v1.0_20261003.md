상위: [전체 계획](K-DOG_개발반영계획_v1.0_20261003.md). 공통 검증·리뷰·버전 확인·저장 보호는 상위 §7을 적용한다.

## 문제와 결과

기존 평가 결과를 보존·이관하는 대신 제거하고 S1에서 처음부터 재채점한다. 이전 점수 조회, 판본 선택, 같은 의미 항목의 점수 복사, 구판 리포트 호환 기능은 만들지 않는다. 참가자·원본 영상·설문 등 재작업 입력과 운영 계정·동의는 유지한다.

근거: 2026-10-03 사용자의 “이전 것들 점수 등은 제거 해도 됨 어차피 다시 할꺼라” 지시. T15의 역사 자료 보존은 고객 원본에 적용하고 기존 앱 점수에는 이 지시를 우선한다. T20의 의미 변경 항목 재채점에 더해 기존 점수 전체를 새로 채점한다. 고객이 제공한 기준 문서·검수 Excel 원본을 삭제한다는 뜻은 아니다.

## 구현 순서와 저장 계약

1. 실제 설정의 데이터 루트와 파일 참조를 읽어 제거할 DB 레코드·파생 파일 및 유지할 입력을 분류한다. 최종 절대 경로가 데이터 루트 안에 있는지 확인하고 `docs/`, 외부 원본, 계정·비밀 저장 위치를 대상에서 제외한다.
2. 실행 중 분석을 중지/무효화하고 새 요청을 차단한 뒤 초기화한다. 옛 worker의 늦은 결과가 다시 등록되지 않도록 claim token·입력 세대를 검증한다. 실행/응답 레코드 제거 전에 원격 업로드 파일 ID·credential reference·삭제 실패 감사 및 미정산 호출을 점검한다. 원격 삭제 실패/응답 유실은 최소 정리 기록으로 남겨 재시도하며, 정리 완료 전에 유일한 삭제 참조를 지우지 않는다. 옛 점수 본문 보존은 필요 없다.
3. 현재 원입력만 S1 접수 계약에 연결한다. 구판 결과의 부모 체인·판본별 조회 어댑터·점수 변환표는 만들지 않는다. 식별·설문 원문 판본·실제 촬영 절차는 입력 사실로 유지한다.
4. 모든 S1 채점값은 미관찰/null로 시작한다. 의미가 바뀐 5개뿐 아니라 기존 점수 전체를 재채점하며, 같은 ID/같은 정의여도 복사하지 않는다. 옛 개32=99·폐기33·미사용4는 새 시트에 없다.
5. 결과 참조 제거와 새 입력 상태를 먼저 원자적으로 반영하고 제거 목록의 파일을 정리한다. 중간 실패 후 같은 작업을 반복해도 원본 손실·참조 부활이 없어야 한다.
6. 새 운영은 S1 경로 하나를 사용한다. 후속 기능이 미구현이면 재분석 필요/기능 준비 중으로 표시하고 구판 채점으로 fallback하지 않는다. 실제 운영 개시는 S15에서 검수한다.
7. 반복 초기화 시 새로 생성된 S1 결과를 무조건 지우지 않도록 초기화 대상 세대/ID 목록을 고정한다. 향후 별도 초기화 실행은 별도 명시 작업으로 구분한다.
8. S1 전환 이후 새로 작성하는 독립 사람/AI 원자료·의견·리포트의 revision/hash·이력은 기존 보호 원칙대로 관리한다. 이번 삭제 허용을 향후 정상 기록의 자동 삭제 정책으로 확대하지 않는다.

## 검증과 완료 조건

- 기존 점수·계산·리포트·실행/전처리 파생물이 제거되고 API/UI/export에서 조회·재사용되지 않는다.
- 원본 영상·수령 MP4·설문 원응답·고객 검수 Excel의 hash, 참가자 식별·동의·계정/설정이 변하지 않는다.
- 초기화 후 모든 S1 점수가 null이고 새 채점으로만 결과가 생성된다.
- 실행 중 worker·삭제 중 중단·반복 초기화·손상 참조·데이터 루트 밖 경로를 시험한다. 늦은 결과가 옛 점수를 되살리지 않는다.
- 초기화 실패 복구와 S1 백업/복원에서 제거한 구점수가 자동으로 다시 연결되지 않는다.
- 공급자 삭제 실패·삭제 응답 유실·실행 중 업로드에서 원격 파일 정리 참조가 초기화 이후에도 남는다. 재시도 완료 뒤 최소 기록을 정리하고 미정산 호출을 성공/0원으로 바꾸지 않는다.
- 신설 후 `uv run --locked python -X utf8 -m unittest discover -s tests -p "test_reset_s1.py" -v`, 접수/권한/삭제 회귀와 화면 시험을 수행한다.

## 경계와 인계

이전 평가 결과의 무손실 이관·조회·백업 복원 호환은 완료 조건에서 제외한다. 원입력을 남기는 최소 전환과 새 S1의 데이터 보호는 유지한다. 이번 문서 개정에서는 실제 데이터 삭제를 실행하지 않았다. 실제 초기화는 S01 구현 작업에서 위 범위와 경로 검증을 거쳐 수행한다.
