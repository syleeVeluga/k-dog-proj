## 1 목표와 문서 사용 순서

[변경 검토](../K-DOG_개발기준변경검토_v1.0_20261003.md)를 바탕으로, 9월 29일판 C00~C07B를 S1.1로 개정하고 기준 코드에서 미구현이던 리포트·현장 운영을 완성하는 계획이다. **기본 16개 PR S00~S15, 실자료와 연구 확인이 필요한 조건부 2개 PR S16~S17**로 구성한다. 번호는 이 계획의 식별자이며 GitHub PR 번호가 아니다. 조건부 단계의 실행 도구·승인 경로는 실자료 수령 전에 구현하고 실제 측정·활성화와 구별한다.

개발 기준은 [통합명세 v1.3](K-DOG_원본자료목록_v1.0_20261003.md), [산출근거 Excel](K-DOG_원본자료목록_v1.0_20261003.md), [운영 요청](K-DOG_원본자료목록_v1.0_20261003.md) 순으로 연결하되 사용자의 후속 결정이 우선한다. 리포트 HTML/PDF 예시는 내용 검토용이며 디자인·레이아웃을 준용하거나 예시 수치를 골든값으로 복사하지 않는다. 기존 C계획은 완료 이력·공통 보호장치의 근거로 보존하며 리포트 재확정과 관련 없는 구현 순서는 이 계획을 따른다.

먼저 이 문서, [원본 자료 목록](K-DOG_원본자료목록_v1.0_20261003.md), [요구사항 추적표](K-DOG_요구사항추적표_v1.0_20261003.md), [확인사항과 적용 경계](K-DOG_확인사항과적용경계_v1.0_20261003.md), [인수 검증 대장](K-DOG_인수검증대장_v1.0_20261003.md)을 읽고 해당 PR 상세 파일로 진행한다. 각 PR의 초기 파일/API 제안과 당시 미실행 체크는 계획 이력이며, 실제 적용 파일·검증·남은 경계는 해당 문서의 날짜별 구현 기록을 따른다. 계획 문서 병합과 앱 구현 완료를 구분한다.

**기존 앱의 점수·계산·AI 분석 결과·리포트·연구 내보내기·재생성 가능한 전처리 산출물은 초기화한다.** 이전 점수 조회·무손실 이관·점수 변환·구판 리포트 호환은 개발 범위에서 제외한다. 참가자 식별과 회차, 원본 영상·수령한 변환본, 설문 원응답, 실제 촬영 시각, 고객 검수 자료, 계정·설정·동의·삭제 이력은 유지한다. 구체적인 제거/유지 범위와 중단 후 재실행은 S01에서 검증한다. 이 결정은 기존 결과의 일회성 정리에 적용하며, S1 전환 후 생성되는 결과의 불변 이력·백업 보호는 계속 적용한다.

| 영상 | 원본 파일 ID/hash·원본 번호·운영 camera_id·원본/파생 관계·변환 설정·공통 시각 offset |

| 최종 출력 | 최종 결과·설문 집계·문장·비교집단·템플릿·모델/프롬프트·출력 파일 hash 고정 |

같은 ID·같은 정의인 항목도 기존 앱 점수를 복사하지 않는다. S1 값은 전부 null에서 시작하고 원본 영상·설문을 기준으로 다시 산출한다. 신규11개도 관찰 전 null이며 폐기33개는 S1 입력/산출에서 제외한다. 개59는 새로 작성하는 별도 메모다. 고객 검수 파일의 과거 값은 원본 대조 자료로만 남기며 현재 시트에 자동 반영하지 않는다. 이전 전처리·AI 출력의 재사용과 점수 변환표는 만들지 않는다. 날짜·동의·관찰 내용을 추정하지 않는다.

모든 저장 PR는 S1의 새 파일·DB 참조 해시 검증, 백업·복원, 삭제 상태 재확인과 삭제 이력 재적용을 함께 구현한다. S15에서 처음 붙이지 않는다. 초기화 후 구판 백업을 복원하여 폐기한 점수를 되살리는 경로는 지원하지 않는다. 이후 복구는 초기화 이후 생성한 검증된 S1 백업과 호환 앱을 함께 사용한다.

## 5 원본 부재와 확인 대기의 처리

최종 빈 입력 원본·지정 영상·INSV/대응 MP4·압축본은 아직 확보되지 않았다. S00은 현재 명세·산출근거에서 검증 가능한 계약을 만들고, S06의 실제 S1 Excel import 활성화는 G01/G04 파일 검증 후에만 한다. 그 전에도 합성 자료로 수기 입력·계약·계산을 구현할 수 있다.

D01~D06의 확인 대기는 해당 기능에 국한한다. 특히 개21의 전체30초 확정값, 비공포 설문 묶음의 결측 정책 확대, 자유 의견→유형 상세 자동화, 외부 비교값 활성화를 임의 확정하지 않는다. 확인 전 진행 가능 범위와 부분 보류의 종료 조건은 별도 대장에 둔다. 기본 PR 완료와 고객 운영 인수, 실제 영상 정확도 검증 완료는 다른 상태다.

## 7 공통 구현과 검증 절차

한 PR 한 브랜치, 기본 접두어 `veluga/`. 구현 착수 시 현재 HEAD·작업트리·선행 병합·해당 문서를 확인한다. 코드 탐색은 graft의 그래프 확인/갱신(`graft check`/`graft build`)→`graft ask`/`graft grep`→`graft skeleton`→`graft callers` 호출 관계를 우선하고, 도구 부재 시 알린 뒤 fallback한다.

각 PR는 구현 → 해당 시험·원본 대조 → 독립 cold review → 발견사항 수용/보류/거절 사유 기록 → 수용 수정 → 관련 재검증 → 문서 실행 기록 → 푸시·PR 순서를 따른다. 실제 PR 생성·병합은 그 시점의 작업 지시에 따른다. 계획 문서만으로 구현·외부AI 호출·배포·고객 발송이 실행된 것으로 보지 않는다.

라이브러리·프레임워크·공급자 API를 구현에서 사용하기 전에 공식 문서·릴리스·레지스트리로 최신 안정판, 런타임/peer 호환성과 API를 확인한다. 확인일·최신/선택 버전·선택 이유·출처는 구현 실행 기록과 각 PR 기록에 남겼다. 기존 잠금 의존성을 유지하고 새 패키지나 관련 없는 일괄 업그레이드는 도입하지 않았다.

아래는 반복 검증 명령이다. 각 PR의 초기 “신설 후” 명령은 계획 당시 안내이며, 현재 시험의 실제 실행 결과는 날짜별 구현 기록을 따른다.

```powershell
# backend/
uv run --locked python -X utf8 -m unittest discover -s tests -v
uv run --locked python -X utf8 -m app.import_catalogs --spec 20261002 --check

# frontend/ — 화면 변경 PR
npm run build
npm run test:e2e

# 저장소 루트
git diff --check
git diff -- docs/
```

S00에서 `--spec 20261002`와 S1 기본 추출 경로를 추가했다. 구판 실행 유지와 모든 과거 판본 추출은 새 완료 조건에서 제외한다. G01 원본 미수령을 “대조 통과”로 숨기지 않고 원본별 검사 결과를 구분한다. 변경에 직접 필요한 회귀를 먼저 수행하고, 전체 검사는 통과 뒤 새 변경·실패가 없으면 반복하지 않는다. 브라우저 시험은 변경 화면과 공통 권한/사례 맥락 회귀를 포함하고 최종 전체 e2e는 S15에서 수행한다. 대체된 구판 전용 시험은 정리하고 공통 보호장치 시험은 S1에 맞춰 유지했다.

## 8 완료 기록과 인계

각 PR 파일의 실행 기록에 실제 commit/PR, 검증 명령과 결과, 리뷰·조치, 최신 버전 확인, 남은 D/G 항목, 운영 활성/보류 상태를 적는다. 체크박스는 실제 근거가 있을 때만 체크한다. 합성·실제 공급자·참가자 영상 검증을 구별한다. 민감한 실제 자료는 저장소·배포물에 넣지 않고 비식별 결과 요약과 보호된 원본 참조로 기록한다.

초기 계획 작성의 검증 범위는 문서 간 링크, 수정 대상 경로, PR 선행 관계, T01~T32와 D01~D06/G01~G05 담당 PR 누락, 원본 불변 여부였다. 이후 앱 구현·시험·리뷰와 실제 로컬 전환 기록을 별도로 추가했다.
