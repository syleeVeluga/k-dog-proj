# PR-S03 영상보관과동시업로드

버전: v1.0 · 2026-10-03 · 상태: 구현 전 · 선행: S01 · 기준: main 3654596

상위: [전체 계획](K-DOG_개발반영계획_v1.0_20261003.md). 공통 검증·리뷰·버전 확인·저장 보호는 상위 §7을 적용한다.

브랜치 제안: `veluga/s03-multi-pc-uploads` · 권장 PR 제목: `feat: 다중 PC 영상 수신과 대상 연결 분리`

## 문제와 결과

현재 업로드는 등록된 case/session과 시작 시 revision을 요구하여 같은 참가자에 대한 3PC 동시 업로드가 충돌할 수 있다. 완전히 수신한 파일을 참가자 연결과 분리해 보존하고, 재전송 없이 안전하게 연결·재시도하는 흐름을 만든다.

근거: 운영 요청 3~4항, 통합명세 2절·D01. 인수: T01·T22의 영상 식별 기반. 카메라 동기화·판독은 S04~S08 범위다.

## 구현 순서와 상태

1. 최소 상태는 수신 중→수신 완료/실패→대상 연결이다. 서버가 발급한 upload ID와 요청 ID로 중복 요청을 구별한다. 원래 파일명은 표시용이며 저장 경로는 서버가 정한다.
2. 수신 완료 시 bytes·hash를 확정하고 불변 파일로 보존한다. 참가자 미등록이면 미연결 보관함에 둔다. 미연결 파일의 접근 주체·현장 운영 권한과 수동 정리 동작을 명시한다. 임의 보관기간을 고객 정책으로 확정하지 않는다.
3. 연결은 명시한 case/session/camera에 대해 최신 manifest를 읽고 권한·삭제·회차 존재를 검증하는 짧은 트랜잭션으로 수행한다. 기존 입력을 덮지 않는 영상 append만 처리하고 revision을 새로 발급한다.
4. 동시 연결 충돌이면 완료 파일을 삭제하지 않고 연결 재시도를 제공한다. 최신 입력을 확인한 재시도에서도 같은 receipt가 중복 영상으로 붙지 않아야 한다. 기존 revision/삭제 보호를 무조건 제거하지 않는다.
5. 원본1→CAM1, 원본3→CAM2, 원본2→CAM3을 기록한다. 카메라 목록은 D01 변경을 허용하며 같은 대상/회차의 여러 파일을 유지한다.
6. INSV는 원본 보관 대상으로 받되 분석 가능 영상으로 표시하지 않는다. 변환 MP4 연결 시 부모 INSV/관련 파일 세트, 변환 설정·도구 버전·hash를 저장하고 S05에서 읽을 수 있는지 검증한다. 확장자 변경으로 변환을 대신하지 않는다.
7. 참가자/회차 수정 후 기존 분석은 이전 입력 상태로 표시한다. 삭제 중 수신·연결·다운로드를 재검사하고 해당 대상에 연결된 원본/파생/미완료 수신물을 삭제 참조에 포함한다.
8. 실패·취소된 일부 파일은 별도 정리하며 수신 완료 후 미연결 상태와 혼동하지 않는다. 재개 가능한 청크 전송·카메라 장치 자동 제어는 이번 최소 구현에 포함하지 않는다.

## 검증과 완료 조건

- 같은 revision에서 시작한 3PC 업로드가 모두 완료 파일로 남고 한 대상에 각각 한 번 연결된다.
- 연결 중 409가 나도 파일을 다시 올리지 않고 연결만 재시도한다. 응답 유실 후 반복 요청은 중복을 만들지 않는다.
- 수신 중 네트워크 중단/디스크 부족/서버 재시작, 연결 중 대상 삭제/권한 철회/회차 변경을 시험한다.
- 동일 hash의 중복 파일과 같은 camera의 다른 촬영 파일을 구별한다. 다른 대상 자료의 존재를 중복 검사 응답으로 노출하지 않는다.
- 미연결 파일과 INSV가 채점 가능한 것으로 표시되지 않는다. 경로 문자열·위장 확장자를 그대로 실행하지 않는다.
- 저장물 백업/복원/삭제, 브라우저 3컨텍스트 동시 시험을 수행한다. 실제 LAN 3PC 검수는 S15에서 반복한다.

## 경계와 인계

S04/S05에는 원본 ID와 camera/파생 관계를 제공한다. INSV 자동 변환기는 기본 제공으로 확약하지 않고 S16 호환성 조사 후 필요 범위를 결정한다. 외부 원격 전송이나 고객 발송 기능은 추가하지 않는다.
