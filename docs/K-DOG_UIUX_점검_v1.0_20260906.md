# K-DOG UI/UX 점검 — 운영자·교수·기능 사용 관점

> 이 문서는 당시 점검·구현 이력이다. 2026-09-06 후속 변경으로 앱 내 수동 전달 이력 기록과 ‘전달 이후 변경’ 표시를 제거했다. 현재 내보내기 계약은 [전달 기록 제거 기록](K-DOG_전달기록제거_v1.0_20260906.md)을 우선하며, 대상 미리보기·해시 검증·버전 고정은 유지한다.

문서 버전: v1.0

점검일: 2026-09-06

범위: 현재 프런트엔드·관련 API·PRD 대조, 실행 중인 로컬 앱의 읽기 중심 화면 점검

결과: 개선안 도출. 애플리케이션 코드·평가 규칙·운영 자료 변경 없음.

이 문서는 수정 전 점검 이력이다. 이후 반영 내용과 검증 결과는 [UI/UX 개선·검증 기록](K-DOG_UIUX_개선검증_v1.0_20260906.md)을 따른다.

## 1. 판단

현재 앱은 자료 연결부터 분석·수정·출력까지 기능을 갖추었지만, 화면의 중심은 여전히 참가자 자료 등록이다. 운영자는 다음에 처리할 대상을 찾고, 교수는 근거를 대조하며 판단하고, 두 역할 모두 정확한 결과 버전을 전달해야 한다. 이를 위해 필요한 정보 밀도와 동시 비교 기능을 확보하는 것이 우선이다.

개선 방향은 **업무별 진입점, 상태의 의미, 근거와 수정의 연결, 중단 후 복귀, 출력 대상과 버전의 명확화**다. 색상·폰트 교체나 여백 확대만으로 해결할 문제는 아니다. 복잡한 업무에서는 기능을 유지하면서 중요한 정보와 보조 정보 사이를 쉽게 이동하도록 설계하는 접근이 적합하다. [NN/g 복잡한 애플리케이션 설계 지침](https://www.nngroup.com/articles/complex-application-design/).

## 2. 점검 근거와 한계

- 현재 소스와 [PRD](K-DOG_PRD_v0.4_20260905.md) §2·4·7.7·8·13, [구현 기록](IMPLEMENTATION_STATUS.md), [개발 안내](DEVELOPMENT.md)를 대조했다. 동의 관리 제거 변경을 반영했다.
- codebase-memory의 `list_projects`·`index_repository`·`search_graph`·`search_code`를 먼저 사용했다. 갱신 후에도 초기 코드만 반환하고 프런트엔드 검색이 비어 있어 실제 파일 탐색으로 보완했다.
- `http://127.0.0.1:8000`의 기존 운영 관리자 로그인 상태에서 목록·상세·리포트·근거 버튼·내보내기 설정을 확인했다. 자료 수정·업로드·재분석·파일 생성은 실행하지 않았다. 교수 화면은 역할 조건과 컴포넌트 코드를 대조했으며 교수 계정으로 새로 로그인하지 않았다.
- 기본 뷰포트 2326×1118과 모바일 360×800을 확인했다. 임시 뷰포트 설정은 원복했다. 화면의 개인별 서술·영상·캡처는 저장소에 추가하지 않았다.
- 아래에서 **화면 확인**은 이번 브라우저 관찰, **코드 확인**은 정적 분석, **개선 제안**은 아직 구현하거나 사용성 시험하지 않은 권고를 뜻한다. 네트워크 실패·동시 편집·20명 이상 업무 처리 시간은 이번에 재현 측정하지 않았다.
- 새 라이브러리 설치·도입·구현은 없었다. 외부 UX·접근성 자료 확인일은 2026-09-06이다. 기존 자동화 테스트의 통과 여부를 이번 UI/UX 점검의 검증 결과로 재사용하지 않는다.

## 3. 유지할 장점

- 참가자 ID의 앞자리 0 보존, 입력 버전과 실행 이력, 과거 실행 경고가 있다.
- 점수와 설명의 상태가 분리되어 있고, 완료된 분기의 결과를 조회할 수 있다.
- 미관찰·근거 충돌·규칙 미정을 구분하고, 결측을 0점으로 채우지 않는다.
- AI 원결과 보존, 수정 사유·작성자·시각 기록, 내보내기 버전 고정이 있다.
- 역할별 메뉴와 API 권한을 구분한다. 검토·승인이 결과 조회와 내보내기의 필수 조건이 아니다.
- 검색·설문 응답 수·키보드 포커스 표시·고정 알림·오류/상태의 접근성 역할이 구현되어 있다.

### UX-01·UX-10: 교수용 검토 공간의 구체안

현재 기본 뷰포트에서 상세 문서 전체 높이는 약 11,324px였다. 행동 점수는 문서 y≈2,243px, 수정은 y≈3,202px, 내보내기는 y≈4,931px, 설문 원응답은 y≈10,970px에 있었다. 값은 확인한 한 사례·접힌 항목 상태에 한정하며 다른 자료의 고정 길이를 뜻하지 않는다.

교수의 기본 진입은 결과 요약으로 하고, PC에서는 왼쪽 항목 목록과 오른쪽 근거·수정 영역을 함께 보여 주는 구성이 적합하다. 55항목을 한꺼번에 편집하게 만들 필요는 없지만, 선택 항목의 점수·원선택지·누락 이유·근거·수정 폼은 같은 맥락 안에 있어야 한다. 관찰 전체 목록과 단계별 로그는 별도로 펼쳐볼 수 있게 한다.

### UX-04: 출력은 생성 이후의 업무까지 연결

현재 버전을 고정하는 기능은 유지한다. 다만 사용자에게 보이는 파일 목록에는 대상 행사·대상 수·촬영/결과 버전·생성 상태·용도가 필요하다. 다운로드와 수동 전달은 서로 다른 사건으로 기록한다. 전달 뒤 결과가 바뀌면 예전 파일을 자동 변조하지 않고 정정 파일 생성과 재전달 기록으로 연결한다. 앱 내부 자동 발송과 수신 확인 기능은 제안 범위에 넣지 않는다.

### UX-05·UX-13: 업로드 편의와 평가 정확도의 연결

카메라만 같다고 같은 시점·같은 촬영 차수라고 볼 수 없다. 업로드 대기표에서 세션·카메라·파일 순서와 동시/순차 촬영 맥락을 확인하도록 해야 한다. 촬영 체크리스트는 기존 확정 절차를 기반으로 완료/미실시/재촬영을 기록하는 방향이며, 파일명만으로 시간 동기화나 참가자 소속을 확정하지 않는다.

## 5. 추가로 정리할 작은 불일치

- `main.tsx:182`의 ‘q23 환산과 영역 집계는 아직 제공하지 않습니다’는 현재 `Scores`의 A·C-1·D 등 설문 집계 표시와 맞지 않는다. 제공되는 집계와 q23/C-2의 보류 범위를 정확히 구분한다.
- 참가자 ID·이름·예약 정정 UI가 없다. PRD의 운영자 ID 수정 요구를 반영하려면 기본 정보 정정과 연결/기존 파일 영향 안내가 필요하다. 현재 누락을 단순 라벨 수정으로 해결할 수는 없다.
- URL이 상세/선택 실행을 표현하지 않는다. 결과 직접 링크, 새로고침 후 복귀, 이전/다음 참가자 이동을 지원하면 공동 검토와 중단 후 복귀가 쉬워진다. 링크 접근 권한 검사는 유지한다.
- `.notice`의 색을 성공에만 의존하지 말고 ‘저장 완료 / 규칙 미정 / 자료 보완’을 문구와 의미별 스타일로 구분한다. 현재 포커스 표시와 알림의 `alert`/`status` 역할은 보존한다.
- 모바일 로그아웃 버튼은 CSS 최소 높이가 32px, 일반 버튼은 42px다. PRD의 44px 기준과 맞춰 검증한다. 이는 프로젝트 기준과의 차이이며 WCAG 위반 판정 자체는 아니다. WCAG 2.2 AA의 최소 타깃 기준은 24×24 CSS px와 간격 등 예외를 함께 평가한다. [W3C 타깃 크기 해설](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

## 6. 역할별 화면 구성 제안

| 진입점 | 운영자가 바로 볼 것 | 교수가 바로 볼 것 |
|---|---|---|
| 참가자·업무 목록 | 행사/예약, 설문·카메라·세션 누락, 처리 상태, 다음 조치 | 결과 준비 상태, 유효 항목 수, 근거 충돌·보류, 수정 이력 유무 |
| 자료 | 참가자·세션 연결, 업로드 대기표, 설문·촬영 체크리스트 | 현재 결과가 참조하는 자료의 읽기용 맥락 |
| 결과·검토 | 결과 요약, 보완할 자료, 설명·파일 준비 상태 | 항목 필터, 영상/음성 근거, AI 원값·수정값, 문단별 근거 |
| 내보내기·전달 | 대상·용도·결과 버전, 파일 생성, 수동 전달·정정 기록 | 선택/전체 결과 파일, 수정 내역과 근거 자료 |

이 구분은 기능별 탭 또는 명확한 화면 내 이동으로 구현할 수 있다. 초기부터 역할별 별도 앱을 만들 필요는 없다. 운영자는 자료 중심, 교수는 결과 중심의 기본 진입을 제공하되 허용된 전체 결과 조회·수정·다운로드는 유지한다. 운영 설정과 개발자 설정의 권한 경계도 유지한다.

## 7. 실행 순서와 검증 제안

1. **현재 기능의 동작 명확화:** 근거 재생 위치, 목록 자동 갱신, 처리/충족도 분리, 초안 보존, 모바일 진입, 업로드 결과 메시지, 척도 안내. 검증은 개별 클릭 성공뿐 아니라 현재 화면에서 결과 인지·실패 후 복귀까지 포함한다.
2. **반복 업무 흐름 개선:** 업무 목록과 교수 검토 공간, 항목/문단별 수정, 내보내기 대상 미리보기. 저장된 결과 계약을 유지하며 화면과 필요한 조회 API부터 보완한다.
3. **기능 보완:** 수동 전달·정정 이력, 원본 Excel 매핑, 촬영 체크리스트, 읽기용 세션 탐색, 기본 정보 정정. 데이터 계약과 API 변경이 필요한 항목을 별도 구현한다.

사용성 검증에는 실제 운영자·교수가 각각 참여해야 한다. 다음은 측정 제안이며 이번 점검에서 달성한 수치는 아니다.

| 시나리오 | 관찰할 성공 조건 |
|---|---|
