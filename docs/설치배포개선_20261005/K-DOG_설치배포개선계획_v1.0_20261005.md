# K-DOG 설치·배포 개선 계획

버전: v1.0 · 2026-10-05 · 상태: D00–D03 구현 완료 (2026-10-05, §11) · 기준: main `6376311`

기능 기준은 [S1 개발 반영 계획](../개발반영_20261003/K-DOG_개발반영계획_v1.0_20261003.md)을 그대로 따른다. 이 계획은 S1 기능을 바꾸지 않고 **설치·실행 방법만** 바꾼다. 공통 구현·검증·리뷰·버전 확인 절차는 상위 계획 §7을 적용한다.

## 1 배경과 현황

K-DOG는 중앙 웹 서비스가 아니라 사용자 PC에서 로컬로 실행한다. 사용자는 기술에 익숙하지 않다. 현재 설치 방식(S15)은 사용자에게 다음을 요구한다.

- `uv`와 FFmpeg/FFprobe를 직접 설치하고 PATH에 등록
- 최초 설치 시 인터넷 연결 (Python 3.14와 의존성 다운로드)
- 영어 안내문 아래에서 계정 이름 입력 (Enter만 누르면 관리자 계정 없이 설치 종료)
- 오류 시 `.venv/Scripts/python.exe -m app.manage ...` 같은 명령 실행

## 2 목표와 비목표

목표: **사용자는 ZIP을 풀고 `Install.cmd`를 더블클릭해 발행 키를 한 번 입력하면 설치가 끝나고, 바탕화면 아이콘으로 실행한다.** 사전 설치·인터넷·명령 입력이 필요 없다.

비목표 (이번 범위에서 하지 않음):

- GUI 설치 마법사, 트레이 아이콘, 자동 업데이트, 제거 프로그램
- 코드 서명 인증서 도입
- 라이선스 서버, PC 고정(하드웨어 바인딩), 키 사용 횟수 제한
- AI 공급자 키 사전 등록 (현행처럼 개발자 계정으로 화면에서 등록. 개발자 계정은 발행 때 함께 지정할 수 있다, D03)
- 사용자 비밀번호 변경 기능 (사용자 결정: 바꾸지 않아도 됨)
- 중앙 서버·3PC 운영 구조 변경 (명령 경로 문서만 갱신)
- S1 기능·채점·리포트 변경

## 4 전체 흐름

```
[개발자]
  build-ffmpeg.sh             → FFmpeg 최소 빌드 + 대응 소스 묶음 (D00, FFmpeg를 올릴 때만)
  build_release.py            → 평문 포터블 ZIP (내부 검증용, D01)
  issue_release.py <평문 ZIP> --customer A --admin manager [--developer keyman]
                              → K-DOG-A-v0.3.0-<commit>.zip + .sha256 (D03)
                              → 발행 키 KDOG-XXXXX-XXXXX-XXXXX-XXXXX-XXXXX와 ZIP의 SHA-256 (ZIP과 다른 경로로 전달)

[사용자]
  ZIP 압축 풀기 → Install.cmd 더블클릭 → 발행 키 입력 (한 번)
     → %LOCALAPPDATA%\Programs\K-DOG\<버전>-<commit>\ 에 설치
     → 발행 계정 생성, 바탕화면 "K-DOG" 아이콘 생성
  바탕화면 K-DOG 더블클릭 → 실행 창 + 브라우저 자동 열림 → 로그인
  창 닫기 → 종료
```

자료는 지금처럼 `%LOCALAPPDATA%\K-DOG\data`(또는 `KDOG_DATA_DIR`)에 두고 프로그램 폴더와 분리한다. 업데이트는 새 버전 폴더에 설치하고 바로가기만 새 버전으로 바꾼다.

## 6 보안 경계

보호하는 것:

- 키가 없는 사람은 발행 ZIP에서 제품 파일(앱 코드·카탈로그·리포트 자산·계정 정보)을 보거나 설치할 수 없다. AES-256-GCM은 인증 암호화이므로 `payload.kdog`가 변조되면 설치 전에 거절된다.
- 계정 비밀번호 원문은 패키지와 저장소 어디에도 남지 않는다. 패키지 안(암호화 영역)에는 기존 `password_hash` 형식(scrypt)만 들어간다.

보호하지 않는 것 (문서와 안내에 명시):

- 설치가 끝난 PC 안의 프로그램 파일은 평문이다. 허가된 사용자 PC로 간주한다.
- 같은 ZIP과 키를 가진 사람은 여러 PC에 설치할 수 있다. 오프라인 앱이라 막을 수 없다.
- 암호화하지 않는 영역(`runtime/`의 공개 Python·라이브러리·FFmpeg와 그 소스 묶음, 설치 프로그램)은 누구나 볼 수 있다. 공개 소프트웨어이므로 비밀이 아니다. FFmpeg는 GPL에 따라 받는 사람이 자유롭게 쓰고 재배포할 수 있어야 하므로 일부러 암호화하지 않는다.
- 평문 영역(`Install.cmd`, 설치 프로그램, `runtime`)은 암호화 검사보다 먼저 실행되므로 변조를 암호화로 막을 수 없다. 사용자는 키와 같은 경로로 받은 SHA-256과 ZIP을 비교한 뒤 설치한다.
- 발행 키와 ZIP을 같은 경로(같은 메일 등)로 보내면 암호화 의미가 없다. 반드시 다른 경로로 전달한다.

## 9 완료 경계

- 각 PR은 현재 Windows에서의 실제 실행 검증까지 완료 조건으로 한다. 깨끗한 OS·다른 PC 설치는 E10 후속 항목으로 남기고 완료로 표시하지 않는다.
- 계획 문서만으로 구현·발행·고객 발송이 수행된 것으로 보지 않는다. 실제 결과는 각 PR 문서의 실행 기록에 적는다.
- 발행 키, 관리자 비밀번호, 발행 기록 파일은 저장소에 커밋하지 않는다 (`releases/`는 git 무시 대상).
