# PR-D02 실행 창과 중복 실행

버전: v1.0 · 2026-10-05 · 상태: 계획 · 선행: D01 · 기준: main `6376311`

## 문제와 결과

결정 K05(실행 창 표시 방식)에 맞춰 일반 사용자가 실행·종료를 헷갈리지 않게 한다. 범위는 런처의 안내 문구와 중복 실행 처리뿐이다.

현재 동작:

- 실행 창 안내가 "Ctrl+C를 누르세요"뿐이다 ([launcher.py:170](../../backend/app/launcher.py#L170)). 창을 닫아도 종료된다는 안내가 없다.
- 이미 실행 중일 때 아이콘을 다시 누르면 실행 잠금 오류(`API·worker 또는 유지보수 작업이 실행 중입니다`)로 실패한다 ([maintenance.py:40](../../backend/app/maintenance.py#L40)). 일반 사용자가 가장 자주 겪을 상황이다.

변경 후:

```
K-DOG 실행 중: http://127.0.0.1:8000
브라우저가 자동으로 열립니다. 열리지 않으면 위 주소를 브라우저에 입력하세요.
이 창을 닫으면 K-DOG가 종료됩니다. 작업 중에는 창을 최소화해 두세요.
```

이미 실행 중이면 오류 대신 다음을 출력하고 브라우저만 연 뒤 종료 코드 0으로 끝낸다.

```
K-DOG가 이미 실행 중입니다. 브라우저를 엽니다.
```

## 파일별 변경

| 파일 | 변경 | 구현 내용 |
| --- | --- | --- |
| `backend/app/launcher.py` | 수정 | ① `launch` 시작 전 `http://127.0.0.1:{port}/api/health`를 짧게 조회하여 `service == "K-DOG"`이면 브라우저만 열고 정상 종료 ② 실행 잠금이 이미 잡혀 있으면(먼저 누른 실행이 아직 준비 중) health를 최대 30초 동안 반복 조회하여 K-DOG가 응답하면 ①과 같이 처리하고, 끝까지 응답이 없을 때만 잠금 오류를 보여준다 ③ 실행 중 안내 문구 변경 ④ 포트를 다른 프로그램이 쓰고 있으면 "다른 프로그램이 8000 포트를 사용 중입니다"로 구분해 안내 |
| `scripts/windows/Start.cmd` | 수정 | `title K-DOG` 추가 (ASCII만 사용, 한국어 문구는 모두 Python에서 출력) |
| `backend/tests/test_packaging.py` | 수정 | 실행 중인 K-DOG 감지 시 브라우저만 열고 자식 프로세스를 만들지 않음, 준비 중인 실행이 잠금을 잡고 있을 때 응답을 기다린 뒤 브라우저만 엶, 다른 서비스가 포트를 쓰면 실패 안내, 안내 문구 출력 시험 |

health 응답은 이미 `{"service": "K-DOG", ...}`를 반환하므로 API 변경은 없다 ([api.py:100](../../backend/app/api.py#L100)). 실행 잠금은 시작 직후부터 잡히고([launcher.py:130](../../backend/app/launcher.py#L130)) 준비 완료까지 최대 30초가 걸릴 수 있어([launcher.py:154](../../backend/app/launcher.py#L154)) ②가 필요하다. 유지보수 작업 중(잠금은 있으나 30초 동안 health 무응답)이면 지금의 잠금 오류를 그대로 유지한다.

## 구현 순서

1. `graft callers launch`, `graft callers main`으로 시험·`verify_release.py` 사용처를 확인한다.
2. health 조회는 기존 `build_opener(ProxyHandler({}))`를 재사용하고 제한 시간을 1초 이하로 둔다. 새 라이브러리는 쓰지 않는다.
3. 문구와 `Start.cmd`를 바꾸고 시험을 추가한다.

## 검증과 완료 조건

- backend 관련 시험과 전체 시험이 통과한다.
- D01 방식으로 만든 ZIP에서 `verify_release.py`가 통과한다.
- 현재 Windows에서 직접 확인하고 실행 기록에 남긴다: ① 아이콘(또는 `Start.cmd`) 실행 → 브라우저 자동 열림 ② 두 번째 실행 → 브라우저만 열리고 창이 바로 닫힘 ②-1 첫 실행이 준비되기 전에 빠르게 두 번 실행 → 오류 없이 브라우저만 열림 ③ 실행 창의 X 버튼으로 닫기 → API·worker 모두 종료, 다시 실행 가능.
- ③은 기존 Job Object 처리([launcher.py:36](../../backend/app/launcher.py#L36))로 보장되는 동작을 실제 창 닫기로 확인하는 것이다. 실패하면 이 PR에서 수정한다.
