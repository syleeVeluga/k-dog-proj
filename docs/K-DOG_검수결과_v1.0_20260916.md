## 1. 판정과 범위

**기존 자동 시험은 모두 통과했지만, 추가 검수에서 재현한 결함 7건을 수정하기 전까지 P1 검수 완료로 판단하지 않는다.** 특히 이관 원본의 무결성, 재촬영 간 입력 분리, 동시 편집의 변경 유실을 먼저 해결해야 한다. 계산·카탈로그의 기본 구조는 확인했으며, 고객 확인 대기 규칙을 새 결함으로 세지 않았다.

사용성의 우선 개선은 **메뉴는 업무별로 분리하되, 선택한 행사·참가자·촬영 회차는 메뉴를 옮겨도 이어지는 구조**다. 운영자는 접수와 자료 등록을, 교수/검토자는 해당 참가자의 응답·영상·구간 확인을 쉽게 할 수 있어야 한다. 자동 다음 단계 실행이나 자동 확정은 제안하지 않는다.

이번 작업은 검수와 개선안 문서 작성이다. 구현·계약·고객 원본·규칙 파일은 수정하지 않았고, GitHub PR 생성·푸시·병합·릴리즈도 하지 않았다. 아래 PR-A 번호는 앞으로 구현할 작업 식별자이며 GitHub PR 번호가 아니다.

실제 영상 테스트는 사용자 요청에 따라 이번 검수에서 제외했다. 테스트에 사용한 것은 합성 바이트와 합성 320×240 영상뿐이다. 운영 자료 폴더를 열거나 그 폴더로 앱을 실행하지 않았다. P2·P3의 AI 채점·사람 검수·리포트·연구 내보내기 부재, 장비 사양 미수령, 미확정 R1~R9는 이번 결함 목록에 포함하지 않는다.

2. **결측과 시행 무효가 함께 있을 때의 상태:** 03 `여러쌍비교!Z6`은 `2_개행동!J25`가 빈칸인지 먼저 검사한 뒤 `3_보호자행동!J13=3`을 본다. 코드는 무효를 먼저 확인한다. R5 질문에 상태 우선순위를 보완하되, 회신 전 계산을 임의로 바꾸지 않는다. [A09](검수개선/K-DOG_PR-A09_검수근거정정_v1.0_20260916.md) 참조.
3. **촬영에서 구간 자체가 없는 경우:** 0초 구간으로 정상 확정할지에 대한 고객 합의는 확인되지 않았다. 현재 입력은 구간 부재 사유를 담지 못한다. 누락을 명시하는 계약은 후속 합의로 정하고, 우선 0초 정상 확정을 막는다. [A04](검수개선/K-DOG_PR-A04_구간입력과확정_v1.0_20260916.md) 참조.

기존 시험에서 키 연결 시험은 mock/브라우저 route 응답으로 대체된다. 실 공급자 호출은 하지 않았다. 신규 라이브러리 설치나 의존성 변경도 없다. 기존 가상환경·node_modules와 잠금 파일을 사용했다. Starlette의 httpx TestClient 사용 중단 예정 경고는 있었으나 시험 실패는 없었다.

코드 검색은 codebase-memory-mcp의 프로젝트 확인 및 fast/full 재색인을 먼저 시도했으나 현 체크아웃과 다른 옛 심볼이 반환됐다. 따라서 사용자에게 한계를 알리고 현재 파일 직접 읽기를 근거로 삼았다. PR #1~#13 본문의 수용·기각 사유도 읽었으며 기존 기각 사항을 근거 없이 재제안하지 않았다.

시험 공백은 재촬영 후 패널 초기화, 구간 동시 편집, 선택 열 매핑, 순번 충돌 미리보기, 0초 확정, 손상된 이관 원본이다. 기존 e2e의 「확정 해제」는 입력 활성화와 DB의 기존 confirmed=true까지 확인하며, 해제 후 수정 저장까지의 왕복을 검증하지 않는다. XLSX는 백엔드에서 확인했고 UI의 XLSX 시트 선택·열 연결과 이관 메모의 브라우저 검증은 후속 PR의 수용 시험으로 지정했다.
