# K-DOG 영상별 직접 평가 변경 계획 — 사건 원장과 분기 분할

버전: v1.1 · 2026-09-08 · v1.0을 확장한다

## 결정 기록

2026-09-08 사용자 결정. 같은 영상으로 반려견 분기와 보호자 분기를 나누어 평가하고 결과를 다시 종합한다. 나누기 전에 두 분기가 공유하는 사실(구령 발화·수행·보상·퇴장·재입장·진정 시각)을 **사건 원장** 한 곳에서만 확정하고, 분기 평가는 원장을 재추정하지 않는다. 참가자는 가이드에 따라 검사를 순서대로 실행하므로, 원장의 시행 경계는 **평가 순서를 준용**한다. 이는 원문 채점 규칙의 확정이 아닌 운영 절차 기반의 경계 결정이며 DOG-12·OWN-14의 `rule_pending`은 유지한다.

## 수용 범위

v1.0의 구조를 유지한다. 영상 파일마다 평가 항목을 제공하고, 영상별로 독립 평가하고, 항목별로 병합하고, 선택지가 다른 항목만 영상별 한 차례 재검토하고, 해결되지 않으면 보류한다. 이번 변경은 "영상 1개 → 호출 1회(55항목)"를 "영상 1개 → 원장 1회 + 반려견 분기 1회(DOG·BS 36항목) + 보호자 분기 1회(OWN 19항목)"로 바꾸고, 프로그램 종합에 원장 일관성 검사를 추가한다. 영상 파일 결합·자동 동기화·카메라 간 횟수 합산은 계속 하지 않는다. 기존 run의 설정·산출물은 유지한다.

Gemini 모델·처리 방식·추론 설정은 [Gemini 영상 API 적용 계획](K-DOG_Gemini영상API_적용계획_v1.0_20260907.md)을 따르며 세 호출 모두에 같은 요청 계약을 적용한다.

## 평가 순서 준용 규칙

[PRD](K-DOG_PRD_v0.4_20260905.md) §촬영 구간의 순서를 프로그램 소유 자료로 고정한다.

| 순번 | 구간 | 시행 | 관련 항목 |
| --- | --- | --- | --- |
| 1 | 입장 | 입장 | BS-01~05, DOG 입장, OWN 입장 |
| 2 | 분리 | 무반응 10초 기준선 | DOG-07 |
| 3 | 분리 | 보호자 퇴장·분리 | BS-06~08, DOG-08~10, OWN-07 |
| 4 | 분리 | 재회 | DOG-11~12, OWN-08 |
| 5 | 훈련 | 지시① 앉아 | DOG-13, OWN-09~15 |
| 6 | 훈련 | 지시② (채점 행 없음, R-09) | 기록만 |
| 7 | 훈련 | 지시③ 엎드려 | DOG-14, OWN-09~15 |
| 8 | 훈련 | 지시④ 앉아 | DOG-15, DOG-17(①→④ 비교), OWN-09~15 |
| 9 | 놀이 | 놀이 | BS-10~12, DOG-18~20, OWN-16~19 |
| 10 | 퇴장 | 퇴장 | BS-13~16 |

- 원장의 모든 사건은 이 순번 중 하나에 귀속한다. 순서에서 벗어나거나 귀속이 불명확한 사건은 `step: unknown`으로 기록하고 채점 근거로 쓰지 않는다.
- 한 시행의 `command_count`는 그 순번 안에서 해당 지시어의 보호자 발화 횟수다. 수행이 있으면 첫 수행까지, 없으면 시행 종료까지 센다. 다른 지시어 혼입은 발화 사실로 기록하고 OWN-11의 "지시어 뒤섞임" 판단 근거로만 쓴다. 시행을 임의로 나누거나 합치지 않는다. 놀이 구간에는 단일 시행 경계가 없으므로 수행 기준 절단을 적용하지 않고 구간 전체의 지시·말 발화를 센다.

시행 간 합산 규칙은 원문에 없으므로 만들지 않는다. DOG-13/14/15는 자기 시행 하나에만, OWN-11은 채점 행이 있는 훈련 세 시행(지시①·③·④) 중 하나에, OWN-18은 놀이 구간에 귀속한다. 지시②는 채점 행이 없어 어느 항목의 귀속 대상도 아니며 그 구간에 걸친 측정은 보류한다. 분기 판단의 측정 구간이 정확히 한 시행과 겹치면 그 시행의 계산값과 일치해야 하고, 어느 시행과도 겹치지 않거나 여러 시행에 걸치면 그 항목만 보류한다. 여러 시행의 횟수를 더한 값은 채택하지 않는다.

한 시행은 그 지시에 해당하는 수행에서 끝난다. 다른 행동을 관찰했다고 시행이 끝나지 않는다. 반려견 항목(DOG-13/14/15)의 횟수는 그 지시어의 발화 수이고, 보호자 항목(OWN-11/18)의 횟수는 원문 선택지가 말하는 지시·말 반복이므로 다른 지시어가 섞인 발화도 포함한다. 놀이 구간의 지시·말은 `play_cue`로 기록하며 보호자 항목의 횟수에 포함된다.
- 지시②는 원문에 채점 행이 없으므로 발화·수행을 기록만 한다. 번호를 재정렬하거나 문항을 추가하지 않는다.
- 세션 `checklist`는 실시 계획·운영 기록이며 사건의 근거도 부재의 근거도 아니다. `skipped`로 표시된 구간에서 실제 사건을 확인했으면 원장은 사실대로 기록하고 `quality_flags`에 불일치를 남긴다. 체크리스트로 관찰된 사실을 거절하지 않는다. `not_performed` 판단은 분기 평가가 관찰 범위로 결정한다.
- 촬영 순서 변경은 운영자 기록이 우선한다. 현재 `checklist`는 구간 단위(입장·분리·훈련·놀이·퇴장)의 실시 여부만 저장하므로 지시 단위 순서 변경은 이번 범위에서 기록하지 않고 `unknown` 귀속과 보류로 처리한다.

## 사건 원장 계약

원장은 **사실만** 담고 점수·선택지·판단을 담지 않는다. 영상별 1회 호출로 생성하며 스키마는 기존 관찰 REST가 지원하는 속성 집합만 사용한다.

사건 필드: `step`(순번 또는 `unknown`), `kind`, `start_sec`/`end_sec`(원본 시작 기준, `duration_sec` 이하), `subject`, `modality`, `command`(①앉아·②·③엎드려·④앉아·기타·해당없음), `observation`(사실 문장), `quality_flags`.

`kind`: `command_utterance`(구령 발화), `dog_performance`(수행), `reward_response`(보상 반응), `owner_exit`, `owner_return`, `dog_settled`(진정), `play_cue`(놀이 지시·말), `other`.

프로그램이 원장에서 결정적으로 계산하는 값은 **시행별 `command_count`와 시행 구간**이다. 계산식은 위 규칙만 사용하고 모델의 자기 보고 횟수를 쓰지 않는다. 보상 간격·진정 시간은 계산하지 않는다. 그 값을 쓰는 OWN-14·DOG-12는 원문 시간 경계 규칙이 미정이어서 계속 `rule_pending`으로 보류하므로, 계산해도 채점에 쓰이지 않는다. 관련 사건(`reward_response`, `dog_settled`, `owner_exit`, `owner_return`)은 사실로 기록하여 규칙 확정 후 사용할 수 있게 남긴다.

검증: 시각 범위, 순번 존재, `command_utterance`·`play_cue`는 `subject=owner`이고 `modality`가 음성을 포함해야 한다. 무음(`audio_status`가 없음)인 영상의 원장은 발화 사건을 만들 수 없고 발성 부재를 추론하지 않는다. 검증 실패는 기존 `observation_schema_invalid` 재시도·수정 요청 경로를 쓴다.

## 분기 호출 계약

같은 영상 파일을 다시 제공하고, 분기 항목과 원장을 컨텍스트로 넣는다. 반려견 분기는 DOG·BS 36항목, 보호자 분기는 OWN 19항목이다. 기존 `video_schema`와 `context(..., item_ids=...)`를 항목 부분집합으로 재사용한다.

프롬프트에 추가하는 지시: 원장의 횟수·시각은 확정 사실이며 재추정하지 않는다. 원장에 없는 사건은 채점 근거로 쓰지 않고 `unconfirmed_conditions`에 기록한다. `measurements`의 `command_count`는 원장 계산값과 같아야 하며 다르면 프로그램이 해당 항목을 보류한다. 재검토는 분기별 항목 부분집합과 `focus_intervals`, 원장을 함께 받는다.

## 프로그램 종합

1. **원장 일관성**: 분기 판단의 `measurements`와 선택지를 원장 계산값과 대조한다. 기존 `measurement_problem`의 "측정 구령 N회가 원문 선택지의 조건과 일치하지 않습니다" 검사를 유지하고, 측정값의 출처를 모델 자기 보고에서 원장 계산값으로 바꾼다. 불일치는 해당 항목만 `insufficient_evidence`로 보류하고 사유에 원장값·모델값을 남긴다. 다른 항목과 명시적 충돌 상태는 보존한다.
2. **영상 간 병합**: v1.0의 항목별 병합·재검토·보류를 그대로 사용한다. 원장은 영상별이므로 영상 간 원장을 합치지 않는다.
3. **분기 산출**: 병합 결과를 `OWN-` 접두사로 나눈 `BranchEvaluation`과 `program_merge` 표시는 유지한다.

## 실행 구조

영상별 단계는 `ledger`(신규) → `observe`(분기 2회, 병렬 가능) → 필요 시 `review_video`(분기별 항목 부분집합) 순이다. 분기 단계의 `branch_key`는 `{video_id}/dog`·`{video_id}/owner`로 하고 원장 단계는 `video_id`를 쓴다. 성공 단계 재사용, 재시도 한도, 점유·중지·삭제 검사, 호출 예약은 기존 `stage`·`reserve_call`을 재사용한다. 정상 호출 수는 영상 N개 × 3 + 리포트 1회이며 충돌 시 분기별 재검토가 추가된다. `max_ai_calls` 기본값 100은 3영상 기준으로 충분하나 화면의 예상 사용량 안내를 갱신한다.

각 단계는 자신의 호출에서 영상을 업로드하고 응답 후 즉시 원격 파일을 삭제한다. 원장 단계가 올린 URI를 분기 단계가 재사용하는 방안은 채택하지 않았다. 단계는 각각 독립적으로 재시도·중단·복구되므로 여러 단계에 걸친 원격 파일 수명은 재시도가 다른 실행 회차에서 일어날 때 무효가 되고, 단계별 `remote_cleanup_pending` 회계와 "참가자 영상을 공급자에 남기지 않는다"는 보장을 단계 단위로 유지할 수 없다. 절감되는 것은 업로드 대역폭뿐이며 토큰 비용은 동일하다. 대역폭이 문제가 되면 단일 업로드 수명을 별도 범위에서 다룬다.

## 비용과 처리 방식

영상당 호출이 1회에서 3회가 되어 영상 컨텍스트 토큰이 3배다. `agentic` 처리 방식은 장편 토큰을 크게 줄이므로 세 호출 합계와 기존 `static` 1회의 토큰·지연·항목 일치율을 같은 영상으로 비교한다. 비용이 문제면 원장 산출을 보호자 분기 호출에 합쳐 2회로 줄이는 후퇴 옵션을 둔다. 이 경우 보호자 호출이 먼저 실행되고 반려견 호출이 그 원장을 받으며 병렬성을 잃는다.

## 구현 순서와 완료 기준

1. 평가 순서표·원장 스키마·원장 계산 함수 → 검증: 순번 귀속, 무음 영상의 발화 거절, 시행별 `command_count`·지연·간격 계산의 합성 시험. 지시②는 계산에서 제외되는지 확인.
2. `ledger` 단계와 파일 URI 재사용·삭제 시점 → 검증: 성공 원장 재사용, 실패 재시도, 중단 후 원격 삭제 시도, 예산 예약.
3. 분기 호출: 항목 부분집합 컨텍스트·프롬프트 추가 지시·`branch_key` 체계 → 검증: 분기별 정확한 항목 집합, 다른 분기 항목 거절, 원장 동봉.
4. 원장 일관성 검사 → 검증: 원장값과 다른 `command_count`의 항목별 보류와 사유, 일치하는 경우 통과, 명시적 충돌 상태 보존.
5. 병합·재검토를 분기 단위로 연결 → 검증: 3시야 병합 회귀, 분기별 재검토 범위, 미해결 보류.
6. 화면: 영상별 결과에 원장(시행별 사건 목록)과 분기 결과를 펼쳐 보고 근거를 재생한다. 예상 사용량 안내 갱신 → frontend build/e2e.
7. 실호출: 합성 샘플 provider 시험(원장·분기)과 허용된 실제 3영상으로 `static` 1회 대비 세 호출 구조의 항목 일치율·보류율·토큰·지연을 기록한다.
8. 독립 cold review 후 수정·재검증·commit·push.

## 유지할 평가 규칙

원문 55항목·선택지·점수를 변경하지 않는다. DOG-12·OWN-14는 `rule_pending`을 유지한다. 지시②에 채점 행을 만들지 않는다. 설문은 영상 평가에 제공하지 않는다. 평균·최댓값·다수결·모델 자신감으로 선택하지 않는다. 카메라 간 횟수·시간을 합산하지 않는다. 검사 전체의 행동 부재는 충분히 관찰한 경우에만 판단하고, 한 시야의 가림·미녹화를 검사 미실시로 바꾸지 않는다. `store=false`, 원격 파일 삭제, 키 비저장, 실행별 설정 스냅샷 고정을 유지한다.
