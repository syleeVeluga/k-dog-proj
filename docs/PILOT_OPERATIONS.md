# K-DOG Windows 설치·S1 운영 안내

macOS 사용자 설치형은 별도 `kdog-s1-macos-online.zip`의 [macOS 설치 안내](../scripts/macos/online/macOS_설치안내.md)를 따른다. ZIP 최상위에도 `macOS_설치안내.md`가 있다. macOS에서는 `Install.command` → `Start.command`를 사용한다. 아래의 `.cmd`·DPAPI·Windows 설치 설명은 Windows용이다.

버전: v2.1 · 2026-10-14 · 통합명세 v1.3 / S1.1

## 일반 사용자 실행

바탕화면의 K-DOG 아이콘(또는 설치 폴더의 `Start.cmd`. 사용자 설치형은 아이콘 없이 프로그램 폴더의 `Start.cmd`)을 실행한다. 실행 창(제목 K-DOG)이 뜨고 준비되면 브라우저가 자동으로 열린다. 열리지 않으면 창에 표시된 주소로 접속한다. 이미 실행 중일 때 다시 실행하면 새로 시작하지 않고 브라우저만 연다 (먼저 누른 실행이 준비 중이면 최대 30초 기다린다). 다른 폴더나 이전 버전의 K-DOG가 같은 포트에서 실행 중이면 안내 후 멈추므로, 그 실행 창을 닫고 다시 실행한다. 중앙 서버 운영에서는 촬영 PC마다 앱을 설치하거나 DB를 만들지 않고 담당자가 전달한 동일 HTTPS 주소를 브라우저에서 연다. 앱 계정은 Windows 계정과 별개이며 기본 비밀번호는 없다. 업무 중 중앙 서버와 실행 창을 유지하고(작업 중에는 최소화), 종료할 때 실행 창을 닫거나 Ctrl+C를 눌러 API·worker를 함께 종료한다. 브라우저 탭만 닫아도 서버 작업은 계속된다.

실제 영상·장비 품질과 시간, 실제 중앙 서버/3PC·깨끗한 OS 검수는 [후속 대장](archive/개발반영_20261003/K-DOG_실측및확인후속대장_v1.0_20261003.md) E01–E10에 있다. 합성 시험이나 현재 Windows의 새 폴더 설치를 현장 검수 완료로 해석하지 않는다.

배포 ZIP에는 이 안내와 계획·후속 문서가 포함된다. 개발 명령·시험 근거는 [소스 저장소](https://github.com/syleeVeluga/k-dog-proj)에서 `release.json`의 commit을 선택해 확인한다. 개발용 시험·스크립트와 고객 원본은 설치 ZIP에 포함하지 않는다.

## 설치 담당자

대상은 Windows 11 x64와 Chromium 계열 브라우저다. Windows ARM/32비트/S모드·다른 OS는 검증 대상이 아니다. 프로그램·자료는 로컬 디스크에 두며 네트워크 공유·동기화 폴더·이동식 드라이브는 운영 검수 대상이 아니다. 공급자 키는 Windows DPAPI로 보호하므로 설치·키 등록·API·worker는 같은 Windows 사용자로 실행한다.

사용자에게 전달하는 기본 설치물은 **고객별 발행 패키지**(`K-DOG-<고객ID>-v<버전>-<commit>.zip`)다. 평문 포터블 ZIP(`build_release.py` 결과)은 내부 검증과 담당자 설치에만 쓴다. uv·FFmpeg를 직접 설치해 쓰는 기존(S15) 방식이 필요하면 [사용자 설치형 ZIP](#사용자-설치형-zip)을 쓴다. GitHub의 구판 v0.2.0 또는 자동 생성 Source code ZIP은 S1 설치물로 사용하지 않는다.

포터블·발행 ZIP에는 Python 3.14와 잠금 의존성(`runtime/python`), FFmpeg/ffprobe(`runtime/ffmpeg`)가 들어 있다. uv·Python·FFmpeg를 따로 설치하거나 PATH에 등록하지 않으며 설치·실행에 인터넷이 필요 없다. FFmpeg는 GPL 2 이상이며 대응 소스는 `runtime/ffmpeg/source`에 있다. 동봉 오픈소스와 라이선스 위치는 `오픈소스고지.txt`를 본다. 자료 기본 경로는 `%LOCALAPPDATA%/K-DOG/data`다. 별도 자료 경로는 설치·실행 전에 `KDOG_DATA_DIR`을 프로그램 밖 로컬 폴더로 지정한다. 기존 데이터 경로를 바꾸면 다른 DB가 열리므로 경로를 먼저 확인한다.

### 발행 (개발자)

저장소 루트에서 평문 ZIP을 만든 뒤 기관별로 하나 발행한다. 기본은 AI 키 등록용 개발자 계정만 넣고, 업무 계정은 PC마다 설치할 때 담당자가 직접 만든다(설치 계정과 발행 키 기간 계획). 업무 계정을 미리 넣어야 하면 `--user`(또는 호환 `--admin`)를 함께 지정한다. 기존 operator/reviewer/admin과 개발자는 모든 업무를 함께 수행하고 설정 변경만 개발자 전용이다. 비밀번호(12~256자)는 숨김 프롬프트로 두 번 입력하며 패키지에는 scrypt 해시만 암호화되어 들어간다.

```powershell
backend/.venv/Scripts/python.exe -X utf8 scripts/issue_release.py "releases/kdog-s1-windows-x64.zip" --customer SCHOOL-1 --developer keyman --expires 2026-12-31
```

- 결과: `releases/issued/<고객ID>/`에 발행 ZIP, `.sha256`, 발행 기록(JSON, 키·비밀번호 없음, 유효 기간 포함). `releases/`는 git 무시 대상이며 커밋하지 않는다.
- 발행 키(`KDOG-XXXXX-XXXXX-XXXXX-XXXXX-XXXXX`)는 콘솔에 **한 번만** 표시되고 어디에도 저장되지 않는다. 발행할 때마다 새 키가 만들어진다.
- `--expires YYYY-MM-DD`는 설치할 수 있는 마지막 날이다(그날 포함, 설치 PC 날짜 기준). 생략하면 기간이 없다. 기간은 암호화 헤더에 인증되어 고치면 키가 맞아도 설치되지 않는다. 기간이 지나면 새로 발행한다. 이미 설치된 앱의 실행은 막지 않는다. 키를 가진 사람은 PC 시계를 되돌리거나 평문 설치 프로그램을 고쳐 기간 뒤에도 설치할 수 있으므로, 오프라인 강제 수단이 아니라 늦게 유출된 ZIP·키의 정상 설치를 막는 수단이다.
- **키와 SHA-256은 ZIP과 다른 경로**(문자·전화 등)로 전달한다. 같은 메일로 보내면 암호화 의미가 없다. 비밀번호도 ZIP과 다른 경로로 전달한다.
- 이미 설치된 PC에 같은 아이디가 있으면 그 계정과 기존 비밀번호가 유지된다 (새 비밀번호는 적용되지 않음).

### 사용자 설치 (발행 패키지)

ZIP 안의 `설치안내.txt`와 같다.

1. 받은 ZIP의 SHA-256을 키와 함께 받은 값과 비교한다 (`Get-FileHash .\<파일>.zip`). 다르면 설치하지 않는다.
2. ZIP을 "모두 압축 풀기"로 푼다. ZIP 안에서 바로 실행하면 안내 후 멈춘다. 인터넷에서 받은 ZIP의 보안 경고는 ZIP 속성의 "차단 해제" 또는 실행 화면의 "추가 정보 → 실행"으로 넘긴다.
3. `Install.cmd`를 더블클릭하고 발행 키를 한 번 입력한다. 대소문자·하이픈·공백은 상관없고 O/0, I·L/1 혼동은 자동으로 바로잡는다. 키가 틀리면 다시 묻고, Enter만 누르면 아무것도 바꾸지 않고 취소한다. 유효 기간이 지난 패키지는 키를 묻기 전에 안내 후 멈춘다.
4. 설치 프로그램은 키 확인 전에는 디스크에 아무것도 쓰지 않는다. 확인되면 `%LOCALAPPDATA%\Programs\K-DOG\<버전>-<commit7>\`에 설치하고 `Start.cmd --check`(전체 파일 SHA-256·Python·FFmpeg)를 통과한 뒤 발행 계정을 만든다.
5. 이 PC에 활성 업무 계정이 없으면 **처음 쓸 업무 계정**(operator)의 아이디와 비밀번호(12~256자, 두 번)를 묻는다. 아이디에서 Enter만 누르면 건너뛰며, 로그인 전에 `Install.cmd`를 다시 실행하면 다시 묻는다. 이미 있거나 예약된 아이디는 거절하고 다시 묻는다. 첫 계정 확인 자체가 실패하면 설치는 오류(바로가기 없음)로 끝나며 프로그램 파일은 남는다. 이어서 바탕화면에 `K-DOG` 아이콘을 만든다. 바로가기를 만들지 못하면 실행할 `Start.cmd` 경로를 보여 준다.
6. 바탕화면 K-DOG 아이콘으로 실행하고 설치 때 만든(또는 전달받은) 아이디·비밀번호로 로그인한다. 다른 운영자·교수 계정은 「직원 계정」에서 추가한다. 설치가 끝나면 압축을 푼 폴더와 ZIP은 지워도 된다.

같은 패키지를 다시 설치하면 파일 확인만 다시 하고 자료와 계정은 그대로 둔다. 활성 업무 계정이 이미 있으면 첫 계정을 묻지 않는다. 역할이 다르거나 비활성인 같은 아이디가 있으면 계정은 바꾸지 않고 실패로 안내한다. 기존 S15 방식(uv)으로 설치한 PC도 같은 자료 경로를 그대로 쓰며, 발행 업무 계정 아이디가 다르면 계정이 하나 추가된다. 기존 `--admin` 발행 옵션도 호환하며 해당 계정의 업무 권한은 동일하다.

### 업데이트와 이전 버전 정리

새 발행 패키지를 같은 방법으로 설치하면 새 버전 폴더가 생기고 바탕화면 아이콘이 새 버전으로 바뀐다. 이전 버전이 실행 중이면 그 실행 창을 닫고 아이콘으로 다시 실행한다 (이전 버전 창이 떠 있으면 런처가 "다른 위치나 버전의 K-DOG"로 안내한다). 이전 버전 폴더는 자동으로 지우지 않는다. 새 버전으로 로그인·자료 확인을 마친 뒤 `%LOCALAPPDATA%\Programs\K-DOG\`에서 이전 `<버전>-<commit7>` 폴더를 지운다. 자료 폴더(`%LOCALAPPDATA%\K-DOG\data`)는 지우지 않는다.

### 담당자 설치 (평문 ZIP, 내부용)

1. 평문 ZIP과 같은 이름의 `.sha256`을 받아 hash를 검사하고 빈 새 폴더(예: `C:/K-DOG/app-s1`)에 푼다. ZIP 내부에서 직접 실행하지 않는다.

```powershell
$releaseZip = (Resolve-Path './kdog-s1-windows-x64.zip').Path
$expectedHash = ((Get-Content -LiteralPath "$releaseZip.sha256" -Raw).Trim() -split '\s+')[0].ToLowerInvariant()
$actualHash = (Get-FileHash -LiteralPath $releaseZip -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actualHash -ne $expectedHash) { throw 'ZIP SHA-256 불일치' }
```

2. 계정은 프로그램 폴더에서 아래 명령으로 만든다. 비밀번호는 숨김 프롬프트로 입력한다. 최초 로그인 전에 일반 업무 계정이 하나 필요하며, 공급자 키를 관리하려면 개발자(`developer`) 계정도 필요하다. 로그인한 업무 계정은 「직원 계정」에서 다른 일반 계정을 만들고 활성 상태를 관리한다. Node.js/npm/Git도 필요 없다.

   ```powershell
   runtime/python/python.exe -X utf8 -m app.manage create-user manager --role operator
   runtime/python/python.exe -X utf8 -m app.manage create-user key-manager --role developer
   ```

3. `Start.cmd --check`로 전체 파일 SHA-256(`release.json`)·Python·FFmpeg를 확인하고 `Start.cmd`를 실행한다. 기본 로컬 주소는 `http://127.0.0.1:8000`이다.

### 사용자 설치형 ZIP

S15와 같은 방식이다. ZIP에 Python·FFmpeg가 없어 작고(포터블은 약 70MB), 대신 사용자가 uv와 FFmpeg를 설치하고 최초 설치 때 인터넷이 필요하다. 개발자는 `build_release.py --variant online`으로 만들고 `verify_release.py`로 검증한다 ([개발 안내](DEVELOPMENT.md#패키지와-종단-리허설)). 암호화·발행 키·발행 계정·바탕화면 아이콘이 없는 평문 ZIP이므로 제품 파일이 그대로 보인다. 받을 사람이 그래도 되는 경우에만 전달하고, 발행 패키지가 필요한 고객에게는 쓰지 않는다 (`issue_release`는 이 ZIP을 거절한다).

1. [uv 공식 설치](https://docs.astral.sh/uv/getting-started/installation/)와 [FFmpeg 공식 다운로드](https://ffmpeg.org/download.html)의 Windows 안내를 따른다 (2026-10-05 확인: uv 0.12.23, FFmpeg 9.0.2). 새 PowerShell 창에서 `uv --version`, `ffmpeg -version`, `ffprobe -version`이 동작해야 한다. H.264/AAC 디코더와 libx264/AAC 인코더가 있는 빌드가 필요하다. Python은 따로 설치하지 않아도 uv가 3.14를 받는다.
2. ZIP과 같은 이름의 `.sha256`으로 위 [담당자 설치](#담당자-설치-평문-zip-내부용) 1번처럼 hash를 확인하고, 빈 새 폴더(예: `C:/K-DOG/app-s1`)에 "모두 압축 풀기"로 푼다. ZIP 안에서 바로 실행하지 않는다.
3. `Install.cmd`를 실행한다. 전체 파일 SHA-256(`release.json`)을 확인한 뒤 uv가 Python 3.14와 잠금 의존성(`backend/uv.lock`)을 `backend/.venv`에 설치하고 `--check`를 실행한다. 이어서 일반 업무(`operator`)와 개발자(`developer`) 계정 이름을 묻고 숨김 프롬프트로 비밀번호를 받는다. 계정 이름에서 Enter를 누르면 생략하므로, 최초 로그인 전에 업무 계정이 하나 필요하다. 생략했다면 프로그램 `backend/`에서 만든다.

   ```powershell
   .venv/Scripts/python.exe -X utf8 -m app.manage create-user manager --role operator
   .venv/Scripts/python.exe -X utf8 -m app.manage create-user key-manager --role developer
   ```

4. `Start.cmd`로 실행한다 (실행 창·브라우저·창 닫기 종료는 포터블과 같다). 바탕화면 아이콘은 만들지 않으므로 필요하면 `Start.cmd` 바로가기를 직접 만든다. 담당자 CLI는 프로그램 `backend/`에서 `.venv/Scripts/python.exe -X utf8 -m app.manage ...`로 실행한다 (이 안내의 `runtime/python/python.exe` 명령과 같은 인자).

`.venv`를 다른 PC·폴더로 복사하지 않는다. FFmpeg를 지우거나 PATH에서 빼면 실행 전 확인이 FFmpeg 설치를 안내한다. 업데이트는 앱 종료·백업 후 새 프로그램 폴더에 같은 방법으로 설치하고 같은 자료 경로를 쓴다. 자료 경로는 포터블·발행 설치와 같으므로 방식을 바꿔도 같은 DB와 계정을 쓴다 (동시에 두 설치를 실행하지 않는다).

첫 실행으로 AI 호출이나 공급자 연결 시험을 자동 수행하지 않는다. 공급자 키 등록·연결 시험·실제 AI 분석은 명시 조작이며 비용이 발생할 수 있다. 조직 정책으로 차단되면 IT 담당자가 검토한다. `--check`가 손상을 알리면 ZIP을 새 빈 폴더에 다시 풀거나 다시 설치한다.

### AI 키 등록과 비밀번호 분실

- AI 공급자 키는 미리 넣지 않는다. 설치한 PC에서 **같은 Windows 사용자**로 K-DOG를 실행하고 발행 개발자 계정으로 로그인해 화면에서 등록한다 (Windows DPAPI 보호).
- Gemini는 「개발 설정 → 공급자 키 관리」에서 주키와 예비키를 따로 등록·시험·교체한다. 연결 확인은 선택 키의 모델 목록 조회이며 영상 평가 품질 확인은 별도다. 원격 접속에서는 아래 HTTPS 운영 주소를 사용한다.
- 새 분석/애착/리포트 실행은 주키부터 시작하고, 주키 미가용·인증/권한/결제·요청 제한·일시 장애에서는 가용 예비키를 자동 사용한다. 입력·근거·스키마 오류는 키 교체로 해결하지 않는다. 전환도 기존 시도/호출 상한을 쓰므로 상한이 남지 않으면 전환하지 않는다. 같은 프로젝트의 두 키는 할당량을 공유해 장애 복구를 보장하지 않는다.
- 「주키를 앱에서 제거」해도 예비키가 남으면 사용할 수 있다. 「Gemini 전체 키 사용 중지」는 다음 시도의 두 키 사용을 막는다. 업무 화면의 실행 중지와 공급자 콘솔의 키 취소는 각각 별도이며 진행 중 원격 요청이 취소됐다고 간주하지 않는다. 복원 뒤에는 두 슬롯을 같은 Windows 계정에서 다시 등록한다.
- 실행 상세의 사용 역할·전환 대기·상한·키 미가용, 과금 미확인과 임시 파일 정리 미완료를 확인한다. 응답을 잃은 호출은 과금됐을 수 있고 비용 미확인은 0원이 아니다. 교체 전 키로 만든 원격 파일은 당시 키 참조가 활성일 때만 앱에서 정리하며 새 키로 대신 삭제하지 않는다. 실공급자 전환·계량·모델 품질/교수·현장 확인의 상태는 실행 기록을 따른다.
- 비밀번호를 잊으면 담당자가 K-DOG 실행 창을 닫은 뒤 설치 폴더(`%LOCALAPPDATA%\Programs\K-DOG\<버전>-<commit7>`)에서 재설정한다. 사용자가 비밀번호를 바꾸는 기능은 없다.

  ```powershell
  runtime/python/python.exe -X utf8 -m app.manage reset-password manager
  ```

### 보안 경계

- 키가 없는 사람은 발행 ZIP에서 제품 파일(앱 코드·카탈로그·리포트 자산·계정 정보)을 보거나 설치할 수 없다. `payload.kdog`는 AES-256-GCM 인증 암호화이므로 변조되면 설치 전에 거절된다.
- 비밀번호 원문은 패키지·저장소·발행 기록 어디에도 남지 않는다.
- 설치가 끝난 PC 안의 프로그램 파일은 평문이다. 같은 ZIP과 키를 가진 사람은 유효 기간 안에 여러 PC에 설치할 수 있다. AI 분석은 개발자가 키를 등록한 PC에서만 가능하다.
- `runtime/`(공개 Python·라이브러리·FFmpeg와 소스), `오픈소스고지.txt`, `Install.cmd`·설치 프로그램은 암호화하지 않는다. 이 평문 영역은 암호화 검사보다 먼저 실행되므로 변조를 막지 못한다. 그래서 설치 전에 키와 같은 경로로 받은 SHA-256과 ZIP을 비교한다.
- 문의처: 벨루가 veluga.app@veluga.io

## 구판에서 S1으로 전환

사용자가 승인한 전환 정책은 **기존 점수·분석·리포트·파생 결과 폐기, 원입력·원영상·접수·운영 기록 보존**이다. 구판 점수를 S1 점수로 읽거나 변환하지 않는다. 운영 앱을 종료한 뒤 아래 명령을 프로그램 폴더에서 실행한다. `--actor`는 활성 admin 계정이다.

```powershell
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" backup "E:/K-DOG/before-s1" --actor manager
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" reset-s1 --actor manager
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" reset-s1 --actor manager --apply
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" backup "E:/K-DOG/after-s1" --actor manager
```

미적용 명령은 대상 수를 보여준다. `--apply`는 원본 hash 검증과 고정 작업 계획으로 처리한다. 원격 공급자 파일 삭제 대기가 있으면 키 상태를 확인한 뒤 같은 자료 루트에서 `reset-s1 --actor manager --retry-remote`로 재시도한다. 초기화 재실행은 이미 고정한 작업만 처리하며 이후 새 S1 시트·결과를 지우지 않는다. 초기화 전 구판 백업은 S1 결과 복원용으로 허용되지 않는다. 원본 보존 백업으로 따로 관리한다.

2026-10-04 현재 로컬 운영 루트에서 백업 후 실제 전환을 수행했다. 참가자2·계정2와 원입력2·영상참조6의 hash를 보존하고 구판 run9/step111을 제거했다. 반복 초기화·초기화 이후 백업/새 폴더 복원·초기화 이전 백업 거절을 확인했다. 이 기록은 다른 PC/현장 전환을 완료한 뜻이 아니다.

## 중앙 서버와 촬영 PC3대

서버 한 대가 DB·원본·불변 산출물과 worker를 소유한다. 촬영 PC3대와 메인 조회 PC는 **같은 서버 주소**에 각 계정으로 접속한다. 각 PC의 `%LOCALAPPDATA%`에 별도 DB를 운영하도록 안내하지 않는다.

기본 `Start.cmd`는 loopback 감독 실행이다. 중앙 서버는 IT 담당자가 HTTPS 인증서·DNS·TLS reverse proxy를 준비한 후 다음 API와 worker를 각각 감독하여 실행한다. 아래 주소는 예시이므로 실제 인증서의 origin으로 바꾼다. proxy가 같은 서버이면 API는 loopback에 유지한다.

```powershell
# 중앙 서버 프로그램 폴더: 서로 별도 감독 프로세스
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" serve --host 127.0.0.1 --port 8000 --public-origin "https://kdog.example.org"
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" worker
```

proxy가 다른 호스트이면 방화벽에서 해당 proxy만 접근하도록 제한한 내부 주소에 bind하고 같은 HTTPS public origin을 지정한다. 앱은 Host와 변경 요청 Origin을 정확히 검사하고 HTTPS origin에는 Secure 세션 cookie를 사용한다. TLS proxy는 Host를 public origin과 동일하게 전달하고 `/api/`를 캐시하지 않아야 한다. 앱은 전달 IP 헤더를 신뢰해 인증을 우회하지 않는다. 개발 서버를 인터넷에 직접 공개하거나 TLS 없이 원격 접속하지 않는다.

IT 담당자는 실제 파일 크기·동시3업로드·전처리·PDF 완료를 기준으로 proxy 요청 본문/timeout·저장 공간·인증서 신뢰·방화벽을 검증한다. 약1GB 원본 세 개를 작은 합성 영상으로 대체해 대용량 검수를 통과 처리하지 않는다. 저장 공간은 원본+변환본+전처리+출력+백업을 포함해 확보한다. 업로드 미완료 파일·실패 batch를 성공으로 보지 않으며 상태 확인 후 같은 업로드 파일의 촬영 정보를 정정해 불필요한 재전송을 피한다.

## 촬영부터 발급까지

1. **접수/설문** — 「일괄 등록 (CSV·Excel)」에서 표준 양식(「명단만」·「명단 + 설문 28문항」, 각각 Excel 또는 CSV)을 내려받아 명단을 채워 올린다. 열은 머리글 이름으로 자동 연결되며, 연결 요약에 「확인 필요·연결 안 됨」이 0개인지 보고 미리보기 후 등록한다(같은 열 대응은 저장해 다음 행사에 재사용할 수 있다). 현장에서 늘어난 참가자는 「참가자 접수」의 참가자 등록으로 한 명씩 이어서 등록한다. 이미 있는 참가자의 설문 파일은 「기존 참가자 갱신 확인」 후 갱신하고, 오류 행은 제외 등록 뒤 파일을 고쳐 다시 올린다. 행사·참가자·회차를 확인한다. 새 양식은 동의 열을 사용하지 않는다. 구 파일의 동의 열·셀은 원본 그대로 보존하며 현재 등록과 설문 계산에서는 사용하지 않는다. 설문 Q01–Q28의 28문항 원응답을 보존하며 0과 빈칸을 구별한다. Q26–Q28 감정의 일관성 문항을 포함한 원척도·역채점·유효 n을 확인하고, 부분 결측의 미정 정책을 임의 평균으로 확정하지 않는다.
2. **영상 파일 업로드** — 「영상 파일 업로드」에서 PC에 저장된 파일을 올리고 파일별로 참가자·촬영 회차·촬영 카메라 번호·원본 번호를 확인한 뒤 「영상 정보 저장」을 누른다. 현행 촬영 자료는 고정 카메라 4대의 MKV이며 `N_CAMk_설명` 파일명(예: `6_CAM1_복도-정면.mkv`)은 카메라 번호를 제안한다. CAM4는 사양 원본 번호가 없으므로 미입력 시 null이다. 촬영 카메라 번호는 해당 파일을 촬영한 카메라를 구분하는 번호이며 기기 연결 설정이 아니다. 파일명 「원본1·원본3·원본2」는 촬영 카메라 1·2·3번으로 제안되며 실제 촬영 번호가 다르면 고친다. 숫자 1·2·3·4는 저장할 때 CAM1·CAM2·CAM3·CAM4 식별자를 사용한다. 영상 먼저/접수 먼저 모두 가능하다.
3. **촬영 기록** — 「촬영 기록 (8구간)」에서 기준 영상과 실제 촬영 절차를 확인하고, 접힌 영역 밖의 「구간 CSV 가져오기」로 녹화 도구의 `segments.csv`를 읽는다. 구간 1~8 시작과 다음 번호 시작에서 유도한 끝, 연결 카메라 평균 offset이 채워지며 누락·미실시 기록은 유지한다. 파일명·SHA-256·계산 열을 확인하고 자동 선택된 「수동 동기화 확인」은 실제 대응을 확인하지 못했으면 해제한다. 기준 영상을 바꾸면 CSV를 다시 가져온다. 1~7구간 시작·끝과 퇴장 시작을 확인해 초안 저장·확정한다(미실시는 사유 기록). 퇴장 끝과 걷기 실제 6국면 시각은 비워 둘 수 있으며, 직접 입력도 같은 조건이다. 상세 사건·관찰 근거·꼬리 선택은 필요한 경우 실제 영상을 보고 추가한다. 걷기 시각을 입력하기 시작했다면 여섯 국면의 경계를 모두 기록한다. 비어 있는 상세 관찰을 추정하거나 0점으로 바꾸지 않으며 해당 근거가 필요한 항목은 미관찰로 남는다. 새 회차와 기존 회차를 구분하고 수정하면 입력 revision이 새로 생긴다. 최종 CSV 적용 기록을 따른다.
4. **전처리/채점** — 현재 입력을 확인해 전처리를 명시 실행한다. 배정 없이 채점 시트를 만들고 원관찰·근거/검토메모를 구분하여 제출한다. 모든 계정이 타인/AI 시트와 이전 판본을 바로 열고 수정할 수 있다. 명시 열람은 실제 계정으로 기록하며 제출 뒤 정정은 새 판본이다. 원평가자의 사전 노출과 후속 편집을 구분하고, 최초 독립 제출 뒤 제3자의 단순 열람은 최초 독립 분모를 바꾸지 않는다. AI 분석은 입력·batch·설정·예산을 확인해 실행하며 중단/명시 재시도와 이전 실행 재사용을 구분한다.

4대 기본 우선순위는 CAM1~CAM4이며 카메라 수를 강제하지 않는다. 수령한 2026-10-14 샘플 4개 MKV는 모두 오디오 트랙이 없다. 발성 평가에는 음성이 녹음된 카메라가 필요하며 무음 영상의 발성을 추정하지 않는다. 전처리의 `audio_absent_or_unavailable`·대표 오디오 `no_usable_audio`를 확인한다. 실제 AI 분석 전에 4영상 구성의 비용·예산을 다시 확인한다. 4카메라 실행 기록의 기술 인수는 실제 행동·공급자 품질 검수를 대신하지 않는다.
5. **계산/의견/최종** — 원자료를 고정하여 계산하고 유효 수기 판정·완료 의견의 우선순위를 적용한다. 관찰 부족과 규칙 미정을 구별한다. 의견의 평가자·C31·해당 영역을 확인하며 유형 없는 문장으로 유형을 추론하지 않는다.
6. **리포트** — 최종결과 판본과 필요한 자체 비교 집단을 선택해 명시 발급한다. 상태·단계·차단 이유·재시도·이전을 조회한다. HTML/PDF/manifest는 발급 당시 고정 판본을 사용하며 입력 변경 뒤에는 이전 입력 기준임을 표시한다. 옛 동의·삭제 상태나 작성자 계정 비활성은 제공을 막지 않는다. 실제 파일 hash·고정 연결·현재 로그인 계정은 검증한다. 인쇄·전달은 사용자 조작이며 고객에게 자동 발송하지 않는다.
7. **검수/연구** — 검수 자료의 XLSX 원셀·수식·저장 계산값과 평가자·판본·독립/AI노출·잠정/재확인/중단을 기록한다. 참고 등록은 현재 점수에 반영하지 않는다. 연구 내보내기는 명시 선택한 시트/결과/참고/cohort 판본을 고정한다. 알려진 식별값은 치환하지만 자유메모의 제3자 식별정보까지 자동 보장하지 않으므로 추가 제외어와 실제 연구 사용 범위를 확인한다. 독립 사람·최초 AI의 유효 항목 쌍만 비교 분모에 들어간다.

외부 비교는 「비교 조건」에서 실제 평균·표준편차·유효/전체 표본 n·문항/원척도·산식/결측·대상 조건·근거와 수치 출처를 입력해 기준 정의를 저장·적용한다. 별도 확인/활성화 승인은 없다. 값 없음·틀린 범위·근거 손상은 미준비/기술 오류이며 수치를 추측하지 않는다. 기준 변경·사용중단은 새 계산에서 검사하며 과거 발급 파일은 당시 고정 기준으로 제공한다.

### 설문 누적 비교 운영(2026-10-21)

2026-10-08 전달 기준표(EXT1.1)에 따라 리포트의 설문 비교는 9개 지표 「평소의 우리를 그래프로」이다. SF(낯선 사람 두려움)·NF(비사회적 두려움)만 미국 연구 참고 평균과 비교하고 나머지 7개 지표는 우리 누적 참여견 평균과 개별 점수만 표시한다. 세부 계약은 누적 비교 계획을 따른다.

1. **기준 등록** — 2026-10-21 사용자 결정에 따라 앱이 처음 시작할 때 SF·NF의 전달 기준값(EXT1.1)을 내장 기준 정의 1판으로 한 번 설치한다. 기록 계정은 로그인할 수 없는 예약 계정 `builtin-reference`이고 근거는 커밋된 매핑 자산과 전달표 hash다. 이미 기준 정의나 연구 확인 기록이 있는 출처, 운영자가 수정·사용중단한 기준은 덮어쓰지 않는다. 운영자는 「비교 조건 > 외부 비교 기준 정의」에서 두 기준이 사용 가능하고 전달 기준과 다르다는 표시가 없는지만 확인한다. 실제 전달표 파일을 근거로 바꾸거나 수치를 정정할 때는 「전달 기준 수치 불러오기」와 근거 업로드로 새 판본을 저장한다. 등록하지 않았거나 전달 기준과 다른 쪽은 그 지표의 외부 비교만 미준비가 되며 수치를 추측해 넣지 않는다.
2. **참여쌍과 대표 설문** — 「설문 현황」 상세의 「누적 비교 참여」에서 보호자–반려견 참여쌍을 새로 만들거나 기존 쌍에 연결하고 최초 제출(현재 입력)을 기록한다. 참여쌍마다 전체 설문 1건만 대표로 누적에 들어간다. 같은 사례의 오입력은 「오입력 정정」으로 대표를 바꾸고, 다시 참여한 설문은 「재방문」으로 기록하며 대표를 바꾸지 않는다. 잘못 연결한 쌍은 연결 정정으로 옮기고, 누적에서 뺄 쌍은 제외·재포함으로 관리한다. 과거 자료는 자동 등록되지 않는다. 근거가 확인되지 않은 자료는 추정으로 연결하지 않고 화면의 미확정·미연결 건수를 확인해 기록한다.
3. **발급** — 「리포트 발급」의 새 발급은 기본으로 누적 비교를 포함한다. 접수 순간의 참여쌍 대표 설문·지표별 유효 n·SF/NF 기준을 고정하며, 이후 재시도·다운로드는 다시 집계하지 않는다. 새 요청만 새로 집계한다. 유효 n이 2 미만인 지표는 누적 표식을 숨긴다. 「이전 방식」의 외부 기준 직접 선택은 누적 비교 없이 발급한다. 연구 내보내기의 비교 표에는 선택한 리포트의 고정 개별·누적·외부 값이 함께 기록된다.
4. **백업** — 백업·복원·정리는 참여쌍 상태·제출(재방문 포함)·대표 입력·발급 snapshot을 보존한다. 참조가 손상되면 정리가 중단된다. 이 기록이 있는 DB를 누적 비교 이전 앱으로 열지 않는다. 문제가 있으면 신규 발급·참여쌍 기록을 멈추고 자료를 보존한 채 수정판을 적용한다.

한계: 운영 DB의 실제 SF/NF 정의 등록, 운영 참여쌍·대표 설문 확인과 실제 발급 대조는 아직 수행하지 않았다. 기준표는 사용 허가나 한국어 측정 동등성의 증거가 아니며, 국내 표준·진단·백분위로 해석하지 않는다. 실제 AI 품질·현장 실측은 별도 인수다.

G01/G04 확인 전 실제 빈 Excel 채점양식 가져오기, D03/D04/D05의 미확정 세부 규칙, SF/NF 외의 미수령 외부 기준·국내 비교값은 보류한다. G02의 후보 문장을 교수님 확정 문장으로 표시하지 않는다. 나머지 검증된 프로그램 근거 설명과 정상 리포트 전체에 임의의 일괄 승인 의무를 추가하지 않는다.

## 백업·복원·참조 보관

배포 전 `app.manage --data-dir <운영 자료 폴더> check-removed-media`의 `total: 0`과 종료 코드0을 확인한다. 제거 대상이 있으면 식별자만 기록하고 사용자에게 처리 방법을 확인한다. 이 명령은 원본 DB/WAL의 임시 복사본과 고정 파일을 읽으며 자료를 삭제·이관하지 않는다. 이전 앱을 같은 DB에 병행 실행하거나 되돌려 운영하지 않는다.

백업에는 참가자 자료가 있으므로 접근·보관을 관리한다. 키와 로그인 세션은 제외한다. 원본·영상 정보 미등록 파일·batch·시트·의견·발급물·검수 참고·비교 집단·연구 export까지 고정 참조를 검사한다. 복원/정리 전에 API·worker·전처리를 모두 종료한다.

```powershell
# 프로그램 폴더; 모든 대상은 새 폴더
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" backup "E:/K-DOG/backup-s1" --actor manager
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" restore "E:/K-DOG/backup-s1" "D:/K-DOG/restored-s1"
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" clean
```

복원은 검증된 백업의 DB·자료·변경 이력을 그 시점 그대로 새 폴더에 복원한다. 현재 삭제대장이나 백업 이후 사건을 병합하지 않는다. 정리는 참조 파일의 존재/hash를 검사한 뒤 미참조 관리 파일만 제거하며 DB·원본·시트·사건을 연쇄 폐기하지 않는다. `--purge-deleted`는 지원하지 않는 사용 오류다. 실제 유실/손상 파일은 정상 복구로 표시하지 않는다. 복원 후 다시 로그인하고 키는 개발자가 같은 Windows 계정에 등록한다.

권한 단순화 전환 후 같은 운영 DB에 옛 동의·삭제 정책 앱을 실행하지 않는다. 실패 복구는 전환 전 검증 백업과 호환 앱을 격리 경로에서 사용한다. 별도 정책 marker나 다운그레이드 차단 시스템은 없다.

## 장애와 계량

같은 PC의 중복 실행은 브라우저만 다시 열고, 유지보수 작업 중이거나 다른 프로그램이 포트를 쓰거나 FFmpeg/자산이 없으면 시작 전에 거절한다. `Start.cmd --check`와 다음 명령으로 상태를 확인한다. 로그인 실패는 사용자/자료 경로를 먼저 확인하고 앱 종료 후 설치 담당자가 `reset-password USERNAME`을 사용한다. 키 문제가 생기면 키 등록 때와 같은 Windows 사용자로 실행했는지 확인한다.

```powershell
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" recovery-status
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" usage-report --event-id EVENT-01
```

중단 후 점유 만료·불변 파일 검증에 따라 복구하며 실패/검토필요를 성공으로 바꾸지 않는다. 응답 유실 외부 요청은 과금되었을 수 있다. 가격 미확인은 0원이 아니며 공급자 계량·재시도·재사용을 구분한다. 실측 시간/품질은 [S16 준비 도구](archive/개발반영_20261003/K-DOG_PR-S16_원본압축본과360도실증_v1.0_20261003.md)로 실제 로그·동일조건·독립 정답을 고정해 기록한다. 로그 공유 시 이름·영상·키·비밀번호를 제거한다.
