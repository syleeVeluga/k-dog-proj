# K-DOG 영상별 직접 평가 구현·검증 기록

버전: v1.0 · 2026-09-07

## 동작과 적용 범위

같은 검사를 여러 각도에서 촬영했을 때 각 영상과 전체 55항목·원문 선택지를 Gemini에 제공한다. 관찰 요약을 다시 읽는 반려견/보호자 AI 평가 호출은 새 경로에서 생략한다. 영상 파일은 결합하지 않는다. [수용 변경 계획](K-DOG_영상별평가_변경계획_v1.0_20260907.md)에 따라 신규 실행은 `video-evaluate-1.0`을 사용한다.

각 영상은 항목별 선택지·상태·관찰 범위와 이유·측정값·원본 시각 근거를 저장한다. 전체 항목의 정확한 집합, 원문에 존재하는 선택지, 같은 영상의 관련 근거, 시간 상한과 오디오 유무를 검증한다. 충분한 관찰 범위 없이 채점하지 않는다. DOG-13/14/15·OWN-11/18의 구령 횟수를 요구하고, 명시 횟수 선택지와의 모순 및 보호자 발화의 음성 근거 부재를 거절한다. 미정 DOG-12/OWN-14와 기존 설문 규칙은 유지한다.

항목의 `observation_indices`가 명시적 근거 연결의 기준이다. 서버는 이를 관찰의 `candidate_item_ids`에 중복 제거하여 역참조로 보완한다. 동일 관계를 두 곳에 중복 출력하다 한쪽 태그가 빠지는 오류를 방지하며, 관찰 사실·주체·시간·측정값은 변경하지 않는다. 존재하지 않는 인덱스와 다른 영상의 근거는 계속 거절한다. 연결 일관성은 의미적 충분성 보증이 아니므로 관찰 범위와 원본 검토는 유지한다.

원문 선택지·ID·인덱스·원본 영상 밖 시각 등 구조/출처 오류는 응답을 거절하고 제한된 수정 요청을 사용한다. 반면 영상 안의 측정값이 관련 관찰 범위로 뒷받침되지 않거나 보호자 음성 근거가 없거나 선택지의 명시 횟수와 모순되면 **그 항목만 채점 보류**한다. 잘못된 측정값은 검증된 측정 목록에서 제거하고 값·범위·보류 이유를 사유에 남긴다. 다른 항목의 검증된 결과는 보존한다. 명시적 충돌·규칙 미정 상태는 보류 정규화로 덮어쓰지 않는다. 저장 산출물의 검증은 계속 엄격하게 유지한다.

서버는 항목별로 충분한 근거가 있는 선택지를 한 번 채택한다. 관찰 불가 영상은 다른 시야의 유효한 판단을 취소하지 않는다. 서로 다른 채점 선택지 또는 명시적 근거 충돌이 있으면 해당 항목만 모든 영상에서 한 차례 재검토한다. 재검토도 독립 요청이며 이전 선택지를 정답으로 제공하지 않는다. 해결되지 않으면 `conflicting_evidence`로 보류한다. 평균·다수결·자신감 가중치·영상 간 횟수 합산은 사용하지 않는다.

재검토는 전체 개별 영상에 항목 목록과 우선 확인 구간을 제공한다. 자동 동기화·물리적 구간 잘라내기는 이번 범위에 없다. 정상 요청 수는 영상 N개 + 리포트 1회이며, 충돌 시 N회의 재검토가 추가된다. 전송/구조 오류 재시도는 기존 최대 3회·구조 수정 1회·총 호출 예산에 포함한다. 병합 자체는 AI 호출 및 과금 집계에서 제외한다.

## 설정·호환·조회

개발자 설정의 `신규 분석 방식`에서 영상별 직접 평가와 기존 관찰→분기 평가를 선택한다. `영상별 직접 평가` 단계에서 모델·프롬프트를 편집한다. 기존 설정 파일에는 새 단계의 기본 프롬프트와 기존 관찰 모델을 보완하여 읽으며 파일 자체를 고치지 않는다. 새 설정은 신규 run에 고정한다. 과거 run의 설정·산출물·재개 경로는 유지하고 legacy 재사용 해시도 호환한다.

성공한 영상은 재시도·worker 재시작·명시적 호환 재사용에서 다시 호출하지 않는다. 재검토 일부가 실패하면 병합 결과를 조기에 확정하지 않는다. 파일 저장 후 DB 채택 이전 중단, 점유 토큰, 삭제/중지, 원본 해시 검사를 유지한다.

상세 화면 `영상별 평가 결과`에서 각 파일의 최초 55항목 판단과 충돌 재검토 결과를 펼쳐 확인하고 근거를 재생한다. 최종 점수에는 채택 이유와 채택 근거를 보존한다. 설문은 영상 평가에 제공하지 않는다.

## Cold review와 수정

독립 reviewer가 합성 DB로 재현한 지적을 수정하고 다시 검토했다.

- 한 시야 `scored`가 다른 시야 `conflicting_evidence`를 가리던 문제: 명시적 충돌도 재검토 대상으로 삼고 미해결 시 보류한다.
- 미정/측정 누락 상태 정규화 전에 잘못된 선택지가 사라지던 문제: 원응답 선택지와 상태 연결을 먼저 검증한다.
- 발화 횟수와 원문 선택지의 모순, 음성 없는 보호자 발화 채점: 숫자 범위·음성 주체·근거 구간을 검증한다. 정상적인 1회 지시·음성 근거는 통과하는 것도 확인했다.
- legacy 재사용 해시에 추가된 모드 필드: 명시 `legacy`를 기존 무필드 표현과 동일하게 정규화한다.
- 실호출에서 드러난 중복 태그 누락: 모델의 명시적 항목→관찰 연결로 서버가 역참조를 보완한다. 별도 설계 cold review와 없는 인덱스 거절·관찰 사실 보존 시험을 거쳤다.
- 한 항목의 의미적 측정 부족으로 전체 영상이 실패하던 문제: 구조/출처 오류와 항목별 근거 부족을 분리했다. 해당 항목의 선택지·측정 목록을 비우고 보류 사유를 남기며 다른 항목과 명시적 충돌 상태를 보존한다. 원본 밖 시각은 보류 전에 거절한다.

수정 후 reviewer의 신규 14개 시험 및 별도 정상 측정 시험이 통과했다. 추가 확정 문제는 발견되지 않았다. 실제 제공자 호환은 별도 실호출로 확인한다.

저장소 밖 합성 자료로 수행했다. 실제 AI 정확도 시험과 구분한다.

## 실제 영상 검증

실제 참가자 영상·응답·검증 DB·실행 스크립트는 `%LOCALAPPDATA%/K-DOG/reviews/20260907-per-video/`에 별도 보관한다. 운영 case와 표시 run은 변경하지 않는다. 이미 검사된 동일 원본·변환 파일의 복사본으로 실제 worker와 Gemini를 실행한다. 원본 변환 자체는 이전 검증 및 자동 미디어 시험에서 확인한 경로를 재사용한다.

초기 실호출에서 Pydantic 전체 JSON Schema가 HTTP 400으로 거절되었다. 기존 관찰 REST와 같은 지원 속성 집합의 `video_schema`로 바꿔 55항목 응답을 수신했다. 이어 영상 길이를 초과한 모델 시각을 서버가 거절하는 것을 확인했다. 응답 스키마에도 실제 길이 상한을 넣고 FPS를 시간 배수로 사용하지 않도록 프롬프트를 명시했으며, 수정 재요청에는 검증 실패 이유를 제공한다. 오류 응답을 임의 보정해 점수로 채택하지 않는다.

최종 확인: **영상 3개 모두 55항목 처리**, 불일치 항목의 영상별 원본 재검토, 두 분기 병합 및 실제 리포트 생성에 성공했다. 개별 채점/보류 수·항목·관찰 내용은 참가자 평가 자료이므로 저장소 밖 검증 결과에만 보관한다. 채점 가능 항목 수는 정확도 지표가 아니다.

검증 방법을 구분한다. 최초 3영상의 실제 Gemini 응답은 같은 검증 작업 중 받은 구조 수정 응답을 최종 서버 처리에 재생하여 사용했다. 합성 예측값이나 수동 수정한 판단을 넣지 않았다. 이어 불일치 항목에 대한 3회의 원본 영상 재검토와 리포트는 Gemini를 새로 호출했다. 최종 코드의 산출물 검증으로 저장 결과를 다시 조회했다. 따라서 이 시험은 실제 응답 재생을 포함한 파이프라인 검증이며, 최종 프롬프트로 최초 3영상을 모두 새로 호출한 독립 반복 시험은 아니다. 재검토와 실제 응답의 근거를 보존한 상세 결과는 로컬 `item-withholding/verified-result.json`, 요약은 `item-withholding/verified-summary.json`에 있다.

운영 데이터의 기존 표시 결과는 그대로 두었다. 이 한 참가자·3각도 시험의 전문가 정답 대비 정확도·다른 참가자에 대한 일반화 성능은 별도 평가가 필요하다. 신규 방식은 앱/worker 재시작 이후 새 분석에 적용된다.

## 버전 확인과 제약

2026-09-07 공식 문서·레지스트리 확인: Python 3.14 환경의 [Pydantic 2.13.5](https://pypi.org/project/pydantic/), [FastAPI 0.141.1](https://pypi.org/project/fastapi/), [React 19.2.8](https://registry.npmjs.org/react/latest), [Vite 8.2.2](https://registry.npmjs.org/vite/latest), [TypeScript 7.0.2](https://registry.npmjs.org/typescript/latest), [Playwright 1.63.0](https://registry.npmjs.org/@playwright/test/latest). 확인된 최신 안정 버전과 기존 잠금 버전이 일치하며 신규 의존성/무관한 업그레이드는 없다. 기존 Node 요구사항 `>=22.12.0`과 Python `>=3.14,<3.15`를 유지한다.

기존 검증 경로의 [Uvicorn 0.52.4](https://pypi.org/project/uvicorn/), [openpyxl 3.1.5](https://pypi.org/project/openpyxl/), [ReportLab 5.0.1](https://pypi.org/project/reportlab/), [Pillow 12.3.0](https://pypi.org/project/pillow/), [HTTPX 0.28.1](https://pypi.org/project/httpx/), [pypdf 6.17.0](https://pypi.org/project/pypdf/)도 당일 공식 PyPI 최신 안정 버전과 잠금 버전의 일치 및 Python 요구 범위를 확인했다. 실행 Node는 24.13.0이다. [FFmpeg 공식 최신](https://ffmpeg.org/download.html)은 9.0.1(8.1 계열은 8.1.2)이며 설치된 8.1.1을 기존 변환 재현을 위해 유지했다. 이번 변경은 미디어 변환/API를 바꾸지 않으며 관련 없는 시스템 바이너리 교체는 수행하지 않았다.

Gemini `gemini-3.8-flash`의 [영상 처리](https://ai.google.dev/gemini-api/docs/video-understanding)·[구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output)과 [Pydantic JSON 검증](https://docs.pydantic.dev/latest/concepts/json/) 계약을 확인했다. 모델 자기 보고의 관찰 범위는 정확도 보증 수치가 아니다. 가림·미녹화·소리 주체 불명확성 및 미정 원문 규칙은 보류와 근거 검토로 남긴다.
