# PR-C10 리포트 실행과 메뉴

버전: v1.0 · 2026-09-30 · 상태: 구현 전 · 선행: C07B·C08·C09 · 추정: 2~3개발일

상위: [전체 계획](K-DOG_개발반영계획_v1.0_20260930.md). 근거: 00 §5·§7, 07 최종 결과, 기존 실행 불변성과 F-04. 권장 제목: `feat: 불변 리포트 생성과 메뉴 연결`.

## 문제와 결과

새 리포트 API·메뉴는 없다. C07A의 실행 보호와 C07B의 AI 계약·설정·사용량 통제를 사용해 고정 입력으로 리포트를 생성한다. 미리보기·인쇄·파일 제공·재생성을 연결하고 생성 시작 시점과 보호자 전달의 운영 정책을 분리한다.

## 구현 순서와 경계

1. 생성 요청은 최종 결과, 기본 AI 실행·시트·판정, 의견, 설문·촬영 판본, 문장·템플릿·비교 승인 상태의 ID·revision·해시를 명시한다. 필요한 로컬 자산의 실제 파일 해시와 새 report 설정·모델·프롬프트·schema 판본도 고정한다. 이 참조가 C08 최종 결과와 일치하는지 검증하고 실행 접수 시 예상 revision을 확인한다. 실행 중 설정·의견·문장이 바뀌어도 해당 실행은 선택한 스냅샷을 사용한다.
2. 자료 부족이 있는 리포트도 생성할 수 있다. 정상 8구간·109개 숫자·사람 final·6영역 의견 완료·관계 유형 확정을 필수조건으로 만들지 않는다. 기본 결과에 기록된 유효한 부분 관찰·미실시·보류와 손상 파일·다른 대상의 참조·확정되지 않은 입력 선택·설정 누락을 구분한다. 영상 재관찰이 필요 없는 출력에 정상 전체 촬영창을 다시 요구하지 않는다. 실행 불가 조건은 이유와 다음 행동을 표시한다.
3. 생성 엔진은 요청 후 자동으로 실행한다. 시작 시점, 즉시·사후 전달, 사람 승인·특정 의견 대기, 재발급 정책은 Q09에서 결정한다. 합의 전 구현 기본은 운영자의 명시한 생성 요청이며 메타데이터 저장·poll·의견 수정만으로 실행을 새로 만들지 않는다. 구판 수동 승인 규칙을 생성 필수조건으로 이어받지 않는다. 공개 링크·이메일·일괄 전달은 이 PR 범위에 추가하지 않는다.
4. 새 report kind와 서술 단계를 worker·settings·usage에 함께 등록한다. C07B의 요청 schema, 호출 예약, `max_ai_calls`·`max_attempts`, schema 보정 재시도, 사용량·비용 기록, 타임아웃의 `billing_uncertain`을 사용한다. 구판 report 프롬프트·55항목 schema로 fallback하지 않는다. 순수 렌더와 검증된 문장 자료 사용에는 AI 비용을 붙이지 않으며 새 모델의 가격 자료가 없거나 청구 상태가 불명확하면 0원으로 표시하지 않는다.
5. 생성은 브라우저 생존에 의존하지 않고 worker에서 처리한다. 화면 poll은 상태 조회만 수행한다. 동일 요청의 중복 접수 방지, 중지·재시도, 점유 토큰·lease·heartbeat·attempt별 불변 파일, 파일 기록 후 채택 전 중단 복구는 C07A 기반을 사용한다. 요청을 명시적으로 다시 만들 때에는 새 run과 스냅샷을 만든다. 중지·실패가 이전 완료 출력이나 발급 이력을 삭제하지 않게 한다.
6. 결과 선택은 명시적이다. 완료 run이 `cases.display_run_id`를 자동으로 덮어쓰지 않는 F-04를 유지한다. 이전 출력·발급 이력을 보존하며 현재 입력과 다르면 어떤 입력·의견·문장 판본이 바뀌었는지 표시한다. 다시 만들기는 새 출력 manifest와 파일 경로를 만들고 과거 출력 경로를 덮지 않는다.
7. 미리보기·인쇄·다운로드는 선택한 출력 스냅샷을 사용한다. HTML뿐 아니라 해당 CSS·그래픽·폰트 등 참조 자산의 실제 해시와 manifest 소속을 확인하고 제공 직전 접근 권한·삭제 상태를 재확인한다. 현재 템플릿 파일을 다시 읽어 이전 발급의 모양을 바꾸지 않는다. 인증·CSP·로컬 자산과 기존 민감정보 표시 정책을 지킨다. 파일 제공 방식에 맞춰 자산을 포함하거나 고정 자산 묶음으로 제공하며 다운로드 후 외부 요청 없이 표시되는지 검증한다.
8. 새 파일 경로·해시 키와 DB 표를 maintenance의 관리 폴더, 참조 탐색·해시 검사·백업·삭제 순서에 명시적으로 추가한다. 새 표가 기존 참조 탐색에 자동 포함된다고 가정하지 않는다. 백업을 복원해도 최신 삭제 이력을 재적용하며 삭제 대상의 생성·채택·출력 제공을 차단한다.
9. 새 kind를 legacy report 함수에 전달하지 않는다. `reporting.py`를 삭제하려면 settings·evaluation·worker·exports의 잔존 import와 기존 대기 실행을 먼저 추적한다. 새 kind의 분기·필요한 지연 import를 연결한 뒤 실제 대체한 호출만 정리하며 기존 이력·미대체 모듈은 읽기 전용으로 보존한다.

이 PR은 C07B 완료 후 운영 AI 서술과 report 실행을 연결한다. C09 렌더 자체를 다시 구현하거나 AI 채점·기본 판정을 리포트 생성 때 재수행하지 않는다. 출력의 최신성 판정과 표시 선택은 기본 결과·독립 연구 시트의 수정 권한을 바꾸지 않는다.

## 검증과 완료 조건

- AI 기본 결과만 있음, 일부 완료 의견, 입장 선택 완료·미완료, 미실시·미접촉·판정보류·설문 없음에서 생성 조건과 문구가 정확하다. 손상 입력과 해당 영역의 보류를 혼동하지 않는다.
- 생성 중 입력·의견·문장·템플릿·설정 변경, 같은 요청 중복, 중지·재시도, lease 만료·이전 토큰, 파일 작성 후 채택 전 중단, 명시 표시 선택·stale를 시험한다. poll·다른 화면 이동·브라우저 닫기가 새 실행을 만들지 않는다.
- 새 report 모델·schema·설정만 사용하고 55항목 fallback을 거절한다. 사용량 등록·호출 상한·schema 보정·재사용 비용·불명확한 청구 상태·비밀값 비노출을 검증한다. 허가되지 않은 provider 호출이 실행되지 않는다.
- HTML·CSS·그래픽의 변조, 다운로드·인쇄 중 삭제 요청, 손상 출력, 백업·복원, 완료 의견 철회 후 재생성에서 이전 발급 스냅샷과 접근 차단을 검증한다. 현재 자산이 바뀌어도 이전 출력은 고정된 자산으로 표시된다.
- 목록 필터·참가자 맥락·업무별 권한·다음 행동과 브라우저를 닫은 뒤의 상태 확인이 동작한다. 실제 브라우저 인쇄와 다운로드 파일의 한글·그래픽·자산 경로를 확인한다.

## 추가 확인과 인계

Q07·Q09·Q11·Q12. 외부 AI 이용과 전달 기능의 운영 활성화는 확정된 조건을 기록한 뒤 수행한다. C11은 비교 없음·미승인을 출력 입력으로 고정하고, C12는 발급 출력과 연구 자료의 스냅샷을 별도로 내보낸다.
