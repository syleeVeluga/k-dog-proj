## 문제와 결과

현재 4개 자극의 필수 입력과 사건 뒤 5초 8fps/나머지 2fps는 구판 임시 규칙이다. 새 미접촉·분리 생략·짧은 부름/접촉·6개 국면을 표현하지 못한다. 절단·오디오·batch/해시·잠금·이전 입력 판별 기반을 재사용하고 판본별 계획 생성을 변경한다.

## 구현 순서와 경계

1. 현재 4개 stimulus의 필수조건을 새 사건 계약으로 대체한다. 미접촉 사건에는 접촉 시각을 요구하지 않고 접촉항목의 미평가 사유를 연결한다. 다른 유효한 구간의 전처리까지 실패시키지 않는다. 접촉 중 중단이면 실제 관찰된 접촉창을 보존하고 정상 시행과의 구분을 함께 기록한다.
2. 초기/후기/전체·부름 뒤 4초·실제 접촉·전환을 제외한 6개 국면 등 항목별 관찰창을 계획한다. 같은 원본의 중첩창은 사건과 원본 시각으로 연결한다. 동일 사건이 여러 클립에 나온다는 이유로 한 원항목의 횟수를 중복 집계하지 않으며, 서로 다른 원항목의 관찰 규칙은 유지한다.
3. 원속도 연속 영상과 전체 오디오를 보존한다. 꼬리 움직임 등을 정지 프레임 몇 장으로 대체하지 않는다. 해상도/fps/오디오 부재·가림은 품질 정보이며 원관찰 0으로 해석하지 않는다. 실제 구간 길이와 음성 관찰 가능 초를 구분해, 일부만 청취한 시간을 전체 발성 비율의 분모로 대체하지 않도록 C06/C07에 전달한다.
4. 클립의 원본 영상/해시·시작/끝·로컬 fps·오디오·원본 시각 오프셋·규칙 판본을 manifest에 넣는다. provider 요청의 fps/media_resolution은 C07에서 별도로 고정한다. 로컬 8fps 추출만으로 AI가 8fps로 판독한다고 보장하지 않는다.
5. 재시도는 기존처럼 새 batch를 만든다. 새 실행 때와 산출물 채택 때 입력 revision/삭제 상태를 재확인한다. 실패·중단·손상 파일을 완료 manifest로 채택하지 않는다. 구판 결과는 ‘이전 입력/기준’으로 조회할 수 있게 보존한다.
6. 여러 카메라는 확인된 수동 오프셋으로만 같은 원본 시각에 연결한다. 카메라 전처리 확대는 실제 장비·동기화 자료가 확보된 범위에서 수행하며 자동 동기화나 반복 횟수 합산을 추가하지 않는다.

## 검증과 완료 조건

- 합성 영상/음성으로 본 구간·전환·짧은 접촉·6개 국면의 클립 길이와 원본 시각 역추적을 검증한다. 접촉 없음/생략/단축 사례가 0초 클립을 만들지 않는다.
- 오디오를 유지하고 전체 발성 관찰창을 놓치지 않는다. 음원 없음이나 녹음 손상으로 생긴 무음은 발성 0의 증거가 아니다. 유효한 녹음을 전체 청취해 발성이 없었던 경우와 구분한다. 실제 단축 구간의 전체 청취와 정상 구간의 일부 청취를 구분하는 품질 정보를 검증한다.
- 규칙/입력 변경·실행 중 수정·삭제·재시도·파일 손상·동시 실행·불완전 완료를 시험한다. 완성 batch의 해시·부모 입력·백업/복원을 확인한다.
- 구판 계획과 최신 A07 동작의 회귀가 유지된다. 새 샘플링 기준이 아직 임시이면 화면/manifest에 그 상태를 표시한다.

## 실자료 검증과 인계

Q02·Q05·Q08을 연결한다. 실제 꼬리·얼굴·몸길이·손/줄·음성 판독에 충분한지는 실영상으로 확인한다. C07은 클립 제작 설정과 provider 읽기 설정을 함께 버전/해시에 포함한다. 운영판 ZIP·실행·백업 검사도 이 PR 완료 시 앞당겨 수행한다.
