# PR-C00 원본 추출과 새 도메인 계약

버전: v1.0 · 2026-09-30 · 상태: 구현 전 · 선행: 없음 · 추정: 1~2개발일

상위: [전체 계획](K-DOG_개발반영계획_v1.0_20260930.md). 근거: 00 §2~4, 01 설문, 02 원항목/눈금/유효성/배점, 03, 두 JSON, 07, 10. 권장 제목: `feat: 9월 29일 원본 카탈로그와 도메인 계약 추가`.

## 문제와 결과

현재 `domain/catalog.py`는 42개 연속 ID, 시트별 9/24/9행, 1~5 척도와 6개 영역을 고정한다. 새 원본의 원항목 117행, 사용 113행, 직접 채점·메모 109행, 자동 계산 4행과 여러 자료형을 표현할 수 없다. 새 판본 모델과 추출물을 추가해 후속 PR이 같은 항목과 규칙을 사용하게 한다. 기존 v2 계약·추출물은 구판 조회와 회귀 검증을 위해 보존한다.

## 구현 순서와 경계

1. `첨부목록.json`의 크기·SHA-256을 대조한다. 02b·02c 수식을 입력 원본으로 합치지 않는다. Excel 캐시값에 의존하지 않고 원항목·라벨·유효성 검사·계산식·배점표를 대조한다. `0_안내!A52`와 07 §3.2가 유지하도록 정한 방향별 분리 합계·관찰 항목 수·접촉 여부도 원점수 참조와 함께 계산 정의에 기록한다. 입장 판단은 `6_행사전문가의견`의 대상별 의견 블록과 기본 자동 초안·최종 출력 연결의 출처를 추출한다(`0_안내!A37`, `여러쌍비교!CA~CC`). 완료 조건에 따른 우선 적용은 C08에서 구현한다. 자료형이 모호하면 Q01~Q03에 기록한다.
2. 원행 코드 `바5/개17/보6`를 판본 안의 식별자로 보존한다. 현재 `BS-01/DOG-17`과 숫자만으로 대응시키거나 이관하지 않는다. 기존 ASCII `Key` 모델을 원코드에 재사용하지 않는다. 바디시그널은 5~45행, 개행동은 5~60행이며 보호자 원항목 20행은 **5·6·9·10·11·12·13·14·16·17·18·22·23·24·25·26·27·38·39·40행**이다. 보호자 시트의 설명행과 빈 행을 연속 항목으로 추출하지 않는다. 행별 유효성 검사·본문·라벨을 대조해 허용값을 명시하며, 헤더의 −2~+2를 모든 행에 적용하지 않는다.
3. 미사용 개20·31·33·35와 자동 개26·27·36·60을 표시한다. 횟수·초·메모는 척도 점수와 다르다. 개32=99는 원코드와 미발생 의미를 보존하며 실제 초와 구분한다.
4. 설문 내부 ID `s01~s28`은 유지할 수 있으나 JSON의 `Q01~Q28`과 명시적으로 대응시킨다. A~E는 인쇄 섹션이고 8개 보고영역은 별도 필드다. 7~9번 NA 삭제, 10~14번 0~4 척도, 26~28번 역채점, 25번 단독 응답을 추출한다. 문항 원문은 01, 대응·허용값은 JSON/03과 교차 확인한다.
5. `Q01-Q06` 범위는 문항 ID 목록으로 확장하고, ‘각 영역의 확정 근거’ 같은 서술은 허용된 결과 근거 목록으로 명시적으로 변환한다. 원본 A열의 ‘앞 당김·기록·분리 변화·전 구간’ 등은 원문 라벨로 보존하고, 실제 구간·여러 관찰창·기회 조건과의 연결은 별도로 정의한다. 단일 `SegmentId`로 강제하지 않는다. 셀과 슬롯은 출처 정보이며 Excel의 20개 슬롯을 참가자 저장 한도로 사용하지 않는다. ‘설문 단독’에는 직접 대응하는 행동코드를 추가하지 않는다.
6. 구판 `base.py/catalog.py/contracts.py`와 v1/v2 추출물을 이 PR에서 일괄 변경하지 않는다. 새 모델의 스키마 버전과 판본별 함수 호출을 명시하고 필요한 분기만 준비한다. 범용 DSL·수식 실행기·임의 자동 코드 추론은 만들지 않는다.

추출 CLI에는 `--spec`을 신설하되 기본값을 `20260913`으로 두어 기존 호출을 유지한다. 기존 `--customer-dir`의 원본 폴더 지정 기능도 유지하고, 각 판본의 기본 원본 경로와 `all`의 두 판본 선택 방식을 문서화한다. 구현 후 `backend/`에서 `uv run --locked python -X utf8 -m app.import_catalogs --check`는 기존 판본을, `uv run --locked python -X utf8 -m app.import_catalogs --spec all --check`는 구판·신판 추출물을 함께 읽기 전용으로 대조하도록 한다.

## 검증과 완료 조건

- 원항목 41+56+20=117행, 사용 41+52+20=113행, 직접 채점·메모 109행, 자동 계산 4행과 정확한 미사용 코드가 원본과 일치한다. 보호자 시트의 불연속 행과 설명행 제외를 검증한다.
- 음수·0·0/1·0~4·0~3·1~3·횟수·초·메모를 자료형별로 검증한다. 잘못된 범주, bool을 수치로 사용한 입력, NaN/Infinity, 자동/미사용 직접 입력, 중복/알 수 없는 코드를 거절한다.
- 설문 28개 원문·척도·ID 대응·8개 보고영역과 두 JSON의 모든 실제 코드/관찰창 참조를 검증한다. 보38·40 등 기회 조건의 참조도 검증한다. 방향별 분리 합계·관찰 수·접촉 여부와 입장 판단의 자동 초안/완료 의견 연결 출처를 확인한다. 서로 다른 방향 반응이 평균 0으로 사라지는 전체 영역 집계를 만들지 않는다.
- v1/v2 원본 대조와 기존 시험을 유지한다. 원자료 파일은 수정하지 않는다. 새 importer 인자 사용법과 추출 출처를 기록한다.

## 추가 확인과 인계

Q01~Q03은 상태 이름·대표값/관찰량·개32 정밀도에 관한 확인 사항이다. 명시된 규칙과 미확정 정책을 구분해 C01~C07에 넘긴다. 테스트 fixture는 합성 입력과 원본 수식의 해석을 검증하는 자료이며 실제 AI 정확도 자료로 표시하지 않는다.
