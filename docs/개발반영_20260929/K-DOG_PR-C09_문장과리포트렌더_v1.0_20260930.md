# PR-C09 문장과 리포트 렌더

버전: v1.0 · 2026-09-30 · 상태: 구현 전 · 선행: C02·C06·C08 · 추정: 2~3개발일

상위: [전체 계획](K-DOG_개발반영계획_v1.0_20260930.md). 근거: 루키 수정 HTML의 구성, 00 §5, 07·10 해석 범위. 권장 제목: `feat: 최종 결과와 분리된 문장 자료 및 리포트 렌더`.

## 문제와 결과

구판 리포트 코드와 미구현 R계획의 유형 표시·숫자 사용 제한, 사람 시트만 입력한다는 전제는 새 기준에 맞지 않는다. C08의 최종 결과를 입력으로 교육태도를 먼저 보여주고 관계·사람과 환경 반응·걷기를 연결한다. 판정·계산 규칙과 출력 문장 자료는 별도 판본으로 관리한다.

## 구현 순서와 경계

1. 리포트 입력은 C08의 명시한 최종 결과, 설문 판본·집계, 연결된 관찰 근거를 받는다. 문장 단계에서 AI가 유형을 새로 판정하거나 원수치·비율을 재계산하지 않게 한다. 독립 시트 중 최신 final을 이 단계에서 선택하지 않는다.
2. 첫 ‘오늘의 결과’는 보호자 교육태도 허용형·조율형·통제형과 근거 비율·대표 장면, 네 관계 이름 또는 판정보류, 사람·환경 반응, 걷기 근접 국면 비율 순서로 구성한다. 별도 전문가 의견 상자를 만들지 않고 같은 양식에 완료 의견을 반영하며 내부 적용 출처는 보존한다. 입장 판단도 C08이 정한 최종 선택 또는 기본 초안을 사용한다.
3. 의견으로 유형이 변경됐으면 자동 근거 비율을 최종 유형의 확률처럼 표시하지 않는다. 걷기 6국면 중 5국면이면 5/6과 반올림한 83%의 뜻을 설명한다. AW·AX·AY는 내부 기술값이다. 방향별 원값·분리 합계·관찰 수·접촉 정보는 필요한 해석 근거로 사용하되 사회성 75점·환경 100점 같은 능력 표시나 새 총점으로 바꾸지 않는다.
4. 8개 설문 보고 영역, 25번 단독 문항, 직접 대응·설문 단독·행동 단독의 관계를 연결한다. 서로 다른 척도를 한 그래프나 차이 점수로 합치지 않는다. 설문 12번의 큰 소리에는 계획된 직접 자극이 없음을 유지한다. 평소 친밀감·사회화 노력·감정 일관성을 당일 영상의 정답으로 판단하지 않는다.
5. 문장 자료에 유형·영역, 허용 근거, 본문·조언, 판본, 검토 상태를 둔다. 제공된 성향 문장이 없으면 확인된 관찰과 보류 사유를 표시하며 임의의 맞춤 조언을 확정하지 않는다. 문장 판본 변경은 새 출력 버전을 만들고 기본 판정·계산은 유지한다. 문장 자료가 누락·손상됐을 때 사용하는 검증된 기본 문구와 생성 불가 조건을 구분한다.
6. 새 네 관계 이름과 세 교육태도 이름, 근거에 필요한 숫자는 허용한다. 외부 임상 유형과의 동일성, 원인·보호자 탓, 일반화된 기질 단정은 차단한다. 실제 으르렁·회피·굳음·중단은 관찰 사실로 서술할 수 있다. 구판 금칙어 목록만 그대로 사용하지 않는다.
7. 서술의 근거 ID·수치·분모·최종 유형·관찰창을 고정 입력과 대조한다. 구조·수치 검사만으로 사실성 검증이 끝났다고 표시하지 않는다. 완료 의견과 메모는 비신뢰 입력 자료로 전달하며 프롬프트 명령으로 실행하지 않는다. 유형·수치 변경을 요구하는 입력이나 생성 문장은 검증에서 거절하거나 검토 대상으로 표시한다.
8. HTML에 넣는 데이터는 escape한다. 외부 스크립트·추적 URL·임의 HTML을 허용하지 않고 로컬 자산을 사용한다. CSS는 로컬 파일로 제공하며 필요한 그래픽은 검증된 렌더러가 만든 자산으로 제한한다. 현재 CSP와 호환되는 미리보기·인쇄 구성을 확인하고 임의 인라인 코드 때문에 앱 전체 CSP를 완화하지 않는다.
9. 템플릿에 원속도 영상·임시 숫자·개발 지시문이 보호자 문구로 새지 않게 한다. 루키 예비 기록의 3/6, 음성 미재평가, 미산출 유형은 새 채점의 골든 결과로 복사하지 않는다. 원본 HTML은 보존하고 새 자산은 `resources/report/`에 둔다.
10. 현재 빌드의 자산 확장자 목록에는 HTML·CSS·SVG가 없으므로 필요한 파일을 포함하는 규칙과 시작 시 필수 자산 검사를 같은 PR에서 수정한다. 폰트는 기존 로컬 배포 방식을 따른다. 파일 목록뿐 아니라 실제 배포본의 템플릿·CSS·그래픽·폰트 경로를 검증한다.

이 PR은 순수 입력 변환·문장 계약·검증·렌더를 제공한다. fixture와 검증된 문장 자료로 외부 AI 없이 미리보기를 시험할 수 있다. 실제 AI 서술 호출은 C07B의 provider 계약과 C10의 실행·사용량 통제를 통해 연결하며 이 PR의 렌더 시험에서 외부 AI 호출을 만들지 않는다. 새 서술 프롬프트·schema·문장 자료 판본은 실행 스냅샷에 넣을 수 있도록 명시한다.

## 검증과 완료 조건

- 첫 화면 순서, 의견 없음·일부 완료·작성 중·완료 후 유형 변경, 입장 선택의 적용·자동 초안 복귀, 미실시·판정보류·설문 없음·접촉 없음·원값 0·빈값을 렌더한다. 모든 관련 부분의 유형과 숫자가 한 최종 결과와 일치한다.
- 문장 판본만 바뀌었을 때 기본 유형·원값은 불변이다. 자료 부족의 보류 사유, 근거 없는 조언의 비활성, placeholder·지시문의 미출력, 문장 자료 누락·손상을 시험한다.
- 허용된 유형명·사실 서술은 통과하고 잘못된 수치·분모·유형, 영상·설문 합산, 진단·원인 단정은 검증 실패 또는 검토 대상으로 표시한다. 의견·메모의 주입 문구, HTML escape, 외부 자산·스크립트 차단도 시험한다.
- 실제 브라우저에서 긴 본문·한글 폰트·그래픽·A4 인쇄의 줄바꿈·페이지 나눔·잘림·대비와 CSP를 확인한다. 이번 자료로 A4 2~3장 고정을 보장하지 않는다. 합성 사례의 PNG·PDF 또는 스크린샷을 검토 근거로 남긴다.
- 실제 배포 ZIP에서 필요한 HTML·CSS·SVG·폰트가 포함되고 경로가 유효하다. 필수 자산을 제거한 배포본은 시작 검사에서 누락 원인을 표시한다. C10 활성화 전에 렌더·미리보기 모듈을 테스트에서 사용할 수 있다.
