## 검사 범위

계획 문서6개(전체1·PR3·cold review1·검증1)의 상대 링크·코드/시험 경로 존재·요구 VM-R01~08와 VM-T01~08 담당·PR 선행·표현 일치·변경 범위를 확인한다. 문서 자신이 명시한 미래 시험 명령을 현재 실행한 성공으로 세지 않는다.

현재 작업은 코드/운영 자료/의존성/lockfile을 변경하지 않는다. Graft freshness/코드 검색과 공식 외부 문서 확인은 계획의 근거이며 제품 시험이 아니다. 고객 원본의 source hash 대조와 실제 파일 판독은 이번 문서 검증에서 실행하지 않는다.

## 2026-10-12 ES/MP 진행 순서 조정 검증

사용자의 후속 지시에 따라 ES01→ES02→ES03→MP01→MP02→MP03을 양쪽 총괄 계획에 반영했다. 문서 조정 기준 HEAD는 `89d3765`이며 최초 코드 조사/독립 review 기준 `1702f2b`는 이력으로 유지한다. 이번 수정은 총괄 계획2개·ES03 인계·MP01~03·이 검증 기록의 기존 문서7개다. 기존 Cold Review 기록/수용 건과 VM-R/VM-T/ES-T 번호를 유지하고 MP03에 조합 인수 VM-ES-T01~04를 추가했다.

- 두 폴더의 문서11개에서 상대 링크97개·앵커42개를 실제 경로 및 `git ls-tree -r --name-only HEAD`의 committed tree와 대조했다. 경로/앵커/코드 줄 범위 오류0, 후행 공백0이다.
- ES03 선행을 ES02 구현·검증·병합으로 맞추고, MP01의 작업 선행을 ES03까지 병합한 실제 commit으로 연결했다. MP02/03은 이 선행을 포함한 MP01/02에서 시작한다. ES가 MP를 기다리는 순환 선행은 없다.
- MP01의 서버 회귀와 MP02의 화면 회귀에 선행 ES에서 신설할 시험 경로를 추가하고 착수 시 실제 인계 경로를 대조하도록 명시했다. 이 미래 시험 파일이 현재 존재하거나 통과했다고 계수하지 않는다.
- `git diff --check`는 명령 환경에서 `must be run in a work tree`로 실패했다. 명시 work-tree 및 외부 diff 미사용에서도 같았으며 성공으로 기록하지 않는다. 실제 문서의 줄 단위 공백 검사와 변경 경로 대조로 별도 확인했다.

이번 검증은 진행 순서·인계·조합 인수의 문서 정합성 확인이다. 기존 독립 review 완료를 새 변경의 독립 재검토로 재계수하지 않는다. 제품 코드/의존성/운영 자료 변경과 앱 시험·영상 처리·공급자 호출·배포·커밋/PR/병합은 수행하지 않았다.

### 후속 로컬/원격 병합 준비

사용자가 로컬 및 원격 병합을 지시했다. 최신 `main`과 `origin/main`이 `89d3765`로 일치하는 것을 확인한 뒤 `codex/es-mp-plan-order`에서 위 문서7개만 staging했다. 커밋 전 전체 staged diff를 검토했고 `git diff --cached --check`는 성공했다. 이전 문서 수정 때의 unstaged diff 명령 실패 기록은 당시 이력으로 유지한다. PR/병합 결과는 해당 Git 이력과 PR에서 확인하며 제품 구현/시험 완료와 구분한다.
