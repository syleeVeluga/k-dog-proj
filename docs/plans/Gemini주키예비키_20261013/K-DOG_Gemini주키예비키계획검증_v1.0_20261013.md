## 1 검사 범위

계획6개(상위1·개별 PR4·검증1)의 상대 링크/앵커, 코드 근거의 실제 경로/줄 범위, committed tree와 신규 계획의 연결, GK-R01~R12/GK-T01~T20 담당과 PR 선행, 전환/폐기/상한/파일 소유권 정책의 문서 간 일치를 검사한다. 신설 후보 코드/시험/실행 기록은 미래 산출물이며 현재 존재/통과로 세지 않는다.

최초 작업은 계획 문서 작성이었다. 제품 코드·의존성/lockfile·운영 DB·점수·키를 변경하지 않았고 실제 공급자 호출·제품 시험·릴리스/배포·commit/push/GitHub PR 생성/병합도 수행하지 않았다. 이후 문서 병합은 §5의 후속 지시와 구분한다. 이전 점검의 합성 시험 통과를 새 fallback 구현의 검증 결과로 전용하지 않는다.

## 2 작성자 문서 검토

| 검토 항목 | 계획에 반영한 처리 |
| --- | --- |
| 예비키가 숨은 내부 호출로 총 상한 우회 | 외부 주키 실패 뒤 Worker 새 attempt/예약으로 전환. max_attempts1/호출 상한 소진 시 자동 증액 없음 |
| 같은 실행에서 주키를 계속 반복/예비→주키 왕복 | 실제 현재 run의 선택 사건을 내구성 기록. 남은 단계/재시작/재시도는 backup, 새 run은 primary |
| 키 정책과 기존 전체 폐기 의미 충돌 | 새 슬롯 제거와 기존 provider DELETE(전체 두 슬롯 중지)를 분리. 환경 변수 부활 금지 |
| 모든 오류를 키 장애로 취급 | HTTP·정규 코드·operation_phase·로컬 credential 사유를 구분. 일반 요청/schema/guard/cleanup-only는 전환0 |
| 다른 프로젝트의 주키 미디어 URI 재사용 | backup 자체 업로드·고정 로컬 hash. upload/cleanup별 같은 reference, 옛 키가 없으면 정리 대기 |
| 기존 재사용 usage를 현재 키 선택/새 비용으로 오인 | 현재 run 실제 선택만 근거. copied usage는 재사용/옛 출처로 표시, 중복 계량 없음 |
| 교체 중 연결 시험 성공을 새 키 성공으로 표시 | slot/reference/시각 고정, 늦은 결과와 409 재입력·원문 초안 미보관 |
| 전체/슬롯 제거를 이미 출발한 원격 요청 취소로 오인 | 적용 경계는 다음 attempt. 진행 중 attempt의 키 일관성, 실행 중지/공급자 콘솔 폐기 구분 |
| 구현·문서 검사·실공급자 품질 혼동 | 개별 PR 모두 계획/미실행, 미래 명령/신설 후보 표시, GK04 실제 공급자 후속 분리 |

위 표는 작성자의 문서 검토이며 독립 cold review 완료 기록이 아니다. 제품 PR마다 독립 검토·발견별 판단·수용 수정/재검증을 수행하도록 계획했다.

초기 committed 경로 검사에서 Git의 비ASCII 경로 quoting 때문에 기존 한국어 경로8개를 누락으로 잘못 판정했다. `core.quotepath=false`로 검사 입력을 수정한 뒤 상대 링크/앵커 누락0을 확인했다. 실제 문서 링크를 임의 변경하지 않았다. 초기 no-index 공백 검사는 새 파일 차이의 종료코드1을 오류로 처리했으며, 최종 git diff check와 직접 공백 검사 결과로 구분한다.

최종 검사는 제품 코드나 고객 source hash를 대조하는 검증이 아니다. 운영 자료/비밀 값은 읽지 않고 코드 구조·계획 문서·Git 경로만 사용했다. 검사 결과를 기록한 문서 자체도 최종 재검사 범위에 포함한다.

## 4 남은 실행 경계

GK01~GK04 제품 구현/검증·독립 cold review·PR 생성/병합·패키지 검증은 미실행이다. 실제 공급자 오류 형식·프로젝트 전환·모델 사용 가능/품질/정산은 구현 시 공식 문서 재확인과 승인된 실공급자 후속으로 구분한다. 다른 공급자 연동이나 평가 규칙 변경을 이 계획에 추가하지 않는다.

## 5 후속 로컬·원격 문서 병합 — 2026-10-13

사용자가 이번 계획의 로컬 및 원격 병합을 지시했다. 로컬 main과 origin/main이 조사 기준 `6b0d1951c99a5fabdb34ff4316eeeabb3ccbc962`로 일치하는 것을 확인하고, `veluga/gemini-primary-backup-plan`에서 이 폴더의 문서6개만 커밋·push·계획 문서 PR로 병합한다. 링크/앵커·코드 경로·요구/시험 추적과 staged whitespace를 커밋 전에 재검증한다.

원격 병합 뒤 로컬 main을 ff-only로 동기화하고 main/origin/main의 같은 commit·문서6개 보존·깨끗한 작업 트리를 확인한다. 이 문서 패키지의 병합은 GK01~GK04 제품 PR의 구현/시험/병합 완료가 아니다. 제품 코드·운영 자료·키·의존성·실제 공급자 실행은 변경하지 않는다. 문서 PR과 최종 병합 commit은 GitHub/Git 이력을 원장으로 확인한다.
