# K-DOG Gemini 주키·예비키 적용 계획

버전: v1.0 · 작성 2026-10-13 · 후속 2026-10-14 · 조사 기준: `main / 6b0d1951c99a5fabdb34ff4316eeeabb3ccbc962` · 상태: GK01~02 병합, GK03 구현·검토 중, GK04/실공급자 인수 대기

## 1 목표와 범위

2026-10-13 사용자는 **우선 Gemini 주키와 예비키만 적용하고, 주키에 문제가 생기면 예비키를 사용하도록 PR 단위 계획을 plans 폴더에 작성**하도록 지시했다. 이 문서와 GK01~GK04는 `docs/plans/Gemini주키예비키_20261013/`에서 관리한다. PR 식별자는 계획 번호이며 실제 GitHub PR 번호가 아니다.

개발자가 주키와 예비키를 각각 등록·교체·연결 시험·앱에서 제거할 수 있게 한다. 등록한 예비키는 아래 전환 조건에 따라 자동 사용한다. 별도 업무 승인이나 매 실행 전환 확인은 요구하지 않는다. 예비키는 선택 사항이며 주키 한 개만 등록한 운영도 유지한다.

적용 대상은 S1 영상 원관찰 채점, 관찰자료 기반 애착 판단(독립 실행 포함), 리포트 문장 생성의 모든 Gemini 호출이다. 기존 모델·프롬프트·S1 산식·평가 기준·관찰창·리포트 HTML/PDF 생성 규칙을 유지한다. OpenAI/Anthropic 실행 연동, 공급자 전환, 부하 분산, 다수 예비키, 전역 장애 탐지/자동 복구 서비스는 이번 범위에 포함하지 않는다. 기존 다른 공급자의 키 저장 기능과 자료를 삭제하지 않는다.

이 계획의 기본 가정은 **주키 한 개 + 예비키 한 개, 같은 Gemini 모델, 한 실행에서 주키→예비키 전환은 최대 한 번**이다. 프로젝트가 달라도 등록할 수 있지만 예비키 프로젝트에도 사용 모델·Files API·결제/권한이 준비되어 있어야 한다. 연결 시험 성공만으로 해당 모델의 실제 평가·문장 품질을 보장하지 않는다.

## 3 키 저장·API 계약

- 내부 슬롯은 `primary`, `backup`, 화면명은 「Gemini 주키」와 「Gemini 예비키」다. 기존 Gemini 등록 이력/ciphertext는 재암호화·DB 이관 없이 주키로 사용한다. 예비키 기본값은 미등록이다.
- 기존 changes를 재사용한다. 주키 target은 기존 `gemini`, 예비키 target은 `gemini:backup`을 후보로 고정한다. 실제 충돌은 GK01에서 확인한다. 두 슬롯의 최신 참조만 활성으로 판단하고 한 슬롯 교체로 다른 슬롯 파일을 제거하지 않는다.
- 신규 후보 API는 `PUT/DELETE /api/developer/keys/gemini/slots/{slot}`와 `POST /api/developer/keys/gemini/slots/{slot}/test`다. slot은 두 literal만 허용한다. 변경은 현재 `expected_reference`를 요구하며 미등록은 null이다. 등록/제거 요청의 슬롯과 기대 참조가 현재와 다르면 409로 거절한다.
- `/api/developer/settings`는 기존 keys와 함께 typed `gemini_slots` 상태를 제공한다. 상태의 source는 vault/environment/none이며 활성 환경 변수 주키의 reference는 기존처럼 environment, 등록 이력과 환경 변수 모두 없는 슬롯의 reference는 null이다. 원문/키 일부/키 hash를 반환하지 않는다. available은 로컬 가용성이지 공급자 정상/모델 사용 가능 보장이 아니다. 시험 결과는 시험한 slot/reference와 시각에 연결한다. 교체 뒤 옛 성공 시험을 현재 키의 성공으로 표시하지 않는다.
- 기존 `PUT /api/developer/keys/gemini`는 주키 등록/교체, 기존 `/test`는 주키 시험으로 유지한다. **기존 `DELETE /api/developer/keys/gemini`는 Gemini 전체 키 사용 중지**로 유지·확장하여 두 슬롯 모두를 원자적으로 폐기한다. 신규 슬롯 DELETE는 선택 슬롯만 제거한다. 다른 공급자 API 의미는 유지한다.
- 주키의 기존 등록 이력이 없을 때만 `GEMINI_API_KEY`를 주키로 사용할 수 있다. 예비키는 개발자 화면/슬롯 API로만 등록하며 새 환경 변수는 추가하지 않는다. 슬롯 또는 전체 폐기 뒤 환경 변수로 되살리지 않는다. 주키 슬롯만 제거하고 예비키가 남으면 예비키를 사용할 수 있으며 화면에 이를 명시한다.
- 동일 원문을 두 슬롯에 등록하는 것은 거절한다. 서버에서 잠깐 비교하고 원문/키 hash를 보존하지 않는다. 같은 프로젝트 여부는 키 문자열로 추정하지 않는다.
- DPAPI 보호·원문 미조회·백업 제외·폐기 commit 후 파일 정리·동시 등록/worker 읽기 직렬화를 유지한다. ciphertext 접근은 typed 활성 슬롯/참조로만 허용하고 웹 요청에 임의 경로를 받지 않는다. 백업 복원 뒤 두 슬롯 재등록이 필요하다.

## 4 자동 전환 규칙

### 4.1 시작·전환·복귀

새 run의 첫 Gemini 작업은 주키를 우선한다. 첫 외부 요청 전에 주키가 없거나 복호화/파일 읽기가 불가능하면 사용 가능한 예비키를 같은 attempt의 첫 키로 선택한다. 이 경우 주키로 외부 호출을 보낸 것으로 기록하지 않는다. 예비키도 없으면 개발자 설정 필요로 종료한다.

주키로 외부 실행을 시작한 뒤 전환 대상 오류를 받으면 현재 attempt를 실패 이력으로 남기고 **기존 Worker의 다음 attempt에서 예비키를 선택**한다. max_attempts/max_ai_calls에 남은 여유가 없으면 예비키를 숨겨 호출하지 않는다. max_attempts=1에서는 외부 주키 실패 뒤 추가 시도가 불가능함을 표시한다. fallback을 위해 상한을 자동 증액하지 않는다.

예비키 선택 사실과 전환 원인을 현재 run/step에 내구성 있게 기록한 뒤, 같은 run의 남은 Gemini 단계는 예비키를 사용한다. 재시작·명시 재시도에도 이 선택을 복원한다. 예비키가 실패하면 기존 상한 내에서 같은 예비키의 허용된 재시도만 수행하고 주키로 왕복하지 않는다. 새 run은 다시 주키부터 시작한다. 성공 산출물 재사용에 복사된 옛 usage는 현재 run의 전환 근거가 아니다.

각 attempt 시작 시 선택 슬롯의 현재 활성 reference를 읽고 원문은 그 attempt 동안만 메모리에 보관한다. 키 교체/제거는 다음 attempt부터 적용하고 이미 시작한 attempt의 업로드·추론·정리 키를 중간에 바꾸지 않는다. 앱에서 키 제거는 공급자 키 취소나 이미 전송한 요청의 취소를 뜻하지 않는다. 즉시 중단이 필요하면 실행 중지와 공급자 콘솔의 키 폐기를 별도로 수행한다.

### 4.2 오류 분류

아래는 **프로젝트의 제안 전환 정책**이다. 공급자가 모든 오류에 키 교체를 권장한다는 뜻은 아니다. 주키→예비키는 이미 설정한 다른 credential을 한 번 선택하는 것이며 동일한 잘못된 키의 반복 재전송과 구분한다.

| 원인 | 예비키 전환 | 처리 |
| --- | --- | --- |
| 주키 미등록·앱에서 슬롯 제거·파일 유실·DPAPI 복호화 실패 | 예 | 외부 호출 전 예비키 선택. 환경 변수 부활 없음 |
| 401/authentication, 403/permission_denied, 402/payment_required | 예 | 주키 동일 오류 반복 없이 다음 attempt 예비키. 주키 오류를 숨기지 않음 |
| 400에서 명확한 키 인증 오류가 기계 판독 코드로 확인됨 | 조건부 예 | API_KEY_INVALID 등 공식 형식으로 확인한 whitelist만 허용. 메시지 부분 문자열로 판단하지 않음. 확인 불가능한 400은 전환하지 않음 |
| 429/rate 또는 quota 제한 | 예 | Retry-After와 기존 backoff를 존중하여 다음 attempt 예비키 |
| 500·502·503·504, 연결 유실·타임아웃 | 예 | 다음 attempt 예비키. 이미 처리/과금됐을 가능성과 billing_uncertain 보존 |
| 일반 400·404·409·416·501, 잘못된 모델/요청/미디어, 안전 차단, 출력 불완전·JSON/schema·평가 계약 오류 | 아니오 | 기술 오류 또는 기존 같은 키의 schema repair/검토 경로. max_schema_repairs는 공유 상한 |
| 앱 권한/세션·중지·입력 변경·lease/token·file hash·호출/시도 상한 실패 | 아니오 | 예비키가 업무/기술 guard를 우회하지 않음 |
| 원격 임시 파일 정리만 실패 | 아니오 | 정리 대기를 보존. 정상 추론을 예비키로 다시 실행하지 않음 |

외부 HTTP 상태·정규화 코드·작업 단계(upload/processing/inference/cleanup)와 로컬 credential 원인을 구분한다. 허용한 코드/상태만 보존하고 비밀·업로드 URL·임의 오류 문자열은 남기지 않는다. 미분류 오류는 자동 키 전환 대상에 포함하지 않는다.

### 4.3 호출·파일·기록 보호

한 attempt는 한 credential과 최대 한 추론 실행만 사용한다. 기존 call_reserved는 공급자 작업 attempt 예약이며 업로드·조회·정리 각각의 HTTP 요청 수 또는 확정 과금 횟수가 아니다. 예비키 attempt도 별도 예약으로 동일 전체 호출 상한에 포함한다. 로컬 실패로 추론까지 가지 못한 예약을 실제 공급자 성공 호출로 표시하지 않는다.

주키 프로젝트의 파일 URI/upload URL을 예비키로 넘기지 않는다. 예비키 attempt는 동일한 고정 로컬 clip bytes/hash를 자기 키로 새 업로드한 뒤 추론한다. 주키로 만든 임시 파일은 주키 attempt의 원문·reference로 정리하고 실패는 대기로 남긴다. 정리 재시도는 **당시 reference와 정확히 일치하는 현재 활성 주키 또는 예비키만** 사용한다. 교체/폐기로 그 참조가 없으면 대기를 유지하며 임의 새 키로 소유권을 추정하지 않는다.

기존 usage/changes에 정책 식별 `gemini-primary-backup-v1`, slot/reference·전환 원인·run/step/attempt·실제 actor·시각을 보강한다. 전환 선택은 guard/예약 상한 확인 후 기존 DB write fence에서 기록하여 재시작으로 주키를 반복하거나 전환 횟수를 초기화하지 않는다. 새로운 전역 상태 머신/키 원문 이력 저장소를 만들지 않는다.

고정 모델/프롬프트/입력 snapshot·재사용 compatibility와 옛 파일/manifest/hash를 재작성하지 않는다. 이전 attempt에 없는 키 역할은 「기록 없음」으로 표시한다. 새 메타데이터는 새 attempt/조회 DTO에만 추가하며 재사용 usage를 새 과금이나 현재 키 선택으로 계수하지 않는다. 현재 사용량 기능은 금액의 강제 결제 상한이 아니라 계량 추정이므로 이 기능을 새 비용 차단기로 표시하지 않는다.
