# K-DOG 촬영 입력 단순화 검토

- 날짜: 2026-10-24
- 범위: CSV 우선 입력, 시간 기준·음성 조건 안내, 모든 영상 등록 화면의 파일 구분 통합

## 검토 결과와 반영

기준 영상은 구간 시각의 좌표를 정하는 파일이다. 영상 품질이나 대표 음성을 사람이 먼저 평가해야 하는 조건이 아니다. 대표 오디오는 기존에도 창별 가용 시간·카메라 순서로 자동 선정하며, 음성이 없는 카메라도 영상 클립을 만들 수 있다. 화면이 이 차이를 전달하지 못해 선행 판단을 요구하는 것처럼 보였다.

1. 촬영 기록의 CSV 입력을 시간 기준 선택보다 앞에 배치했다. 기준 영상·카메라가 아직 없어도 CSV 형식을 검사하고 같은 브라우저 탭에 임시 보관한다. 영상 등록 탭에서 카메라를 연결하고 돌아와 적용할 수 있다.
2. 임시 CSV는 계정·참가자·회차별로 분리한다. 새로고침에도 유지하지만 브라우저 탭 종료·로그아웃·세션 만료 또는 기록 저장 성공 시 제거한다. 서버에 촬영 기록이 저장되기 전까지는 브라우저 임시 보관임을 표시한다.
3. 기존 기준 영상이 없거나 CSV 카메라와 맞지 않고 기존 구간 시각도 없다면, CSV와 연결 영상의 카메라가 일치하는 시간 기준을 사용한다. 이미 기록한 시각이 있으면 임의로 다른 좌표로 바꾸지 않는다.
4. 필수 열 `종류`, `구간번호`, `CAM1_영상초` 등 카메라별 영상초와 UTF-8, 0 이상의 초 단위 숫자를 안내하고 빈 양식을 제공한다. CSV 없는 수동 입력도 유지한다. 실제 구간 확정·누락·선택 상세 관찰 규칙은 유지한다.
5. 음성 선택을 선택 사항으로 표시하고 자동 선정·무음 영상 처리 가능 여부를 안내한다. 음성 손실을 실제 관찰이나 0점으로 바꾸지는 않는다.
6. 참가자별 업로드·공용 보관함·보존 영상 등록에서 원본/변환 MP4 구분과 변환 부모·도구·버전·설정 입력을 제거했다. 신규 UI 등록은 `received_file`로 기록하여 촬영 원본 여부를 추정하지 않는다. 기존 명시적 변환 출처와 부모 해시 검증은 보존한다.
7. 확장자 목록에 의한 수신 제한을 제거했다. 파일을 보관하는 것과 실제로 읽어 분석할 수 있는 것은 구분한다. FFmpeg가 읽지 못하는 파일이나 영상이 없는 파일은 기존 읽기 검증에서 실패할 수 있다. 전용 360도 영상 보정 기능을 복원한 변경은 아니다.

## 검증·검토

- `npm run build` 통과. 기존 번들 크기 경고는 남아 있다.
- 백엔드 업로드·보존 영상·전처리·폐기 형식 점검 56건 통과. 확장자 없는 파일·MTS·INSV의 바이트 보존과 출처 기록을 검사했고, 일반 목록에 없는 확장자로 등록한 실제 MKV와 무음 카메라의 전처리를 검증했다.
- 브라우저 촬영·CSV·업로드·전처리 관련 31건 통과. 최초 30건 중 29건 통과 후 카메라 중복 안내를 수정해 촬영 등록 7건 재검증 통과. 이후 업로드 3건 재검증과 비영상 MIME 다운로드 1건 검증 통과. MIME 테스트의 최초 실패는 두 파일에 같은 합성 바이트를 사용하여 기존 중복 연결 방어가 동작한 것으로, 파일별 fixture를 분리해 검증했다.
- CSV 먼저 가져오기 → 영상 등록 → 돌아와 적용, 잘못된 CSV·UTF-8, 비동기 읽기 중 입력 변경, 기준 영상 변경, 이전 수동 기록 보존, PC·390px 화면을 검증했다.
- 검토에서 수용한 수정: 새 중립 출처에도 카메라 중복 안내 적용. 브라우저 임시 CSV를 로그아웃·세션 만료에서 정리. 이전 출처 이력은 재분류하지 않음.
- 확장자 제한 제거에 맞춰 비영상 MIME 파일은 `application/octet-stream` 다운로드로만 제공하고, 영상 MIME은 기존 미리보기를 유지한다. 기존 `nosniff` 응답도 검증했다.
- 로컬 기존 데이터 경로로 재배포했다. 원격 병합은 하지 않았다.
- 실측 범위: 합성 영상 및 브라우저 검증이다. 모든 제조사 파일·코덱의 재생 가능성을 보증하지 않는다.
