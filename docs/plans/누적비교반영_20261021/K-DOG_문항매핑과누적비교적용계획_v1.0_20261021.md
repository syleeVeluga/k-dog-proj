### 4.1 참여쌍과 대표 자료

- `pair_id`는 한 보호자–한 반려견 조합의 명시 식별자다. 행사별 `participant_id`나 이름으로 자동 생성·병합하지 않는다. 한 보호자와 두 반려견은 서로 다른 pair다.
- 기존 case·입력 bytes를 수정하지 않는 비교 원장을 사용한다. 명시 case→pair 연결과 실제 제출 사실을 불변 파일/`changes`에 기록하고 기대 판본으로 동시에 하나만 갱신한다.
- 대표는 **설문 한 건 전체**다. 최초 명시 제출을 대표로 고정하고 오입력 정정만 새 대표로 교체한다. 재방문으로 결측을 메우거나 지표별로 더 좋은 회차를 골라 섞지 않는다.
- 기존 자료는 실제 최초 제출 근거를 확인해 연결한다. 근거가 없으면 미확정으로 남긴다. case 생성일·현재 input revision·이름으로 최초 제출을 발명하지 않는다. 전환 시 자동 대표 생성은 없다.
- 모든 문항에 숫자를 입력해야 제출할 수 있는 조건은 추가하지 않는다. 제출 사실과 지표별 완전응답/미경험 판정은 다르다. 기준이 맞는 과거·현재 자료를 날짜와 무관하게 포함한다.

### 4.2 새 집계·발급 계약

- 신규 발급 접수 시 동일 기준의 대표 설문 집합을 한 번 읽고 원입력·pair 원장·정정·제외 판본·매핑 hash·기준 정의를 고정한다. 같은 request ID 재전송·Worker 재시도·파일 다운로드에서 현재 DB를 재집계하지 않는다. 새 발급 요청만 새 cutoff로 집계한다.
- 리포트의 개별값은 선택 최종 결과가 고정한 설문이다. 같은 pair의 누적 기여값은 대표 설문이다. 재방문 리포트의 개별값이 바뀌었다고 누적 대표를 교체하거나 한 pair를 두 번 넣지 않는다.
- 해당 지표가 완전 응답인 pair만 분모에 넣는다. n=0은 평균 null, n=1은 계산값은 보존하되 누적 표식/비교문장 생략, n≥2부터 표시한다. 개별이 결측이면 해당 패널을 안내로 대체한다.
- SF/NF 기준을 독립 판정한다. SF만 유효하면 SF 미국 비교를 유지한다. 실제 기준 정의가 없거나 범위가 다르면 해당 외부점만 미준비로 두며 다른 지표의 개별·누적값을 없애지 않는다. 손상·변조는 조용히 생략하지 않는 기술 오류다.
- HTML/PDF와 연구 export는 동일한 새 비교 snapshot을 사용한다. 기존 수동 선택 집단은 이름·기능을 유지하며 전 회차 누적으로 명칭만 바꾸지 않는다.

### 4.3 출처와 과거 자료 보존

`resources/report/comparison-sources-v4.json` 및 기존 설문 자산 bytes를 덮어쓰지 않는다. 기존 외부 snapshot은 출처/자산 hash를 검증하므로 신규 매핑 hash를 `comparisons.assets()`의 기존 반환에 무조건 추가하지 않는다. 새 매핑은 새 실행/표현 판본에만 포함한다. 옛 S1 발급·내보내기·대기 실행 재시도는 자기 판본으로 읽는다. 구판 점수를 복원하거나 변환하는 기능은 추가하지 않는다.

외부 수치는 기존 기준 정의 저장/적용으로 실제 업무 계정이 근거 XLSX와 함께 등록한다. 새 매핑 자산 자체가 운영 DB의 사용중단 결정을 덮거나 가짜 승인/actor를 생성하지 않는다. 신규 발급의 기본 흐름은 등록된 유효 기준을 자동 연결하며, 수동 picker를 다시 거쳐야만 비교가 나오는 구조는 남기지 않는다.

## 6 실행 절차와 완료 판정

각 PR는 **구현 → 국소 검증 → 독립 cold review → 발견사항 수용/보류/거절 → 수용 수정·재검증 → 문서 → push/PR** 순서로 진행한다. Graft로 대상 symbol·호출 관계를 착수 시 재확인한다. 단계별 실제 commit·명령·건수·시간·결과·한계는 해당 파일의 실행표에 남긴다. 이 계획의 체크박스는 아직 실행 결과가 아니다.

신규 의존성은 계획하지 않는다. 각 구현 PR 착수 전에 사용하는 기존 라이브러리의 최신 안정판·공식 문서/registry·호환성을 확인하고 최신/선택 판본·고정 유지 이유·확인일/링크를 실행표에 남긴다. 무관한 업그레이드는 섞지 않는다. 이번 계획 작성은 Python 표준 라이브러리와 Graft만 사용했고 설치·lockfile 변경은 없다.

완료는 코드 병합만으로 판정하지 않는다. 9지표의 실제 발급 경로, SF/NF 실제 기준 등록, 전달표 기대값의 API/HTML/PDF/CSV/XLSX 대조, 과거 산출물·백업 보존을 각각 확인한다. 운영 참여쌍 미확정 자료가 있으면 누락 사유/건수를 남기며 전체 누적 전환 완료로 과장하지 않는다. 사용 허가·측정 동등성·실제 공급자·현장 실측은 별도 후속이다.
