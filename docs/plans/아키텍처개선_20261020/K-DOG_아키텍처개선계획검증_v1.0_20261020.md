## 4 실행하지 않은 작업

- 제품 source·DB·설정·의존성·잠금 파일 변경, 제품 시험/프런트 build 실행.
- 고객 원본 파일 접근·해시 재대조, 실제 공급자 호출·운영 데이터 처리.
- 제품 AC01~AC05 구현 PR, ZIP 발행·배포·현장 인수. 계획 문서 자체의 commit·push·PR·병합은 후속 사용자 요청 범위에 포함한다.

보고서 자체의 SHA-256과 현재 저장소 경로·commit은 확인했다. 고객 원본에 의존하는 산식 변경이 없으므로 로컬 원본 검증을 제품 시험 통과로 기록하지 않았다. 계획의 미래 명령은 구현 시점의 공식 버전 확인과 실제 실행 결과를 각 PR에서 채운다.

## 5 후속 subagent cold review와 판단

사용자의 `subagents cold review > 수용 건만 반영 > 병합(로컬, 원격 모두)` 지시에 따라 프런트, 백엔드, 인수·문서 정합성을 세 독립 reviewer가 검토했다. 제안 총 3건 중 **수용 2건·거절 1건·보류 0건**이다. 제품 구현은 변경하지 않았다.

| ID / 심각도 | 발견 및 근거 | 결정·반영 |
| --- | --- | --- |
| CR01 / P2 | `RecordingPanelV4.tsx:98–99,116–117`은 같은 CSV 요청 중 일반 편집 시 재선택 오류와 busy 종료를 수행한다. AC-T04가 이를 요청 무효화와 함께 무반영으로 기술함 | 수용. AC01의 AC-T04를 일반 편집과 요청 번호 무효화로 분리하고 입력/기존 summary 보존, 오류 표시, busy 종료를 명시 |
| CR02 / P2 | `PreprocessingPanelV4.tsx:70–87`의 공유 준비 상태 조회 403/404와 지정 상세 성공 조합은 상세를 보존한다. 공통 접근 상실 규칙이 이 부분 결과를 지울 수 있음 | 수용. AC02의 adapter 책임·전이 표·AC-T10에 전체 접근 상실 판정과 부분 실패 보존을 구분하고 연결 실패·실행 차단·오류 안내를 명시 |
| CR03 / P3 | `attachment_runs_v4.py:247–251`은 access 확인을 점유 확인보다 먼저 수행한다. 공통 쓰기 적용 시 두 실패가 동시에 발생하면 내부 예외 우선순위가 달라질 수 있음 | 거절. 유일 실행 경로인 Worker.process→Worker.once에서 HTTPException의 status/detail을 외부로 반환하지 않아 공개 응답·DB 결과 차이가 확인되지 않았다. 내부 순서만 보존하는 `access_first` 옵션의 인터페이스 비용을 정당화하지 못하므로 AC03/AC04 인터페이스는 유지 |

인수·문서 reviewer는 요구사항 추적, 선행 관계, 명령, 공유 접근 정책과 미실행 상태 표기에 actionable 지적이 없었다. 수용 두 건만 AC01/AC02 기대값에 반영하며, 전체 계획의 상태와 본 기록은 이번 검토·문서 통합 범위에 맞춰 갱신한다.

프런트 reviewer의 수정 후 재검토에서 CR01/CR02 해결을 확인했다. 검증 기록의 전처리 파일명 오타도 정정했다. 수정 후 8개 문서의 상대 링크 79개(기존 tracked 대상 참조 59개·신규 계획 참조 20개), 코드 줄 참조 28개, 요구사항 12개, 시험 ID 22개를 다시 검사해 오류 0건을 확인했다. 제품 시험·build는 문서 변경 범위여서 실행하지 않았다.
