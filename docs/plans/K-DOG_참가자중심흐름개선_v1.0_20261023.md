# K-DOG 참가자 중심 자료 준비 흐름 개선

버전: v1.0 · 2026-10-23 · S1.1 · 로컬 실행본 반영

## 사용자 결정과 범위

2026-10-23 사용자가 참가자 목록에서 설문 확인·영상 등록·촬영 기록을 열고, 별도의 분석 영역에서 대상별 준비 상태를 확인하는 흐름에 동의했다. 설문 화면의 상단 「자세히」 제거, 중복 안내 축소, 안내 문구와 일괄 등록 이동 버튼 정렬, 수정 → 검증 → cold review → 로컬 재배포를 요청했다.

이전 같은 세션에서 승인한 개발 설정의 미구현 인증 상태 버튼 제거, 「자료 상태 별 조회」, 「참가자 및 설문 일괄 등록」, 「설문 확인」 명칭도 유지한다. 접수·일괄 등록은 등록 방법의 선택지이며 설문 확인을 영상 등록의 필수 관문으로 만들지 않는다.

근거: [현행 개발 안내](../DEVELOPMENT.md), [S1 개발 계획](../archive/개발반영_20261003/K-DOG_개발반영계획_v1.0_20261003.md), [인수 대장](../archive/개발반영_20261003/K-DOG_인수검증대장_v1.0_20261003.md). 관련 범위는 S02 설문, S03 수신·대상 연결, S04 촬영 기록, S05 전처리의 UI 진입이다. 특히 O04의 참가자 등록 전 영상 도착 경로를 보존한다.

## 구현

- 접수 목록의 참가자별 설문 확인·영상 등록·촬영 기록 버튼은 최신 참가자를 조회한 뒤 선택 대상과 촬영 회차를 유지하며 이동한다. 실패하거나 사용자가 다른 메뉴로 이동하면 늦은 조회가 화면을 덮어쓰지 않는다.
- 설문 확인은 수치 응답, 해당 없음, 빈칸 사유 기록, 사유 미기록을 구분한다. 상단 인원은 현재 검색 결과 중 28개 수치 응답이 있는 참가자 수다. 등록 완료·분석 자격을 새로 판정하지 않는다. 정상 응답 0은 수치 응답에 포함한다.
- 상단 「자세히」와 반복 안내를 제거했다. 등록·보완 안내와 이동 버튼은 전용 flex 배치로 수직 중앙 정렬하고 좁은 화면에서는 줄바꿈한다.
- 「열기」는 「응답 보기」, 상세 「닫기」는 「참가자 목록으로」로 바꿨다. 원응답을 먼저 펼치고 계산·비교 정보를 아래에 둔다. 상세에도 같은 참가자의 영상·촬영 기록 바로가기가 있다.
- 영상 업로드 메뉴 직접 진입은 참가자 선택부터 시작한다. 참가자별 화면은 해당 회차의 수신 파일만 표시한다. 참가자 등록 전에 도착한 자료는 명시적으로 「공용 업로드 보관함 열기」를 선택해 기존 방식으로 수신·연결할 수 있다.
- 전처리 화면에 전체 대상의 서버 준비 상태와 자료 보완 버튼을 표시한다. 조회는 동시에 최대 4건이며 입력 판본 변경·조회 실패·실행 실패·중단·이전 입력 결과를 구분한다. 현재 전처리 결과가 있는 대상은 분석·채점으로 이동한다. 목록 조회는 전처리나 AI 실행을 요청하지 않는다.
- 서버의 `ready`는 촬영 기록 조건이며 파일 무결성 검증 완료의 의미로 확대하지 않는다. 실제 전처리 실행의 원본 hash·입력 판본·점유·명시 요청 검증은 기존 경로를 사용한다.

## 검증과 cold review

합성 데이터 전용 브라우저 서버(8765)에서 검증한다. 운영 참가자·원영상·API 키를 테스트 fixture로 사용하지 않는다. backend 채점·설문 정책·저장 API는 변경하지 않는다.

구현 후 별도 검토 패스에서 변경 파일과 호출 관계, 비동기 대상 전환, 업로드 회차 고정, 미저장 입력, 서버 준비 상태의 의미, 원응답 0/빈칸 구분을 다시 검토했다.

| 발견 사항 | 처리 |
| --- | --- |
| 준비 상태와 실행 이력에 동일 참가자가 나타나 기존 테스트가 두 행을 선택 | 실행 이력 테스트 범위를 해당 영역으로 한정 |
| 영상 셀에 작업 버튼을 추가해 전체 accessible name이 달라짐 | 기존 영상 수 검증을 해당 셀의 내용으로 유지 |
| 대상 조회 전에 선택 목록을 닫으면 실패 시 이전 참가자 화면으로 돌아갈 수 있음 | 조회 성공을 반환하고 성공한 경우에만 선택 목록 닫기. 실패·늦은 응답 회귀 추가 |
| 접수 바로가기에서 조회 실패 전에 미저장 입력 표시를 지우면 다음 이동이 보호되지 않을 수 있음 | 성공한 대상 전환 때만 편집 표시 해제. 실패 후 입력과 이동 경고 유지 회귀 추가 |
| 촬영 기록 조건은 충족하지만 직전 전처리가 실패·중단된 상태 | 실패·중단을 별도로 우선 표시 |
| 검색 결과와 상단 설문 응답 인원 분모가 달라 혼동 가능 | 현재 검색 대상 기준으로 집계 |
| 참가자별 업로드에서 다른 참가자의 파일·변환 부모가 보임 | 선택 참가자·회차로 목록과 부모 선택지 제한. 공용 경로 유지 |
| 원응답이 없는 초기 문항에서 사유 미상 안내 누락 가능 | null과 미등록 문항 모두 명시적으로 빈칸 사유 표시 |

### 최종 실행 결과

- `frontend/`에서 `npm run build`: 통과. 기존 단일 JS 번들의 500 kB 초과 안내만 남는다. 의존성이나 번들 분할은 이번 범위에서 변경하지 않았다.
- `npm run test:e2e`: 171건 중 170건 통과(11.4분). 실패 1건은 영상 셀에 바로가기 버튼을 추가하면서 바뀐 accessible name을 기존 테스트가 완전 일치로 찾은 경우다. 해당 셀의 영상 수 내용 검증으로 수정했다.
- 최종 빌드 후 `npm run test:e2e -- tests/participant-workflow.spec.ts tests/analysis-progress-v4.spec.ts`: 10건 모두 통과(23.9초). 위 실패 항목과 새 참가자 흐름 6건을 포함한다. 추가한 미저장 입력 테스트는 초기 목록 조회가 끝나기 전에 등록 폼을 열던 대기를 보완한 뒤 통과했다. 전체 172개 고유 테스트를 전체 실행과 후속 재검증에 걸쳐 확인했으며, 한 번의 172건 일괄 통과로 기록하지 않는다.
- 데스크톱 설문 목록과 분석 대상 목록, 390px 설문 목록·업로드 참가자 선택 화면을 캡처해 확인했다. 안내문·이동 버튼의 수직 중심 차이 2px 미만, 상단 「자세히」 부재, 원응답 우선 표시, 모바일 가로 넘침 없음도 자동 검증했다. 360·390·768·1440px 기존 배치 회귀는 전체 실행에서 통과했다.
- `git diff --check`: 통과. `graft build`로 코드 그래프를 갱신했다.

## 배포와 한계

배포 대상은 현재 PC의 `http://127.0.0.1:8000` 로컬 실행본이다. frontend 생산 빌드를 서버가 제공하는 `frontend/dist`에 반영한다. 외부 호스팅 게시·고객 발송·배포 ZIP 발행은 이번 요청에 포함하지 않는다. 실제 공급자 품질·물리 3PC·원본 영상 분석 인수는 이 UI 검증으로 완료 처리하지 않는다.

최종 빌드 반영 후 `/api/health`와 `/`의 HTTP 200을 확인했다. 서버가 제공한 HTML은 로컬 `dist/index.html`과 바이트 단위로 일치한다. JS·CSS도 내려받아 빌드 파일과 전체 바이트 및 SHA-256 일치를 확인했다.
