## 범위와 완료 조건

사용자 후속 요청에 따라 항목군에 필요한 관찰창의 영상만 제공하고, 같은 run에서 같은 실제 파일의 원격 업로드를 재사용한다. 구현 → 검증 → 두 subagent의 독립 cold review → 문서 갱신 → 병합 순서를 따른다. 같은 자료의 전체 분석과 리포트 발급을 N=4로 한 번 확인한다. N=4는 관찰 항목군 네 개의 동시 처리이며 전체 분석 네 번을 의미하지 않는다.

PA06의 별도 실측 DB와 누적 $50 원장을 유지한다. 기존 추정 사용액 $3.775935를 초기화하지 않는다. 생성 요청 직전 최대 토큰 비용을 먼저 예약하고 다음 예약으로 상한에 닿거나 넘으면 중지한다. 청구서 확인과 요율 추정은 구별한다. 운영 기본값 1, 모델·프롬프트·원본/FPS·해상도·사고 수준·관찰/채점 규칙은 유지한다. 독립 사람 정답, P50/P95, 일반 처리시간 보장이나 운영 기본값 상향 승인을 주장하지 않는다.

## 구현

- `preprocess_v4`는 여러 논리 창을 하나의 큰 클립으로 합치던 경로를 창별 절단으로 바꾼다. 같은 카메라에서 시작·끝이 완전히 같은 창만 물리 파일을 공유한다. 한 창 안의 여러 이벤트는 첫 시작부터 마지막 끝까지 맥락을 보존한다. 이벤트 사이 공백은 원래 `source_intervals` 교집합과 근거 검증에서 관찰량으로 세지 않는다.
- `CUT_SETTINGS=s1-cut-4-window-end`를 batch compatibility에 고정한다. 새 분석에는 새 전처리가 필요하다. 기존 batch·run·발급 결과의 고정 읽기와 같은 request ID 재조회는 유지한다.
- 파생 파일의 실제 재생 PTS와 원본 프레임 쌍으로 시각 변환을 확인한다. 원본형과 AI형은 각각의 파일 시계를 사용한다. 기존 cut 시작 anchor와 모든 프레임이 2ms 이내로 맞으면 인코더 tick 정밀도만 정리하고, 실제 큰 원점 변화는 보존한다. FFmpeg의 AI 선택에는 입력 원점 정규화 시계를 사용하며 ffprobe의 마이크로초 정밀도로 정수 초 경계의 부동소수점 오차를 제거한다. 프레임을 복제하거나 빈 구간을 관찰로 채우지 않는다. 창 경계가 달라지므로 실제 샘플 프레임과 생성형 응답이 전과 동일하다고 보장하지 않는다.
- 원본형과 AI 파일은 B-frame 재정렬을 끄고 [setts](https://ffmpeg.org/ffmpeg-bitstream-filters.html#setts)에서 PTS/DTS를 명시적으로 보존한다. 원본형을 실제 파일로 만든 뒤 mux 원점을 측정하여 요청한 cut 끝으로 마지막 실제 packet의 표시기간을 맞추고, AI는 그 시계와 끝을 유지한다. 유음과 무음 MP4의 원점 차이를 추정하지 않는다. 짧은 파일의 마지막 프레임 직후 영상이 종료되어 기존 전체 관찰이 강제 결측으로 바뀌는 회귀와 창 밖 초과 표시를 막는다. 실제 파일·브라우저의 재생 시각/길이, 프레임 수·원본 시각, 전체 관찰 gate와 evidence 범위를 검증한다. metadata에 가짜 길이를 쓰거나 프레임을 복제하지 않는다.
- `UploadPool`이 run·파일 SHA-256·credential reference로 원격 파일 소유를 관리한다. 동시 owner 한 개가 업로드하고 다른 요청은 기다린다. 다른 run·키·내용에는 재사용하지 않는다. 실제 원본/파생 hash와 요청 계정·점유 검증을 유지한다.
- 정상 retry wait에서는 파일을 유지하고 새 claim에서는 원격 상태를 재검증한다. 404는 재업로드하며 재사용으로 계량하지 않는다. 알려진 파일은 정확한 원래 키로 정리하고, 응답 유실로 이름을 모르는 파일이나 사용할 수 없는 과거 키는 정리 대기로 남긴다. 모든 소비자가 수습된 뒤 종료/중지/재시작/정상 Worker 종료에서 정리한다. 정리 metadata는 DB usage에 반영하되 불변 시도 파일을 다시 쓰지 않는다.

API의 static 전용 start/end clipping 옵션을 agentic 요청에 혼용하지 않고 실제 파일을 절단한다. 항목군이 요구하는 창 1~2개와 지원 카메라 최대 4개로 요청의 영상 수는 최대 8개다. [Interactions API](https://ai.google.dev/api/interactions-api.md), [영상 이해](https://ai.google.dev/gemini-api/docs/video-understanding), [Files API](https://ai.google.dev/gemini-api/docs/files?hl=en), [영상 수 제한](https://firebase.google.com/docs/ai-logic/analyze-video)을 2026-10-24 확인했다. Interactions는 v1beta 계약을 유지한다.

## 검증과 검토

실제 공급자 호출 전 관련 core 48개, 통합 발급/복원 1개, 공유 업로드 최종 12개를 확인했다. CUT4의 전처리·진행조회·관찰·공유 회귀 79개는 90.020초에 통과했다. 독립 검토자는 유음/무음·저FPS/분수 초 끝의 최종 4개를 9.592초에 통과했고 Chromium의 원본/AI 재생 시각·길이와 끝 10ms 앞 탐색도 대조했다. 앞선 후보 `a08b5ac`의 browser 23개·배포 검증은 통과했으나 실제 사전 gate에서 카메라 한 대의 근거 끝이 22.937ms 짧은 것을 발견하여 유료 호출 없이 보류했다. 최종 제품 `fb50a10`의 전체 backend 928개는 925개 통과·3개 명시 skip으로 1935.787초에 완료했다. skip은 역사 원본 미확보 2개와 실제 macOS Keychain 1개다. 관련 browser 23개는 2.9분에 통과했고 S1 원본 자산 8개와 frontend build도 통과했다. 잘못된 1-byte 업로드 fixture를 실제 크기로 고치고 공급자 오류 사유까지 확인한 회귀도 통과했다. G01/G04 계산 양식 미수령 및 기존 현장 인수 대기는 유지한다.

독립 subagent 두 명이 원격 소유/오류/계량과 관찰창/프레임/채점 경계를 나눠 읽기 전용으로 검토했다. P1 세 건과 P2 다섯 건을 수용하고 재현 회귀·재검토로 해소했다. 실제 키·참가자·실측 DB는 reviewer가 열지 않았다. 외부 실행기의 공통 예산/OS 잠금/한 번 실행/기존 결과 보존/Worker 종료 정리와 새 준비시간 계량도 검토했다. 정확히 $50에 닿는 다음 예약도 차단하며, 불명 계량은 0과 구분하고 최대 비용 예약을 유지한다. 합성 예산 경계·null 계량 검증은 실제 공급자 호출 없이 통과했다.

## 버전과 실행 경계

2026-10-24 확인: 최신 Python [3.15.1](https://www.python.org/downloads/release/python-3151/) 대신 프로젝트 `>=3.14,<3.15`와 기존 배포 pin 3.14.8을 유지한다. 최신 [Pydantic 2.14.1](https://pypi.org/project/pydantic/) 대신 기존 pin 2.13.5를 유지하며 기존 모델 API를 사용한다. [FFmpeg 공식 안정판](https://ffmpeg.org/download.html)은 기존 배포와 같은 9.0.2다. Python 표준 threading을 사용하고 의존성/lockfile/DB schema 변경은 없다. frontend의 최신/선택 버전·호환성 확인은 같은 날짜의 [PA04/PA05 실행 기록](K-DOG_AI병렬화_검증실행대장_v1.0_20261024.md)을 따른다.

실제 자료의 CAM3는 변하는 동기화 차이 때문에 원본만 보존하고 판정을 보류한다. CAM1/2/4, 입력 revision 7, 원래 결측 설문·음성·국면·이벤트를 유지한다. 새 batch와 새 OPT 출력만 만들고 기존 SYNC 리포트·원본을 보존한다. 한 번씩의 전후 기능 벽시계는 기록할 수 있으나 정식 동기화 카메라 benchmark 채택이나 반복 성능 비교로 확대하지 않는다.

## 실제 1회 실행·발급 결과

최종 배포 후보 `fb50a106afb055353e555392d1600362b06f3a03`의 ZIP은 75,299,693 bytes, SHA-256 `fd4e6d85f50d8480ba378c9096bf263d77b3f17240121701431f0e92288fa3a1`이다. 내장 Python/FFmpeg만 쓰는 현재 Windows 설치·무결성/변조 거절·한글/공백 경로·로그인/업무/재시작·supervisor·발급 봉인/복원·계정/개발자 경계·재설치 보존 검증을 통과했다. 다른 PC/새 OS 인수로 확대하지 않는다.

사전 gate는 논리 관찰창 31개, 완료 물리 클립 33개, 43개 항목군의 카메라별 근거 범위·관찰량 유지와 새 강제 결측 없음, 원본 11개·보존 raw 영상 4개·기존 전달본 3종 hash를 확인했다. 후보별 준비 검증은 보존하며 유료 전체 분석은 최종 CUT4에서 한 번만 실행했다.

위 합산은 같은 자료의 전처리와 분석→PDF 시간을 더한 값이며 최초 등록/복사까지 잰 전체 이용시간은 아니다. 새 전처리는 파일 수 증가로 길어졌다. 긴 공급자 응답도 관측되어 일반 사용자 SLA나 P50/P95로 삼지 않는다. 관찰/검증 규칙을 완화하지 않고 점수 응답 2건·서술 1건을 거절 후 모두 두 번째 응답으로 수습했다. 최신 51개 분기가 성공했고 전체 분석과 리포트 발급은 각각 한 번이다. 프레임 경계와 비결정적 생성 응답에 따른 결과 차이는 독립 사람 정확도 입증과 구분한다.

업로드 cache는 파일 사용 84회 중 51회를 재사용했고 원격 고유 업로드는 33개였다. 원격 정리 대기 0, 원본 11개·raw 복사 4개·기존 리포트 3종 hash 유지, 새 HTML/PDF/manifest의 앱/전달 hash 일치를 확인했다. PDF 6페이지를 모두 PNG로 렌더링해 직접 확인했고 HTML은 오프라인 1440/390px의 가로 넘침·대체 문자·외부 요청이 0이었다. 기존 문구 중복과 390px의 두 자리 행동 번호 세로 줄바꿈은 본문을 가리지 않는 표현상 한계로 남는다.

중지된 최초 N1까지 포함한 누적 생성은 74회, 요율 추정 $4.79184225로 $50 미만이며 청구서는 미확인이다. 실제 키는 주키 31회였고 예비키 실전 전환을 입증하지 않는다. 운영 DB의 예약 호출 69·활성 run 0은 전후 같았으며 별도 실측 DB도 공식 설정으로 N1에 복귀했다. [비식별 실행 요약](evidence/PA07-functional-summary-20261024.json), [PR #157](https://github.com/syleeVeluga/k-dog-proj/pull/157)에 연결한다.

최종 문서 4개와 비식별 JSON을 두 독립 subagent가 재검토했다. 현재 설계 절의 과거 캐시 제외 문구와 PA07 구현이 충돌한 문서 P2 1건을 수용하여 초기/후속 설계를 구분했고 재검토로 해소했다. 제품 발견 3P1/5P2와 별도 문서 발견이다. 최종 미해결 P1/P2·병합 blocker 없음, Git index 상대 링크 41개·개인정보/키/비공개 경로·대체 문자·공백·JSON 검사를 통과했다.
