## 범위와 완료 조건

사용자 후속 요청에 따라 항목군에 필요한 관찰창의 영상만 제공하고, 같은 run에서 같은 실제 파일의 원격 업로드를 재사용한다. 구현 → 검증 → 두 subagent의 독립 cold review → 문서 갱신 → 병합 순서를 따른다. 같은 자료의 전체 분석과 리포트 발급을 N=4로 한 번 확인한다. N=4는 관찰 항목군 네 개의 동시 처리이며 전체 분석 네 번을 의미하지 않는다.

PA06의 별도 실측 DB와 누적 $50 원장을 유지한다. 기존 추정 사용액 $3.775935를 초기화하지 않는다. 생성 요청 직전 최대 토큰 비용을 먼저 예약하고 다음 예약으로 상한을 넘으면 중지한다. 청구서 확인과 요율 추정은 구별한다. 운영 기본값 1, 모델·프롬프트·원본/FPS·해상도·사고 수준·관찰/채점 규칙은 유지한다. 독립 사람 정답, P50/P95, 일반 처리시간 보장이나 운영 기본값 상향 승인을 주장하지 않는다.

## 구현

- `preprocess_v4`는 여러 논리 창을 하나의 큰 클립으로 합치던 경로를 창별 절단으로 바꾼다. 같은 카메라에서 시작·끝이 완전히 같은 창만 물리 파일을 공유한다. 한 창 안의 여러 이벤트는 첫 시작부터 마지막 끝까지 맥락을 보존한다. 이벤트 사이 공백은 원래 `source_intervals` 교집합과 근거 검증에서 관찰량으로 세지 않는다.
- `CUT_SETTINGS=s1-cut-4-window-end`를 batch compatibility에 고정한다. 새 분석에는 새 전처리가 필요하다. 기존 batch·run·발급 결과의 고정 읽기와 같은 request ID 재조회는 유지한다.
- 파생 파일의 실제 재생 PTS와 원본 프레임 쌍으로 시각 변환을 확인한다. 원본형과 AI형은 각각의 파일 시계를 사용한다. 기존 cut 시작 anchor와 모든 프레임이 2ms 이내로 맞으면 인코더 tick 정밀도만 정리하고, 실제 큰 원점 변화는 보존한다. FFmpeg의 AI 선택에는 입력 원점 정규화 시계를 사용하며 ffprobe의 마이크로초 정밀도로 정수 초 경계의 부동소수점 오차를 제거한다. 프레임을 복제하거나 빈 구간을 관찰로 채우지 않는다. 창 경계가 달라지므로 실제 샘플 프레임과 생성형 응답이 전과 동일하다고 보장하지 않는다.
- 원본형과 AI 파일은 B-frame 재정렬을 끄고 [setts](https://ffmpeg.org/ffmpeg-bitstream-filters.html#setts)에서 PTS/DTS를 명시적으로 보존한다. 원본형을 실제 파일로 만든 뒤 mux 원점을 측정하여 요청한 cut 끝으로 마지막 실제 packet의 표시기간을 맞추고, AI는 그 시계와 끝을 유지한다. 유음과 무음 MP4의 원점 차이를 추정하지 않는다. 짧은 파일의 마지막 프레임 직후 영상이 종료되어 기존 전체 관찰이 강제 결측으로 바뀌는 회귀와 창 밖 초과 표시를 막는다. 실제 파일·브라우저의 재생 시각/길이, 프레임 수·원본 시각, 전체 관찰 gate와 evidence 범위를 검증한다. metadata에 가짜 길이를 쓰거나 프레임을 복제하지 않는다.
- `UploadPool`이 run·파일 SHA-256·credential reference로 원격 파일 소유를 관리한다. 동시 owner 한 개가 업로드하고 다른 요청은 기다린다. 다른 run·키·내용에는 재사용하지 않는다. 실제 원본/파생 hash와 요청 계정·점유 검증을 유지한다.
- 정상 retry wait에서는 파일을 유지하고 새 claim에서는 원격 상태를 재검증한다. 404는 재업로드하며 재사용으로 계량하지 않는다. 알려진 파일은 정확한 원래 키로 정리하고, 응답 유실로 이름을 모르는 파일이나 사용할 수 없는 과거 키는 정리 대기로 남긴다. 모든 소비자가 수습된 뒤 종료/중지/재시작/정상 Worker 종료에서 정리한다. 정리 metadata는 DB usage에 반영하되 불변 시도 파일을 다시 쓰지 않는다.

API의 static 전용 start/end clipping 옵션을 agentic 요청에 혼용하지 않고 실제 파일을 절단한다. 항목군이 요구하는 창 1~2개와 지원 카메라 최대 4개로 요청의 영상 수는 최대 8개다. [Interactions API](https://ai.google.dev/api/interactions-api.md), [영상 이해](https://ai.google.dev/gemini-api/docs/video-understanding), [Files API](https://ai.google.dev/gemini-api/docs/files?hl=en), [영상 수 제한](https://firebase.google.com/docs/ai-logic/analyze-video)을 2026-10-24 확인했다. Interactions는 v1beta 계약을 유지한다.

## 검증과 검토

실제 공급자 호출 전 관련 core 48개, 통합 발급/복원 1개, 공유 업로드 최종 12개를 확인했다. CUT4의 전처리·진행조회·관찰·공유 회귀 79개는 90.020초에 통과했다. 독립 검토자는 유음/무음·저FPS/분수 초 끝의 최종 4개를 9.592초에 통과했고 Chromium의 원본/AI 재생 시각·길이와 끝 10ms 앞 탐색도 대조했다. 앞선 후보 `a08b5ac`의 browser 23개·배포 검증은 통과했으나 실제 사전 gate에서 카메라 한 대의 근거 끝이 22.937ms 짧은 것을 발견하여 유료 호출 없이 보류했다. 최종 전체/backend·browser·배포 검증과 실제 발급은 진행 중이다. S1 원본 자산 8개와 frontend build는 통과했다. G01/G04 계산 양식 미수령 및 기존 현장 인수 대기는 유지한다.

독립 subagent 두 명이 원격 소유/오류/계량과 관찰창/프레임/채점 경계를 나눠 읽기 전용으로 검토했다. P1 세 건과 P2 다섯 건을 수용하고 재현 회귀·재검토로 해소했다. 실제 키·참가자·실측 DB는 reviewer가 열지 않았다. 외부 실행기의 공통 예산/OS 잠금/한 번 실행/기존 결과 보존/Worker 종료 정리와 새 준비시간 계량도 검토했다. 정확히 $50에 닿는 다음 예약도 차단하며, 불명 계량은 0과 구분하고 최대 비용 예약을 유지한다. 합성 예산 경계·null 계량 검증은 실제 공급자 호출 없이 통과했다.

## 버전과 실행 경계
