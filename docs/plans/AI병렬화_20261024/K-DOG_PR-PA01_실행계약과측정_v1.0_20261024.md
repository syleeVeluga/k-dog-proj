# K-DOG PR-PA01 실행 계약과 측정

버전: v1.0 · 2026-10-24 · 상태: 구현·검증·독립 cold review 완료, 병합 준비 · 선행: 없음

상위: [병렬화 계획](K-DOG_AI병렬화계획_v1.0_20261024.md) · 다음: [PA02](K-DOG_PR-PA02_호출예약과공유제한_v1.0_20261024.md) · 추적: AP01

## 목표

동시성 설정을 변경해도 이전 실행의 재현·검증이 깨지지 않고, 직렬과 병렬의 실제 벽시계를 비교할 수 있게 한다. 이 PR은 실행 순서를 바꾸지 않는다.

## 구현 범위

- `backend/app/domain/runs_v4.py`, `backend/app/settings_v4.py`, `backend/app/run_v4.py`의 설정 생성·읽기·hash·재사용 호출 관계를 Graft로 확인한다. 후보 필드 `max_parallel_score_groups`는 1~4의 정수로 검증하고 신규 기본값은 1로 둔다. PA03 전에는 2~4 요청을 명시적으로 미지원 처리한다.
- 기존 실행 snapshot에 필드가 없으면 직렬 의미로 읽는다. 저장 JSON/hash를 수정하거나 새 기본 필드를 주입한 직렬화를 과거 hash 대조에 사용하지 않는다. 새 설정의 판본/직렬화 규칙과 기존 읽기 규칙을 구분하여 구체화한다.
- `settings_hash`, `config_hash`, `active_settings_version`, 명시 reuse manifest 간 관계를 점검한다. 병렬 수만 다르더라도 현재 전체 설정 hash 기반 재사용 검증은 유지한다. 기존 점수/시도 재작성은 없다.
- 계량은 배정 대기·작업 시작/종료·요청 구간·후속 단계·전체 벽시계를 구분한다. 같은 프로세스의 경과시간은 monotonic clock, 영속 감사 시각은 UTC를 사용한다. 재시작 전후 monotonic 값을 직접 차감하지 않는다.
- `scripts/benchmark_s1.py`의 실행 모드, 설정 hash, 실제 동시성 증거 필드를 설계한다. 병렬 미지원 거절은 PA03 구현까지 유지하고 기록 없는 과거 run을 병렬로 추정하지 않는다.
- 기존 실측 계약은 필수 세 조건과 카메라 1/3개를 전제로 하며 반복 키에 동시성 N이 없다(`Condition/Trial/BenchmarkManifest.complete/summarize`). 따라서 병렬화 비교에는 별도 명시 판본/모드를 마련한다. 실제 채택한 카메라 ID·개수·파일 크기를 기록하여 4카메라 자료도 수용하고, 기존 S16 필수 조건을 충족했다고 오인하지 않는다. 기존 1/3카메라·용량 판정과 이전 manifest 읽기/검증은 보존한다.
- 새 비교 키는 대상/회차·고정 입력/전처리·반복 번호·동시성 N·cold/reuse를 구분한다. 같은 반복 번호의 N=1과 N=4는 서로 다른 trial로 허용하되 같은 run_id의 중복 집계는 계속 거절한다. 모델·프롬프트·FPS 등 N 이외 조건 일치는 별도 비교 검증으로 확인하며 전체 설정 hash 검증을 완화하지 않는다.

## 검증과 합격 기준

1. 필드 누락 이전 fixture의 저장 bytes/hash·재사용 판정·보고서 읽기가 변하지 않는다.
2. 신규 1~4, 경계 밖 0/5, null, bool, 소수, 문자열에 대해 명시 계약대로 수용/거절한다. 개발자 설정 권한을 우회할 경로가 없어야 한다.
3. 실행 중 설정 변경은 이미 고정된 run에 영향을 주지 않는다. 신규 run에만 새 판본이 반영된다.
4. 겹친 두 작업의 시간 합과 전체 벽시계가 다른 fixture로 계량 중복 합산을 검출한다. 중단·재시작·reuse 시점도 구별한다.
5. 기존 설정·실행·report replay 관련 unittest를 통과하고 미구현 병렬 표기를 거절한다.
6. 실제 카메라 4개인 새 판본 fixture가 실측 후보로 인정되고, 기존 S16 세 조건의 미측정 상태는 변하지 않는다. 동일 반복 번호의 N=1/2/3/4는 각각 보존하며 run 중복·다른 입력/모델이 섞인 비교를 거절한다.

## 리뷰와 인계

설정 호환성을 이유로 새 S1 결과의 검증을 느슨하게 하지 않았는지 검토한다. 추가 DB 열이 필요하면 additive 변경과 구버전 읽기/복원 영향을 적고, 단순 usage JSON 확장으로 충분하면 새 테이블을 만들지 않는다. 실제 변경 파일·명령·결과·PR/commit·버전 확인을 실행 대장에 기록한다. 완료 전 체크 항목은 모두 미완료로 둔다.

## 2026-10-24 구현 기록

- 기준 `0335f60`, 브랜치 `veluga/pa01-execution-contracts`. AP01 설정 계약과 실측 준비를 구현했다. 신규 `max_parallel_score_groups`는 strict 정수 1~4이며 기본 1, PA03 전 저장/실행의 2~4 요청은 422다.
- 과거 pipeline은 필드 부재를 직렬화에서도 보존한다. 과거 run 판본은 기존 config 직렬화를 유지하고 새 설정은 `ai-scoring-20261024-pa01`을 사용한다. 저장 원본 bytes/hash와 전체 config 기반 reuse 검증은 유지한다. DB 열·패키지 추가는 없다.
- attempt별 `usage.execution_interval`은 회차 고유 clock ID, monotonic 시작/종료·배정대기, UTC 감사시각, reuse 여부를 기록한다. 실패·중지의 늦은 완료에도 해당 attempt 계량만 병합하며 lifecycle/출력은 채택하지 않는다. 회차가 다른 monotonic 값은 합치지 않는다. 공급자 세부 구간은 기존 timing과 구별한다.
- `benchmark-20261024-pa01`은 `parallel_score_groups` 한 조건과 N별 반복 키를 사용한다. `--template <외부경로> --parallel`로 준비한다. 카메라 수/ID/파일 크기와 N을 기록하고 입력·전처리·모델 등 N 외 비교 hash 불일치를 거절한다. 기존 S16 세 조건을 충족한 것으로 표시하지 않는다. 병렬 실행 증거 채택은 PA03까지 거절한다. 부분 실패는 실패 원장에 남기며 속도 통계에서 제외한다.
- 독립 subagent 2명이 계약/계량과 실측 도구를 분리 검토했다. 실패 예외의 계량 누락과 부분 실패의 성공 속도 집계를 수용 수정했고 재검토에서 추가 결함이 없었다. 정확한 검증/PR는 [실행 대장](K-DOG_AI병렬화_검증실행대장_v1.0_20261024.md)에 기록한다.
