# K-DOG PR-PA04 운영 설정과 진행 표시

버전: v1.0 · 2026-10-24 · 상태: 미착수 · 선행: PA03

상위: [병렬화 계획](K-DOG_AI병렬화계획_v1.0_20261024.md) · 이전: [PA03](K-DOG_PR-PA03_항목군병렬실행_v1.0_20261024.md) · 다음: [PA05](K-DOG_PR-PA05_장애복구와통합인수_v1.0_20261024.md) · 추적: AP07

## 목표

개발자는 새 설정 판본에서 동시 분석 수를 선택하고, 업무 사용자는 현재 진행·대기·중지를 정확히 확인한다. 설정 변경이 진행 중인 분석을 바꾸지 않도록 화면과 서버를 일치시킨다.

## 구현 범위

- 설정 API와 React의 개발자 설정·분석 실행·상세 진행 화면을 Graft로 찾고 호출 관계를 확인한다. 정확한 화면 파일은 착수 기록에 명시한다. 기존 화면 구조를 유지하며 별도 관리 대시보드를 만들지 않는다.
- 개발자 설정에 동시 분석 1~4를 제공하고 기본 1, 신규 실행부터 적용됨을 표시한다. 서버가 최종 권한·범위를 검증한다. 활성 업무 계정의 공통 실행/재시도 권한을 축소하지 않는다.
- 실행 상세에 완료/전체 항목군, 실제 진행 중 항목군, 재시도·공급자 제한 대기를 표시한다. 최종 번호 하나로 전체 진행률을 추측하거나 아직 시작하지 않은 항목을 실행 중으로 표시하지 않는다.
- program 결과·reuse·공급자 요청의 수를 혼동하지 않는다. 실제 적용 동시성은 run snapshot에서 읽고 현재 전역 설정으로 과거 run을 표시하지 않는다.
- 중지 시 미시작 작업과 실행 중 요청을 구별한다. 이미 보낸 요청을 즉시 중단했다고 표시하지 않는다. 잔여 수습/정리 상태는 사용자에게 필요한 수준으로 표시하고 내부 token·SQL·파일 경로는 노출하지 않는다.
- 중지 상태와 정리 완료는 별개로 표시한다. 중지 직후 재시도가 접수되면 이전 요청 정리가 끝날 때까지 대기함을 보여 준다. 서버/API도 이 경계를 지키며 화면 버튼 비활성화만으로 중복 실행을 막지 않는다.
- 예상 완료시간은 충분한 실측이 없는 동안 확정값으로 제공하지 않는다. 경과시간·진행 상태를 우선 제공한다. 신규 세션 생성이 속도 향상에 필요한 절차처럼 안내하지 않는다.
- 기존 예비키 등록·연결 확인 기능을 사용한다. 실행 상세는 주키/예비키 선택, 전환 사유, 예비키 재시도 대기, 예비키 사용 불가, 시도/호출 한도 소진을 구별한다. 전환 중 주키·예비키 요청이 공존할 수 있으므로 run의 다음 선택과 각 attempt의 실제 사용 키를 혼동하지 않는다. 비밀 키·파일 경로는 표시하지 않는다. [PA02 FB01~FB11](K-DOG_PR-PA02_호출예약과공유제한_v1.0_20261024.md#예비키-fallback-계약과-시험-행렬)의 상태를 API와 e2e에서 확인한다(AP09).

## 검증과 합격 기준

1. developer만 설정 변경 가능, 나머지 활성 업무 계정은 기존 공통 업무 가능. UI 숨김과 별개로 API 직접 요청을 검증한다.
2. 4개 동시 실행·역순 완료·retry_wait·영구 실패·정리 대기를 모의한 e2e에서 표시가 서버 상태와 같다.
3. 설정을 1→4로 바꾸어도 실행 중/과거 run 표시와 적용값은 변하지 않는다.
4. 중지·재시도·새로고침·다른 사례 이동 후 복귀에서 중복 실행이 생기지 않는다. 모바일에서도 버튼과 진행 목록을 사용할 수 있다.
5. `frontend/`에서 build와 관련 e2e, backend 설정/권한/API 시험을 통과한다. UI 변경 전후 PC·모바일 synthetic 스크린샷을 PR에 첨부한다.

실제 참가자 정보가 들어간 화면은 저장소에 넣지 않는다. 공통 권한 정책과 S1 source/판본 검증의 변화가 없음을 리뷰에 남긴다.
