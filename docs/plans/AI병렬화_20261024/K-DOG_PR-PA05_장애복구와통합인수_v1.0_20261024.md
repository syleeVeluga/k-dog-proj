## 구현과 검증 절차

- 앞선 PR의 단위 시험을 반복 복사하지 않고 프로세스 종료·진짜 DB 경합·전체 출력 연결의 빈틈을 보강한다. 실제 API 비용 없이 통제 가능한 synthetic transport/fixture를 사용한다.
- AP09는 [PA02 FB01~FB11](K-DOG_PR-PA02_호출예약과공유제한_v1.0_20261024.md#예비키-fallback-계약과-시험-행렬)을 필수 인수 행렬로 삼는다. 특히 주키 4개 요청의 성공/실패가 엇갈리는 중 예비키 전환, 예비키도 실패, 키 교체와 정리, 전환 후 재시작, 애착·report 경로를 통합 검증한다. mock은 키 값 대신 비식별 credential reference별 송신/정리 횟수를 확인한다.
- 강제 종료 시험은 임시 data directory와 자식 프로세스에서 실행한다. 운영 DB나 이미 발급한 실제 최종본을 장애 주입 대상으로 삼지 않는다.
- 전체 backend: `backend/`에서 `uv run --locked python -X utf8 -m unittest discover -s tests -v`.
- frontend: `frontend/`에서 `npm run build`, `npm run test:e2e`. PA04 이후 변경 영향에 맞는 전체 검증을 한 번 수행하고 새 실패/수정 없이는 반복하지 않는다.
- 실제 배포 방식으로 새 임시 설치에서 Worker 시작·중복 시작 거절·종료·재시작을 확인한다. DB 변경이 있다면 기존 snapshot 복원과 새 데이터 복원을 각각 검증한다.
- synthetic HTML/PDF를 렌더링해 페이지 전체를 확인한다. 병렬화를 이유로 무음·설문 결측·시각 미확정·정책 보류를 해제하지 않는다.

## 인수와 인계

치명적 출처 오류, 이중 호출, 예산 초과, 중지 후 채택, 다른 run 침범, 미수습 자식 작업이 있으면 배포 후보를 승인하지 않는다. 수정은 원인 PR 범위를 따라 기록하고 관련 시험을 다시 수행한다. 기존 대장 E03/E05/O11/O13의 기술 하위 사례와 연결하되 실제 품질·현장 수용성 완료로 확대하지 않는다.

완료 산출물은 commit/PR, 환경·명령·시험 수·실패와 재검증, 설치/복원 근거, 실제 공급자 미검증 항목 목록이다. 통과 후 PA06의 실측 후보를 고정한다.
