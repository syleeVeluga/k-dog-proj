# K-DOG 패치 릴리스 v0.3.2

버전: v0.3.2 · 2026-10-23 · 기준: `main / 36816cf` · S1.1

## 범위

v0.3.1(`cd139c6`) 이후 병합한 두 변경을 배포한다.

- [설치 계정 생성과 발행 키 유효 기간](K-DOG_설치계정과발행키기간_v1.0_20261023.md) (PR #126, [실행 기록](K-DOG_설치계정과발행키기간_실행기록_v1.0_20261023.md)): 발행 패키지는 개발자 계정만 담을 수 있고, 설치 중 이 PC의 첫 업무 계정을 만든다. `issue_release --expires`로 설치 가능한 마지막 날을 인증 헤더에 넣는다. 예약 이름(`builtin-reference`, `kdog-ai-service`)은 모든 계정 경로에서 거절한다.
- [최종 CSV 촬영 입력 개선](K-DOG_최종CSV촬영입력개선_v1.0_20261023.md) (PR #128): 구간 CSV 입력을 접힌 영역 밖에 두고, 퇴장 끝·걷기 6국면 없이도 8구간 기록을 확정할 수 있게 확정 조건을 맞췄다.

백엔드·프런트엔드와 두 lockfile의 앱 버전을 0.3.2로 맞춘다. 평가 산식·저장 스키마·의존성 버전은 변경하지 않는다. 이번 패치를 위해 S1 점수를 초기화하지 않는다. 자동 구간·자동 분석 계획(PR #127)은 보류 상태이며 포함하지 않는다.

Windows 포터블·Windows 사용자 설치형·macOS 사용자 설치형을 같은 깨끗한 커밋에서 새로 빌드한다. 고객 원본·참가자 자료·키·운영 DB는 포함하지 않는다. 기존 S1 사용자는 [업데이트 안내](../PILOT_OPERATIONS.md#업데이트와-이전-버전-정리)에 따라 종료·백업 후 새 폴더에 설치하고 같은 자료 경로를 쓴다.

## 계정과 키

- GitHub 릴리스 ZIP 3종에는 계정이 들어 있지 않다. 포터블은 `app.manage create-user`, 사용자 설치형은 `Install.cmd`/`Install.command`가 설치 중 계정을 묻는다.
- 고객별 발행 패키지는 별도이며 고객 ID와 개발자 계정 ID가 필요하다. 비밀번호는 발행 시 숨김 프롬프트로 입력한다. 설치 중 첫 업무 계정을 만든다.
- AI 공급자 키는 어느 패키지에도 넣지 않는다. 개발자가 설치한 PC에서 「개발 설정 → 공급자 키 관리」로 등록한다.

S1 원본 대조 명령은 로컬 전용 SRC02가 없어 실패했다. 원본 대조 통과로 표시하지 않는다. macOS 네이티브 키체인·실기기 설치, 깨끗한 OS·물리 PC 3대, 실제 공급자·영상·교수·현장 인수는 별도다. 운영 자료 등록이나 외부 AI 호출은 수행하지 않았다. 이번 릴리스의 ZIP에는 계정과 키가 없고, 발행 패키지와 키 등록은 별도 절차다.

## 라이브러리 확인

새 라이브러리나 버전 변경이 없다. 같은 날(2026-10-23) v0.3.1 릴리스에서 공식 PyPI/npm 메타데이터와 문서·릴리스를 확인한 [표](K-DOG_패치릴리스_v0.3.1_20261023.md#라이브러리-확인)를 그대로 적용하며, 포터블 런타임은 기존 고정 SHA-256의 Python 3.14.8이다. 관련 없는 최신판 이관은 수행하지 않는다.
