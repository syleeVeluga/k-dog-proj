## 1 사용자 결정과 범위

2026-10-12 사용자는 전처리 화면의 전체 업무 단계 드롭다운이 대메뉴와 맞지 않아 혼란스럽다고 지적했다. ‘실행시킨 사용자’는 **현재 로그인한 직원**으로 확인했고, 그 직원이 실행한 작업만 기본 목록에 표시하는 구성을 수용했다. 이어 분석 시작 이후의 상태와 처리 과정 표시를 검토하고, 이 개선을 합친 계획을 `docs/plans/`에 PR별로 작성한 뒤 독립 cold review의 수용 건만 반영하도록 요청했다.

최초 산출물은 수정 계획과 계획 검토 기록이다. 제품 코드 수정·AI 호출·운영 데이터 변경은 포함하지 않는다. 후속 사용자 지시로 이번 세션의 문서 5개를 별도 폴더에 분리해 로컬/원격 병합하는 범위를 추가했다(§6). ES01~03 제품 구현 PR의 병합을 뜻하지 않는다.

- 전처리 기본 목록은 **내가 실행한 전처리**다. 로그인 직원이 원래 실행을 시작한 작업을 회차·시도별로 표시한다.
- 드롭다운은 `전체 / 실행 중 / 완료 / 확인 필요`다. 촬영 확정·채점·최종 결과·리포트는 이 필터에서 제거한다.
- 미실행 참가자는 별도의 `전처리 실행` 대상 선택에서 찾는다. 촬영 기록 확인 여부는 그 안의 준비 안내로 유지한다.
- 전처리와 AI 분석은 기존의 별도 실행 버튼/계약을 유지한다. 화면에 존재하는 ‘분석 시작’ 대응 기능은 독립 채점 상세의 `현재 입력으로 AI 실행 생성` 버튼이다. 이 문서에서는 이를 ‘AI 분석 시작’으로 부른다.
- AI 분석에는 현재 선택한 실행의 실제 단계와 상태를 항상 펼쳐 보여준다. 기존 공유 실행 이력과 원자료 조회는 유지한다. 전처리의 내 목록 변경을 채점·리포트 목록의 계정 제한으로 확대하지 않는다.
- 내 목록은 조회 범위다. 활성 업무 계정의 공유 조회·수정·재사용·재실행 권한, 실제 행위자 기록, 이전 판본·원평가자·최초 독립 제출 출처는 유지한다.

## 3 최종 화면 계약

### 3.1 전처리

```text
전처리                                      [전처리 실행]
내가 실행한 전처리
[참가자·반려견 검색] [행사] [전처리 상태: 전체]

참가자·반려견 | 촬영 회차 | 전처리 상태 | 실행 시각 | 작업
합성 대상 A  | 1회차    | 실행 중     | 시작 시각 | 상태 확인
합성 대상 B  | 1회차    | 확인 필요   | 시작 시각 | 상세 보기
합성 대상 C  | 2회차    | 완료        | 시작 시각 | 결과 보기
```

한 행은 한 실행 시도다. 같은 직원의 재실행도 이전 행을 덮어쓰지 않는다. 이전 회차의 보존 결과와 현재 입력 기준 결과를 구분한다. 실패/중단/일부 완료는 `확인 필요` 필터에 포함하고 행에는 구체 상태를 쓴다. 입력이 바뀐 과거 성공은 성공 기록을 유지하면서 `현재 입력과 다름` 배지를 붙인다. `확인 필요`에도 포함하고 현재 입력으로 새 실행할 경로를 제공한다. **작업 성공과 현재 입력에 대한 유효성은 별도 값**이다.

내 실행이 없으면 `아직 실행한 전처리가 없습니다.`와 `전처리 실행` 버튼을 표시한다. 검색 결과 0건은 `조건에 맞는 전처리 작업이 없습니다.`다. 실행할 대상 선택은 공유 참가자/현재 회차를 찾고 촬영 기록 준비 조건을 안내한다.

### 3.2 실행 후 표시

클릭 직후 `실행 요청 중`을 표시하되 서버 접수/실행 확정과 구분한다. 서버 기록이 생기면 그 **실행 식별자**를 고정하여 상태를 조회한다. 현재 단계, 시작 시각, 마지막 상태 조회 성공 시각, 실제 단계 종료 여부를 표시한다. 측정하지 않은 백분율·예상 남은 시간·공급자 내부 진행은 만들지 않는다.

전처리는 실제 프로그램 경계의 `클립 제작 → 관찰창 결과 정리 → 결과 검증·저장` 또는 `재사용 검증 → 결과 검증·저장`을 표시한다. AI는 `요청 접수/대기 → 항목군 관찰 → 기본 계산 → 애착 판단 → 결과 게시`를 고정 실행 계획과 단계 기록으로 표시한다. 기술 정보에는 시도별 시간·호출·토큰·비용·출처를 유지한다.

### 3.3 계정과 문맥

다른 직원이 같은 참가자를 처리해도 내 실행의 상태·결과 링크를 바꾸지 않는다. 로그아웃/계정 전환 시 내 목록과 폴링을 즉시 비우고 새 계정 기준으로 조회한다. 메뉴·대상·회차 전환과 뒤늦게 온 응답이 다른 문맥을 덮어쓰지 않도록 한다. 새로고침·재진입은 조회만 수행하며 자동 새 실행을 만들지 않는다.

## 5 검증 및 완료 조건

- PR별 인수 항목/명령은 개별 파일을 따른다. 함수·화면 단위 검증 뒤 새로운 실패/변경이 없으면 동일 전체 시험을 반복하지 않는다.
- 새 조회/상태 계약은 실제 로그인 actor, 시도 식별자, 고정 입력·hash·token·lease·명시 재사용을 검증한다. 원자료/결과/기존 감사 이력은 보존한다.
- 합성 사용자 A/B와 합성 영상/가짜 공급자로 상태 전이를 재현한다. 관찰 결과나 비용·실제 시간을 만들어 성공으로 처리하지 않는다. 실제 외부 AI 호출 0건을 검증 기록에 명시한다.
- 1366px와 390px에서 기본 카드의 단계·상태·오류/복구 안내·버튼을 확인하고 합성 화면을 캡처한다. 색상만으로 상태를 표현하지 않는다.
- 계획 문서에서는 상대 링크, 기준 commit, 선행 관계, 요구사항과 시험 대응, 문서 간 상태 정의, `git diff --check`를 확인한다. 이번 제품 시험은 미실행으로 기록한다.
- 구현 시 라이브러리/프레임워크 사용 전에 공식 문서·release·registry로 최신 안정판과 선택 잠금판의 호환성을 다시 확인하고 날짜·출처·유지 이유를 실행 기록에 남긴다. 이번 계획은 의존성을 설치/변경하지 않는다.
