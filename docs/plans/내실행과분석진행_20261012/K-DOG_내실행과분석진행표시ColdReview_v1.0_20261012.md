## 1 검토 기준

독립 reviewer는 작성자와 다른 에이전트다. 사용자 결정과 현재 코드에 대해 누락·모순·범위 확대·실행 식별 오류·이력 파괴·권한 회귀·허위 진행/완료를 검토한다. 제품 구현은 하지 않는다. 코드 근거가 필요한 경우 Graft로 정확한 span/호출 관계를 확인한다.

- 현재 직원의 전처리 시작 원장만 내 목록에 포함하고 공유 업무 접근은 유지하는가?
- 시도/회차/직원이 달라도 진행 상태·결과·응답·후속 재실행이 섞이지 않는가?
- 동기 전처리 POST와 실제 잠금, 접수 여부 미확인/단계 기록 부재/과거 성공/부분 실패를 사실대로 다루는가?
- AI 현재 run/고정 계획/최신 attempt/stop/retry_wait와 결과 게시를 구분하는가?
- 초기 조회와 배경 갱신, 응답 유실, 일시적 연결 오류, 계정/문맥 변경의 검증이 구체적인가?
- 새 큐/권한/실공급자 호출/원자료 변경 등 요청하지 않은 구현을 확대하지 않는가?
- 계획 검토와 실제 실행 시험/실자료 인수 완료를 구분하는가?

## 3 반영 후 재검토와 문서 검증

수용 수정 후 같은 reviewer에게 재검토를 요청했다. reviewer는 ES-CR01·02·04 해결을 확인했고, ES-CR03의 포괄적인 ‘항목군 관찰 중’ fallback과 queued/retry_wait 안내가 새 claim/lease 조건과 충돌할 수 있다고 지적했다. 이를 기존 ES-CR03의 잔여 정합성 수정으로 수용했다. 단계/claim 미확정은 확인 안내로, 현재 claim의 score_v4가 확인된 공급자 응답 대기만 관찰 중으로 표시하며 정상 queued/retry_wait는 확인 필요로 바꾸지 않는다. 최종 재검토는 **ES-CR01~04 모두 해결·추가 actionable 0건**이다. 기존 run/step의 claim 필드 연결 근거도 확인했다. 메타데이터를 제외한 최종 계획 변경은 위 수용 건만 반영했다.

초안 단계 검증은 문서 5개·상대 링크 46개 누락 0, 기존 참조 파일 16개가 모두 기준 HEAD에 존재, 코드 #L 링크 27개 범위 오류 0, 파일별 후행 공백 0이다. 수용 반영 후 문서 5개·상대 링크 55개 누락 0, 기존 참조 파일 17개 모두 HEAD에 존재, 코드 #L 링크 36개 범위 오류 0, 후행 공백 0으로 재검증했다.

초안 검증 당시 `git diff --check`는 실행했으나 명령 환경에서 ‘must be run in a work tree’로 종료했다(`rev-parse --is-inside-work-tree`는 true). 당시 새 파일은 untracked여서 같은 명령 실행에서 생성한 빈 임시 파일과 `git diff --no-index --check`로 파일별 점검했다. 5개 모두 새 파일 차이의 exit 1·공백 진단 0이며 별도 후행 공백 검사도 통과했다. 이를 당시 표준 diff 명령의 성공으로 기록하지 않는다. 변경 범위는 이번 계획 5개 Markdown 파일뿐이며 앱/의존성/저장소 설정은 변경하지 않았다.

이번 계획 작성·검토는 제품 코드 수정, 앱/실행 시험 또는 실공급자 인수를 수행한 것이 아니다. 현재 열려 있던 로컬 앱의 빈 목록/필터는 확인했으나 운영 자료로 실행 상태를 재현하지 않았다. 다른 작업의 `docs/plans/360통합MP4업로드_20261012/`는 검토/변경하지 않았다.

## 4 후속 문서 정리 경계

2026-10-12 사용자가 별도 폴더 분리와 본 세션 작업물만 로컬/원격 병합하도록 지시했다. `docs/plans/내실행과분석진행_20261012/`로 5개 파일을 이동하고 상대 링크·병합 범위 메타데이터만 정리했다. 수용된 4건과 ES01~03 계약/인수 내용은 유지한다. 문서 이동은 새 제품 구현 검토로 계수하지 않는다. 최종 경로에서 링크/코드 근거/스테이징 파일 범위/공백과 원격 PR 변경 파일을 검증한다.

정리 후 문서 5개·상대 링크 55개·기존 참조 파일의 HEAD 존재·코드 줄 범위를 다시 확인했고 누락/범위 오류/후행 공백은 0이다. 저장소 접근이 가능한 명령 환경에서 `git diff --cached --check`와 `git diff --check`를 성공 확인했다. 스테이징 경로를 정확한 5개 파일 목록과 대조해 다른 작업물이 없음을 확인했다. 원격 병합 후에는 PR 파일 범위와 로컬/원격 main commit 일치를 확인한다.
