# K-DOG 촬영 확정 사용성 검토

- 날짜: 2026-10-24
- 범위: 절차 확인과 기록 확정 통합, 중복 입력 제거, 필수·선택 안내
- 선행 변경: [촬영 입력 단순화](K-DOG_촬영입력단순화_검증검토_v1.0_20261024.md)

## 판단과 반영

1. 별도 「현재 절차 확인」은 과거 기록이 현재 S1 8구간 절차에 해당하는지를 구분하던 값이다. 사용자가 화면의 절차·시각을 확인하고 「촬영 기록 확정」을 누르면 이 확인까지 한 번에 저장한다. 이전 기록은 로딩만으로 현재 절차로 바꾸지 않으며, 이전 확정본에 절차 확인이 빠졌으면 다시 확인하도록 표시한다.
2. 확정 저장에 성공하면 참가자의 전처리 탭으로 이동한다. 필수 시각 누락·충돌·서버 오류이면 이동하지 않는다. 실제 클립 제작 실행은 그 화면의 실행 버튼으로 시작한다.
3. 「촬영 기록 초안 저장」과 별도 「현재 촬영 메모 수정」 폼을 제거했다. 선택 메모는 촬영 기록의 접힌 상세 항목에서 기록과 함께 확정한다. 기존 회차 메모와 이력은 삭제하지 않는다.
4. 「재촬영 등록」은 촬영 기록에서 제거하고 영상 등록의 「새로 촬영한 영상을 등록할 때」 안으로 이동했다. 다른 날 새로 촬영한 경우만 새 회차를 만들며 같은 촬영의 파일 추가·재분석에는 사용하지 않는다고 안내한다. 기존 회차를 덮어쓰지 않는다.
5. 「보존 영상 출처 등록」은 일반 신규 업로드에는 필요 없다. 이전 방식으로 등록되어 연결 정보가 없는 파일만 영상 등록의 「기존 영상 카메라 연결」에 표시하고 한 번 연결하면 숨긴다. 파일 바이트·영상 ID·해시를 유지한다.
6. 카메라는 원본 여부의 분류가 아니라 CSV 시각과 파일을 연결하는 식별자다. 파일명 추정을 유지하고 CSV의 CAM1이면 카메라 1이라는 예시를 제공한다. 별도 「원본 번호」 입력은 제거하고 기존 서버 매핑을 사용한다. 모호한 파일명을 임의 추정해 연결하지 않는다.
7. 대표 음성의 기본 선택 문구를 「자동」으로 통일했다. 필수 시간 기준·8구간 시각·상태별 사유와 선택 사건·관찰 근거·수동 오프셋의 조건과 예시를 표시한다.

## 검토에서 유지한 조건

- 실제 구간 시간과 미실시·단축·복지 중단 사유는 확정에 필요한 자료다. CSV가 채워 주지만 사실이 없는 값을 만들어 통과시키지 않는다. 퇴장 끝과 상세 관찰은 기존 정책대로 선택이다.
- 카메라 연결을 완전히 없애면 서로 다른 파일의 CSV 초를 잘못 적용할 수 있어 유지한다. 파일명에서 확인할 수 있는 경우 입력 부담을 줄인다.
- 파일 수신과 분석 가능 여부는 다르다. 파일 형식 선택은 없지만 실제 영상 읽기 검증은 유지한다.
- S1 계산 규칙, 이전 출처·회차 이력, 버전 충돌 및 불변 파일 보호는 변경하지 않는다.

## 검증

- `npm run build` 통과. 기존 500 kB 번들 경고는 유지된다.
- 촬영·CSV·업로드·전처리·회차 이력·접수·업무 맥락·반응형 화면 33개 시나리오의 최종 결과가 모두 통과했다. 최초 실행 29개 통과, 기존 테스트가 접힌 메모를 열지 않거나 참가자 탭 렌더링 전에 이동한 4개 실패는 화면 동선·대기를 수정한 뒤 4개 모두 재검증했다.
- 확정 한 번으로 `confirmed=true`와 `procedure_edition=s1_confirmed`가 저장되고 전처리 탭으로 이동하는 것을 검증했다. 필수 시각 누락 시 서버 기록을 만들지 않으며 입력을 유지한다. 상세 관찰을 추가하지 않은 CSV도 확정되고 미관찰 창은 그대로 남는다.
- 재촬영 후 기존 회차·설문 보존, 다른 입력 버전과의 충돌, 보존 영상 연결 후 ID·바이트·해시 유지, 원본 번호 입력 제거 후 기존 카메라 매핑을 검증했다. 1440px·390px CSV 화면 캡처와 360~1440px 레이아웃 검사를 수행했다.
- `git diff --check` 통과. Graft 그래프를 갱신했다.
- 로컬 `http://127.0.0.1:8000`의 정상 응답과 새 `index-BooGgjrc.js` 제공을 확인했다. 이번 프런트엔드 변경은 서버 재시작 없이 반영된다. 운영 데이터는 수정하지 않았다. 이번 변경은 로컬 작업 트리에 있으며 원격 병합하지 않았다.

의존성 추가·버전 변경은 없다. 같은 날 확인한 공식 버전과 기존 잠금 버전 유지 사유는 선행 검토 문서를 따른다.
