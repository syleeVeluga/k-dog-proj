# K-DOG 리포트 발급 사용설명서

버전: v1.0 · 작성일: 2026-10-13 · 확인 기준: `main`의 `53889b7`, S1 및 RP03/RP04 내용·출력 개편

대상: 결과를 확인해 보호자에게 제공할 파일을 만드는 운영자·교수자. 현재 `operator`·`reviewer`·`admin`은 화면에 **업무 계정**, `developer`는 **개발자**로 표시되며 네 계정 모두 같은 발급·조회·저장·인쇄 기능을 사용할 수 있습니다.

## 1. 언제 사용하는 기능인가요?

행사에서 사용할 최종 결과판이 준비되었을 때, 그 판본으로 관찰 리포트를 생성하여 HTML·PDF를 확인·저장·인쇄할 때 사용합니다. 운영자는 참가자·회차·발급본을 확인해 제공할 파일을 준비하고, 교수자는 해석·관찰 부족·근거와 생성 문장이 일치하는지 검토할 수 있습니다. 이러한 업무 분담은 팀이 정하며 앱은 계정 역할별 승인 단계를 두지 않습니다.

**리포트 메뉴를 여는 것만으로 생성되지 않습니다.** 선택한 최종본을 명시적으로 생성해야 합니다. 생성 후 조회·다운로드·인쇄는 저장된 발급 파일과 문장을 사용하며 매번 AI 문장을 새로 생성하지 않습니다.

최신 발급본과 이전 발급본은 모두 당시의 입력·최종 결과·문장·출력 파일을 보존합니다. 새 발급은 기존 파일 덮어쓰기가 아니라 새 실행과 새 파일입니다.

## 2. 화면 위치와 사전 조건

**분석·평가 → 리포트 → 리포트 발급**으로 들어갑니다. 메뉴 경로는 `#/report`입니다. 참가자 목록에서 **「참가자번호 리포트 열기」**를 누릅니다.

| 조건 | 확인 방법 |
| --- | --- |
| 활성 로그인 | 모든 업무 계정과 개발자가 사용할 수 있습니다. 로그인 만료·계정 비활성은 다시 확인해야 합니다. |
| 현재 S1 접수 형식 | `intake-4.0` 참가자를 대상으로 합니다. 구형 접수 형식의 출력 경로로 대체하지 않습니다. |
| 참가자·회차 | 반려견 이름, 행사/참가자번호, **리포트 회차**를 확인합니다. |
| 고정 최종본 | [해석과 최종 결과](K-DOG_해석과최종결과_사용설명서_v1.0_20261013.md)에서 만든 최종본을 명시 선택해야 합니다. |
| 파일·참조 무결성 | 최종본·원자료·설문·규칙·템플릿·관련 파일을 읽고 고정 해시를 검증할 수 있어야 합니다. |
| 문장 생성 실행 환경 | 신규 리포트는 고정 근거로 AI 설명·총평·실천 문장을 생성합니다. 실제 공급자 연결·키 등 실행 환경 문제는 담당 개발자와 확인합니다. |
| 비교 | 자체 집단·외부 기준은 선택 사항입니다. 비교 없이도 생성할 수 있습니다. 선택했다면 검증된 정확한 판본을 사용할 수 있어야 합니다. |
| 승인·옛 정책 | 타인의 최종본도 사용할 수 있습니다. 교수자 승인, 공개 허가, 배정, 동의 확인·삭제 요청 해제는 발급의 선행 조건이 아닙니다. |

일부 관찰 부족이나 유형 보류가 있다고 해서 모든 정상 발급이 금지되는 것은 아닙니다. 확인된 프로그램 근거로 발급하고 부족 사유를 표시합니다. 다만 허구 사건·잘못된 수치·상충한 근거 등 내용 검증 오류가 해결되지 않은 출력을 정상 발급으로 제공하지는 않습니다.

## 3. 생성할 최종본과 비교 선택

1. 대상 화면의 **리포트 회차**에서 이번에 발급할 촬영 회차를 고릅니다. 이전 회차 발급 이력도 이곳에서 확인합니다.
2. **현재 접수 입력 새로고침**으로 접수 입력판을 확인합니다.
3. **리포트 상태 새로고침**으로 최종본·발급 실행 목록을 조회합니다.
4. **리포트에 고정할 최종본**에서 생성 시각·작성 계정·기본판을 확인하고 선택합니다.
5. 필요할 때 **기술 정보**를 펼쳐 최종본 식별자·해시를 확인합니다.
6. 비교를 넣지 않는다면 **리포트 자체 비교집단**을 **비교 없이 생성**으로 둡니다.
7. 비교가 필요하면 사용 목적에 맞는 집단 또는 확인된 외부 기준을 명시 선택합니다.

최종본 목록이 없으면 독립 채점 화면에서 사용할 기본 결과를 선택하고 최종본을 먼저 만듭니다. 최신 접수판과 예전 최종본이 동시에 존재할 수 있으므로 날짜가 최근이라는 이유만으로 선택하지 말고 평가하려는 회차·원자료판을 확인하세요.

### 자체 비교집단

**리포트 자체 비교집단**에서 미리 만든 집단을 선택합니다. 집단 제목과 선택 대상 수를 읽습니다. **이전 응답 기준**이라면 일부 응답이 이후 수정되었지만 선택한 고정 집단의 **당시 평균**을 사용합니다. 최신 평균이 필요하면 비교 조건 메뉴에서 새 집단을 만든 뒤 선택합니다.

선택한 집단이 목록에서 없어졌다면 화면의 안내에 따라 다른 집단 또는 **비교 없이 생성**을 다시 명시적으로 선택합니다. 임의로 비교 없음으로 바뀌었다고 생각하고 진행하지 않습니다. 유효 n·제외 수·척도는 발급본에서 다시 확인합니다.

### 외부 비교

외부 비교는 [비교 조건 설명서](K-DOG_비교조건_사용설명서_v1.0_20261013.md)의 실제 기준 등록·검증과 대상별 선택을 따릅니다. 별도 관리자 결재는 필요하지 않지만, 문항·척도·산식·대상·설문 원입력의 기술적 일치 조건은 유지됩니다. 실제 기준표가 없거나 검증되지 않았다면 외부 비교 수치·그래프를 임의로 넣지 않습니다.

자체 집단과 외부 기준은 출처가 다릅니다. 외부 참고 평균을 자체 집단 평균으로 설명하거나, 설문 외부 비교를 영상 규준·진단·백분위로 설명하지 마세요.

### 누적 비교 자동 연결 (2026-10-21 추가)

새 발급은 별도 선택 없이 **평소의 우리를 그래프로 · 자동 연결**을 포함합니다. 접수 순간에 [설문 현황](K-DOG_설문현황_사용설명서_v1.0_20261013.md)의 **누적 비교 참여**로 대표 설문이 확정된 모든 참여쌍을 모아 9개 설문 지표의 우리 누적 평균을 계산하고, [비교 조건](K-DOG_비교조건_사용설명서_v1.0_20261013.md)에 등록된 미국 연구 기준을 SF·NF에 따로 연결합니다.

1. 안내에 보이는 **현재 누적 대상**(포함·대표 미확정·제외·미연결 S1 대상)을 확인합니다. 미확정·미연결 자료는 포함되지 않으므로 필요하면 먼저 설문 현황에서 근거를 확인해 기록합니다.
2. SF·NF 기준이 등록되지 않았거나 전달 기준과 다르면 그 지표의 미국 연구 비교만 준비되지 않은 것으로 표시되고, 나머지 지표는 정상 발급됩니다.
3. **이전 방식: 외부 비교 명시 선택**은 접혀 있습니다. 여기서 외부 비교를 직접 고르면 누적 비교 없이 예전 방식으로 발급됩니다. 특별한 이유가 없으면 사용하지 않습니다.

## 4. 새 리포트 생성

1. 선택한 최종본과 비교 조건을 마지막으로 확인합니다.
2. 처음 생성한다면 **검증된 내용 명시 재사용**을 **재사용 없이 새 생성**으로 둡니다.
3. **선택한 최종본으로 리포트 생성**을 누릅니다.
4. 실행 목록에 **대기**가 생겼는지 확인합니다.
5. **생성 중 → 발급 완료**로 진행되는지 확인합니다. 진행 중에는 약 2초 간격으로 상태를 자동 조회합니다.
6. 발급 완료 실행에 **발급 요약·HTML·PDF 열기**가 나타나면 엽니다.

**실행 제어 기록**은 중지·재시도할 때 사유를 적는 입력입니다. 신규 생성 버튼을 누르기 위해 별도의 승인 사유를 제출하는 절차는 아닙니다. 다른 직원이 생성한 실행도 함께 확인·제어할 수 있으며 실제 행위자가 기록됩니다.

신규 실행은 기본 한 번의 문장 요청과 제한된 재시도를 사용합니다. 실제 실행 시간과 호출·비용은 목록의 기록으로 확인하며 일정 시간 안에 반드시 끝난다고 예상하지 마세요.

생성 응답을 확인하지 못하면 **응답 확인이 필요한 요청** 안내가 남을 수 있습니다. 먼저 상태를 새로 조회하여 이미 접수된 실행이 있는지 확인합니다. 같은 선택 입력의 재요청에는 같은 요청 ID를 사용하여 중복 접수를 구분합니다. 최종본·비교·재사용 선택을 바꾸면 다른 생성 요청이 될 수 있습니다.

## 5. 진행 상태와 단계 읽기

| 실행 상태 | 의미와 다음 행동 |
| --- | --- |
| 대기 | 서버에 접수되어 처리 순서를 기다립니다. |
| 생성 중 | 생성 작업이 진행 중입니다. 아래 단계 기록을 펼쳐 확인합니다. |
| 재시도 대기 | 제한된 자동 재시도를 기다립니다. 중복 생성하기 전에 기존 상태를 확인합니다. |
| 발급 완료 | 내용·출력 검증과 게시를 마친 발급본입니다. 열어서 본문을 확인합니다. |
| 실패·검토 필요 | 리포트를 완성하지 못했습니다. 사유 코드와 실패 단계를 확인하고 필요한 조건을 해결합니다. |
| 중지 | 사용자가 중지한 실행입니다. 필요하면 고정 입력 재시도를 합니다. |

**기술 정보 · 단계·시도·시간·재사용**를 펼치면 아래 단계가 표시됩니다.

| 단계 | 확인하는 내용 |
| --- | --- |
| 내용 작성 | 고정 사실·해석·설문에서 설명·총평·실천 문장을 작성합니다. |
| 내용 검증 | 문장이 고정 근거와 일치하는지 확인합니다. |
| HTML·PDF 생성 | 검증한 내용을 각각의 출력 파일로 만듭니다. |
| 출력 검증 | 출력 파일과 고정 참조가 유효한지 확인합니다. |
| 게시 | 발급본과 그 출처를 보존합니다. |

각 시도에는 상태·시간·호출 예약·토큰·비용·명시 재사용 여부가 나옵니다. **시간 미측정**, **비용 미확인**, **과금 여부 미확인**을 0초·무료로 읽지 않습니다. 공급자 호출 예약 수는 실제 정산 확정 수와 다를 수 있습니다.

## 6. 발급 요약과 본문 확인

**발급 요약·HTML·PDF 열기**를 누르면 **리포트 발급본**에서 네 결과 요약과 HTML 미리보기를 확인할 수 있습니다.

| 핵심 카드 | 확인할 점 |
| --- | --- |
| 보호자 교육태도 | 적용 유형·설명과 자동 배점/관찰 기회의 근거가 맞는지 |
| 반려견과 보호자의 애착관계 | 적용된 애착 판단·의견과 지지/반대 근거·보류 사유가 맞는지 |
| 사회성: 사람 반응·비사회적 반응 | 두 반응의 확인된 관찰을 구분했는지, 부족한 쪽을 확인된 사실처럼 설명하지 않았는지 |
| 함께걷기 | 실제 계산 조건과 관찰량이 있는지, 부족·주의 조건을 표시했는지 |

현재 새 출력은 **핵심 결과 → 평소 응답 → 28문항 설문/영상 설명 → 세부 관찰 → 총평/실천 → 출처**를 따라 구성합니다. 보호자 설문과 현장 영상은 서로 다른 자료로 설명하며, 실제 존재하지 않는 과제·관찰을 만들어 넣지 않습니다.

신규 리포트에는 **「오늘의 장면들」, 사진 카드, 빈 사진 상자, 장면 전용 페이지가 없습니다.** 사진을 위한 영상 프레임 추출도 하지 않습니다. 관찰 사건·시간 근거는 분석 출처로 계속 보존됩니다. 사진을 넣으려고 별도 지정·승인 작업을 할 필요는 없습니다.

PDF는 고정 6쪽이 아닙니다. 실제 내용의 길이에 따라 페이지가 달라집니다. 긴 의견·표가 있다면 마지막 문장까지 이어졌는지 확인하세요. 같은 내용을 사용해도 서버 PDF와 브라우저 인쇄의 페이지 나눔은 다를 수 있습니다.

비교를 선택했다면 **발급 당시 자체 집단**에서 영역별 원척도·평균·유효 n·제외 수를 확인하고, **발급 당시 외부 비교**에서 대상 설문값·외부 평균/표준편차·유효 n/전체 n·대상 범위·논문 출처를 확인합니다. 현재 설정값이 아니라 **발급 당시 고정값**이라는 점을 기억하세요.

누적 비교로 발급한 리포트에는 **평소의 우리를 그래프로** 9개 패널이 있고, 발급 요약에도 **발급 당시 누적 비교** 표(지표·우리 아이·우리 누적(n)·미국 연구)와 **집계 기준일**(한국 시간)이 나옵니다.

| 지표 | 표시 |
| --- | --- |
| 낯선 사람 두려움(SF)·비사회적 두려움(NF) | 0~4점 축에 최대 세 점: 미국 연구 참고 평균(회색 마름모), 우리 누적 평균(파란 사각형), 우리 아이(주황 원) |
| 나머지 7개 지표 | 1~5점 축에 우리 누적 평균과 우리 아이 두 점 |

값은 소수 둘째 자리로 표시하고 지표마다 실제 유효 n으로 나눕니다. 누적 n이 2 미만인 지표는 누적 표식을 표시하지 않습니다. 우리 아이 응답이 부족한 지표는 점수 대신 응답 부족 안내가 나옵니다. 우리 누적 평균은 국내 전체 평균이 아니라 우리 프로그램 참여견의 평균이며, 미국 연구 평균은 국내 표준·진단 기준이 아닙니다.

유형 보류·일부 관찰·관찰 부족이 표시된 카드도 실제 결과입니다. 비어 보인다고 임의의 유형이나 정상 수치를 추가하지 않습니다. 잘못된 원자료나 해석이 있다면 해당 앞 단계에서 수정한 후 새 최종본·새 리포트를 만듭니다.

## 7. HTML·PDF·출처 파일 저장과 인쇄

발급본을 연 뒤 필요한 버튼을 사용합니다.

| 버튼·링크 | 언제 사용하나요? |
| --- | --- |
| HTML 저장 | 보존된 리포트 HTML을 파일로 저장할 때 |
| PDF 저장 | 보호자에게 전달하거나 보관할 서버 생성 PDF를 저장할 때 |
| 출처 manifest 저장 | 입력·설정·최종본·출력 파일의 고정 참조를 확인하거나 검수 자료로 남길 때. JSON 파일로 저장됩니다. |
| HTML 새 창 | 저장된 HTML을 별도 브라우저 탭에서 크게 읽을 때 |
| 열린 리포트 인쇄 | 현재 열린 리포트를 브라우저 인쇄창으로 보낼 때 |
| 발급본 닫기 | 현재 상세를 접고 실행 목록으로 돌아갈 때 |

저장 파일 이름은 `kdog-s1-실행식별자.html`, `.pdf`, `.json` 형태입니다. 브라우저의 다운로드 목록에서 저장 위치와 파일이 생겼는지 확인합니다. manifest는 보호자용 본문 대신 기술적 출처를 확인하는 파일입니다.

인쇄는 먼저 발급본을 열고 HTML 미리보기가 표시된 뒤 **열린 리포트 인쇄**를 누릅니다. 브라우저 인쇄 미리보기에서 용지·여백·페이지를 확인하고 프린터 또는 PDF 저장을 선택합니다. 버튼을 눌렀다는 사실만으로 실제 인쇄가 완료되었다고 앱이 확인하는 것은 아닙니다.

다운로드·인쇄 시 고정 파일과 출처를 다시 검증합니다. 미리보기만 보였더라도 저장 시 파일 변조·유실 등의 오류가 나면 실제 저장 성공을 확인해야 합니다. 파일 제공은 수동 작업이며 앱이 이메일이나 다른 외부 채널로 자동 발송하지 않습니다.

## 8. 재발급과 이전 발급본

### 같은 최종본의 검증된 내용 재사용

이미 성공한 내용이 있고 출력 단계를 다시 진행하려면 **검증된 내용 명시 재사용**에서 해당 실행을 고릅니다. 선택한 최종본과 같은 해시이며 내용 작성에 성공한 후보가 표시됩니다. **선택한 최종본으로 리포트 생성**을 누르면 새 실행과 새 발급 파일이 만들어집니다.

서버는 고정 최종본·설문·내용 규칙·템플릿 등 호환 조건을 다시 확인합니다. 출력 개편으로 템플릿 판본이 바뀐 경우처럼 호환하지 않으면 거절될 수 있습니다. 이때 이전 파일을 바꾸거나 억지로 재사용하지 말고 **재사용 없이 새 생성**을 선택합니다.

### 변경 내용을 반영한 새 발급

접수·설문·촬영·채점·의견이 수정되면 그 변화가 기존 최종본과 발급본에 자동 반영되지 않습니다. 필요한 새 원자료/계산 → 새 최종본 → 그 최종본의 새 리포트 순서로 진행합니다. 비교집단만 새로 사용하려는 경우에도 원하는 비교를 명시한 새 생성이 필요합니다.

실행 목록의 **최신 발급본**은 해당 회차에서 가장 최근 생성된 성공 발급 실행 표시입니다. 최신 접수·채점·의견을 모두 반영했다는 보증 표시가 아닙니다. 함께 표시되는 **이전 입력·기준** 여부와 최종본판을 확인합니다.

누적 비교 값도 같습니다. 발급본은 접수 시점의 누적 평균·n·기준을 유지하며, 재시도·다운로드·인쇄는 다시 집계하지 않습니다. 이후 참여쌍이 늘거나 대표가 정정되었다면 새 발급 요청에서만 새 값이 계산됩니다.

**이전 발급본**은 당시 파일을 계속 보존합니다. 현재 의견·기준이 바뀌었다는 이유만으로 그 파일의 내용을 새 값으로 바꾸지 않습니다. 읽을 수 있는 고정 파일·참조의 검증은 계속 필요합니다.

## 9. 중지와 고정 입력 재시도

생성 중·대기·재시도 대기 실행을 멈추려면 **실행 제어 기록**에 이유를 적고 해당 실행의 **이 리포트 실행 중지**를 누릅니다. 종료된 실행에는 중지 버튼이 없습니다.

실패·중지 실행을 다시 처리하려면 원인을 해결하고 같은 입력에 대한 실행 제어 기록을 적은 뒤 **고정 입력으로 리포트 재시도**를 누릅니다. 같은 실행이 대기 상태로 돌아갑니다. 고정 최종본을 최신판으로 바꾸는 작업은 아니며, 원본·참조·설정 조건을 검증하지 못하면 재시도도 거절됩니다.

다른 직원 또는 자동 진행이 실행 상태를 바꾸어 「리포트 실행 상태가 변경되었습니다」가 나오면 **리포트 상태 새로고침**을 누르고 최신 상태에서 다시 판단합니다. 반복 중지·재시도 대신 먼저 상태를 확인합니다.

## 10. 잘 안될 때

| 화면 상황 | 해결 순서 |
| --- | --- |
| 선택한 최종본으로 리포트 생성이 비활성화됨 | 최종본 선택·목록 조회 완료·사용 가능한 선택 집단을 확인합니다. |
| 최종본 목록 없음 | 독립 채점 화면에서 기본 결과와 현재 의견을 연결하여 최종본을 먼저 만듭니다. |
| 대기 상태가 계속됨 | 상태 새로고침과 서버 연결을 확인합니다. 정상 조회인데 진행되지 않으면 담당자에게 실행 식별자·입력판·시각을 전달합니다. |
| 실패·검토 필요 | **기술 정보 · 고정 최종본**의 사유 코드와 단계별 실패를 확인합니다. 공급자 연결, 내용 검증, 파일·템플릿 검증 등 해당 원인을 해결합니다. |
| 검증을 마친 발급본이 아직 없음 | 성공·게시 완료 전입니다. 상태를 조회하고 완료 후 엽니다. |
| 외부 비교 제공 차단 | 표시된 실제 기준·범위·파일 문제를 확인합니다. 당시 발급 이력과 파일은 보존되지만 제공은 검증을 통과해야 합니다. 필요한 경우 검증된 기준 또는 비교 없는 새 리포트를 만듭니다. |
| 재사용 호환 오류 | 선택한 입력·규칙·템플릿과 호환하는지 확인합니다. 호환하지 않으면 새 내용 생성으로 진행합니다. |
| 생성·저장 중 409 충돌 | 현재 접수판·선택 최종본·참조와 실행 상태를 새로 조회하여 맞는 판본을 다시 선택합니다. |
| 파일 유실·해시 불일치 | 파일을 직접 수정하거나 검증을 우회하지 않습니다. 담당자가 정상 보관본·백업을 확인하도록 전달합니다. |
| 부족 카드 또는 유형 보류 | 원자료·최종 해석의 실제 부족 사유를 확인합니다. 사실이 보완되면 앞 단계 수정과 새 최종본을 거쳐 재발급합니다. |
| 인쇄창이 안 열림 | 발급본과 미리보기를 먼저 연 뒤 다시 시도합니다. 브라우저 팝업·인쇄 상태를 확인하고 필요하면 저장 PDF를 사용합니다. |
| PDF 쪽 수가 예상과 다름 | 현재 출력은 내용에 따라 가변 페이지입니다. 누락·잘림이 있는지를 확인합니다. |

오래된 발급 실행에는 **일부 문장은 준비 중이며 정상 발급에는 영향이 없습니다** 안내가 있을 수 있습니다. 당시 내용 판본을 확인합니다. 신규 문장 생성 구현과 실제 교수 검토 품질을 같은 완료 상태로 보지는 않습니다.

## 11. 제공 전 확인과 기록

파일을 전달하기 전 참가자·회차·최종본판, 핵심 카드의 유형·부족 사유, 설문/영상 구분, 비교 출처·유효 n, 총평·실천 내용과 마지막 페이지까지 확인합니다. 원자료나 해석의 잘못은 새 판본에서 바로잡고, 기존 파일을 편집해 같은 발급본으로 취급하지 않습니다.

각 실행의 **열람·수정 기록**을 펼치면 생성 요청·발급·중지·재시도·열람의 시각과 실제 계정을 확인할 수 있습니다. 목록 조회·상태 폴링만으로 매번 열람 사건을 남기지는 않습니다. 명시적으로 발급 요약을 열거나 파일을 저장·제공받는 동작은 기록됩니다. 이 기록은 외부 전달 완료·읽음·인쇄 완료 확인서가 아닙니다.
