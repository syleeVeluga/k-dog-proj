# K-DOG 운영자와 교수자 사용설명서 Cold Review

버전: v1.0 · 검토일: 2026-10-13 · 제품 기준: `main / 53889b7` · 문서 브랜치: `veluga/operator-professor-manuals-20261013`

검토 대상은 [기능별 사용설명서](../README.md)의 17개 매뉴얼과 목차다. 사용자 지시에 따라 서브에이전트 3명이 독립 cold review를 수행했고, 주 에이전트가 발견사항의 코드 근거를 확인한 뒤 수용한 문서 수정만 반영했다. 이 기록은 이번 후속 검토의 결과이며, 초안 작성 때의 자체 검수와 구분한다.

## 1 검토 범위와 방법

| 독립 검토자 | 담당 문서 | 검토 결과 |
| --- | --- | --- |
| `cold_manual_access_intake` | 목차, 로그인과 공통 화면, 직원 계정, 개발 설정, 참가자 접수, 일괄 등록, 설문 현황 | P1·P2·P3 발견 0건. 상대 링크 110개 대상 확인 |
| `cold_manual_media_recovery` | 영상 파일 업로드, 촬영 기록, 전처리, 백업과 복구 | P1·P2·P3 발견 0건 |
| `cold_manual_analysis_outputs` | 독립 채점, AI 분석, 해석과 최종 결과, 리포트 발급, 비교 조건, 연구 내보내기, 검수 자료 | P2 2건·P3 1건 발견 |

각 검토자는 실제 화면의 버튼·이동 경로와 서버의 저장·실행 조건을 graft로 탐색하여 대조했다. 현행 업무 권한 정책, ES 진행 표시, MP 통합 영상 처리, RP 리포트 개편을 기준으로 과거 승인 조건과 현재 기술 조건을 구분했다. 원자료·완료 상태·판본·독립성·응답 유실·재사용·파일 검증의 설명을 중점적으로 확인했다.

실제 앱 실행, 운영 DB·참가자 파일 조회, 외부 AI 호출은 수행하지 않았다. 이번 변경은 사용설명서와 검토 기록이며 앱 코드·의존성·평가 규칙·실제 인수 상태를 변경하지 않는다.

## 2 발견사항과 수용 판단

독립 cold review 3건과 스테이징 문서 검사 2건을 분류했다. **수용 4건, 보류 0건, 거절 1건**이다. 스타일 취향이나 관련 없는 제품 개선은 반영하지 않았다.

| ID | 우선순위 | 발견사항과 영향 | 판단과 반영 |
| --- | --- | --- | --- |
| MR-C01 | P2 | 기존 행사 의견이 있는 참가자 채점 화면에 들어오면 의견 본문을 자동 조회한다. 타인·AI 기반 또는 타인 작성 의견이 같은 촬영에 연결되어 있으면 원평가자의 사전 노출로 분류될 수 있으나, 기존 안내는 별도 결과 열기만 피하면 되는 것으로 읽힐 수 있었다. | 수용. 독립 채점·AI 분석·해석과 최종 결과·목차에 자동 조회 경계와 의견 등록 전 최초 독립 제출 순서, 이미 노출된 경우 검수·출처 확인을 추가했다. |
| MR-C02 | P2 | 외부 비교는 기준 문항의 모든 원응답과 산출 가능한 평균을 요구한다. 자체 집단의 영역별 유효 응답 포함과 조건이 다른데 시작 조건·미응답 해결 안내가 부족했다. | 수용. 비교 조건에 완전 응답 조건을 명시하고 실제 원응답 보완 후 새 고정 입력을 선택하거나 외부 비교 없이 출력하도록 안내했다. |
| MR-C03 | P3 | 연구 파일의 의견 표는 최종본에 고정된 작성 중·완료·철회 의견을 상태와 함께 보존한다. 완료 의견만 들어가는 듯한 표 설명은 비적용 원문을 완료 결과로 오해하게 할 수 있었다. | 수용. 연구 내보내기에서 포함 상태를 바로잡고 `opinions.state`와 `final_results.source`로 실제 적용 출처를 확인하도록 설명했다. |
| MR-V01 | P3 | 신규 파일을 스테이징한 뒤 `git diff --cached --check`에서 설문 현황·일괄 등록 문서 끝의 추가 빈 줄 2곳을 검출했다. | 수용. 두 파일 끝을 단일 개행으로 정리했다. 내용·사용 조건은 변경하지 않았다. |
| MR-V02 | 해당 없음 | 자동 형식 검사가 `docs/README.md` 코드 블록 안의 PowerShell 주석을 Markdown 제목으로 해석하여 빈 줄 경고를 냈다. | 거절·오탐. 코드 블록 주석은 문서 제목이 아니며 실제 문서 결함이 아니다. 문서를 수정하지 않고 검사에서 코드 블록을 제외하여 재검증했다. |

## 3 수용사항의 구현 근거

### MR-C01 자동 의견 조회와 사전 노출

[공유 채점 화면](../../../frontend/src/ScoreSheetsV4.tsx#L53)은 참가자 화면에서 의견·최종 결과 컴포넌트를 함께 표시한다. [의견 초기 조회](../../../frontend/src/FinalResultsV4.tsx#L35)는 기존 의견이 있으면 최초 본문 조회에 `purpose=open`을 사용한다. [노출 집계](../../../backend/app/sheets_v4.py#L312)는 원평가자의 같은 촬영에 대한 타 자료 열람을 분류하며, [새 시트 생성](../../../backend/app/sheets_v4.py#L439)은 사전 노출이 있으면 독립 목적을 검수로 구분한다. 원평가자 자신의 기본 자료와 자신의 의견 작성인 경우 등 제외 조건도 유지한다.

현재 화면 동작의 안내를 보완했다. 앱의 열람 동작이나 접근 정책을 바꾸지 않았고, 타인 열람을 승인제로 전환하지 않았다. 이미 보존된 최초 제출본을 제3자의 후행 열람으로 소급 변경한다는 설명도 추가하지 않았다.

### MR-C02 외부 기준 문항의 완전 응답

[외부 비교 생성 검사](../../../backend/app/external_comparisons_v4.py#L82)는 기준 문항·평균·산출 상태가 맞고 `answered_count == target_count`인 경우에만 비교를 고정한다. 이 조건을 [비교 조건 매뉴얼](../K-DOG_비교조건_사용설명서_v1.0_20261013.md)의 시작 조건·사용 순서·오류 해결에 반영했다. 기준 문항 외의 모든 설문을 무조건 요구하는 조건으로 확대하지 않았다.

### MR-C03 연구 파일의 의견 상태

[연구 표 구성](../../../backend/app/exports_v4.py#L361)은 최종본의 의견을 완료 상태만으로 필터하지 않고 `state`와 함께 보존한다. 같은 코드의 최종 결과 표에는 영역별 `source`가 들어간다. [연구 내보내기 매뉴얼](../K-DOG_연구내보내기_사용설명서_v1.0_20261013.md)은 원문 보존과 최종 적용을 구분하도록 수정했다.

## 4 재검토와 문서 검증

`cold_manual_analysis_outputs`가 수용한 내용 이슈 3건을 읽기 전용으로 재검토하여 모두 해결됐고 수정으로 생긴 추가 actionable 이슈는 없음을 확인했다. 기존 코드 근거를 재사용했으며 제품 코드 변경은 없다. 형식 오류 MR-V01도 수정 후 공백 검사로 확인했다.

| 검증 | 결과 |
| --- | --- |
| 초안 문서 형식 검사 | 매뉴얼·목차 18개, 상대 링크 270개, 파일/제목·소스 행 fragment 35개, 표 64개 검사. 문제 0건 |
| 초안 스테이징 트리 링크 검사 | 상대 링크 270개 모두 스테이징 트리의 파일로 연결됨 |
| MR-V01 반영 후 공백 검사 | `git diff --cached --check` 통과 |
| 수용 내용 재검토 | MR-C01~03 해결, 추가 actionable 0건 |
| 최종 변경 문서 검사 | 변경 Markdown 20개, 스테이징 트리 상대 링크 294개, 제목·소스 행 fragment 41개, 표 68개. UTF-8·대체문자·개행·코드 블록·표·제목·링크 검사 문제 0건 |
| 최초 커밋 트리 검사 | `fcc0e24`의 변경 Markdown 20개와 상대 링크 294개가 커밋 트리에 존재함. 문제 0건 |
| 최초 PR 상태 조회 | [PR #93](https://github.com/syleeVeluga/k-dog-proj/pull/93)의 최초 head `fcc0e24`에서 `CLEAN`·`MERGEABLE`, checks 목록 없음. CI 통과로 표시하지 않음 |

문서 전용 변경이므로 앱의 backend·E2E 시험이나 새 빌드·설치를 실행하지 않았다. 실제 UI·서버 코드 조건은 독립 검토의 읽기 전용 대조로 확인했으며 문서 검사를 제품 인수 시험으로 표시하지 않는다.

GitHub Copilot의 자동 검토는 사용량 한도로 실행되지 않았다는 댓글만 남았다. 이를 검토 성공으로 기록하지 않으며, 이번 독립 cold review의 근거는 위 서브에이전트 3명과 수용 수정 재검토다.

## 5 병합 범위

문서 패키지는 기능별 매뉴얼 17개·목차, [docs 진입 안내](../../README.md)의 링크, 이 cold review 기록으로 구성한다. 제품 기준 코드는 `53889b7`로 유지한다. 제품의 실제 영상·공급자 품질, 교수 판단 검토, 원본·규칙·외부 기준 수령, 물리 장비 인수는 기존 대장의 미완료 조건을 유지한다.

문서 PR은 [#93](https://github.com/syleeVeluga/k-dog-proj/pull/93)이다. 실제 최종 head·checks·merge 상태와 merge commit은 이 PR 기록을 원장으로 확인한다. 병합은 확인한 head로 수행하고 원격 병합 뒤 로컬 `main`을 `origin/main`과 동기화한다.
