# K-DOG 해석과 최종 결과 사용설명서

버전: v1.0 · 작성일: 2026-10-13 · 확인 기준: `main`의 `53889b7`, S1 및 RP02 애착 판단 후속

대상: 행사 의견을 기록하고 발급할 결과를 구성하는 운영자·교수자. 현재 `operator`·`reviewer`·`admin`은 **업무 계정**, `developer`는 **개발자**로 표시됩니다. 네 계정 모두 사람·AI 기본 결과를 열고, 공유 의견을 수정하고, 새 최종본을 만들 수 있습니다.

## 1. 언제 사용하는 기능인가요?

사람 또는 AI의 원자료로 기본 계산을 만든 뒤, 행사에서 실제로 확인한 의견을 연결하고 **어떤 판본을 발급에 쓸지 고정**할 때 사용합니다. 교수자는 실제 근거에 대한 의견과 유형을 남길 수 있고, 운영자는 적용된 출처·판본을 확인하여 리포트 단계로 이어갈 수 있습니다. 앱은 두 업무에 역할 제한을 두지 않습니다.

다음 세 가지를 구분하면 작업이 쉬워집니다.

| 자료 | 무엇을 보존하나요? |
| --- | --- |
| 기본 결과 | 특정 채점 원자료의 계산·자동 판정·수동 판정 |
| 행사 의견 | 선택한 기본 결과에 연결한 평가자 원문·명시 유형·근거·완료 상태 |
| 최종본 | 그때 명시한 기본 결과와 현재 의견을 함께 고정한 읽기 전용 결과 |

원자료·자동 비율은 의견을 쓴다고 바뀌지 않습니다. 이미 생성한 최종본도 나중에 의견을 수정했다고 자동으로 바뀌지 않습니다. 수정된 의견을 반영하려면 **새 최종본**을 만들어야 합니다.

## 2. 화면 위치와 사전 조건

**분석·평가 → 독립 채점 → 참가자 열기 → 행사 의견과 최종 결과**에서 사용합니다. 메뉴 경로는 `#/scoring`이며 별도 교수자 전용 메뉴는 없습니다.

참가자 화면에 들어오면 기존 행사 의견 본문이 자동으로 불러와지고 열람이 기록됩니다. 같은 촬영의 타인·AI 기반 또는 타인 작성 의견이면 원평가자의 제출 전 조회가 사전 노출로 분류될 수 있습니다. 독립 평가를 남길 계획이라면 의견 등록 전에 최초 채점을 제출하는 순서로 운영하고, 이미 노출된 경우 시트 목적·노출 이력을 확인하여 검수로 구분합니다. 별도 열기 버튼을 누르지 않았다고 의견을 조회하지 않은 것으로 보지 않습니다.

| 조건 | 확인 방법 |
| --- | --- |
| 로그인·대상·회차 | 활성 계정으로 로그인하고 참가자·선택 회차를 확인합니다. |
| 고정 기본 결과 | 사람 채점의 제출 원자료 계산 또는 게시된 AI 기본 결과가 있어야 합니다. [독립 채점](K-DOG_독립채점_사용설명서_v1.0_20261013.md)과 [AI 분석](K-DOG_AI분석_사용설명서_v1.0_20261013.md)을 참고합니다. |
| 정확한 기본 판본 | 의견·근거·최종본은 같은 대상·회차·기본 결과판에 연결되어야 합니다. 다른 기본 결과로 바꾸면 의견 연결도 다시 확인해야 합니다. |
| 파일 무결성 | 고정 원자료와 기본 결과의 파일·해시·영상 참조를 읽고 검증할 수 있어야 합니다. |
| 공통 업무 범위 | 타인의 기본 결과·의견·최종본을 바로 열 수 있습니다. 공개 허가·재개방 승인·교수자 배정은 없습니다. 옛 동의·삭제 상태는 차단 조건이 아닙니다. |

최종본을 만들기 위해 여섯 영역을 모두 작성하거나 모든 사람 판정을 완료할 필요는 없습니다. 확인되지 않은 영역은 원자료·부족·보류 상태를 함께 고정합니다. 「모든 사람이 승인해야 발급」이라는 단계도 없습니다.

**사람 독립 채점과 행사 의견은 최종본의 필수 단계가 아닙니다.** 게시된 AI 기본 결과만 선택하고 의견 없이도 최종본을 만들 수 있으며, 서버도 기본 결과의 사람/AI 구분과 사람 시트 제출 여부를 확인하지 않습니다. 다만 이렇게 만든 최종본은 영역별 상태가 확정이 아닐 수 있으므로 [§9의 안내](#ai-기본-결과만으로-만든-최종본)를 확인하세요.

## 3. 사용할 고정 기본 결과 선택

1. **의견·최종 목록 새로고침**을 누릅니다.
2. **행사에 사용할 고정 기본 결과**에서 평가자·사람/AI·원자료 판본·계산 판본을 확인하고 선택합니다.
3. 선택 후 표시되는 평가자와 기본 결과판, 입력판을 확인합니다. 같은 이름의 참가자라도 다른 회차·판본을 섞지 않습니다.
4. 이미 의견이 있으면 **현재 행사 의견**에서 의견 판본·상태·작성 계정을 확인합니다.
5. 기존 의견에 연결된 기본 결과를 사용하려면 **현재 의견의 고정 기본 결과 선택**을 누르면 됩니다.

선택 목록에는 현재와 보존 기본 결과판이 포함됩니다. 오래된 판본을 선택하는 것 자체가 오류는 아니지만, **어느 입력을 발급하려는지 명시적으로 결정**해야 합니다. 이전 판본을 최신 촬영의 결과처럼 설명하지 마세요.

기존 의견과 다른 기본 결과를 선택하면 원문이 보여도 이전 근거 코드·장면이 새 입력에 유효하지 않을 수 있습니다. **이전 근거 ○○ 제거** 등의 안내에 따라 근거를 다시 연결하여 저장한 뒤 최종본을 만듭니다.

## 4. 여섯 영역 의견 작성

먼저 **의견 평가자**에 실제 해석을 남기는 평가자 이름을 적습니다. 이 이름과 실제 로그인 저장 계정은 서로 다른 기록입니다. 예를 들어 교수자의 의견을 운영자가 입력하면 평가자 이름과 저장한 계정이 각각 보존됩니다.

| 영역 | 작성하는 내용 |
| --- | --- |
| 애착 | 분리·재회·접촉·탐색 등 실제 근거에서 확인한 반려견·보호자 관계 의견 |
| 교육태도 | 보호자의 행동과 실제 관찰 기회를 바탕으로 한 교육태도 의견 |
| 사람 반응 | 보호자·낯선 사람 등 사람에 대한 실제 반응 |
| 비사회적 반응 | 물건·과제 등 사람 이외 자극에 대한 실제 반응 |
| 환경 | 관찰 환경과 실제 환경 반응에 대한 의견 |
| 성향 | 확인된 관찰 범위를 바탕으로 정리할 성향 의견 |

1. 필요한 영역의 **○○ 의견 원문**에 실제 의견을 적습니다. 양식 예시를 관찰 결과처럼 복사하지 않습니다.
2. **근거 항목·반대 근거·고정 장면**을 펼칩니다.
3. 해당 의견과 연결되는 **근거 원코드**를 체크합니다. 선택 목록에는 고정 기본 입력의 실제 유효 관찰과 확인량이 있는 근거가 나옵니다.
4. 반대 사례도 확인하고 해당 항목을 **반대 근거로 검토**에 체크합니다.
5. **반대 근거 검토**에 상충하는 관찰을 어떻게 검토했는지 적습니다. 반대 사례가 없으면 검토 후 없는 이유를 적습니다.
6. 특정 근거를 강조할 필요가 있으면 **지정 장면**을 체크합니다. 영상·카메라·원본 시각·실제 관찰량은 원항목의 근거 그대로 연결됩니다.
7. 필요한 경우 **D39 우선 도움**에 도움 방향을 적습니다.

지정 장면은 원항목의 근거 연결입니다. 현재 신규 리포트는 사진과 「오늘의 장면들」을 출력하지 않으므로 지정 장면을 선택해도 사진 카드가 생기지 않습니다. 관찰 사건과 시각 근거는 계속 보존됩니다.

## 5. 명시 유형과 서술 의견의 차이

**애착**과 **교육태도**에는 **명시 유형**과 **유형 근거**가 있습니다. 다른 네 영역은 원문 의견으로 보존하며 임의 유형을 추론하지 않습니다.

| 명시 유형 영역 | 화면의 선택값 |
| --- | --- |
| 애착 | 곁에서 안심하는 사이 / 가까이 있어도 안심이 어려운 사이 / 거리를 두고 지내는 사이 / 다가감과 물러섬이 함께 나오는 사이 |
| 교육태도 | 허용형 / 조율형 / 통제형 |

유형을 명시하려면 평가자·유형 근거·해당 영역의 실제 지지 근거가 필요합니다. 반대 근거 또는 검토 후 없는 이유도 확인합니다. 교육태도는 실제 관찰 기회가 있는 배점 근거여야 하며, 분리·재회가 미실시인 관계 판단은 보류됩니다.

의견을 저장한 뒤 **유형 선택 미적용**이 나오면 선택값이 있다는 사실만으로 그 유형이 적용된 것은 아닙니다. 안내된 근거·반대 근거·조건을 보완하거나 유형 없는 의견으로 남깁니다. **의견 완료 여부**와 **유형 선택 유효성**은 별개로 확인합니다.

애착 원문을 작성하고 유형을 선택하지 않은 경우에는 아래 별도 AI 해석 경로를 사용할 수 있습니다. 교육태도 원문만으로 유형을 자동 추정하는 버튼은 제공하지 않습니다.

## 6. 초안 저장과 실제 완료

### 작성 중으로 저장

1. 원문과 근거를 작성합니다.
2. **B40 의견 완료 요청**을 아직 체크하지 않습니다.
3. **의견 저장·상태 변경 사유**를 적습니다.
4. **의견 저장·완료 조건 확인**을 누릅니다.
5. **작성 중** 상태와 의견 판본을 확인합니다.

작성 중 의견은 최종본에 출처로 연결할 수 있지만 완료 의견으로 적용되지 않습니다. 내용을 중간 저장해 두고 나중에 다시 작성할 수 있습니다.

### 완료 의견으로 저장

현재 실제 완료 조건은 다음 세 가지입니다.

- **B40 의견 완료 요청**을 체크했습니다.
- **의견 평가자**가 있습니다.
- 여섯 영역 중 적어도 하나에 실질적인 **의견 원문**이 있습니다.

조건을 준비한 뒤 사유를 적고 **의견 저장·완료 조건 확인**을 누릅니다. **실제 완료: 충족 · 완료**가 나왔는지 확인합니다. 체크만 했거나 D39 도움만 썼거나 유형만 고른 경우에는 완료되지 않습니다. 화면에 나오는 미충족 사유를 해결해 다시 저장합니다.

여섯 영역 전체를 채우도록 강제하지 않습니다. 완료된 의견의 원문이 있는 영역만 그 의견을 적용하고, 원문이 없는 영역은 유효 수동 선택·고정 기본 결과 등 해당 출처를 사용합니다. 자료가 없는 영역에 형식적으로 문장을 만들어 넣지 마세요.

실제 빈 Excel 원양식의 「입장 선택」을 완료의 대안으로 삼는 기능은 확인 대기입니다. 현재 화면에서는 위 세 가지 조건으로 완료 여부를 확인합니다.

## 7. 유형 없는 완료 애착 의견을 AI로 해석하기

이 기능은 **완료 상태의 애착 의견 원문이 있고, 애착 명시 유형이 없는 경우**에만 표시됩니다. 의견과 선택 기본 결과가 일치해야 하며 활성 AI 설정과 실제 실행 환경도 필요합니다.

1. 애착 의견을 실제 완료 상태로 저장합니다. 아직 입력 중인 내용이 있다면 먼저 저장합니다.
2. **새 최종본 고정** 안의 **완료 애착 의견 AI 해석**을 확인합니다.
3. **완료 애착 의견을 AI로 해석**을 누릅니다.
4. 실행 상태와 예약 호출 수를 확인합니다. **애착 해석 상태 새로고침**으로 조회합니다.
5. 원하지 않는 진행 중 작업은 **애착 해석 중지**로 중지할 수 있습니다.
6. **이 해석 판본을 새 최종본에 연결합니다** 안내가 나오면 해당 결과를 연결하여 새 최종본을 생성합니다.

이 실행은 원채점·기본 계산을 다시 호출하지 않습니다. 고정 원문과 기본 결과를 보존하고 별도 AI 해석을 남깁니다. 사람의 명시 유형을 다시 바꾸는 기능도 아닙니다. 애착 의견이 불명확하거나 근거가 부족하면 유형을 보류할 수 있습니다.

**원채점 재호출 없이 처리 중이거나 보류·실패했습니다**가 나오면 상태를 새로 조회하여 처리 중인지, 보류·실패인지 구분합니다. 접수 응답이 확인되지 않은 요청은 같은 입력으로 다시 누를 때 같은 요청 ID를 사용합니다. 의견·기본 판본을 바꾸면 이전 해석은 새 최종본의 일치 출처로 사용할 수 없습니다.

## 8. 의견 수정·철회와 동시 작업

다른 직원이 작성한 완료 의견도 바로 수정·저장할 수 있습니다. 원문 평가자와 저장 계정은 별도로 기록되고 이전 의견판은 보존됩니다. 별도 재개방 승인을 받는 단계는 없습니다.

의견을 더 이상 현재 적용 의견으로 사용하지 않으려면 **의견 저장·상태 변경 사유**를 적고 **의견 철회**를 누릅니다. 철회는 의견의 업무 상태입니다. 참가자의 동의 철회나 자료 삭제 작업과 다릅니다. 기존 최종본·발급본은 당시 고정한 원문과 출처를 유지합니다. 이후 발급에 철회 상태를 반영하려면 새 최종본을 만들어 사용합니다.

미저장 입력이 있으면 철회나 최종본 생성이 비활성화될 수 있습니다. 먼저 저장하거나 **미저장 의견 버리고 최신 조회**를 선택합니다. 버리는 동작은 아직 저장하지 않은 편집을 없앱니다.

다른 직원의 저장이나 기본 결과 변경으로 409 충돌이 발생하면 자신의 편집값은 유지됩니다. 필요한 원문을 확인해 둔 뒤 최신 의견과 연결 기본판을 읽고 차이를 검토하여 다시 입력·저장합니다. 최신판을 확인하지 않고 반복 저장해도 충돌은 해결되지 않습니다.

## 9. 새 최종본 만들기

1. **행사에 사용할 고정 기본 결과**가 맞는지 확인합니다.
2. 현재 의견의 판본·상태와 기본 결과 연결을 확인합니다. 의견이 없으면 **없음**, 작성 중·철회이면 해당 상태가 함께 고정됩니다.
3. 미저장 의견이 없도록 정리합니다.
4. AI 후속 해석을 사용할 경우 고정 해석 참조가 준비되었는지 확인합니다.
5. **최종본 고정 사유**를 적습니다. 예: 「재회 근거 재검토 후 의견 r3을 발급 기준으로 고정」.
6. **선택한 판본으로 새 최종본 생성**을 누릅니다.
7. 아래 **고정 최종본 · 읽기 전용**에서 기본판·의견판·작성 계정·적용 출처와 각 영역의 보류 사유를 확인합니다.

영역별 적용 순서는 **완료된 해당 영역 의견 → 유효 수동 선택 → 고정 기본 결과**입니다. 유형 없는 완료 애착 의견에 별도 AI 해석을 연결한 경우는 **완료 의견의 AI 후속 해석**으로 표시됩니다. 원래 자동 유형과 자동 교육태도 비율은 보존됩니다.

완료 의견 원문이 있지만 명시 유형이 유효하지 않거나 필요한 AI 해석을 연결하지 않은 경우, 해당 영역의 유형이 보류·규칙 대기로 남을 수 있습니다. 다른 출처가 있으니 알아서 확정되었을 것이라고 생각하지 말고 최종본의 **출처·상태·사유**를 읽습니다.

현재 의견을 누락하거나 철회 전 과거 의견을 임의로 연결해 우회할 수 없습니다. 기존 의견과 다른 기본판을 사용하려면 공유 의견을 그 기본판과 유효 근거에 맞춰 수정·저장한 뒤 최종본을 만듭니다. 서버 오류에 과거 용어 「재개방」이 나오더라도 현재 화면에 별도 승인 절차는 없습니다.

### AI 기본 결과만으로 만든 최종본

사람 채점 시트와 행사 의견 없이 **게시된 AI 기본 결과**를 선택하여 최종본을 만들 수 있습니다. 이때 화면 조건은 기본 결과 선택, 최종본 고정 사유 입력, (의견이 있다면) 의견과 기본 결과의 일치뿐입니다.

| 확인할 것 | 내용 |
| --- | --- |
| 상단 표시 | AI 원본(판본 r1)을 사람이 수정하지 않았고, 수동 판정·완료 의견·우선 도움이 없을 때만 **독립 AI 기본 결과**로 표시됩니다. 하나라도 있으면 **선택한 입력과 의견을 적용한 행사 결과**로 표시됩니다. |
| 의견 | 의견이 없으면 의견은 **없음**으로 고정됩니다. 작성 중·철회 의견은 출처로 고정되지만 완료 의견으로 적용되지 않습니다. |
| 비교 | 사람 채점과의 비교는 선택 사항입니다. 비교가 필요하면 먼저 사람 시트를 제출한 뒤 참고 결과를 여는 순서([독립 채점 §1](K-DOG_독립채점_사용설명서_v1.0_20261013.md))를 지킵니다. |

**최종본이 만들어진다는 것은 모든 영역이 확정되었다는 뜻이 아닙니다.** 의견 없이 AI 기본 결과만 쓰면 영역별 상태가 대체로 다음처럼 나옵니다.

| 영역 | 화면에 나오는 상태 | 읽는 방법 |
| --- | --- | --- |
| 애착 | AI 애착 판단이 있으면 **유형 선택 적용** 또는 판정보류, 판단이 없으면 **규칙 확인 대기** | 판정보류는 화면에 `held`라는 영문 상태로 표시될 수 있습니다. 같은 뜻으로 읽고 사유를 확인합니다. |
| 교육태도 | 자동 유형이 있으면 **작성 중**(자동 초안), 없으면 **근거 부족** | 자동 초안은 교수 확정이 아닙니다. 원래 자동 배점 비율은 그대로 보존됩니다. |
| 사람 반응·비사회적 반응·환경 | 확인된 원관찰이 있으면 **원관찰 있음**, 없으면 **근거 부족** | 설명 문장이나 유형은 이 단계에서 만들지 않습니다. |
| 성향 | **근거 부족** | 기본 결과만으로는 성향의 확정 해석을 연결하지 않습니다. |

따라서 AI 기본 결과만으로 발급한 리포트에는 초안·근거 부족·보류 표시가 포함될 수 있습니다. 사람 검수 후 발급할지 AI 기본 결과로 바로 발급할지는 앱이 강제하지 않는 **팀의 운영 기준**입니다. 검수가 필요하면 AI 시트를 사람이 수정하거나 행사 의견·수동 판정을 남기고 **새 최종본**을 만든 뒤 그 판본을 발급에서 선택합니다. 이 경우 최초 AI 판본은 보존되고 새 최종본은 더 이상 독립 AI 결과로 표시되지 않습니다.

## 10. 보존 최종본 읽기와 결과 확인

**보존 최종본** 목록에서 시각·작성 계정·기본판·의견판을 확인한 뒤 **최종본 짧은식별자 읽기**를 누릅니다. 여기에는 실제로는 실행마다 다른 8자리 식별자가 표시됩니다.

읽기 전용 상세에서 다음을 확인합니다.

- 기본 결과와 의견 판본이 의도한 판본인지
- 각 영역의 출처가 완료 의견/AI 후속 해석/유효 수동 선택/기본 결과 중 무엇인지
- 유형·원문·원래 자동 유형·사용 항목·반대 근거·보류 사유가 일치하는지
- **우선 도움**이 완료 의견에서 적용되었는지
- 자동 교육태도 배점 비율이 보존되어 있는지
- 사람의 의견·수정이 반영된 결과를 최초 독립 AI 결과로 표시하지 않는지

**최종본·기본 입력·의견 출처 해시**는 판본 확인이나 문제 전달이 필요할 때 펼칩니다. 최종본 자체는 편집하지 않습니다. 수정이 필요하면 기본 판정 또는 의견을 수정한 뒤 **새 최종본 생성**으로 이어갑니다.

## 11. 오류·보류 해결

| 상황 | 해결 방법 |
| --- | --- |
| 기본 결과 목록이 비어 있음 | 채점 원자료 저장·제출·계산 또는 AI 결과 게시를 먼저 마칩니다. |
| 실제 완료 미충족 | B40, 평가자, 최소 한 영역의 실질 원문을 확인합니다. D39만으로 완료되지 않습니다. |
| 유형 선택 미적용 | 유형 근거·실제 해당 영역 지지 근거·반대 근거 검토·절차 조건을 확인합니다. 완료 의견 저장과 유형 적용은 별개입니다. |
| 연결할 실제 유효 관찰 없음 | 현재 고정 원자료의 근거를 확인합니다. 없는 영상 근거를 직접 만들어 연결하지 않습니다. |
| 현재 의견과 기본 결과가 다름 | 의견에 연결된 기본 결과를 선택하거나, 의견 원문·근거를 새 기본판에 맞춰 저장합니다. |
| 최종본 생성 비활성화 | 기본 결과 선택, 의견 목록 조회, 일치 연결, 고정 사유, 미저장 의견을 확인합니다. |
| 저장·최종 조립 중 입력/의견/기본 결과 변경 | 최신 목록을 조회하고 필요한 판본을 다시 명시합니다. 미저장 의견은 확인 후 보존하거나 버립니다. |
| 애착 해석 버튼 없음 | 완료 의견인지, 애착 원문이 있는지, 명시 유형을 선택하지 않았는지 확인합니다. |
| AI 해석 보류·실패 | 상태와 실제 근거를 확인합니다. 불명확한 원문이면 실질 의견을 보완해 새 판본으로 해석합니다. 활성 설정·연결 문제는 개발자와 확인합니다. |
| 이미 만든 최종본이 수정 내용과 다름 | 정상적인 판본 보존일 수 있습니다. 수정 후 새 최종본을 만들고 발급에서 그 판본을 선택합니다. |
| AI 결과만 썼는데 영역이 작성 중·근거 부족으로 나옴 | 오류가 아니라 의견·수동 판정이 없는 상태의 정상 표시입니다. 위 「AI 기본 결과만으로 만든 최종본」을 읽고 검수 여부를 정합니다. |
