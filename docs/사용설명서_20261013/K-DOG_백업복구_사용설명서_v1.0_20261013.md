# K-DOG 백업과 복구 사용설명서

버전: v1.0 · 작성일: 2026-10-13 · 제품 기준: `main / 53889b7` · 평가 기준: S1.1

메뉴 경로는 **자료 관리 → 백업·복구**입니다. 운영자·교수자·관리자·개발자 모두 백업을 만들 수 있습니다. 화면에서는 저장공간·복구 안내 확인과 백업 생성이 가능하며, 실제 복원과 파일 정리는 서버 PC의 관리 명령으로 수행합니다.

## 1 언제 사용하나요

행사 운영 전후, 많은 자료를 등록한 뒤, PC 교체·업데이트·장애 대응 전에 백업을 만듭니다. 복원은 검증된 백업 시점으로 별도 데이터 폴더를 만들 때 사용합니다. 파일 정리는 서버 저장공간을 관리할 때 참조되지 않는 관리 파일을 제거하는 기능입니다.

‘복원’은 백업과 현재 자료를 합치는 기능이 아닙니다. 백업 이후의 변경은 복원 결과에 포함되지 않으므로, 현재 데이터가 읽힌다면 이를 별도로 백업한 뒤 복구를 진행하세요.

## 2 화면에서 백업 만들기

1. **백업·복구** 메뉴를 엽니다.
2. **자료 백업·복구**를 펼칩니다.
3. **남은 공간**, **최근 백업**, 복구 안내를 확인합니다. 백업은 DB와 참조 파일을 복사하므로 서버 디스크에 충분한 공간이 필요합니다.
4. **자료 백업 생성 · 키 제외**를 누릅니다.
5. **파일 검증·백업 중…** 동안 기다립니다. 여러 번 눌러 새 백업을 계속 만들지 마세요.
6. **검증된 백업 저장 완료: 경로** 메시지를 확인하고 저장된 폴더 경로를 기록합니다. 최근 백업 표시를 다시 보려면 메뉴에 재진입해 확인합니다.

파일은 **서버 PC의 데이터 폴더 옆 `backups` 아래 새 폴더**에 저장됩니다. 브라우저가 열려 있는 촬영 PC에 다운로드되는 기능은 아닙니다. 보관용 다른 드라이브로 옮길 때는 백업 폴더 전체를 복사하세요.

## 3 백업에 포함되는 자료

참가자 입력과 회차, 원본·영상 정보 미등록 파일, 채점 시트·의견·결과·발급 파일, 검수 참고 자료, 비교 집단, 연구 내보내기 등 DB에서 참조하는 관리 파일을 검증하여 보존합니다. `backup.json`은 백업 파일 목록과 해시를 기록합니다. 해시는 파일 내용이 달라졌는지 확인하는 식별값입니다.

공급자 API 키와 로그인 세션은 제외됩니다. 계정 자체가 사라지는 것은 아니며 복원 후 다시 로그인합니다. 키는 개발자가 대상 PC에서 다시 등록해야 합니다. 백업에도 참가자 자료가 포함되므로 업무 자료와 같은 보관 기준으로 관리하세요.

## 4 관리 명령으로 별도 백업 만들기

담당자가 설치본의 프로그램 폴더에서 실행하는 예입니다. 데이터 경로·새 백업 경로·`manager`를 실제 서버의 경로와 활성 업무 계정으로 바꿉니다. 대상 폴더는 아직 존재하지 않아야 하며 소스·원본 데이터 폴더와 분리합니다.

```powershell
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" backup "E:/K-DOG/backup-20261013" --actor manager
```

백업 경로·파일 수·작성 시각 결과가 나오면 성공입니다. 설치본에서 `runtime/python/python.exe`가 없는 개발 환경은 [개발 안내](../DEVELOPMENT.md)의 실행 방식으로 같은 `app.manage` 명령을 사용합니다.

## 5 검증된 백업 복원하기

1. 어떤 백업 날짜로 돌아가야 하는지 확인합니다. S1 초기화 경계가 있는 운영 DB에서는 같은 초기화 이후의 백업이 필요합니다.
   복원 명령의 `--data-dir`은 경계를 확인할 기존 `kdog.sqlite3`가 있는 데이터 폴더여야 합니다. DB가 유실되었거나 새 PC에 기존 DB가 없다면 빈 경로로 아래 명령을 바로 실행할 수 없습니다. 설치·서버 담당자가 먼저 기존 DB와 호환 복구 경로를 확인해야 합니다.
2. 서버의 API·worker·전처리를 모두 종료합니다. 설치본은 K-DOG 실행 창을 닫습니다.
3. 백업 폴더와 분리된 **새 복원 폴더**를 정합니다. 현재 운영 폴더와 겹치거나 기존 폴더를 덮어쓰는 복원은 허용되지 않습니다.
4. 프로그램 폴더에서 다음 형식으로 실행합니다.

```powershell
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" restore "E:/K-DOG/backup-20261013" "D:/K-DOG/restored-20261013"
```

5. `백업 snapshot 복원 완료` 결과를 확인합니다. snapshot은 백업 시점에 고정한 DB·자료·변경 기록을 뜻합니다.
6. 설치·서버 담당자가 앱이 사용할 데이터 경로를 복원 폴더로 지정합니다. 복원 명령 자체가 현재 운영 경로를 자동 전환하지는 않습니다.
7. 앱을 시작하여 다시 로그인하고 참가자·회차·영상·이전 발급 파일을 확인합니다. 개발자는 같은 Windows 실행 계정에서 공급자 키를 등록하고 AI 준비 상태를 확인합니다.

현재 삭제대장을 다시 적용하거나 백업 이후 기록을 병합하지 않습니다. 구판 동의·삭제 정책 앱을 이 운영 DB에 실행하지 마세요. 실패 복구도 호환 앱과 격리된 데이터 경로에서 진행합니다.

## 6 참조되지 않는 파일 정리하기

이 작업은 실제 파일을 제거합니다. 저장공간 정리가 필요한 경우 먼저 검증된 백업을 만들고, API·worker·전처리를 모두 종료한 서버에서 담당자가 수행합니다.

```powershell
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" clean
```

정리는 모든 참조 파일의 존재·해시를 확인한 뒤 참조되지 않는 관리 파일만 제거합니다. `removed_files`는 제거한 파일 수, `retained_files`는 보존한 참조 파일 수입니다. 참가자·채점표·발급본을 연쇄 삭제하는 기능이 아닙니다. 과거 삭제 요청에 따른 purge 옵션은 지원하지 않습니다.

## 7 문제 해결

| 상황 | 해결 방법 |
| --- | --- |
| 백업·복원 해시 오류 | 해당 파일이 유실·변경되었는지 담당자가 확인합니다. 오류가 난 백업을 정상 백업으로 취급하지 않습니다. |
| 새 폴더를 지정하라는 안내 | 존재하지 않는 경로를 사용합니다. 원본·소스·백업 폴더와 겹치지 않게 지정합니다. |
| 복원·정리 중 실행 프로세스 오류 | K-DOG 실행 창, 별도 worker, 전처리가 모두 종료되었는지 확인한 뒤 재시도합니다. |
| S1 이전 백업 거절 | 같은 S1 초기화 이후의 호환 백업을 사용합니다. 옛 점수를 복원하기 위해 경계 검사를 우회하지 않습니다. |
| 복원 후 AI 준비 안 됨 | 공급자 키는 백업에서 제외됩니다. 개발자가 대상 PC에 다시 등록합니다. |
| 공간 부족 | 서버 디스크와 백업 경로의 공간을 확인합니다. 원본 파일을 수동 삭제하기 전에 백업·참조 정리 절차를 사용합니다. |
