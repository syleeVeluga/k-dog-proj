# K-DOG AI 분석 사용설명서

버전: v1.0 · 작성일: 2026-10-13 · 확인 기준: `main`의 `53889b7`, S1 및 ES03 진행·조회 복구 화면

대상: AI 관찰 초안을 생성·검토하는 운영자·교수자. `operator`·`reviewer`·`admin`은 화면에 **업무 계정**, `developer`는 **개발자**로 표시되며 네 계정 모두 AI 분석을 시작·조회·중지·재시도할 수 있습니다. 활성 AI 설정과 키 설정의 변경은 개발자 업무입니다.

## 1. 언제 사용하나요?

촬영과 전처리를 마친 뒤 AI가 항목별 관찰 원자료를 작성하고, 앱의 기본 계산과 근거 기반 애착 판단을 수행하게 할 때 사용합니다. 사람 채점과 비교하거나 교수자가 검수할 초안을 마련하는 단계입니다.

현재 AI 분석은 **숫자 83개·관찰 메모 3개**를 요청하고 **자동 4개**는 앱이 계산합니다. 관찰 → 계산 → 별도 AI 애착 판단 → 결과 게시 순서입니다. 한 번의 버튼 클릭으로 곧바로 리포트가 발급되는 기능은 아닙니다. 게시 결과를 확인한 뒤 [해석과 최종 결과](K-DOG_해석과최종결과_사용설명서_v1.0_20261013.md), [리포트 발급](K-DOG_리포트발급_사용설명서_v1.0_20261013.md)으로 이어집니다.

독립 사람 평가가 필요하다면 교수자는 AI 원자료를 열기 전에 자신의 최초 관찰을 저장·제출하는 순서로 작업하세요. AI 실행의 상태 조회에는 점수·판정이 표시되지 않습니다. AI 시트나 기본 결과를 실제로 열면 열람 이력이 기록됩니다.

다만 같은 참가자 화면에는 **행사 의견과 최종 결과**도 함께 표시되며, 기존 행사 의견이 있으면 본문을 자동 조회해 열람을 기록합니다. 같은 촬영의 타인·AI 기반 또는 타인 작성 의견이면 원평가자의 제출 전 노출로 분류될 수 있으므로, 독립 평가가 목적일 때는 행사 의견 등록 전에 최초 관찰·제출을 마칩니다. 이미 노출된 자료는 목적·노출 이력을 확인하여 검수로 작업하세요. AI 상태 조회 자체와 같은 화면에서 함께 불러오는 의견 열람을 구분합니다.

## 2. 화면 위치와 시작하기 전 조건

**분석·평가 → 독립 채점 → 참가자 열기 → AI 분석**에서 사용합니다. 메뉴 경로는 `#/scoring`입니다. 별도의 AI 분석 로그인이나 AI 전용 메뉴는 없습니다.

| 조건 | 확인과 준비 |
| --- | --- |
| 대상·회차 | 반려견 이름, 참가자번호, 선택 촬영 회차를 확인합니다. |
| 현재 입력의 전처리 | 전처리 결과가 완료 또는 부분 완료여야 하며, 현재 접수 입력판과 일치해야 합니다. **이전 입력 기준** 결과로 새 분석을 시작할 수 없습니다. |
| 활성 설정 | 개발자가 관찰 적용 범위를 확인한 AI 설정을 활성화해야 합니다. 설정이 없으면 안내가 표시됩니다. |
| 서버 실행 환경 | 분석 작업을 처리하는 서버가 실행 중이어야 합니다. 실제 공급자 이용에 필요한 키·연결 문제는 개발자와 확인합니다. |
| 상태 조회 확인 | 준비 정보와 실행 상태를 최신 조회로 확인해야 시작·중지·재시도할 수 있습니다. 연결이 끊긴 상태에서 화면에 남은 과거 상태를 확정 상태로 보지 않습니다. |
| 권한·옛 정책 | 다른 사람이 시작한 실행도 함께 조회·제어할 수 있습니다. 배정·동의 확인·공개 허가·재개방 승인 절차는 없습니다. |

전처리가 부분 완료라면 사용할 수 있는 카메라·클립으로 분석하고, 없는 자료는 관찰 부족 사유로 유지합니다. 모든 항목을 임의로 채우는 기능이 아닙니다. [전처리 설명서](K-DOG_전처리_사용설명서_v1.0_20261013.md)에서 카메라·범위별 상태를 먼저 확인하세요.

## 3. 새 AI 분석을 시작하는 순서

1. **AI 실행 상태 새로고침**을 눌러 현재 입력·설정·전처리 상태를 확인합니다.
2. **기술 정보**를 펼쳐 입력판, 활성 설정, 기본 예정 공급자 호출 수를 확인합니다. 호출 수는 관찰 항목 개수와 다릅니다.
3. 처음 분석하는 경우 **성공 항목군 재사용**을 **재사용 없이 새 실행**으로 둡니다.
4. **AI 분석 시작**을 한 번 누릅니다.
5. 상단의 **AI 초안: 분석 요청 중**이 요청 접수 후 **분석 대기**로 바뀌는지 확인합니다.
6. **현재 AI 분석 실행**에서 **내가 시작한 이번 실행**, 입력판, 시작 시각을 확인합니다.
7. 실제 진행 중에는 현재 단계와 각 단계의 완료/예정/실패/실행 중/대기 수를 읽습니다.

메뉴를 열거나 새로고침하는 것만으로 분석이 시작되지는 않습니다. **AI 분석 시작**이 실행을 만드는 명시 동작입니다. 실제 공급자 호출과 비용이 생길 수 있으므로 이미 같은 목적의 실행이 진행 중인지 목록을 먼저 확인합니다.

클릭 직후 응답이 늦다고 여러 번 누르거나 창을 새로 만들어 분석을 겹치게 시작하지 마세요. 접수 응답이 유실되면 화면은 같은 요청의 접수 여부를 조회하고 **요청 접수 여부 확인 중**을 표시합니다. 이 상태는 실패 확정이나 미접수 확정이 아닙니다.

## 4. 진행 표시 읽는 방법

상단 요약은 **현재 선택한 하나의 실행**에 관한 표시입니다. 이전에 성공한 결과가 있어도 새 분석이 진행 중이면 새 분석의 상태를 표시합니다. 과거 결과는 **이전 분석 결과 있음**으로 구분됩니다.

| 단계 | 무엇을 하고 있나요? |
| --- | --- |
| 항목군 관찰 | 고정한 계획의 항목군별 관찰 원자료를 요청합니다. 완료 수는 항목군의 처리 상태이며 83개 숫자 각각의 최종 승인 수가 아닙니다. |
| 기본 계산 | 확인된 원자료에 앱의 계산 규칙을 적용합니다. |
| 애착 판단 | 원자료·계산·근거와 반대 근거를 바탕으로 별도 AI 판단을 수행합니다. |
| 결과 게시 | 원자료와 기본 계산 등 검증된 결과를 시트·결과로 연결합니다. |

각 단계의 **완료 ○ / 예정 ○ · 실패 ○ · 실행 중 ○ · 대기 ○**를 확인합니다. **실행 계획에 없음**은 이 고정 실행에 해당 단계의 처리 계획이 없다는 뜻입니다. **명시 재사용**은 이전 성공 결과를 검증하여 사용한 것이며 새 공급자 호출로 읽지 않습니다.

앱은 확인되지 않은 AI 내부 백분율이나 남은 시간을 추정하지 않습니다. 상단의 **현재 단계**는 현재 실행 작업이 확인될 때만 표시됩니다. **실행 상태 확인 필요 · 현재 단계를 확인할 수 없습니다**라면 오래된 진행 기록을 현재 작업으로 단정하지 말고 상태를 다시 조회합니다.

**시작**은 서버에 실행이 만들어진 시각, **기록 변경**은 실행 기록이 변경된 시각, **마지막 확인**은 브라우저가 상태 조회에 성공한 시각입니다. 서로 다른 시각이므로 「기록 변경」을 마지막 통신 시각으로 해석하지 마세요.

## 5. 상태마다 무엇을 해야 하나요?

| 화면 표시 | 의미 | 다음 행동 |
| --- | --- | --- |
| 분석 요청 중 | 서버로 시작 요청을 보내는 중 | 접수 결과를 기다립니다. |
| 요청 접수 여부 확인 중 | 시작 응답을 확정하지 못해 같은 요청을 조회하는 중 | 연결을 확인하고 상태 새로고침을 사용합니다. 새 실행을 자동으로 다시 만드는 상태가 아닙니다. |
| 분석 대기 | 실행이 접수되어 처리 순서를 기다리는 중 | 현재 실행과 시각을 확인합니다. 긴 대기는 서버 작업 상태를 담당자에게 확인합니다. |
| 분석 중 | 실제 실행 중 | 단계와 실패 수를 확인하며 기다립니다. |
| 자동 재시도 대기 | 제한된 자동 재시도 예정 | 표시된 **자동 재시도 예정** 시각·사유를 확인합니다. 시각이 지났다는 이유만으로 실행 중이라고 추정하지 않습니다. |
| 분석 완료 | 성공했고 게시된 결과가 있음 | AI 시트·기본 결과를 실제로 열어 검토합니다. |
| 결과 게시 확인 필요 | 성공 상태지만 화면에서 게시 결과를 확인하지 못함 | 다시 조회하고, 계속되면 실행 식별자와 사유를 전달합니다. |
| 일부 완료 · 확인 필요 | 일부 유효 결과가 있지만 실패한 단계가 있음 | 성공·실패를 나눠 확인합니다. 필요하면 성공 항목군을 명시 재사용해 **새 실행**을 만듭니다. |
| 분석 실패 | 실행을 완성하지 못함 | 실행 사유와 단계별 오류를 확인한 뒤 조건을 해결하여 고정 입력 재시도 또는 새 실행을 선택합니다. |
| 설정 확인 필요 | 설정 관련 조건을 해결해야 함 | 개발자에게 실행 사유·입력판·설정판을 전달합니다. |
| 중지됨 | 실행 중지 상태 | 이미 예약된 호출의 과금 여부를 확인하고, 필요할 때 허용된 재시도를 합니다. |
| 준비 안 됨 | 현재 선택 실행이 없거나 시작 조건 미충족 | 현재 입력 전처리·활성 설정·상태 조회를 확인합니다. |

**이전 입력 기준 실행입니다**와 **현재 활성 설정과 다릅니다**는 상태와 별개의 안내입니다. 예전 성공 결과를 현재 입력으로 새로 분석한 결과처럼 사용하지 마세요. 어떤 입력·설정으로 만들어졌는지 확인한 뒤 해당 판본을 사용하거나 최신 입력으로 새 분석을 수행합니다.

## 6. 결과를 실제로 확인하기

1. 실행 목록에서 완료 여부와 **원자료와 기본 계산이 게시되었습니다** 안내를 확인합니다.
2. 같은 독립 채점 화면의 시트 목록에서 해당 AI 시트를 찾습니다. 필요하면 목록의 자동 갱신을 기다립니다.
3. **원평가자 출처**를 펼쳐 AI 여부와 고정 입력을 확인합니다.
4. **시트 열기**를 누릅니다. 이때 실제 AI 결과 열람이 기록됩니다.
5. 항목별 원값, 빈값 상태, 실제 영상 근거, 관찰량을 확인합니다. AI가 쓰지 못한 행은 부족 이유를 읽습니다.
6. 시트 아래 **계산과 기본 판정**에서 기본 결과를 선택하여 자동 비율·분자/분모·제외 항목·애착 판단과 보류 사유를 확인합니다.
7. 교수자 검토 후 필요한 경우 사람 수정 판본 또는 행사 의견을 남깁니다. [독립 채점 설명서](K-DOG_독립채점_사용설명서_v1.0_20261013.md)의 정정 방법을 따릅니다.

실행 상태 카드에는 점수·판정·관찰 문장이 나오지 않습니다. 「분석 완료」만으로 모든 관찰이 충분하거나 모든 판단이 확정되었다고 보지 마세요. AI 시트의 관찰량·근거와 기본 결과의 보류 사유까지 확인해야 합니다.

게시된 AI 기본 결과는 사람 채점 없이도 [해석과 최종 결과](K-DOG_해석과최종결과_사용설명서_v1.0_20261013.md)에서 최종본의 기본 결과로 선택할 수 있습니다. 의견·수동 판정이 없으면 영역별 상태가 초안·근거 부족일 수 있으므로 사람 검수 여부는 팀 기준으로 정합니다.

AI 원본을 사람이 수정하면 후속 판본은 사람 수정·검수로 구분되고 최초 AI 판본은 보존됩니다. 타인이 이후 열어 읽는 것과 원평가자가 제출 전에 다른 결과를 참고하는 것은 독립성 기록에서 구분됩니다.

## 7. 중지·재시도·성공 항목군 재사용

### 진행 중 실행 중지

1. **실행 제어 사유**에 중지 이유를 적습니다.
2. 중지하려는 실행의 **이 AI 실행 중지**를 누릅니다. 현재 진행 요약이 다른 실행을 가리킬 수 있으므로 목록의 입력판·시각도 확인합니다.
3. **중지 요청 중** 뒤 **중지됨**으로 바뀌는지 조회합니다.

중지는 이미 예약·전송된 외부 호출을 없었던 것으로 만들지 않습니다. 결과 응답 또는 정산을 확인하지 못했다면 **과금 여부 미확인**이 남을 수 있습니다. 이미 끝난 실행에는 중지 버튼이 없습니다.

### 같은 고정 입력으로 재시도

실패·중지·설정 확인 필요인 실행에서 제공됩니다.

1. 원인을 확인해 해결합니다.
2. **실행 제어 사유**에 재시도 이유를 적습니다.
3. **고정 입력으로 AI 재시도**를 누릅니다.
4. 같은 실행이 다시 대기 상태가 되는지 확인합니다. 최초 실행 요청자는 유지되고 재시도 행위자는 별도로 기록됩니다.

이는 최신 입력으로 갈아끼우는 동작이 아닙니다. 이전 입력 기준이거나 고정 파일·설정·참조 검증을 통과하지 못하면 사용할 수 없습니다. 최신 입력으로 분석해야 한다면 전처리부터 확인해 새 실행을 시작합니다.

### 일부 완료 결과의 성공 항목군 재사용

1. **기술 정보 · 단계별 시간·호출·부분 실패**에서 성공한 항목군과 실패한 항목군을 확인합니다.
2. **성공 항목군 재사용**에서 해당 실행을 명시적으로 선택합니다.
3. 현재 입력·전처리·활성 설정을 확인하고 **AI 분석 시작**을 누릅니다.
4. 새 실행의 진행에서 **명시 재사용** 표시를 확인합니다.

일부 완료는 같은 실행의 재시도 버튼으로 처리하지 않습니다. **성공 부분을 검증해 재사용하는 새 실행**으로 기록합니다. 재사용에는 원본·관찰창·카메라·오프셋·모델·설정 해시의 일치가 필요합니다. 목록에 보인다고 모든 단계 재사용이 보장되는 것은 아니며 서버 검증에서 거절될 수 있습니다.

## 8. 연결이 끊기거나 화면을 다시 열었을 때

실행 중에는 상태를 약 2초 간격으로 조회합니다. 일시적인 조회 오류가 나면 **상태 조회 연결 끊김**과 마지막으로 확인한 상태가 표시되고 재조회를 시도합니다. 마지막 상태가 실행 중이라고 해서 지금도 반드시 실행 중이라는 뜻은 아닙니다.

**AI 실행 상태 새로고침**을 누르거나 브라우저 탭을 다시 활성화하면 최신 상태를 조회합니다. 같은 브라우저 세션의 계정·대상·회차에 저장된 선택 실행과 접수 확인 요청을 복구할 수 있습니다. 저장된 선택이 없으면 내가 처음 시작한 최근 실행을 찾아 표시하며, 공유 실행은 **이 실행 상태 보기**로 직접 선택합니다. 다른 직원의 실행을 선택하면 **실행 직원: 계정명**으로 표시됩니다.

화면을 닫는 것은 중지 버튼을 누르는 것과 다릅니다. 서버 실행을 중지하려면 명시 중지를 사용합니다. 로그인 만료·계정 전환 뒤에는 표시 자료와 실행 선택을 다시 확인합니다. 브라우저 저장 복구를 모든 PC·브라우저 간 자동 복구로 기대하지 마세요.

## 9. 오류·비용 표시를 읽는 방법

| 상황 | 확인과 해결 |
| --- | --- |
| AI 분석 시작이 비활성화됨 | 상태 조회 완료, 활성 설정, 현재 입력의 완료/부분 전처리, 접수 확인 중 요청 여부를 확인합니다. |
| 현재 입력 기준 전처리 필요 | [전처리](K-DOG_전처리_사용설명서_v1.0_20261013.md)에서 최신 입력으로 결과를 만들고 다시 조회합니다. |
| 설정 비활성 안내 | [개발 설정](K-DOG_개발설정_사용설명서_v1.0_20261013.md)의 담당 개발자에게 활성 설정 확인을 요청합니다. 일반 직원의 역할을 바꾸려고 할 필요는 없습니다. |
| 실행 상태가 변경됨·409 | 다른 작업 또는 자동 진행으로 상태가 바뀌었습니다. 최신 상태를 조회하고 그 상태에서 필요한 작업만 다시 합니다. |
| 실패·일부 완료 | 내부 실행 사유 코드와 항목군별 최신 시도를 확인합니다. 유효 결과와 실패 결과를 나눠 검토합니다. |
| 시간 미측정·미확인 비용 | 측정 자료가 없다는 뜻입니다. 0초·무료로 해석하지 않습니다. |
| 과금 여부 미확인 | 호출 예약은 있으나 응답·정산 확인이 불완전한 상태입니다. 실제 공급자 기록을 담당자와 확인합니다. |
| 공급자 임시 파일 정리 미완료 | 원격 임시 파일 정리가 확인되지 않았습니다. 반복 분석을 시작하기 전에 담당자에게 실행 정보를 전달합니다. |
| 상태가 오래 바뀌지 않음 | 마지막 확인 시각과 연결 오류부터 확인합니다. 정상 조회인데 대기가 계속되면 서버 작업 상태를 담당자에게 확인합니다. |

시간 상세의 업로드·공급자 처리 대기·추론·스키마 수리·정리·계산·게시·전체 단계 값은 각 기록의 측정값입니다. 스키마 수리와 전체 단계는 다른 시간과 겹칠 수 있으므로 단순 합산하지 않습니다. 토큰·호출 예약·비용을 서로 같은 지표로 보지 않습니다.

## 10. 마무리와 확인 근거

검토 완료 여부는 실행 성공뿐 아니라 정확한 대상·회차·입력판, 원자료의 유효 관찰과 부족 사유, 애착 판단의 지지/반대 근거와 보류 사유로 확인합니다. [해석과 최종 결과](K-DOG_해석과최종결과_사용설명서_v1.0_20261013.md)에서 행사에 쓸 기본 결과를 명시 선택하고, [설명서 목록](README.md)에서 다른 기능으로 이동할 수 있습니다.

- 화면·복구: [AI 분석 화면](../../frontend/src/AiRunsV4.tsx#L14), [현재 실행과 버튼](../../frontend/src/AiRunsV4.tsx#L110), ES03 구현·검증 기록.
- 서버 조건: [실행 접수·고정 입력](../../backend/app/run_v4.py#L133), [현재 입력과 파일 연결 재검증](../../backend/app/run_v4.py#L75), [현재 진행 판정](../../backend/app/run_v4.py#L237), [접수 조회 복구](../../backend/app/run_v4.py#L266), [중지·재시도](../../backend/app/run_v4.py#L277).
- 현재 권한: [업무권한 단순화 결정](../plans/K-DOG_업무권한단순화계획_v1.1_20261011.md).
- 품질 경계: 실제 공급자 정확도·처리 시간·가격·원본/압축본/360도 영상의 판독 품질과 교수 검토는 [실측 및 확인 후속 대장](../archive/개발반영_20261003/K-DOG_실측및확인후속대장_v1.0_20261003.md)의 별도 후속입니다. AI 관찰·애착 판단 구현이나 합성 자동 시험 통과를 실제 현장 품질 보장으로 읽지 않습니다. 미확정 집계 규칙은 계속 규칙 대기로 남습니다.
