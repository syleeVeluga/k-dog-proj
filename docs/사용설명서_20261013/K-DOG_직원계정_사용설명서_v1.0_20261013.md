# K-DOG 직원 계정 사용설명서

버전: v1.0 · 작성일: 2026-10-13 · 제품 기준: `main / 53889b7` · 평가 기준: S1.1

메뉴 경로는 **자료 관리 → 직원 계정**입니다. 운영자·교수자·관리자·개발자 모두 업무 계정을 추가하고 일반 계정의 활성 상태를 변경할 수 있습니다.

## 1 언제 사용하나요

새 운영 직원이나 교수자에게 개인 계정이 필요할 때, 퇴직·업무 종료 등으로 로그인을 중단할 때, 비활성 계정의 업무를 다시 시작할 때 사용합니다. 현재 화면에서는 역할별 업무 권한을 나누지 않습니다. 새로 만든 계정은 모든 공통 업무를 사용할 수 있습니다.

## 2 시작 전에 준비할 조건

본인의 활성 계정으로 로그인하고 새 직원에게 사용할 계정 이름과 초기 비밀번호를 준비합니다. 계정 이름에는 영문·숫자·밑줄 `_`·하이픈 `-`을 사용하세요. 초기 비밀번호는 **12~256자**입니다. 기존 계정 이름을 다시 만들 수는 없습니다.

개발자 계정은 이 화면의 목록·발급·변경 대상에서 제외됩니다. 개발자 발급이나 변경이 필요하면 설치·서버 담당자가 로컬 관리 경로를 사용합니다. 운영자나 교수자가 업무 기능을 이용하려고 개발자로 승격할 필요는 없습니다.

## 3 새 업무 계정 추가하기

1. **직원 계정** 메뉴를 엽니다.
2. **직원 계정 추가**를 펼칩니다.
3. **새 계정**에 다른 사람과 구별할 이름을 입력합니다. 예를 들어 `staff_02`처럼 담당자가 알아볼 수 있는 이름을 정합니다.
4. **초기 비밀번호**에 준비한 비밀번호를 입력합니다.
5. **계정 생성**을 누릅니다.
6. 목록에 계정이 추가되고 **활성**으로 표시되는지 확인합니다. 새 직원은 해당 계정으로 로그인해 사용할 수 있습니다.

비밀번호는 직원에게 별도로 전달하고 참가자 메모나 문서에 적지 않습니다. 계정을 만든 사람이 이후 업무 자료를 소유하거나 해당 직원의 채점표에 대한 승인자가 되는 것은 아닙니다.

## 4 활성 상태 변경하기

1. 목록에서 정확한 계정 이름을 확인합니다.
2. **활성** 체크를 해제하면 비활성, 체크하면 활성입니다.
3. **계정 변경 저장**을 누릅니다. 체크만 바꾸고 저장하지 않으면 서버에 반영되지 않습니다.
4. 해당 계정의 기존 로그인 세션은 만료됩니다. 다시 활성화한 직원은 재로그인해야 합니다.

활성 상태를 저장하면 체크를 그대로 유지했더라도 해당 계정의 세션이 만료될 수 있습니다. 작업 중인 직원의 계정을 저장할 때는 진행 중 입력이 있는지 서로 확인하세요. 현재 로그인한 자기 계정은 비활성화할 수 없습니다.

비활성화는 로그인 중단입니다. 그 사람이 만든 원본·채점표·의견·발급 결과를 삭제하지 않으며 다른 활성 계정이 자료를 계속 열고 수정·재시도할 수 있습니다.

## 5 비밀번호 분실과 개발자 발급

웹 화면에는 비밀번호 변경·재설정 기능이 없습니다. 설치·서버 담당자가 실행 창을 닫고 정확한 데이터 폴더를 대상으로 로컬 명령을 실행합니다. 아래는 설치본의 프로그램 폴더에서 사용하는 예입니다. `staff_02`와 데이터 경로를 실제 값으로 바꾸세요.

```powershell
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" reset-password staff_02
```

새 비밀번호를 두 번 입력합니다. 성공하면 이전 세션과 실패 잠금이 해제되고, 해당 직원은 새 비밀번호로 다시 로그인합니다. 비활성 상태 자체를 활성으로 바꾸는 명령은 아니므로 목록의 활성 상태도 확인합니다.

개발자 계정 신규 발급은 로컬 관리 담당자가 다음 형식으로 수행합니다. 기존 계정을 덮어쓰거나 웹 화면에서 개발자 권한을 부여하는 기능은 아닙니다.

```powershell
runtime/python/python.exe -X utf8 -m app.manage --data-dir "D:/K-DOG/data" create-user developer_02 --role developer
```

개발 환경 명령과 설치본 경로는 [개발 안내](../DEVELOPMENT.md)·[운영 안내](../PILOT_OPERATIONS.md)를 확인합니다.

로컬 계정 명령은 웹 로그인 없이 실행하며, 해당 기록의 계정은 생성·재설정 대상 계정으로 남습니다. 웹 화면에서 계정을 생성·변경할 때의 실제 로그인 행위자 기록과 구분해서 읽으세요.

## 6 문제 해결

| 상황 | 해결 방법 |
| --- | --- |
| 새 계정 입력이 거절됨 | 이름의 사용 가능 문자와 비밀번호 길이를 확인합니다. 이미 존재하는 이름이면 기존 계정을 확인하거나 다른 이름을 사용합니다. |
| 비활성화가 거절됨 | 현재 로그인한 자기 계정인지 확인합니다. 자기 계정의 비활성화는 다른 활성 업무 계정으로 처리합니다. |
| 개발자가 목록에 없음 | 개발자 계정은 웹 관리 목록에서 제외됩니다. 로컬 관리 담당자가 확인합니다. |
| 저장 뒤 직원이 로그아웃됨 | 활성 상태 저장에 따른 세션 만료입니다. 활성 계정이면 다시 로그인합니다. |
| 비활성 직원 자료를 열어야 함 | 본인의 활성 계정으로 해당 자료를 엽니다. 원작성자의 계정을 재활성화할 필요는 없습니다. |

## 7 다음 업무와 기준 근거

새 직원은 [로그인과 공통 화면](K-DOG_로그인과공통화면_사용설명서_v1.0_20261013.md)을 읽고 본인 계정으로 업무를 시작합니다. 개발자 설정은 [별도 안내](K-DOG_개발설정_사용설명서_v1.0_20261013.md)를 확인합니다.

기준 구현은 [직원 계정 화면](../../frontend/src/Users.tsx), [계정 API](../../backend/app/api.py), [비밀번호 검증](../../backend/app/auth.py), [로컬 관리 명령](../../backend/app/manage.py)입니다. 공통 권한과 원작성자 비활성화의 의미는 [업무 권한 계획](../plans/K-DOG_업무권한단순화계획_v1.1_20261011.md)을 따릅니다. [목차로 돌아가기](README.md).
