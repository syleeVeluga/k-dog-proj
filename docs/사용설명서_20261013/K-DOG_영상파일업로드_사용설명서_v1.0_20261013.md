# K-DOG 영상 파일 업로드 사용설명서

버전: v1.0 · 작성일: 2026-10-13 · 기능 확인 기준: `main / 53889b7` · 평가 기준: S1(`20261002`, `intake-4.0`)

대상: 현장 운영자, 교수자·검토자, 관리자, 개발자 중 로그인 가능한 활성 계정. [사용설명서 목차](README.md)

## 1. 이 기능을 언제 사용하나요?

촬영 PC나 외장 저장장치에 있는 영상을 K-DOG 서버에 보관하고, 어느 참가자의 어느 촬영 회차에 속하는지 등록할 때 사용합니다. 영상 파일을 먼저 올린 뒤 참가자를 지정하는 흐름도 지원합니다. 업로드 완료와 참가자·회차 정보 저장은 서로 다른 단계입니다.

예를 들어 촬영 담당자가 영상을 올리고 교수자가 파일 목록을 확인하여 참가자 정보를 저장할 수 있습니다. 업로드한 직원만 다음 작업을 할 수 있는 구조가 아닙니다. 분석을 준비하려면 파일 업로드 이후 [촬영 기록](K-DOG_촬영기록_사용설명서_v1.0_20261013.md)과 [전처리](K-DOG_전처리_사용설명서_v1.0_20261013.md)를 진행합니다.

| 로그인 계정 | 이 화면에서 할 수 있는 일 |
| --- | --- |
| 운영자(`operator`) | 공통 파일 목록 조회, 업로드·재시도, 참가자·회차 연결, 처리 정보 정정, 보관 파일 내려받기 |
| 교수자·검토자(`reviewer`) | 운영자와 같은 업무. 다른 직원이 업로드한 파일도 확인·등록 가능 |
| 관리자(`admin`) | 운영자와 같은 업무 |
| 개발자(`developer`) | 운영자와 같은 업무. 개발 설정은 별도 메뉴 |

현재 화면은 운영자·검토자·관리자를 모두 **업무 계정**으로 표시합니다. 교수자 전용 업로드 화면이나 공개 승인 절차는 없습니다. 동의·배정·소유자·과거 삭제 상태는 이 기능의 사용 조건이 아니며, 실제 요청한 로그인 계정과 저장 이력은 남습니다.

## 2. 메뉴와 시작 전 준비

메뉴 경로: **현장 운영 → 촬영 → 영상 파일 업로드**.

1. 업로드할 파일이 현재 PC에서 열리는 위치에 있는지 확인합니다. 이 화면은 카메라를 원격 촬영하거나 Studio에서 영상을 내보내는 기능이 아닙니다.
2. 이미 참가자를 등록했다면 ID·반려견 이름·행사와 현재 촬영 회차를 확인합니다. 참가자가 아직 없으면 파일부터 보관하고, [참가자 접수](K-DOG_참가자접수_사용설명서_v1.0_20261013.md) 후 연결할 수 있습니다.
3. 동일 중앙 서버에 접속했는지 확인합니다. 서로 다른 PC의 독립 설치는 같은 파일 목록을 공유하지 않습니다.
4. 파일이 촬영 원본인지, 등록된 원본에서 변환한 MP4인지, 외부에서 만든 360 통합 MP4인지 확인합니다. 잘 모르는 처리 정보는 확인되지 않은 상태로 남깁니다.
5. 재촬영 영상이라면 새 촬영 회차를 먼저 준비합니다. 과거 영상의 카메라 번호만 바꾸어 새 회차처럼 등록하지 않습니다.

## 3. 영상 파일 구분을 고르는 방법

| 화면 선택지 | 사용 시점 | 필요한 정보와 지원 범위 |
| --- | --- | --- |
| 촬영 원본 | 카메라에서 나온 원파일을 보관할 때 | 참가자·회차 연결 시 촬영 카메라 번호 확인. 선택창은 MP4·MOV·M4V·AVI·MKV·WEBM·INSV를 표시하지만 실제 코덱 판독은 전처리에서 확인 |
| 변환 MP4 | 이미 보관한 부모 원본을 변환한 MP4를 올릴 때 | 파일 선택 전에 부모 원본, 실제 변환 도구·버전·설정 입력. 어떤 원본에서 만들어졌는지 연결 |
| 360 통합 MP4 (Studio 등에서 내보낸 파일) | Studio 등의 외부 도구에서 통합 MP4 하나를 만들어 전달받았을 때 | MP4 한 파일씩 선택. 원본 INSV 사전 업로드·부모 원본·카메라 번호 입력 없이 등록. 영상 배치와 촬영 시간 대응을 기록 |

**INSV는 원본 보관 전용입니다.** 업로드·등록 성공으로 INSV 직접 판독이 가능해지지 않습니다. 판독에 사용할 대응 MP4를 별도로 마련해야 합니다. 현재 앱에는 INSV를 자동 스티칭하거나 360 펼침 화면을 자동 재구도하는 메뉴가 없습니다.

### 3.1. 360 통합 MP4의 처리 정보

처리 정보는 사용자가 확인하여 제공하는 정보입니다. 앱이 파일 내용으로 자동 인증한 결과가 아닙니다.

| 입력 항목 | 선택 방법 |
| --- | --- |
| 영상 배치 → 잘 모름 | 화면이 일반 영상인지 펼침 영상인지 확인하지 못한 경우. 기본값 |
| 영상 배치 → 일반 화면으로 내보냄 | 외부 도구에서 일반 화면으로 재구도하여 내보낸 MP4인 경우 |
| 영상 배치 → 360 펼침 영상 | 구면 영상을 펼쳐 놓은 형태의 MP4인 경우. 일반 화면으로 재구도한 MP4가 필요 |
| 촬영 시간 → 잘 모름 | 촬영 원래 시각과 파일 시각의 대응을 확인하지 못한 경우. 기본값 |
| 촬영 시간 → 촬영 시간의 순서·속도 유지 | 원촬영의 순서·속도와 시각 대응을 확인한 경우 |
| 촬영 시간 → 구간 편집·속도 변경 있음 | 잘라 이어 붙이기, 속도 변경 등으로 촬영 시각 대응이 달라진 경우 |
| 내보내기 도구·메모 (선택) | 실제로 확인한 도구명·버전·처리 메모. 확인하지 않은 값은 비워 둠 |

**일반 화면 + 촬영 시간의 순서·속도 유지**인 파일만 영상 클립 제작 후보가 됩니다. 실제 프레임·오디오·코덱의 정상 판독 여부는 전처리 결과에서 확인합니다.

360 펼침 영상이라도 촬영 시간 대응을 유지한 파일은 시간 근거로 촬영 기록을 확정할 수 있으나, 그 파일의 영상 클립 제작은 제한됩니다. 반대로 일반 화면이라도 촬영 시간이 편집되었거나 미확인이면 기준 영상·사건·관찰 근거의 시간 앵커로 확정할 수 없습니다. 단순히 제한을 없애기 위해 확인하지 않은 정보를 바꾸지 않습니다.

## 4. 따라 하기: 영상 업로드와 정보 저장

### 4.1. 파일을 선택하고 전송하기

1. **영상 파일 업로드** 메뉴를 엽니다. 이미 선택한 참가자가 있으면 파일 선택 영역에 해당 참가자와 현재 회차가 표시됩니다. 다른 대상이면 먼저 대상을 바꿉니다.
2. **영상 파일 구분**을 선택합니다.
3. **360 통합 MP4**라면 영상 배치·촬영 시간과 선택 메모를 입력합니다. **변환 MP4**라면 부모 원본과 변환 도구·버전·설정을 먼저 입력합니다.
4. **영상 파일**에서 파일을 고릅니다. 360 통합 MP4는 한 파일씩, 다른 구분은 여러 파일을 선택할 수 있습니다.
5. 아래 대기 목록에서 파일명·용량을 확인합니다. 파일 선택 시의 구분·참가자·회차가 각 항목에 고정됩니다. 상단 선택지를 바꿔도 이미 고른 항목은 바뀌지 않습니다.
6. 360 통합 MP4의 처리 정보는 **전송 시작 전** 해당 파일의 처리 정보 영역에서 고칠 수 있습니다. 구분이나 대상을 잘못 고른 대기 항목은 **목록에서 숨기기** 후 올바른 선택으로 다시 고릅니다.
7. **업로드 시작·재시도**를 누릅니다. 대기 항목별로 전송 상태가 표시됩니다. 파일 수나 용량이 많으면 완료까지 화면을 유지합니다.
8. 전송이 끝나면 **영상 정보 입력 대기**의 파일 카드를 확인합니다. 파일이 안 보이면 **목록 새로고침**을 누릅니다.

**목록에서 숨기기**는 화면 대기 항목을 숨기는 동작입니다. 이미 서버에 접수된 파일을 취소하거나 등록된 원본을 삭제하는 동작으로 사용하지 않습니다.

### 4.2. 참가자·회차·카메라를 저장하기

1. **업로드 완료** 파일의 카드에서 파일명을 확인합니다.
2. 참가자가 지정되지 않았으면 **참가자 찾기**에 순번·ID·반려견 이름 등을 넣고 **참가자**를 선택합니다. 파일 선택 시 참가자를 고정한 경우 그 대상을 바꿀 수 없습니다.
3. **촬영 회차** 표시를 확인합니다. 현재 선택 회차가 바뀌었다는 안내가 나오면 해당 참가자의 올바른 회차로 돌아가 확인합니다.
4. 촬영 원본·변환 MP4라면 **촬영 카메라 번호**를 입력합니다. 숫자 `1`은 1번 카메라로 처리하며, 직접 식별자는 영문·숫자·밑줄·하이픈으로 입력합니다.
5. 파일명에 원본 번호가 있으면 앱이 아래처럼 미리 채울 수 있습니다. 추정이 실제 촬영 배치와 맞는지 확인하고 다르면 고칩니다.

   | 파일명의 원본 번호 | 미리 채우는 촬영 카메라 번호 |
   | --- | --- |
   | 원본1 | 1번 |
   | 원본3 | 2번 |
   | 원본2 | 3번 |

6. 별도 원본 번호를 확인한 경우 **원본 번호**에 입력합니다. 원본 번호와 카메라 번호는 같은 개념이 아닙니다. 360 통합 MP4에는 이 두 입력란이 나오지 않으며 **360 통합 영상**으로 표시됩니다.
7. **영상 정보 저장**을 누릅니다.
8. **정보 저장 완료한 파일**을 펼쳐 해당 카드가 **등록됨 · 영상 읽기 확인 대기** 또는 **등록됨 · 원본 보관 전용**으로 바뀌었는지 확인합니다.

다른 직원이 같은 회차에 같은 촬영 원본 카메라를 이미 등록했다면 경고가 표시될 수 있습니다. 실제 파일과 카메라를 확인해야 하며, 경고를 없애기 위한 임의 번호를 넣지 않습니다.

### 4.3. 변환 MP4의 부모 원본·설정 입력

변환한 파일의 실제 출처를 남길 때 사용합니다. 부모 원본은 먼저 업로드 완료 또는 등록된 상태여야 합니다. 최종 연결할 때는 대상·회차의 연결 관계도 확인합니다. 여러 원본으로 만든 변환본이면 실제 부모를 모두 선택합니다.

**변환 도구**, **변환 도구 버전**은 실제 값으로 입력합니다. **변환 설정**은 JSON 객체 형식입니다. 형식 예시는 `{"fps":30}`이며, 이 값이 운영 권장 설정이라는 뜻은 아닙니다. 확인한 설정만 기재합니다. 빈 설정 객체 `{}`도 객체 형식이지만 도구·버전·부모를 생략하는 대신 사용할 수는 없습니다. 형식이 어렵다면 변환 담당자에게 실제 설정과 JSON 표현을 확인합니다.

원본이 등록되지 않은 외부 360 통합 MP4라면 **360 통합 MP4** 구분을 사용합니다. 기존 **변환 MP4**의 부모 요구를 가짜 원본 등록으로 채우지 않습니다.

## 5. 등록 후 확인·정정·원본 내려받기

### 5.1. 정상 등록의 확인 기준

| 표시 | 의미 | 다음 행동 |
| --- | --- | --- |
| 업로드 대기·진행 중 | 서버 수신이 아직 끝나지 않음 | 전송 완료를 기다리거나 중단 사유 확인 |
| 업로드 완료 | 파일은 보관했으나 참가자·회차 연결은 아직임 | 영상 정보 저장 |
| 등록됨 · 영상 읽기 확인 대기 | 참가자·회차에 연결되었으나 클립 제작·판독은 아직 확인 전 | 촬영 기록 작성·확정 후 전처리 |
| 등록됨 · 원본 보관 전용 | INSV 등 보관 전용 원자료 | 판독할 대응 MP4 마련 |
| 업로드 실패·취소 | 해당 접수를 완료하지 못했음 | 실패 사유와 재선택·재시도 안내 확인 |

**보관 원본 내려받기**는 업로드 완료·등록 완료 파일을 내려받습니다. 어떤 로그인 계정으로 올렸는지와 무관하게 공통 업무 계정이 사용할 수 있습니다. **기술 정보**의 업로드 ID·파일 용량·SHA-256·연결 입력 버전은 문제를 담당자에게 전달할 때 유용합니다.

### 5.2. 360 통합 영상의 처리 정보 정정

외부 도구의 처리 내용을 나중에 확인했거나 잘못 입력했을 때 사용합니다. 같은 파일의 정보만 정정하며 파일을 다시 전송하지 않습니다.

1. **정보 저장 완료한 파일**에서 해당 360 통합 영상 카드를 엽니다.
2. **처리 정보 확인·정정**을 펼칩니다.
3. **업로드 당시** 선언과 **현재 입력**의 처리 정보를 비교합니다.
4. 영상 배치·촬영 시간을 실제 확인한 값으로 수정하고 필요하면 도구·메모를 남깁니다.
5. **처리 정보 저장**을 누릅니다.
6. 현재 입력 버전이 갱신되었는지 확인하고 촬영 기록을 검토합니다. 시간 근거로 쓰인 정보가 달라지면 촬영 재확정이 필요합니다.
7. 새 입력으로 분석하려면 **새 클립으로 전처리**를 명시적으로 실행합니다. 이전 전처리·점수·발급 리포트가 자동으로 새 정보로 바뀌지는 않습니다.

저장 중 **다른 변경이 저장되었습니다**가 나오면 초안은 유지됩니다. 최신값을 확인하고 **입력 버리고 최신 값 보기**를 사용하여 다시 입력합니다. **선택 촬영 회차가 변경되었습니다**이면 파일의 원래 회차로 돌아온 뒤 저장합니다. 상태를 모르겠다면 먼저 새로고침하여 현재 저장값을 비교하고, 같은 내용을 무조건 반복 전송하지 않습니다.

### 5.3. 기존 보존 영상의 출처 등록

기존 영상이 참가자·회차에 있지만 업로드 출처 정보가 아직 연결되지 않은 경우에만 **촬영 기록 (8구간)** 화면 하단의 **보존 영상 출처 등록**이 나옵니다. 새 파일을 다시 업로드하기 위한 메뉴가 아닙니다.

1. 올바른 참가자·회차의 촬영 기록을 엽니다.
2. 보존 영상의 파일명·용량을 확인하고 **보존 영상 자료 구분**을 고릅니다.
3. 원본·변환본이면 카메라와 원본 번호를 확인합니다. 변환본은 부모 원본을 같은 회차에 먼저 등록하고 도구·버전·설정을 입력합니다.
4. 360 통합 MP4이면 처리 정보만 확인합니다. 카메라 번호와 부모 원본은 요구하지 않습니다.
5. **보존 영상 출처 등록**을 누릅니다. 파일과 영상 식별자는 유지됩니다.
6. 응답을 받지 못한 경우 **같은 출처 등록 요청 재시도**, 판본 충돌이면 최신 내용을 확인한 뒤 **최신 버전 …에 같은 출처 등록 재시도** 또는 **출처 입력 수정**을 사용합니다. 이미 등록한 자료 구분을 이 메뉴로 덮어쓰지 않습니다.

## 6. 중단·오류·동시 작업에 대응하기

| 상황 | 친절한 해결 순서 |
| --- | --- |
| 전송 화면이 멈추거나 완료 응답을 못 받음 | **목록 새로고침**으로 서버 상태부터 확인합니다. 이미 완료면 영상 정보 저장만 합니다. 현재 대기 목록에 남아 있으면 **업로드 시작·재시도**는 같은 접수 요청을 사용합니다. 파일을 새로 골라 중복 접수를 만드는 일을 먼저 하지 않습니다. |
| 실패·진행 중 카드에 **중단 파일 다시 선택**이 나옴 | 같은 파일명·크기의 원본을 다시 고릅니다. 내용이 다른 파일을 이름만 맞춰 선택하지 않습니다. 서버 상태에 따라 오류가 지속되면 표시된 사유를 확인한 뒤 새 접수 여부를 판단합니다. |
| 파일 전송을 멈추고 싶음 | 대기 항목의 **이 전송 중단**은 현재 브라우저 전송을 멈춥니다. 이후 목록을 새로고침하여 서버 상태를 확인합니다. |
| 등록하지 않은 접수를 취소하고 싶음 | 카드의 **업로드 취소**와 화면 확인창을 사용합니다. 다른 PC에서 같은 접수를 전송 중이면 그 전송도 영향을 받습니다. 취소한 파일의 실제 정리는 유지보수 때 진행됩니다. 이미 연결한 원자료는 수신 취소할 수 없습니다. |
| 부모 원본 때문에 취소가 거절됨 | 그 원본을 사용하는 변환 접수를 먼저 확인합니다. 계보에 연결된 자료를 억지로 제거하지 않습니다. |
| 영상 정보 저장에서 충돌 또는 회차 변경 | 참가자·회차·카메라를 다시 확인하고 **다시 저장**합니다. 업로드 완료 파일은 보관되어 있으므로 파일 전송을 반복하지 않습니다. |
| 360 통합 MP4 선택이 거절됨 | `.mp4` 한 파일인지 확인합니다. 여러 파일은 한 번에 묶어 선택하지 않습니다. 확장자만 MP4로 바꾸는 방법은 변환이 아닙니다. |
| 처리 정보 저장 버튼이 비활성화됨 | 변경 여부, 입력 버전 충돌, 파일의 회차와 현재 선택 회차 일치를 확인합니다. 회차가 바뀌었으면 해당 회차로 돌아갑니다. |
| 로그인 만료·계정 비활성화 | 로그인 상태를 확인하고 재접속합니다. 다른 직원의 소유자 변경이나 공개 승인으로 해결하는 오류가 아닙니다. |
| 파일 해시·손상·저장 공간 오류 | 원본을 임의 덮어쓰지 않고 파일명·회차·업로드 ID·오류 문구를 담당자에게 전달합니다. 보관 원본·검증된 백업과 비교하여 복구합니다. |

## 7. 완료 기준과 다음 기능

이 기능의 완료 기준은 **원파일 보관 + 올바른 참가자·촬영 회차에 영상 정보 저장**입니다. 업로드 성공은 실제 영상 판독, 채점 정확도, AI 분석, 리포트 발급 완료를 뜻하지 않습니다.

- 다음: [촬영 기록 사용설명서](K-DOG_촬영기록_사용설명서_v1.0_20261013.md)에서 실제 8구간·사건·관찰 근거를 기록하고 확정합니다.
- 이어서: [전처리 사용설명서](K-DOG_전처리_사용설명서_v1.0_20261013.md)에서 파일별 판독과 관찰창·클립을 확인합니다.
- 대상이 없을 때: [참가자 접수](K-DOG_참가자접수_사용설명서_v1.0_20261013.md).

실제 참가자 INSV·Studio 통합 MP4의 화질·시간 대응·항목 정확도·처리시간과 물리 PC 3대의 현장 LAN 동시 운영은 별도 실측 대기입니다. 현재 코드·합성 영상·한 Windows 환경의 설치 검증은 이 현장 품질을 보장하지 않습니다. 미확인 자료도 보관·출처 기록은 가능하며 지원 여부는 해당 파일의 기술 상태로 확인합니다.
