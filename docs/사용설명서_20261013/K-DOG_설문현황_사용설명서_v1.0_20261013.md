- 문서 버전: v1.0 / 작성일: 2026-10-13

- 대상: 현장 운영자, 교수자·검토자, 관리자, 개발자

## 1. 언제 사용하는 화면인가요?

보호자 설문 28문항이 올바른 참가자·촬영 회차에 등록됐는지, 빠진 문항이 무엇인지, 현재 정책에서 어떤 영역을 계산할 수 있는지 확인할 때 사용합니다.

운영자는 파일 등록 직후 응답 수와 누락 문항을 점검하고 보완 요청에 사용할 수 있습니다. 교수자는 영역별 집계와 원응답을 함께 읽고 영상 관찰 결과와 구별해 검토할 수 있습니다. 이 화면의 설문 숫자는 보호자가 제공한 원응답 및 그 집계이며, 영상 애착 유형을 설문만으로 확정하는 기능은 아닙니다.

**설문 입력·정정은 이 화면에서 직접 하지 않습니다.** 보호자 설문은 [일괄 등록](K-DOG_일괄등록_사용설명서_v1.0_20261013.md)의 CSV·Excel 파일 등록으로 처리합니다. 이 화면은 등록 현황과 집계·원응답 확인용입니다.

## 2. 로그인별 사용 범위와 시작 조건

| 로그인 | 가능한 일 |
|---|---|
| 운영자 `operator` | 전체 참가자 설문 현황·집계·원응답 확인, 일괄 등록으로 이동해 보완 |
| 교수자·검토자 `reviewer` | 운영자와 같은 작업, 원응답과 집계를 전문 검토에 활용 |
| 관리자 `admin` | 운영자와 같은 작업 |
| 개발자 `developer` | 동일한 설문 업무 사용 |

운영자·교수자·관리자는 현재 화면에서 모두 **업무 계정**으로 표시합니다. 교수자 전용 설문 메뉴는 없으며 다른 직원이 접수한 자료도 볼 수 있습니다. 소유·배정·동의·공개 승인 상태는 조회나 보완 작업의 조건이 아닙니다.

시작 조건은 활성 계정으로 로그인하고 참가자가 접수되어 있는 것입니다. 설문이 아직 한 문항도 없더라도 현황을 확인할 수 있습니다. 집계값을 보려면 해당 영역에 필요한 원응답이 있어야 하며, 원자료 참고용 과거 판본은 S1 집계에서 제외됩니다.

## 3. 전체 등록 현황을 확인하는 방법

1. 메뉴에서 **설문 현황**을 엽니다.
2. 화면 위의 **모두 응답 / 전체 참가자 수**를 확인합니다. 이 숫자는 전체 목록 기준입니다. 검색·행사 필터로 줄인 표시 대상의 합계와는 다를 수 있습니다.
3. **행사 필터**에서 해당 행사를 고릅니다.
4. **검색**에 순번·참가자 ID·반려견·보호자 이름을 입력합니다.
5. 표에서 참가자 ID, 행사, 반려견 이름을 먼저 맞춘 뒤 설문 숫자를 읽습니다.

| 표의 항목 | 읽는 방법 |
|---|---|
| 순번 | 행사 안의 진행 순서. `—`는 미지정 |
| 참가자 | 참가자 ID와 행사 ID |
| 반려견 / 보호자 | 설문 파일이 연결된 대상을 확인하는 정보 |
| 설문 | 화면에서 센 등록 응답 수 / 28 |
| 미응답 | 위 등록 수를 28에서 뺀 수 |
| 해당 없음 | 회차에 저장된 해당 없음 상태 수. 현재 S1 파일 등록에서 NA를 새로 입력하는 기능은 아님 |
| 현황 | **열기 ↗**를 눌러 상세 집계·원응답 확인 |

현재 S1 설문 등록 수는 수치 원응답을 기준으로 읽으세요. **빈칸 사유가 적혀 있어도 수치 응답 수에는 더하지 않습니다.** 예를 들어 25개 숫자와 3개 빈칸 사유가 있으면 수치 응답은 25/28이고 사유는 3개입니다.

목록에서 `28/28`이 초록색으로 보여도 모든 평가 단계가 끝난 것은 아닙니다. 실제 설문 등록 완료 기준은 화면에 **등록 완료 기준 미확정**으로 따로 표시합니다. 전체 응답 수와 정책상 등록 완료·외부 비교 자격은 서로 다른 상태입니다.

아무 대상도 보이지 않으면 검색어·행사 필터를 해제합니다. 아직 접수하지 않은 대상은 [참가자 접수](K-DOG_참가자접수_사용설명서_v1.0_20261013.md) 또는 [일괄 등록](K-DOG_일괄등록_사용설명서_v1.0_20261013.md)에서 먼저 등록합니다.

## 4. 참가자 한 명의 상세 현황을 확인하는 방법

1. 대상 행의 **열기 ↗**를 누릅니다. 이미 참가자를 선택한 상태로 메뉴에 들어왔다면 그 참가자의 상세가 열릴 수 있습니다.
2. 반려견 이름·참가자 ID와 공통 화면의 선택 회차를 확인합니다. 설문은 회차별로 저장되므로 같은 참가자라도 회차가 다르면 응답이 다를 수 있습니다.
3. 위쪽의 **수치 응답 N/28 · 명시 빈칸 사유 M개**를 읽습니다.
4. **집계** 상태를 확인합니다.

| 집계 표시 | 뜻과 다음 행동 |
|---|---|
| 8영역·25번 산출 | 8개 영역과 Q25 단독 값이 모두 산출됨. 원응답 연결도 확인 |
| 완전응답 영역만 산출 | 일부 영역만 조건 충족. 각 영역의 `보완 문항` 확인 |
| 산출값 없음 | 현재 산출 가능한 영역·Q25 값이 없음. 원응답과 미응답 원인 확인 |

5. 각 영역 카드의 응답 수·평균·분모·보완 문항을 읽습니다. 예를 들어 `응답 5/6`과 `보완 문항: Q06`이 보이면 Q06이 필요한 묶음에서 누락된 것입니다.
6. **25번 단독 응답**을 따로 확인합니다. 값이 없으면 미응답과 빈칸 사유 또는 `사유 미상`이 표시됩니다.
7. 화면 아래의 **설문 원응답**을 펼쳐 각 문항을 원문·원척도와 함께 확인합니다.
8. 목록으로 돌아가려면 **닫기**를 누릅니다.

원응답이 바뀌면 선택한 참가자의 입력 버전에 따라 집계가 다시 조회됩니다. 다른 직원의 최신 변경이 화면에 반영되지 않은 것 같으면 공통 화면에서 최신 자료를 불러온 뒤 같은 참가자·회차를 다시 확인하세요.

## 5. 원응답과 계산 결과를 읽는 방법

### 5.1 숫자 0, 미응답, 빈칸 사유

- **Q10~Q14의 0**은 허용된 정상 응답입니다. 0을 미응답으로 처리하지 않습니다.
- **미응답**은 숫자가 없는 상태입니다. 평균 계산을 위해 임의로 0을 넣지 않습니다.
- **빈칸 사유**는 실제 미응답의 이유를 별도로 남긴 기록입니다. 사유가 있어도 답변 숫자가 생기지는 않습니다.
- **사유 미상**은 확인한 빈칸 사유가 없다는 뜻입니다. 추정 사유를 대신 작성하지 않습니다.
- 현재 판본에서 **NA·해당 없음**을 숫자 응답 대신 넣을 수 없습니다. 특히 Q10~Q14는 0~4 원응답을 쓰며 NA를 허용하지 않습니다. 과거 기록에 해당 없음 수가 보이면 판본과 원자료를 확인합니다.

예를 들어 Q10=0, Q11=2이면 평균은 1.0입니다. Q10=0, Q11 미응답이면 해당 두 문항 묶음은 산출하지 않습니다. Q11의 빈칸 사유가 있어도 두 문항 평균은 생기지 않습니다.

### 5.2 영역별 묶음과 완전응답 조건

현재 실행 정책은 **`survey-policy-20261007-rp01`**입니다. 원문 설문 판본 **`survey-20260929-v3`**의 원응답을 유지하고 다음과 같이 집계합니다.

| 원문 문항 묶음 | 표시하는 값 | 산출 조건 |
|---|---|---|
| Q01~Q06 | 묶음 평균 | 6개 모두 유효 응답 |
| Q07~Q09 | 묶음 평균 | 3개 모두 유효 응답 |
| Q10~Q11 | 두려움 묶음 평균 | 2개 모두 유효 응답, 0 포함 |
| Q12~Q14 | 두려움 묶음 평균 | 3개 모두 유효 응답, 0 포함 |
| Q15~Q21 | 묶음 평균 | 7개 모두 유효 응답 |
| Q22~Q23 | 불안 평균 | 2개 모두 유효 응답 |
| Q24 | 재회 반응 원값 | 해당 문항의 유효 응답 |
| Q25 | 별도 단독 응답 원값 | 해당 문항의 유효 응답 |
| Q26~Q28 | 역채점 후 묶음 평균 | 3개 모두 유효 원응답 |

평균 묶음은 하나라도 빠지면 해당 묶음만 미산출합니다. 다른 완전응답 영역은 유지합니다. 누락을 뺀 부분평균이나 0 대체를 하지 않습니다. Q24와 Q25는 다른 평균 묶음으로 합치지 않습니다. **설문 총점은 만들지 않습니다.**

### 5.3 Q26~Q28 역채점

보호자가 답한 원응답을 저장하고 계산할 때 **6 − 원응답**으로 변환합니다. 상세에는 원응답과 변환값을 함께 표시합니다.

예를 들어 Q26 원응답=1이면 변환=5, Q27=3이면 변환=3, Q28=5이면 변환=1입니다. 이 경우 변환 평균은 3입니다. 파일 등록 전에 5·3·1로 직접 바꾸면 앱에서 다시 역채점하므로 보호자가 답한 1·3·5를 그대로 등록해야 합니다.

### 5.4 외부 비교 준비 중 표시

이 화면의 **외부 비교: 준비 중(원문 확인 전)**과 **외부 비교 · 자세히**는 설문 조회 API에서 외부 기준 적용 상태·사유를 표시하는 부분입니다. 숫자 응답이 모두 있어도 외부 규준값이 자동으로 만들어지는 것은 아닙니다.

외부 비교에 필요한 실제 기준의 문항·척도·산식·대상 근거를 갖추는 일은 [비교 조건](K-DOG_비교조건_사용설명서_v1.0_20261013.md)에서 별도로 다룹니다. 현재 정책에서는 일반 업무 계정에 관리자 결재를 추가로 요구하지 않습니다. `준비 중`은 실제 근거·자료 확인 상태이며 역할 승인이 부족하다는 뜻이 아닙니다.

## 6. 누락이나 잘못된 응답을 발견했을 때

1. 참가자 ID·행사 ID·촬영 회차부터 확인합니다. 잘못 선택한 회차를 보완하지 않도록 합니다.
2. 원응답을 펼쳐 누락 문항과 기존값을 기록합니다.
3. 보호자가 제공한 원파일 또는 확인된 응답을 대조합니다. 원응답이 없으면 임의 점수를 넣지 않습니다.
4. [일괄 등록](K-DOG_일괄등록_사용설명서_v1.0_20261013.md)에서 정확히 같은 행사·참가자 ID의 파일로 필요한 응답을 갱신합니다.
5. 미리보기의 이전·반영 값과 빈칸 사유를 확인하고 확정합니다.
6. 설문 현황으로 돌아와 수치 응답 수·보완 문항·원응답·집계 상태를 다시 확인합니다.

일반 ID 갱신에서는 파일 빈칸이 기존값을 지우지 않습니다. 기존 숫자를 실제 미응답으로 정정하려면 확인된 빈칸 사유를 별도 열에 적어 연결하고 미리보기 결과를 확인하세요. 특정 회차에 명시적으로 연결하는 고급 기능은 전체 설문 대체이므로 단순 보완과 다릅니다. 자세한 조건은 일괄 등록 설명서에 있습니다.

## 7. 자주 생기는 실수와 해결 방법

| 상황 | 확인·해결 방법 |
|---|---|
| 파일을 올렸는데 설문이 0/28 | 일괄 등록에서 실제 확정했는지, 설문 열이 연결됐는지, 행사·ID·회차가 맞는지 확인합니다. 명단만 등록했을 수도 있습니다. |
| 빈칸 사유가 3개인데 응답 수가 25/28 | 정상 표시입니다. 사유는 수치 응답이 아니며 누락 문항의 평균 조건을 채우지 않습니다. |
| 28/28인데 완료 기준이 미확정 | 수치 응답 완료와 별도 정책상 등록 완료는 구별됩니다. 이 표시를 지우려고 원응답을 바꾸지 않습니다. |
| 몇 영역만 평균이 없음 | 해당 카드의 보완 문항을 확인합니다. 하나라도 누락되면 그 묶음만 미산출하며 다른 영역은 유지됩니다. |
| 0이 화면에 보여 걱정됨 | Q10~Q14라면 0~4 척도의 정상 응답인지 원파일과 대조합니다. 다른 문항의 0은 허용되지 않습니다. |
| Q26~Q28이 원파일과 다르게 보임 | 원응답과 변환값을 구별해 읽습니다. 변환은 6−원응답입니다. |
| 회차를 바꾸면 설문이 달라짐 | 회차별 자료이므로 가능합니다. 선택한 회차와 원파일의 대상을 확인합니다. |
| 과거 설문 원자료 참고 상태라는 오류 | 그 회차는 현재 S1 집계 대상 판본이 아닙니다. 과거 척도를 현재 척도로 임의 환산하지 않습니다. |
| 결과 조회 중이 오래 지속되거나 오류가 남음 | 연결·로그인 상태를 확인하고 최신 자료로 다시 엽니다. 오류 문구와 참가자·회차를 기록해 담당자에게 전달합니다. |
| 설문 수치로 영상 애착 유형을 결정하려 함 | 설문은 별도 근거입니다. 영상 관찰·채점·최종 해석의 근거를 함께 검토하고 설문만으로 유형을 정하지 않습니다. |
