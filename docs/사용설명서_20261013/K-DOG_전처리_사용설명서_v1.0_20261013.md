# K-DOG 전처리 사용설명서

버전: v1.0 · 작성일: 2026-10-13 · 기능 확인 기준: `main / 53889b7` · 평가 기준: S1(`20261002`, `intake-4.0`)

대상: 현장 운영자, 교수자·검토자, 관리자, 개발자 중 로그인 가능한 활성 계정. [사용설명서 목차](README.md)

## 1. 전처리를 언제 사용하나요?

전처리는 확정한 촬영 기록의 실제 시각을 기준으로 카메라별 클립을 만들고, 항목별 관찰창·영상 가용 범위·오디오·가림·손실 근거를 정리하는 기능입니다. 영상 업로드와 촬영 기록을 마친 뒤 채점·AI 분석을 준비할 때 사용합니다. 이 단계에서 점수나 유형을 결정하지 않습니다.

다음 경우에도 사용합니다.

- 촬영 시각·사건·오프셋·360 처리 정보를 수정하여 **현재 입력으로 새 클립**이 필요할 때.
- 같은 입력과 설정의 검증된 클립을 **명시적으로 재사용**할 때.
- 실행을 시작한 뒤 다른 메뉴로 이동했거나 응답이 끊겨 **내 실행의 접수·진행·결과**를 확인할 때.
- 교수자가 구간 경계·가림·실제 프레임과 원본 시각 대응을 검토할 때.

| 로그인 계정 | 전처리 업무 | 내 실행 목록 |
| --- | --- | --- |
| 운영자(`operator`) | 공유 참가자 대상으로 실행·결과 검토·명시 재사용 | 이 로그인 계정이 시작한 실행만 표시 |
| 교수자·검토자(`reviewer`) | 운영자와 동일. 다른 직원의 공유 결과도 확인 가능 | 이 로그인 계정이 시작한 실행만 표시 |
| 관리자(`admin`) | 운영자와 동일 | 이 로그인 계정이 시작한 실행만 표시 |
| 개발자(`developer`) | 운영자와 동일 | 이 로그인 계정이 시작한 실행만 표시 |

운영자·검토자·관리자는 화면에서 **업무 계정**으로 표시됩니다. 내 실행 목록의 범위는 자료 접근 권한이 아닙니다. 동의·배정·소유자·공개 승인 없이 공통 업무를 수행하며 실제 실행자는 이력에 남습니다.

## 2. 메뉴와 사전 조건

메뉴 경로: **분석·평가 → 전처리**.

1. 참가자는 현재 S1로 등록되어 있어야 합니다.
2. 올바른 참가자·현재 촬영 회차에 영상이 연결되어 있어야 합니다. 업로드 완료만 된 파일은 [영상 정보 저장](K-DOG_영상파일업로드_사용설명서_v1.0_20261013.md#42-참가자회차카메라를-저장하기)까지 진행합니다.
3. [촬영 기록](K-DOG_촬영기록_사용설명서_v1.0_20261013.md)의 **실제 촬영 절차 → 현재 절차 확인**과 실제 시각 **확정**이 필요합니다. 초안·미확인·이전 절차 기록은 현재 S1 전처리 조건을 만족하지 않습니다.
4. 다른 카메라를 사용할 때는 실제 오프셋과 근거를 확인합니다. 미확인 오프셋의 영상은 클립 제작에서 제외됩니다.
5. 원파일·입력·규칙 파일이 보존되어 있어야 합니다. 실행 가능 표시가 있어도 실제 파일 해시·공간·판독 검사는 실행 중 다시 수행합니다.
6. 서버의 전처리 작업이 이미 실행 중이면 종료를 확인합니다. 현재 전처리는 전역 잠금으로 동시 실행을 거절하며 자동 대기열은 없습니다.

전처리는 서버의 영상 처리 도구를 사용합니다. 버튼을 누른 뒤 파일·FFmpeg·저장 공간 오류가 발생하면 운영 담당자가 설치 환경과 공간을 확인합니다. 전처리 자체는 외부 AI 채점 실행이 아닙니다.

### 2.1. 파일별 지원 경계

| 파일 상태 | 전처리에서의 의미 | 운영자가 할 일 |
| --- | --- | --- |
| 정상 판독 가능한 원본·연결된 변환 MP4 | 실제 프레임과 오디오를 검사하여 클립 제작 | 결과·가림·손실을 확인 |
| INSV 원본 보관 전용 | 원본 보관 가능, 직접 영상 클립 제작 지원 아님 | 대응 MP4 마련·출처 등록 |
| 360 통합 MP4, 일반 화면 + 촬영 시간 유지 | 클립 제작 후보 | 촬영 확정 후 실제 판독 결과 확인 |
| 360 통합 MP4, 펼침 영상 또는 배치 미확인 | 해당 파일의 클립 제작 제한 | 일반 화면으로 재구도한 MP4 마련 또는 배치 확인 |
| 360 통합 MP4, 촬영 시간 편집·미확인 | 해당 파일 클립 제한, 시간 앵커로 촬영 확정·전처리할 수 없음 | 시간 유지가 확인된 영상으로 실제 시각 다시 확인 |
| 오프셋 미확인·카메라 미등록 | 영상은 보관되나 해당 카메라의 클립을 만들지 못할 수 있음 | 촬영 기록 동기화·파일 출처 확인 |
| 파일·오디오 가용 범위 부족, 실제 프레임 없음 | 일부 결과 또는 클립 없음·사유 표시 | 없는 근거를 0점으로 바꾸지 않고 실제 사유 검토 |

**360 펼침 영상 + 촬영 시간 유지**는 시간 근거로 사용할 수 있다는 점과, 그 파일의 영상 클립이 제한된다는 점을 구별합니다. 다른 정상 영상이 있으면 그 영상의 가능한 처리는 유지됩니다. 처리 정보를 나중에 고치면 현재 입력 판본만 바뀌며 과거 결과의 처리 정보는 그대로 보존됩니다.

## 3. 내 실행 목록과 공유 자료를 구별하기

참가자를 선택하지 않은 상태에서 전처리 메뉴를 열면 **내가 실행한 전처리** 목록이 나옵니다. 참가자가 이미 선택되어 있으면 해당 대상 상세가 나올 수 있습니다. 내 목록을 보려면 상단 **회차 안내·바로가기 → 전체 목록으로 돌아가기**로 선택을 해제합니다.

### 3.1. 내 실행 목록 읽기

1. **내 실행 새로고침**으로 상태를 확인합니다.
2. 검색·행사 필터와 **전처리 상태**를 사용합니다.
3. 참가자·반려견, 촬영 회차, 상태, 실행 시각을 대조합니다.
4. 실행 중이면 **상태 확인**, 결과가 있으면 **결과 보기**, 결과가 없으면 **상세 보기**를 누릅니다.
5. 다음 페이지가 있으면 **더 보기**를 누릅니다. 기본 목록은 최신 실행부터 표시합니다.

| 상태 필터 | 포함되는 이력 |
| --- | --- |
| 전체 | 현재 계정이 시작한 모든 조회 가능한 실행 |
| 실행 중 | 해당 실행이 실제로 활성 전처리 작업인 경우 |
| 완료 | 정상 완료 이력. 나중에 입력이 바뀌어도 당시 완료 이력은 보존 |
| 확인 필요 | 일부 완료·실패·중단 또는 현재 입력과 다른 이력 |

완료한 과거 실행이 **현재 입력과 다름**이면 **완료**와 **확인 필요** 필터 양쪽에 나타날 수 있습니다. 이는 상태와 현재 입력 적합성을 별도로 보여 주기 때문이며 중복 실행이 발생했다는 뜻이 아닙니다.

### 3.2. 다른 직원의 공유 결과를 확인할 때

다른 직원이 실행한 결과가 내 목록에 없는 것은 정상입니다. **전처리 실행**을 눌러 **전처리 실행 대상 선택**에서 공유 참가자를 선택하면 해당 회차의 공유 준비 상태와 보존 결과를 확인할 수 있습니다. 대상을 선택하는 것만으로 실행되지 않습니다.

공유 상태는 그 회차의 최신 시도와 보존 결과를 보여 줍니다. 반면 내 목록에서 연 결과는 **선택한 실행 자체**의 결과입니다. 예를 들어 A가 성공한 뒤 B가 같은 회차에서 실패해도 A의 지정 실행은 A의 원래 성공 결과를 유지합니다. 다른 최신 시도의 실패나 입력 변경으로 지정 실행의 파일이 바뀌지 않습니다.

과거 실행 상세는 해당 **회차·실행**에 고정됩니다. 다른 직원이 새 회차를 선택해도 과거 결과가 새 회차 결과로 바뀌지 않습니다. 새 작업은 **현재 입력으로 재실행**을 눌러 대상 선택으로 돌아간 뒤 현재 회차에서 시작합니다.

## 4. 따라 하기: 새 클립으로 전처리

1. **분석·평가 → 전처리 → 전처리 실행**을 누릅니다.
2. 검색·행사 필터로 참가자를 찾고 **선택**을 누릅니다. **촬영 기록 확인 필요**이면 촬영 화면에서 실제 절차와 시각을 먼저 확인·확정합니다.
3. 상단 ID·반려견 이름·촬영 회차와 **현재 입력**을 확인합니다. 과거 실행을 보고 있었다면 현재 입력 대상 선택으로 이동합니다.
4. **다중 카메라 전처리**의 준비 안내·360 통합 영상 처리 제한을 읽습니다.
5. **제작 설정 → 카메라 우선순위**를 확인합니다. 필요한 카메라의 **위로 / 아래로**를 눌러 순서를 바꿉니다. 우선순위는 관찰창의 대표 선택에 사용하며 확인하지 않은 카메라 배치를 승인하는 기능은 아닙니다.
6. **대표 오디오 선택**을 고릅니다. 기본은 창별 가용 시간이 긴 영상이며 같으면 카메라 우선순위입니다. 특정 영상의 소리를 사용해야 한다면 그 영상을 명시적으로 선택합니다.
7. **새 클립으로 전처리**를 한 번 누릅니다.
8. 화면의 접수·진행 단계와 **마지막 확인** 시각을 봅니다. 오래 걸려도 상태를 확인하기 전에 실행 버튼을 반복하지 않습니다.
9. 완료 후 **저장된 결과**, 항목별 관찰창과 클립 미리보기를 확인합니다.

카메라 기본 목록에 실제로 없는 카메라가 보일 수 있습니다. 우선순위 목록에 있다는 것만으로 그 카메라 영상이 업로드되거나 제작되는 것은 아닙니다. 실제 회차 파일·동기화·관찰창 가용성으로 처리됩니다.

대표 오디오로 선택한 영상의 소리가 없거나 사용할 수 없으면 해당 사유가 표시됩니다. 여러 카메라의 같은 소리를 중복 합산하지 않습니다. 오디오 가용 초는 실제 청취 초나 발성 초가 아닙니다.

## 5. 진행 표시와 응답 유실 대응

| 표시·단계 | 의미 |
| --- | --- |
| 전처리 실행 요청 중 | 브라우저가 요청을 보냈으며 접수·결과를 확인하는 중 |
| 요청 접수 여부 확인 중 | 완료 응답을 받지 못해 같은 요청의 서버 접수 여부를 조회하는 중 |
| 실행 중 / 클립 제작 | 실제 클립 제작 단계 시작 |
| 관찰창 결과 정리 | 관찰창별 파일 가용성과 손실 근거 정리 단계 시작 |
| 재사용 검증 | 명시 재사용 요청의 기존 결과 무결성·호환성 검사 |
| 결과 검증·저장 | 입력·원본·규칙·산출물을 다시 확인하고 결과 저장 |
| 단계 기록 없음 | 과거 실행 등에 당시 단계 기록이 없음. 기록을 소급 생성하지 않음 |
| 완료 / 일부 완료 / 실패 / 중단됨 | 해당 실행의 종료 상태. 결과와 사유를 확인 |

진행 중에는 약 2초 간격으로 상태를 자동 조회합니다. 메뉴 재진입·같은 탭 새로고침으로 추적 정보를 복구할 때도 **조회만** 하며 새 전처리를 자동 요청하지 않습니다. 정상 종료 뒤에는 반복 조회가 멈춥니다. 단계가 바뀌는 시점을 표시하며 완료율이나 예상 남은 시간을 제공하지 않습니다.

**상태 조회 연결 끊김**은 서버 작업의 실패 판정과 다릅니다. 마지막 확인 시각과 마지막 상태를 보존하면서 조회를 계속합니다. 먼저 네트워크·로그인을 확인하고 **전처리 상태 새로고침** 또는 **내 실행 새로고침**을 사용합니다. 다른 최신 공유 결과를 읽지 못해도 선택 실행 결과는 별도로 유지됩니다.

응답을 받지 못했을 때는 이미 접수된 실행을 요청 식별로 찾습니다. 자동으로 재POST하지 않습니다. 실제 실행이 찾아지면 그 실행의 완료·실패를 확인합니다. 접수 자체가 확정 거절된 경우에는 최신 상태를 확인하고 사용자가 명시적으로 다시 실행합니다. 로그인 계정을 바꾸면 이전 계정의 내 실행 목록·일시적 추적 화면과 구별되므로 자신의 계정을 확인합니다.

## 6. 결과를 읽는 방법

### 6.1. 저장된 결과와 현재 입력

**저장된 결과**에서 입력 버전, 생성 시각, 물리 클립 수, 항목 관찰창 수를 확인합니다. 클립 수와 항목 수는 같은 숫자가 아닙니다. 여러 항목의 겹치는 관찰창이 같은 물리 클립에 연결될 수 있습니다.

**이전 입력 기준 결과입니다** 또는 **현재 입력과 다름**이 나오면 당시 결과는 보존되지만 현재 입력을 반영한 결과가 아닙니다. 기준 입력·최신 입력을 비교하여 새 전처리 필요 여부를 판단합니다. 과거 결과를 열었다는 이유만으로 그 결과가 현재 입력의 결과로 채택되지 않습니다.

360 통합 영상은 **현재 입력**의 처리 정보와 **이 결과의 처리 정보**를 각각 표시합니다. 정정 전 파일 배치·시간 정보와 정정 후 정보를 구별합니다. 발급된 과거 리포트나 고정 시트가 새 처리 정보로 자동 바뀌지 않습니다.

### 6.2. 항목별 관찰창

1. **항목별 관찰창**에서 검토할 창을 펼칩니다.
2. 연결 항목, 기준 영상의 시작·끝 초와 창 상태를 확인합니다.
3. **영상 가용**, **대표 오디오 가용**, 대표 오디오 선택 이유와 오디오 손실 범위를 봅니다.
4. 카메라별 파일 가용성·실제 관찰 기록, 오프셋, 가림·신체 미관찰·오디오 손실 사유를 확인합니다.
5. **…클립 …보기**를 눌러 연결된 실제 클립으로 이동합니다.

| 표시 | 해석과 다음 행동 |
| --- | --- |
| 영상 있음 + 관찰 미확인 | 파일 범위는 있으나 실제 사람 관찰 기록은 아직 확인 전 |
| 전체 관찰 기록 / 일부 관찰 기록 | 촬영 기록의 실제 관찰 근거. 파일이 길다는 이유로 전체 관찰이 되지 않음 |
| 영상 가림 / 신체 미관찰 | 해당 카메라·범위의 시각 근거 제한을 유지 |
| 오프셋 미확인 | 촬영 기록에서 실제 동기화 근거 확인 |
| MP4 변환 필요 | 보관 전용 파일 또는 외부 처리 정보 제한 확인 |
| 실제 프레임 없음 / AI용 실제 프레임 없음 | 해당 범위에 유효 실제 프레임이 없거나 AI용 클립이 없음. 없던 프레임을 만들어 채우지 않음 |
| 미수행 / 기회 없음 / 규칙 미확정 / 절차 확인 필요 | 서로 다른 근거 상태. 촬영 사실과 평가 정책 확인을 구별 |
| 사용할 오디오 없음 | 소리 근거 부족. 영상만 존재한다고 발성을 0으로 확정하지 않음 |

**일부만 완성**은 무조건 전체 업무 실패라는 뜻이 아닙니다. 만들어진 클립과 부족한 카메라·창의 사유를 각각 확인합니다. 가능한 근거를 사용하되 없는 항목의 관찰 부족을 유지합니다. 개21 등 규칙 대기를 영상 재실행만으로 해결하지 않습니다.

### 6.3. 물리 클립 미리보기와 원본 시각

1. **물리 클립 미리보기 → 미리볼 클립**을 고릅니다.
2. **클립 제작 방식**에서 **원본 FPS 클립** 또는 **AI용 1초 1프레임 클립**을 선택합니다.
3. **영상 열기**를 눌러 플레이어를 엽니다. 단순 목록·상태 조회와 실제 파일 열기는 별도 기록입니다.
4. 재생하여 내용·구간 경계를 확인합니다.
5. **확인할 실제 프레임 번호**를 바꾸어 **클립 초 → 원본 초 → 기준 영상 초**의 대응을 확인합니다.
6. 파일 상태를 확인해야 할 때 **클립 해시·출처**를 펼쳐 파일 참조·SHA-256·용량을 봅니다.

원본 FPS 클립은 실제 원본 프레임을 보존합니다. AI용은 **1초마다 실제 프레임 최대 1장**을 선택하고 연속 오디오를 보존합니다. 원본이 드물거나 결손이면 항상 매초 한 장이 생기는 것은 아닙니다. 외부 공급자 요청의 FPS·리사이즈는 이후 AI 분석 단계의 설정이며, 여기의 두 제작 방식과 구별합니다.

## 7. 검증된 결과를 재사용하는 방법

같은 입력·원본·동기화·규칙·제작 설정의 기존 결과를 다시 활용하려는 경우 사용합니다. 다른 입력의 결과를 강제로 가져오는 기능이 아닙니다.

1. 현재 입력 대상의 전처리 화면에서 기존 결과를 확인합니다.
2. 설정이 다르면 **이 결과의 설정 불러오기**를 누릅니다. 카메라 우선순위와 대표 오디오 설정을 저장 결과에 맞춥니다.
3. **현재 입력과 다름** 안내가 없는지, 제작 설정이 같은지 확인합니다.
4. **검증된 결과 재사용**을 누릅니다.
5. **재사용 검증 → 결과 검증·저장** 진행을 확인합니다.
6. 결과의 **해시를 검증한 기존 결과를 명시적으로 재사용했습니다**와 재사용 출처를 확인합니다.

재사용도 실제 요청 계정의 새 실행으로 기록되며, 원래 결과를 덮어쓰지 않습니다. 입력·원본·카메라·오프셋·FPS·규칙·제작기 호환성이나 파일 해시가 달라지면 거절합니다. 버튼이 비활성화되면 최신 입력 적합성, 동일 설정, 결과 존재, 진행 중 상태와 연결 상태를 확인합니다. 새 입력이 필요하면 **새 클립으로 전처리**를 사용합니다.

## 8. 오류·중단·충돌 해결

| 상황 | 해결 순서 |
| --- | --- |
| 촬영 절차와 실제 시각을 확인·확정한 뒤 전처리하세요 | 촬영 기록의 절차 선택·확인 근거·8구간·걷기·예외를 검토하고 현재 S1 기록을 확정합니다. |
| 이미 전처리 실행 중 / 잠금 충돌(409) | 활성 실행 종료를 확인한 후 명시적으로 실행합니다. 자동 대기열에 들어간 상태가 아닙니다. |
| 전처리 중 입력 참조·영상 계보·규칙이 변경됨 | 어느 직원이 어떤 입력을 저장했는지 확인합니다. 이전 실패 이력은 남기고 최신 입력을 검토·확정한 후 새 실행을 시작합니다. 처리 정보 정정도 입력 변경입니다. |
| 선택 회차가 바뀜 / 이전 회차의 보존 결과 | 과거 결과는 그대로 봅니다. 새 실행은 현재 저장 대상 회차에서 시작하며 필요하면 올바른 회차를 다시 선택합니다. |
| 중단됨 | 종료 없이 활성 작업이 사라진 상태입니다. 새 요청으로 다시 시작하라는 안내와 파일·서버 상태를 확인하고 명시 실행합니다. 실패·중단 실행을 완료로 표시하지 않습니다. |
| 접수 거절 응답 | 상태·최신 입력을 새로고침하고 원인을 수정한 뒤 다시 실행합니다. 시작 원장이 없는 거절 요청은 내 실행 목록에 행이 생기지 않을 수 있습니다. |
| 응답 유실·연속 상태 조회 오류 | 마지막 확인 시각과 현재 계정을 확인하고 조회로 접수 여부를 찾습니다. 조회 화면을 반복 열어 새 실행이 생기는 것은 아닙니다. |
| 파일·FFmpeg·저장 공간 오류 | 원본을 임의 덮어쓰지 않고 설치 도구·디스크 공간·원본 무결성을 확인합니다. 해결 후 명시 새 실행을 시작합니다. |
| 재사용 원본·설정이 다름 | 입력과 원본을 확인하고 설정을 맞추거나 새 클립을 제작합니다. 해시 검사와 호환성 검사를 우회하지 않습니다. |
| 결과·클립 손상 또는 유실 | 정상 결과로 사용하지 않습니다. 지정 실행 결과를 다른 성공 결과로 대체하지 않고 보관 파일·검증된 백업을 확인합니다. |
| 미리보기만 재생되지 않음 | 선택한 제작 방식의 클립 존재·로그인·원본 상태를 확인하고 **전처리 상태 새로고침**을 누릅니다. 브라우저 재생 오류와 서버 실행 실패를 구별합니다. |
| 로그인 만료 | 로그인 복구 후 자신의 목록과 공유 대상을 다시 확인합니다. 타인 공개 허가나 소유자 변경으로 해결할 문제는 아닙니다. |

동시에 촬영 기록을 수정하는 직원과 전처리하는 직원이 있으면 입력 버전 보호로 실행이 거절·실패할 수 있습니다. 최신 사실을 보존하려는 보호이므로, 전처리 동안 동일 대상 입력 변경 시점을 서로 조정하고 다시 확인합니다.

## 9. 완료 기준과 다음 기능

전처리 완료 기준은 **해시·입력·원본·규칙을 검증한 결과가 저장되고, 사용하려는 창·클립의 가용성과 사유를 확인한 상태**입니다. **완료**는 전 항목 관찰·점수 확정·AI 정확도·최종 유형의 보장이 아닙니다.

- 실제 클립과 관찰 근거를 바탕으로 [독립 채점](K-DOG_독립채점_사용설명서_v1.0_20261013.md)을 진행합니다.
- 현재 입력의 전처리가 준비되면 [AI 분석](K-DOG_AI분석_사용설명서_v1.0_20261013.md)을 명시 실행할 수 있습니다.
- 과거 고정 시트·결과는 해당 입력 판본의 자료로 보존됩니다. 입력을 바꾸었다고 기존 시트를 새 판본으로 자동 덮어쓰지 않습니다. 현재 입력으로 새 AI 분석을 할 때는 현재 유효 전처리가 필요합니다.
- 사건 시각·동기화를 고쳐야 하면 [촬영 기록](K-DOG_촬영기록_사용설명서_v1.0_20261013.md), 파일 출처·360 처리 정보를 고쳐야 하면 [영상 파일 업로드](K-DOG_영상파일업로드_사용설명서_v1.0_20261013.md)로 돌아갑니다.

실제 참가자 영상의 원본/압축본·낮은 FPS·1카메라/3카메라·Studio 처리의 품질과 시각 대응·처리시간, 실제 LAN·물리 PC 3대 운영은 실측 대기입니다. 합성 MP4의 실제 디코딩·클립 생성·가짜 공급자 연결 성공은 기술 경로의 검증이며 참가자 영상 품질이나 실 공급자 정확도를 보장하지 않습니다.
