## 문제와 결과

U01–U06은 메뉴별로 나눠 진행하므로, 남은 화면(설문 현황·검수 자료·직원 계정·백업)의 문구와 메뉴 사이 흐름은 따로 점검해야 한다 (F12). 현장 스태프와 교수의 실제 하루 흐름을 처음부터 끝까지 한 번에 확인하는 시험도 없다.

이 PR 이후:

- 남은 화면에 [§7 문구 기준](K-DOG_UIUX개편계획_v1.0_20261011.md)을 적용한다. 정책 부정문은 「자세히」 접기로 옮기고 각 화면 첫 줄을 다음 행동으로 바꾼다. 정책 내용은 지우지 않는다.
- 역할별 통합 시나리오 e2e를 추가한다 (합성 서버, 합성 바이트 파일, 외부 호출 0).
  - **행사 스태프**: 표준 양식 내려받기 → 명단 10명 업로드 → 현장 추가 1명 단건 접수 → 설문 파일 업로드(기존 참가자 갱신 확인, 오류 1행 제외) → 원본1~3 수신·연결 → 촬영 기록 화면 진입.
  - **교수**: 로그인 → 「내가 할 일만」 목록 → 참가자 열기 → 선행 조건 체크리스트 확인 → 읽기 전용 확인.
  - **관리자**: 교수 계정 추가 → 백업 화면 진입.
- 화면 텍스트 자동 점검: 운영자·교수 화면에서 개발 진행 코드(`S16`, `G0[1-5]`, `D0[1-6]`, `공급자 호출`, `교수 테스트 대기`)와 UUID·64자리 해시가 기본 노출되지 않는지 확인한다. 「기술 정보」 접기 안은 예외.
- [운영 안내](../PILOT_OPERATIONS.md)의 촬영 당일 절차를 새 메뉴 이름과 일괄 등록 흐름으로 고치고, 표준 양식 사용법을 추가한다. [개발 안내](../DEVELOPMENT.md)의 시험 설명을 갱신한다.
