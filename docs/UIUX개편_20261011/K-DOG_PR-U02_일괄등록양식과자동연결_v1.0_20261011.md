## 문제와 결과

현장 스태프는 사전 신청 명단이나 Google Forms 응답을 받아 올리기만 하면 되기를 원한다. 지금은 파일을 읽은 뒤 모든 열 연결을 비워 두어([FormsImporter.tsx:55](../../frontend/src/FormsImporter.tsx#L55)) 헤더가 화면 항목과 같아도 최대 71칸을 손으로 고른다 (F05). 미리보기 버튼은 이유 없이 비활성이고, 「원자료 프로필」「매핑 버전」을 직접 입력하게 한다 (F06).

이 PR 이후 「현장 운영 › 일괄 등록」은 4단계 화면이 된다.

```
① 양식 받기(선택)  →  ② 파일 올리기  →  ③ 열 연결 확인  →  ④ 미리보기·등록
```

- **① 표준 양식**: 「명단만」「명단 + 설문 28문항」 두 가지를 CSV·XLSX로 내려받는다. 헤더는 화면 항목 이름(한국어)과 같고, XLSX는 ID 열을 텍스트 형식으로 지정하고 선택지(성별·크기·동의 등)를 데이터 유효성 목록으로 넣는다. 첫 시트에 짧은 작성 안내를 둔다.
- **② 파일 올리기**: 끌어다 놓기 또는 선택. 행사 ID를 이 단계에서 받는다 (최근 사용 행사 ID를 기본값으로 제안, 브라우저 저장은 편의용이며 실패해도 동작).
- **③ 자동 연결**: 헤더가 표준 이름 또는 알려진 별칭과 같으면 자동으로 연결한다. 결과를 「자동 연결 N개 · 확인 필요 M개 · 연결 안 됨 K개」로 요약하고, 연결 안 된 **필수 항목**(반려견 이름 등)만 먼저 펼쳐 보여준다. 나머지는 「모든 연결 보기」 안에서 고칠 수 있다.
- **④ 미리보기**: 기존 S02 미리보기·확정을 그대로 쓴다. 버튼이 비활성이면 옆에 빠진 조건을 쓴다 (예: 「행사 ID를 입력하세요」「반려견 이름 열을 연결하세요」).

명단만 있는 파일(설문 열 없음)과 설문만 있는 파일도 같은 화면에서 받는다. 설문 열이 없으면 설문 상태는 「미등록」으로 남는다 (현행 서버 동작).

## 범위와 결정

- **자동 연결은 헤더 문자열 기준**이다. 셀 값으로 열 의미를 추정하지 않는다. 정규화: 앞뒤 공백·전각/반각·대소문자·괄호 안 보조 설명 제거 후 비교. 한 원본 열이 여러 항목 후보와 맞으면 자동 연결하지 않고 「확인 필요」로 둔다.
- 별칭 표는 코드에 고정한다 (`participant_id`: 참가자 ID·참가번호·접수번호, `dog_name`: 반려견 이름·강아지 이름·강아지, `guardian_name`: 보호자명·보호자 이름·성함, `s01`~`s28`: Q1·Q01·1번·문항 1 등, `sXX_reason`: Q01 빈칸 사유 등). Google Forms 타임스탬프·이메일 열은 연결하지 않는다.
- 자동 연결은 **제안**이다. 서버에는 지금처럼 명시한 `columns`만 보낸다. 서버 계약(`FormsMappingV4`) 변경 없음.
- 「원자료 프로필」「매핑 버전」은 기본값(`google-forms`, `forms-map-1`)으로 두고 「고급 설정」 접기로 옮긴다. 「과거 판본 원자료 참고만 등록」도 고급 설정으로 옮기고 체크박스 스타일 결함을 고친다.
- 응답 라벨 연결(「매우 그렇다=5」 등)은 문항별 입력을 유지하되, 같은 라벨 집합을 여러 문항에 한 번에 적용하는 「선택 문항에 같은 라벨 적용」을 둔다.
- 표준 양식 XLSX는 서버에서 만든다 (`openpyxl`은 이미 잠금 의존성). CSV 양식은 같은 엔드포인트에서 UTF-8 BOM으로 내려준다 (Excel 한글 깨짐 방지).
