## 문제와 결과

화면 안내는 「원본1→CAM1 · 원본3→CAM2 · 원본2→CAM3」인데 모든 수신 카드가 CAM1·원본 번호 1로 채워져, 그대로 누르면 잘못 연결된다. 연결 완료 카드에 회차 UUID가 보이고, 해시·수신 ID가 크게 표시되며, 처음 연결도 「대상 연결·충돌 재시도」로 쓴다 (F08). 선택한 참가자의 촬영 기록은 수신 보관함 아래에 있어 길게 스크롤해야 하고, 연결 후에도 「영상 0개」로 보여 실패처럼 보인다 (F09).

이 PR 이후:

- U01에서 나눈 두 하위 메뉴를 다듬는다.
  - **영상 수신·연결** (`#/recording/inbox`): 현장 PC들이 공유하는 보관함. 미연결 수신물이 위, 연결 완료는 「오늘 연결한 파일」 접기 아래.
  - **촬영 기록 (8구간)** (`#/recording/record`): 선택 참가자의 기록 패널이 화면 맨 위. 이 참가자에 연결된 영상과 「영상 읽기 확인 대기 N개」를 패널 상단에 요약한다.
- 파일명이 `원본1`·`원본2`·`원본3`(또는 같은 규칙의 숫자)이면 원본 번호와 카메라를 안내 표대로 미리 채운다 (원본1→CAM1, 원본3→CAM2, 원본2→CAM3). 규칙에 맞지 않으면 빈칸으로 두고 직접 입력하게 한다.
- 같은 참가자·회차에 같은 카메라를 두 번 고르면 연결 전에 칸 아래 경고를 띄운다.
- 「연결 참가자」 목록은 순번·참가자 ID·반려견 이름으로 보이고 검색할 수 있다. 촬영 기록 화면에서 연 경우 선택 참가자를 기본값으로 둔다.
- 버튼 문구: 처음은 「연결」, 충돌 뒤에만 「다시 연결」. 「화면 대기 항목 제거」는 「목록에서 숨기기」로, 「미연결 수신물 정리」는 「수신 파일 삭제」로 바꾸고 삭제는 확인을 받는다.
- 회차는 「1차 촬영」 이름으로 쓴다. 수신 ID·SHA-256·입력 버전은 카드의 「기술 정보」 접기로 옮긴다.
- 영상 상태를 세 단계로 쓴다: 「수신 완료」 → 「연결됨 · 영상 읽기 확인 대기」 → 「사용 가능」. 맥락 바와 목록의 영상 수는 「사용 가능 1 · 확인 대기 2」처럼 나눠 쓴다.

## 범위와 결정

- 카메라 기본값 규칙은 현재 화면 안내 문구와 같은 매핑만 쓴다. 다른 규칙을 추정하지 않는다. 기본값은 제안이며 서버 검사는 그대로다.
- 영상 상태 표시는 기존 응답 필드(수신·연결·probe 결과)로 만든다. 상태 판정이 기존 응답만으로 불가능하면 이 PR에서 읽기 전용 필드를 추가하되, 저장 형식은 바꾸지 않는다. 착수 시 `UploadInbox`·사례 응답의 실제 필드를 확인해 기록한다.
- 2026-10-05에 만든 촬영 기록 8구역 접기·상단 고정 저장 도구는 유지한다. 「촬영 기록 초안 저장」「확정」이 비활성일 때 빠진 조건(예: 「기준 영상을 고르세요」「실제 촬영 절차를 확인하세요」)을 도구 옆에 쓴다.
- 교수/검토자는 촬영 기록만 읽기 전용으로 보고 수신·연결 메뉴는 보이지 않는다 (현행 권한과 같음).
