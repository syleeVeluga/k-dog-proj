## 문제와 결과

전처리·독립 채점·리포트는 같은 3열 표(행사/참가자·반려견·열기)를 각자 구현하고, 참가자별로 어느 단계까지 왔는지 보이지 않는다. 교수가 채점을 열면 「S1 Excel 가져오기 비활성 — G01/G04 수령 후」「S16 측정 대기」「기본 예정 공급자 호출 43회」「실제 적절성은 교수 테스트 대기입니다」 같은 개발 내부 문구와, 채점을 막는 조건 3줄이 흩어져 나온다 (F10·F11). 연구 내보내기는 독립 채점 화면 맨 아래 접기에 숨어 있다.

이 PR 이후:

- 세 화면이 **공통 참가자 목록**을 쓴다. 열: 순번 · 참가자/반려견 · 진행 단계 · 다음 할 일 · 담당. 진행 단계는 `촬영 확정 → 전처리 → 채점 → 최종 결과 → 리포트`를 점 5개로 보여준다. 행사·단계로 거르고, 「내가 할 일만」 필터(교수: 나에게 배정된 시트)를 둔다.
- 참가자를 열면 화면 위에 **선행 조건 체크리스트**를 둔다.

  ```
  채점을 시작하려면
  ✓ 촬영 기록 확정
  ✗ 전처리 완료        → 운영자가 「전처리」에서 실행합니다
  ✗ 평가자 배정        → 운영자가 배정합니다
  ```

  교수에게는 「운영자에게 요청할 일」로, 운영자에게는 해당 메뉴로 가는 버튼으로 보인다.
- 교수/검토자 화면에서 개발 진행 코드와 비용·호출 수 문구를 뺀다. AI 실행 상태는 「AI 초안: 준비 안 됨 / 실행 중 / 완료」 한 줄로 쓰고, 세부(설정·호출 수·비용)는 운영자·관리자에게만 「기술 정보」로 보인다. Excel 가져오기 비활성 안내는 운영자에게만 「준비 중인 기능」으로 짧게 둔다.
- 연구 내보내기를 「리포트 › 연구 내보내기」 하위 메뉴로 옮긴다 (운영자·관리자, 참가자 선택 필요는 현행과 같음).
- 리포트 발급 이력의 「불변 출력 출처」·단계별 시간·토큰은 「기술 정보」 접기로 유지한다.

## 범위와 결정

- 진행 단계는 기존 사례·실행 응답에서 계산한다. 목록 한 번에 단계를 계산할 정보가 `/cases` 응답에 없으면, 읽기 전용 요약 필드(`progress`)를 `/cases`에 추가한다. 계산 규칙은 서버 한 곳에 둔다. 저장 형식 변경 없음.
- 선행 조건 문구는 현재 `ScoreSheetsV4`·`AiRunsV4`·`ReportRunsV4`가 내는 상태를 그대로 분류해 쓴다. 새 판정 규칙을 만들지 않는다.
- **Q03**: 권장안(교수/검토자 리포트 조회 허용, 발급 불가)으로 결정되면 `Report` 권한 분기와 메뉴 역할에 `reviewer`를 읽기 전용으로 추가하고, 서버 조회 API 권한을 함께 고친다. 결정 전에는 현행 권한을 유지한다.
- 독립 채점의 정보 비공개 규칙(독립 제출 전 다른 평가 결과 비공개)은 그대로다. 공통 목록의 「담당」 열은 배정 여부만 보이고 다른 평가자의 점수·진행률은 보이지 않는다.
- 문구 정리는 [개편 계획 §7](K-DOG_UIUX개편계획_v1.0_20261011.md) 기준을 따른다. 지운 개발 문구의 원문은 개발자 화면과 기존 문서에 남아 있는지 확인한다.
