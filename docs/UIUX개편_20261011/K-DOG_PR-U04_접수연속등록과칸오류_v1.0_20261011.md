## 문제와 결과

일괄 등록(U02·U03)이 기본 경로가 되더라도, 현장 접수 데스크에서는 명단에 없는 참가자를 한 명씩 추가한다. 지금은 저장하면 상세 화면으로 넘어가고 폼이 접혀 다음 사람을 받으려면 두 번 더 눌러야 한다 (F02). 순번만 겹쳐도 「중복 ID 또는 연결 충돌입니다」라는 전역 오류만 나오고(`api.py`의 `sqlite3.IntegrityError` 공통 처리), 형식 오류는 브라우저 기본 툴팁뿐이다 (F03). 목록 행은 클릭되지 않고, 채점 전 참가자에 「S1 재분석 필요」가 붙는다 (F04).

이 PR 이후:

- 저장 후 **폼 화면에 머문다.** 행사 ID는 유지하고 나머지 칸을 비우며, 순번은 「다음 빈 순번」을 제안한다. 상단에 「0003 콩이 등록됨 · 상세 보기 · 촬영으로」 알림을 띄운다. 「저장하고 상세 열기」는 보조 버튼으로 둔다.
- 참가자 ID·순번 중복은 **해당 칸 아래**에 「순번 1은 이미 0001(초코)이 쓰고 있습니다」처럼 표시하고 그 칸으로 포커스를 옮긴다.
- 행사 ID·참가자 ID·나이 형식 오류는 입력 중(blur) 칸 아래에 한국어로 표시한다.
- 목록 행 전체를 눌러 상세를 연다. 버튼은 「열기」로 쓰고 ↗를 없앤다.
- 채점값이 없는 참가자의 상태는 「채점 전」으로 쓴다. 「S1.1 · 10월 2일」 같은 판본 표기는 상세의 「기술 정보」로 옮긴다.
- 동의 항목 3개를 「동의서 확인」 묶음 하나로 모아 동의서 순서대로 세로 배치한다. 설명 문단은 묶음 아래 한 줄 + 「자세히」로 줄인다.

## 범위와 결정

- 서버는 `POST /api/cases`에서 삽입 전에 `(event_id, participant_id)`와 `(event_id, sequence_no)` 중복을 확인하고, 409 응답에 `{"detail": "...", "field": "participant_id" | "sequence_no", "existing": {"participant_id", "dog_name"}}`를 준다. 동시 요청 경합으로 `IntegrityError`가 나면 기존 공통 처리로 떨어지되 화면은 기존 문구를 그대로 보여준다.
- `existing`에는 같은 행사 안의 참가자 ID와 반려견 이름만 담는다 (운영자·관리자에게 이미 목록으로 보이는 정보).
- 「다음 빈 순번」은 화면에서 현재 목록으로 계산한 제안값이며 서버 검사는 그대로다.
- 정정(`참가자 기본 정보 정정`) 폼에도 같은 칸 오류 처리를 적용한다.
- `api.ts`의 `ApiError`에 `field`·`existing`을 실어 보낸다. 다른 화면의 오류 처리는 바꾸지 않는다.
- 교수/검토자 접수 화면은 등록 폼이 없으므로 행 클릭·상태 용어만 적용된다.
