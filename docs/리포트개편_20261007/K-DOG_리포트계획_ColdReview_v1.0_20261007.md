## 검토 범위

사용자의 cold review→수용 항목만 반영→원격·로컬 병합 요청에 따라 총괄 계획·PR별 계획 6개와 기존 요구사항 대장 4개의 변경을 검토했다. 회신의 수용 범위, 개발/교수 책임, 실제 코드의 판본·실행 계약, 선행 관계와 검증 가능성을 대조했다. 고객 원본·참가자 자료·제품 코드·운영 설정을 변경하는 작업은 아니다.

Graft의 정책 문자열 전수 검색과 실행 handler 조회를 사용해 계획의 영향을 확인했다. 문서의 링크·파일·시험 경로 검사는 실제 제품 테스트와 구분한다. 이 리뷰는 계획에 대한 검토이며 RP01~RP06 제품 구현의 결함 검증을 완료했다는 뜻이 아니다.

CR01 근거는 [설문 결과 계약](../../backend/app/survey_v4.py), [비교 계약](../../backend/app/domain/comparisons_v4.py), [비교 처리](../../backend/app/comparisons_v4.py)다. CR02 근거는 [AI 실행 handler](../../backend/app/scoring_ai_v4.py)이며 기준 코드에서 `handler`는 채점·계산·게시만 처리하고 게시 결과를 `basic_data`와 대조한다. 제품 코드 결함으로 단정하지 않고, 새 기능 구현 계획에 필요한 조건을 보완했다.

두 항목 외에 수용 범위를 넓히는 변경은 적용하지 않았다. 다음 경계는 검토 후 유지한다.

- 1~3번은 방향 수용과 실제 구현/교수 품질 검증을 구분한다. 문장은행 제공을 새 선행조건으로 만들지 않는다.
- 외부 비교의 출력 의사와 문항별 동등성 확정은 구분한다. 교수님이 두 기준표를 작성·확정하며 RAG/임베딩과 개발자의 전문 기준 추정은 제외한다.
- 장면 제거는 사진 출력·프레임 추출에 적용한다. 분석 사건 근거·중복 계수 방지와 기존 S1 불변 결과를 보호한다.
- 추가 관찰 무효·실측·원본 부재를 이번 회신으로 완료 처리하지 않는다. 교수 검토를 매 발급의 일괄 승인 요건으로 확대하지 않는다.

## 재검증과 병합 기록

수용 수정 후 RP01/RP02의 변경 지점·시험 조건과 총괄 RP-T07/RP-T11의 대응을 재검토했다. 계획 범위에서 수용한 두 지적은 반영됐으며 추가로 확인한 미해결 계획 결함은 없다. 제품 구현은 미착수다.

- 변경 문서 12개(신규 계획 7·리뷰 1, 기존 대장 4), 상대 링크 107개 존재 확인.
- 코드 참조 41개(명시한 신설 예정 포함), backend 시험 모듈 22개, 브라우저 시험 경로 10개 확인.
- SRC02/SRC03 SHA-256이 원본 자료 목록과 일치. 고객 원본 변경 없음.
- A01~A06 및 RP-T01~14 담당, RP01→RP02→RP03→RP04→RP05→조건부 RP06의 선행 관계 검토.
- 문서 공백 검사와 `git diff --check` 통과. 원격 PR의 최종 상태는 병합 시 별도로 확인한다.

계획·수용 수정 commit은 `9292b22e3b22f85316a6f04b0455868d5a9d6e10`이며 [PR #53](https://github.com/syleeVeluga/k-dog-proj/pull/53)에서 병합한다. 이 head의 원격 검사 조회는 checks/statuses가 비어 있었고 GitHub는 `CLEAN`/`MERGEABLE`을 반환했다. Copilot 자동 리뷰는 요청자의 할당량 제한으로 실행되지 않았으므로 자동 리뷰 통과로 기록하지 않는다. 위 문서 cold review·수용 수정·로컬 검증과 원격 자동 리뷰의 미실행을 구분한다. 이 기록의 최종 head와 병합 상태는 PR 및 완료 응답에서 확인한다.

제품 코드 변경이 없으므로 backend/frontend 제품 시험은 실행하지 않는다. 실제 AI 호출·교수 검토·외부 비교표 수령·운영 배포·고객 발송도 수행하지 않는다. 원격 병합은 검증한 최종 PR head와 병합 가능 상태를 확인한 뒤 수행하고 로컬 `main`을 같은 원격 결과로 동기화한다.
