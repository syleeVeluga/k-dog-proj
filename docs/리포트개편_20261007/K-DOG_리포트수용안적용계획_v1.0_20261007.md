## 1 목적과 근거

확정된 설문 계산 방향, 근거 기반 AI 문장 생성, AI 애착 유형 우선 판단·교수 검토 방식을 현재 앱에 반영한다. 이미 결정된 사진 장면 제거와 새 디자인을 함께 적용하고 HTML·PDF 생성/발급 기반을 재사용한다. 외부 비교는 교수님이 확정한 문항 대조표와 지표별 산출·출력 기준표를 받은 후 연결한다.

| 근거 | 적용 범위·상태 |
| --- | --- |
| 사용자가 2026-10-07 대화에서 전달한 의뢰자 회신 1~4번 | 회신 내용을 수령한 것으로 기록. 원메일 파일·발송일을 별도로 확보한 것은 아니며 이 날짜는 검토·계획일이다. 연락처·서명은 복제하지 않음 |
| 후속 사용자 지시 | RAG·임베딩 방식 제외. 전문적인 문항 동등성 판단·비교표 확정은 교수님 담당. 수용안의 별도 적용 계획 작성 |
| 통합명세 SRC02 | 9절, 10.1~10.5, 부록 E/G. 회신과 충돌하는 종전 보류 절차는 회신 범위에서 개정 |
| 산출근거 SRC03·포맷 안내 SRC10·리포트 예시 | 문항·산출·출력 연결 근거. 예시 레이아웃·6쪽·사례 값은 새 요구사항으로 복사하지 않음 |

## 5 공통 구현 원칙과 판본

1. 원자료·83개 직접 수치·확정 계산·역채점은 프로그램 계약을 유지한다. AI는 원점수나 비교 수치를 새로 계산/보정하지 않는다. 원본 추출 자산에 회신을 소급 반영하여 SRC02/SRC03의 내용인 것처럼 만들지 않는다.
2. RP01의 새 설문 정책, RP02의 판단 지침, RP03의 문장 지침, RP04의 표현 자산을 각각 판본/hash로 고정한다. 구현 제안은 기존 추출물을 보존한 날짜별 새 정책 자산이다. 범용 규칙 엔진이나 영구 구판 채점 경로는 추가하지 않는다.
3. 기존 S1 불변 결과·발급 bytes와 원입력은 보호한다. 새 정책은 새 실행/결과에 적용하며, 영향받는 기존 실행은 재생성 필요를 안내한다. 이전 S1 파일을 읽는 데 필요한 최소 판본 처리를 유지하되 폐기된 9월 점수 실행을 복원하지 않는다.
4. AI 입력에는 허용된 관찰 근거·계산·설문·완료 의견만 전달한다. API 키·불필요한 식별정보·검토 메모·견본 사례를 넣지 않는다. 실제 자료 호출은 기존 동의·권한·예산·삭제 검사를 따른다.
5. AI 요청·응답·검증·수리·사용량·판본을 실행 단계의 불변 산출물로 남긴다. 기존 점유 토큰·중복 호출 제어·권한/삭제 재검사·정확한 재사용 조건을 재사용한다. 응답 유실을 무조건 성공 또는 무료 재시도로 처리하지 않는다.
6. 구조·허용 유형·근거 ID·수치/대상 일치의 자동 검증과 전문적 의미·판정 적절성의 교수 검토를 구분한다. 생성 AI나 검사 AI만으로 전문적 타당성 검증 완료를 선언하지 않는다.
7. 교수 테스트 검토를 매 리포트 발급마다 사람 승인을 받는 새 운영 절차로 확대하지 않는다. 보류는 해당 영역에 한정하고 다른 유효 결과는 출력할 수 있게 한다.
8. 기존 발급/Worker/화면·비교 등록 기능을 우선 재사용한다. RAG·임베딩·벡터 DB·파인튜닝·논문 전체 업로드 기능·새 비교 관리 플랫폼은 범위 밖이다.
9. 계획 작성 중 새 라이브러리 설치나 공급자 호출은 없다. 구현 때 실제 사용할 라이브러리/공급자 API의 최신 안정판·호환성·공식 문서를 확인하고 날짜·선택 버전·유지 이유·링크를 PR 기록에 남긴다. 무관한 의존성 업그레이드는 하지 않는다.

## 6 통합 수용 기준

## 7 상태·결정 변경과 검증 기록

각 PR 파일에 `commit/PR, 실행 명령·결과, 입력이 합성인지 실제인지, 교수 검토 상태, 발견사항·조치, 미완료 항목, 적용 판본`을 추가한다. 아직 위 항목을 실행하지 않았으므로 기존 S단계의 체크박스를 복사하지 않는다.

추가 취소·축소가 도착하면 A01~A06 및 관련 RP 범위·기대값을 먼저 갱신한다. 요구 취소는 구현 완료로 표시하지 않는다. 고객 원본·실제 참가자 결과·회신 원메일은 공개 저장소에 추가하지 않고 비식별 결정 요약과 보호된 원본 참조를 사용한다.

계획 문서 검증은 상대 링크·참조 파일·PR 선행관계·A/RP-T 담당 누락·원본 hash·`git diff --check`로 수행한다. 결과는 이번 작업 완료 응답에 기록하며 제품 테스트 통과와 구분한다.
