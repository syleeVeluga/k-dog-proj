# K-DOG 구현 문서 검수

검수일: 2026-09-05  
대상: 구현 지시서 v1.0, AI 처리 파이프라인 v0.1, PRD v0.4의 연결 요구사항  
방식: 최신 사용자 요구와 문서 간 일관성·처리 순서·데이터 계약 대조

## 판정

핵심 범위는 반영되어 있으나, 구현 인계 전에 아래 5건의 계약 보완이 필요하다. P1은 결과 무결성·전송 중단에 영향을 주는 우선 수정 사항이며, P2는 구현 방식에 따라 실패·비용 증가·잘못된 결과 선택을 일으킬 수 있는 충돌 또는 명세 공백이다.

이번 검수는 문서 검수다. 실제 앱의 결함을 재현하거나 AI 품질·성능을 시험한 결과가 아니다. 원본 Excel의 모든 셀을 이번에 다시 검산한 것도 아니다. 기존 문서와 Excel은 수정하지 않았다.

## F-01 · P1 · 점유 확인 전에 공용 결과 파일을 교체할 수 있음

**위치:** AI 파이프라인 §9.1, 537~542행. 구현 지시서 §11, 414행. 파이프라인 §8.3의 단계 결과 경로 예시도 함께 해당한다.

**문제:** 저장 순서가 ‘최종 파일 반영 → 점유 토큰 재확인 → DB 성공 기록’이다. 오래된 실행이 점유를 잃은 뒤 늦게 응답하면, 새 실행이 성공시킨 같은 경로의 결과 파일을 먼저 교체할 수 있다. 이후 DB 변경을 거절해도 파일은 이미 바뀌어 ‘오래된 실행은 덮어쓰지 못한다’는 조건이 성립하지 않는다.

**수정안:** 결과 파일은 run·step·attempt별로 고유하고 불변인 경로에 기록한다. 검증 후 짧은 DB 트랜잭션에서 현재 점유 토큰과 단계 상태가 일치할 때만 성공 상태와 해당 파일 참조를 함께 변경한다. 조회는 DB가 채택한 참조를 사용한다. 점유를 잃은 시도의 파일은 미채택 산출물로 남기고 정리한다. 복구에서도 현재 유효한 시도인지 확인하며, 입력 해시가 같다는 이유만으로 과거 시도를 채택하지 않는다. 파일 교체 직전 토큰 검사만 추가하는 방식은 검사와 교체 사이의 경합을 해결하지 못한다.

**검증 사례:** 실행 A 응답을 지연 → 점유 만료 → 실행 B 성공 → A 응답 도착. 이후 DB 참조·화면·내보내기 모두 B 결과를 유지해야 한다.

## F-02 · P1 · 삭제 상태가 실행 도중 변경될 때의 재확인 계약

**2026-09-06 범위 개정:** 참가 신청은 앱 밖에서 사전 처리한다. 기존 검수의 동의 관리 요구는 폐기하고 자료 삭제에 대한 재확인 계약을 유지한다. [변경·검증 기록](K-DOG_동의관리제거_v1.0_20260906.md).

**위치:** AI 파이프라인 S0 및 §7.2, 구현 지시서 §7 S0·§8.3, PRD §7.7·§11.

**문제:** 접수 당시 입력만 사용하면 대기 또는 실행 도중 삭제 요청이 들어온 뒤에도 후속 공급자 호출과 내보내기를 계속할 수 있다.

**수정안:** 분석 재현용 입력 스냅샷과 현재 삭제 상태를 분리한다. 원격 파일 업로드, 각 외부 AI 요청·재시도, 산출물 채택, 내보내기 생성·파일 제공 직전에 현재 상태를 재확인한다. 삭제 접수는 진행 작업의 점유를 무효화한다. 늦은 완료 응답이 삭제 상태를 해제하거나 파일을 재노출하지 못하도록 한다. 이미 전송된 요청의 취소·회수는 보장하지 않으며, 원격 임시 파일 정리는 계속 수행한다.

**검증 사례:** 대기 중 삭제 시 외부 호출 0회, 업로드·관찰·병렬 평가·설명·출력 생성 도중 삭제 시 늦은 결과 채택 차단, 기존 export_id 재다운로드 차단, 백업 복원 후 삭제 상태 재적용을 확인한다.

## F-03 · P2 · 이전 run 재사용과 다른 run 근거 거절이 충돌함

**위치:** AI 파이프라인 S4 245행, §7.2 435행, §10 581행·587행.

**문제:** 설문 변경 시 새 run에서 영상 관찰·행동 평가를 재사용하도록 하면서, 다른 run의 근거는 거절하도록 한다. 재사용 자료를 새 run에 어떻게 연결하는지 없다. 이전 evidence_id를 그대로 쓰면 검증에서 거절될 수 있고, 검사를 무조건 완화하면 무관한 근거까지 허용할 수 있다. 이로 인해 불필요한 영상 재호출이나 근거 연결 실패가 발생할 수 있다.

**수정안:** 같은 case·session, 동일한 관련 입력/설정 해시, 현재 접근·삭제 상태를 확인한 뒤 새 run manifest에 재사용 산출물의 원본 run·해시·버전을 등록한다. 검증 규칙을 ‘현재 run의 허용 근거 목록에 포함된 자료만 허용’으로 정의한다. 파일 복사와 참조 방식 중 하나를 명확히 택하고, 평가 결과까지 재사용할 때 근거 ID 연결도 함께 보존한다. 무관한 run의 참조는 계속 거절한다.

**검증 사례:** 설문만 수정한 새 run은 Gemini/S4 호출 없이 기존 행동 평가를 읽고 설문·설명만 갱신한다. 다른 참가자·세션·변경된 영상의 근거를 연결하면 거절한다.

## F-04 · P2 · 여러 실행 중 기본 조회·전체 내보내기에 사용할 결과가 정의되지 않음

**위치:** 구현 지시서 §5.1~5.3, 특히 179행·185행·200행, §9 360행. AI 파이프라인 §8.2 475행.

**문제:** 재촬영·재분석·사람 수정 버전은 보존하지만, 한 참가자에게 여러 run이 있을 때 목록과 전체 내보내기가 어느 결과를 선택하는지 정하지 않았다. ‘가장 늦게 완료된 결과’를 쓰면 이전 입력의 느린 실행이 최신 입력의 결과를 밀어낼 수 있다. 파일 생성 중 참가자별 최신 결과를 차례로 조회하면 전체 묶음의 기준 시점도 달라질 수 있다.

**수정안:** 현재 선택 세션·입력 revision과 그에 대응하는 표시 run을 명시하고, 완료 시간만으로 교체하지 않는다. 새 실행이 미완료인 경우 이전 결과는 이전 버전임을 표시해 열람할 수 있게 한다. 전체 내보내기를 접수할 때 대상 case·session·run·결과 revision 목록을 한 번 고정한 batch manifest를 만든다. 처리 중·결과 없음인 참가자도 상태 행으로 남긴다. 기술적인 결과 선택이며 사람 승인 단계를 추가하지 않는다.

**검증 사례:** 입력 v1 실행을 지연시킨 뒤 v2 실행 완료 → v1 뒤늦게 완료해도 기본 결과는 v2 유지. 전체 출력 도중 점수 수정이 발생해도 해당 묶음은 최초 고정한 revision만 사용해야 한다.

## F-05 · P2 · 미정 시간 경계에 ‘초안 규칙’을 사용할 수 있다는 예외가 모호함

**위치:** 구현 지시서 §6.3 234행. 같은 문서 작업 시작 지시의 ‘집계 경계를 추측하지 말 것’, §6.3 238행과 대조.

**문제:** 애매한 대표 행동·시간 경계 항목을 `insufficient_evidence 또는 명시적 초안 규칙`으로 처리하도록 허용한다. 누가 정한 초안인지, 개발 시험용인지, 실제 참가자 결과에 쓸 수 있는지가 없다. 코딩 에이전트가 임의 경계를 문서화한 뒤 운영 규칙으로 사용할 여지가 있다. 영상 근거가 충분해도 규칙만 미정인 상황을 근거 부족과 혼동할 수도 있다.

**수정안:** 실제 결과에서는 미정 규칙의 영향을 받는 점수만 null로 두고 `rule_pending` 사유를 별도로 저장한다. 모델의 관찰 부족 상태와 구분하며 다른 항목은 계속 처리한다. 개발자가 작성한 초안은 명시적인 시험 모드에서만 사용하고, 책임자가 정한 규칙을 버전으로 등록한 뒤 운영 적용한다. 이는 참가자별 승인 흐름과 별개다.

**검증 사례:** 정확히 2초·5초·15초인 관찰과 복수 행동 사례에서 규칙 미정 시 임의 점수가 생기지 않아야 한다. 초안 시험 결과는 운영 결과·전체 내보내기에 섞이지 않아야 한다.

## 유지해도 되는 주요 결정

- 참가자 직접 접속 없이 운영자·교수 조회 및 수동 파일 전달.
- 검토를 승인·반려 절차로 바꾸지 않고, 완료 분기·점수를 바로 조회.
- 참가자 20명·카메라 2대·영상 약 3분을 계획 예시로 사용하고 입력 제한으로 강제하지 않음.
- Gemini 관찰 뒤 선택한 GPT 또는 Claude 공급자로 반려견 36항목·보호자 19항목 병렬 평가.
- 실제 행동 55항목·설문 30문항을 유지하면서 Excel 배치는 단순화.
- 개발자 전용 키·프롬프트 관리, 로컬 PC 관리자에 대한 키 보호 한계 명시.
- 최소 UI·5개 핵심 테이블·별도 worker, 로컬 우선과 클라우드 확장 경계.
- q23·4영역·②④ 유형 미정 상태를 명시하고 다른 결과는 계속 제공.

## 보완 적용 범위

F-01~F-03은 AI 파이프라인의 단계 계약과 구현 지시서·필수 테스트에 함께 반영해야 한다. F-04~F-05는 구현 지시서의 버전 선택·계산 상태 계약에 우선 반영하고 파이프라인을 맞춘다. PRD의 핵심 사용자 요구나 55/30 항목을 변경할 필요는 없다.

현재 검수서는 지적 사항과 수정 제안이다. 기존 문서에 수정 반영이 완료되었다는 의미는 아니다.
