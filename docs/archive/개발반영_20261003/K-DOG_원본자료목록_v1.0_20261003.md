## 2 새 작업 환경에서 확보

1. 프로젝트 담당자가 제공하는 기존 보호된 전달 경로로 이 묶음을 받는다. 공개 다운로드 URL이나 저장소 첨부를 새로 만들지 않는다.
2. 원본은 위 로컬 폴더 또는 접근을 통제한 외부 폴더에 둔다. 이 문서의 크기/hash와 확인하고 경로 대응을 로컬 기록에 남긴다. `Get-FileHash -Algorithm SHA256 -LiteralPath <원본 절대 경로>`를 사용할 수 있다.
3. 해시가 다르면 정정본 여부·판본·변경 근거를 먼저 기록한다. 알 수 없는 파일을 같은 판본으로 덮어 넣지 않는다.
4. S00부터 원문 대조가 필요한 작업은 자료 확보 후 진행한다. 자료가 없으면 합성 구조 검토만 가능하며 원문 검증 통과로 표시하지 않는다. PR에 넣을 테스트는 합성·비식별 자료만 사용한다.
5. 업로드/푸시 전 staged 파일에서 이 폴더 및 참가자 원본·응답·채점·사례 리포트가 제외됐는지 확인한다. 자료를 삭제하는 절차가 아니므로 로컬 원본 bytes는 유지한다.

## 3 미수령 자료와 기존 이력

- G01/G04: `구간순_채점용_간소화안_20261002.xlsx` 최종 빈 입력 원본. 주소·수식·예시 메모 정정 여부의 실물 검증이 남는다.
- 별도 `K-DOG_개발기준_개정이력_20261002.docx`는 미수령이다.
- 네 사례의 카메라 영상·원본 INSV·대응 MP4·압축본·저FPS 파일은 이번 묶음에서 확인되지 않았다. S16의 각 비교 행에 맞춰 확보한다.
- 종전 검토의 원본27개는 이 목록의 새12개와 기존 자료15개를 합한 범위다. 과거 입력/규칙은 구현 이력 대조용이며 S1 원문을 대체하지 않는다.

이 목록과 계획만 있는 clone은 고객 원본을 포함한 완전한 실행·검증 환경이 아니다. 공개 문서의 링크는 이 목록으로 연결하고, 원본 부재는 [확인사항 대장](K-DOG_확인사항과적용경계_v1.0_20261003.md)에 명시한다.
