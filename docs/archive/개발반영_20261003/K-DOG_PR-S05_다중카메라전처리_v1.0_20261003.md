## 문제와 결과

기존 전처리는 선택된 기준 영상 한 개를 절단한다. 같은 관찰창에 여러 카메라의 유효 시야를 연결하고 원본/변환본 시각을 역추적할 수 있는 S1 batch를 만든다.

근거: 통합명세 2~6절·10절 장면, D01, 운영 요청 3·5항. 선행 S04 창의 의미는 전처리에서 바꾸지 않는다.

## 구현 순서와 산출물

1. 원본 hash와 S03 변환 계보, S04 확정 offset을 검증한다. INSV만 있고 지원 파생 MP4가 없으면 변환 필요로 표시하며 읽을 수 있는 다른 카메라 창은 유지한다.
2. 창마다 선택한 카메라의 공통 구간을 원본 시각으로 변환해 절단한다. 원본 범위를 벗어나면 실제 가능한 교집합과 부족 사유를 기록한다. 없는 프레임을 복제해 관찰량을 늘리지 않는다.
3. 같은 사건창의 view들을 한 논리 창 아래 묶는다. 카메라별 clip ID/hash/시각과 공통 사건창 ID를 분리한다. 시야가 겹친다고 관찰 시간을 더하지 않고 시간구간 합집합을 사용한다.
4. 발성용 오디오는 전체 실제 구간을 보존한다. 대표 오디오의 선택 근거와 손실 구간을 기록하고 여러 카메라의 같은 소리를 중복 합산하지 않는다. 합산/이어붙임은 확인된 시각 대응과 연속성 범위에 한정한다.
5. 제작 FPS는 기존 원본 보존 원칙을 유지한다. provider 요청 FPS·리사이즈와 별개로 기록한다. 저FPS/압축 파생본은 별도 hash·설정으로 남겨 원본 품질을 덮지 않는다.
6. 바54/55의 사건창, 전체 관찰 횟수, 개12의 새 창을 검증한다. 선택 꼬리/카메라 하나의 실패가 다른 유효 창을 삭제하지 않게 한다.
7. 진행 중 입력 변경·삭제·점유 상태를 재검사한다. 완성되지 않은 batch를 최신 정상 결과로 채택하지 않는다. 성공/부분실패와 창별 사유를 유지하고 재생성은 새 batch다.
8. batch에 원본들·변환본들·촬영 snapshot·정책/카탈로그/절단 설정 hash를 고정한다. 다른 카메라·offset·FPS가 바뀐 재사용을 거절한다.

## 검증과 완료 조건

- 3개 합성 영상에 알려진 offset/가림 구간을 넣어 같은 사건의 원본 시각을 복원한다.
- 한 카메라 오류/음성 누락/짧은 영상이 나머지 창의 정상 출력에 미치는 범위를 검증한다.
- 실제 프레임 없는 극단적으로 짧은 창, 원본 소리 있음/클립 소리 누락, 누적 발성량 과대 평가를 검사한다.
- 겹치는 3view가 전체 관찰량을 3배로 만들지 않는다. 중복 사건 계수는 S08의 검증 입력으로 전달한다.
- 같은 크기 파일 변조·파생 부모 변경·offset 변경·설정 변경 시 hash 검증/재사용 차단을 확인한다.
- 신규 파일의 백업·복원·삭제 및 합성 미디어 시험을 수행한다. 실제 INSV 판독 성능은 S16에서만 판정한다.

## 경계와 인계

INSV 자동 스티칭 엔진 설치·자동 개체 추적·카메라 3대 병렬 공급자 호출은 포함하지 않는다. S08은 같은 논리 창의 동기화 view들을 함께 해석하며 원자료 사건을 카메라별로 더하지 않는다. S10은 이 batch의 실제 시각·가시성으로 장면을 선택한다.
