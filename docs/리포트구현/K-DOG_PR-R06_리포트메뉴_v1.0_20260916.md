# PR-R06 리포트 메뉴(화면)

상위: [리포트 구현 계획](K-DOG_리포트_구현계획_v1.0_20260916.md). 근거: P1 계획 §0 「대메뉴 하나가 PR 하나」, 검수결과 §1 「자동 다음 단계 실행이나 자동 확정은 제안하지 않는다」, A05 「새로운 AI 채점·리포트 메뉴를 빈 화면으로 추가하지 않는다」(→ R04까지 끝난 뒤에만 이 PR을 연다), 01 §5 「사람이 먼저 … 나중에 AI 값을 여는 순서」.

## 목적

주 메뉴에 **「리포트」** 를 추가한다. 운영자는 참가자별 준비 상태를 보고 생성을 누르고, 결과를 미리 보고, 장별 포함/제외 이유를 확인하고, 서술 문장을 고치고, 승인하고, 내려받는다. 교수/검토자는 같은 화면을 읽기만 한다. 자동 생성·자동 승인·일괄 승인은 없다.

## 현재 상태

- `frontend/src/App.tsx:17` `menu` 배열: 접수·설문·촬영·자료 가져오기·직원 계정. `Page` 타입에 추가하면 된다. 메뉴 이동 시 `setSelected(null)`(A05가 바꿀 예정 — 이 PR은 A05 반영 여부에 따라 선택 유지 방식을 맞춘다).
- 페이지 구조 관례: `pages/Recording.tsx`처럼 `page-heading` + 목록 `table` + 선택 시 하단 패널. 목록 정렬은 순번·참가자 ID.
- `types.ts`에 `Case.report_status`(R04에서 `CaseView`에 추가)를 받을 자리가 필요.
- CSP `frame-ancestors 'none'`은 다른 출처의 iframe만 막는다. 같은 출처 `<iframe src="/api/cases/…/html">`는 허용되며, 리포트 응답의 자체 CSP(R04)가 내부에 적용된다.

## 화면 구성

| 영역 | 내용 | 권한 |
| --- | --- | --- |

| 목록 | 검색(순번·참가자 ID·반려견·보호자)·행사 필터·**상태 필터**(생성 가능 / 초안 / 승인 / 다시 만들기 필요 — 접수·설문·촬영과 같은 검색 UI, A05). 열: 순번 · 참가자 · 반려견/보호자 · 사람 채점(`sheet_summary`: 확정/없음, 채점자 수) · 설문 n/28 · 구간(없음/초안/확정) · 리포트 상태(R04 표의 우리말, 다음 행동이 문구에 들어 있음) · 「열기」. 행 앞 체크박스로 **선택 → 「선택 n명 리포트 만들기」**(생성 가능 상태만 대상, 확인 대화에 대상 목록·서술 생성 여부; 승인은 개별로만). 촬영 뒤 72쌍을 하나씩 열지 않게 하는 유일한 일괄 동작이며, 사용자가 눌러야만 실행된다 | 목록은 모두, 일괄 생성은 writer |
| 상세 — 준비 | 행사/참가자/반려견/회차(A05 형식). 준비 조건 세 줄(구간 확정 · 사람 채점 시트 확정 · 설문)과 각각의 다음 행동(「촬영 메뉴에서 확정」「채점 화면에서 검수 확정(P2)」「설문 가져오기」; 설문은 없어도 생성 가능함을 표시). 시트가 여럿이면 **리포트에 쓸 시트 선택**(채점자 라벨·확정 시각·채점 41/미판독 n; 기본은 최근 확정). 「서술 초안 생성」 체크(기본 켬, 키 없으면 비활성+이유) → **「리포트 만들기」** | 생성은 writer |
| 상세 — 판 목록 | run별: 만든 시각 · 상태 · 채점자 · 서술(없음/AI 초안/수정됨) · 승인 표시 · 「이전 입력 기준」 표시 · 열기 | 모두 |
| 상세 — 미리보기 | 선택한 판의 HTML을 `<iframe sandbox="" src=…/html>`로 표시(스크립트 없음). 「내려받기(HTML)」(`?download=1`), 「인쇄」(iframe `contentWindow.print()`는 sandbox로 막히므로 새 탭으로 열어 브라우저 인쇄 안내 — R08) | 모두 |
| 상세 — 장 구성 | 포함된 장 목록(번호·제목·근거 항목 ID)과 **넣지 않은 장과 이유**(`Omission.operator_detail`) — 예: 「꼬리로 본 하루: 꼬리 항목 7개 중 3개 판독(5개 필요) · BS-05, DOG-06 미판독: 개가 화각 밖」. 각 장의 「어떤 항목에서 나왔나」를 접이식으로 보여 교수가 리포트 문장과 채점표를 맞대 볼 수 있게 한다. 06b `00_읽어주세요` 표와 같은 정보 | 모두 |
| 상세 — 서술 수정 | AI 초안 문장(장면·만나는 곳·해보실 만한 것·말할 수 없는 것)을 문장 단위 `textarea`로 고침. 각 문장 옆에 **근거 항목의 점수 상태·사유 원문**(`source_items` → 시트 `reason`)을 함께 보여 사실 확인 없이 문장만 다듬는 일이 없게 한다. 「검사 후 새 판 만들기」(`POST …/narrative`) → 위반이 있으면 422 목록을 해당 문장 옆에 표시, 어떤 규칙(유형 이름·점수 숫자·판정어)인지 우리말로. 저장 전 이동 보호(`useUnsaved`) | writer |
| 상세 — 승인 | 「이 판을 승인」(확인 대화: 채점자·설문 등록·구간 확정 상태, 포함 장 목록, 서술이 AI 초안인지 사람이 고친 것인지, `result_hash` 앞 8자리). 승인 뒤 「승인 취소」(사유 입력, 감사 기록). 입력 변경으로 `superseded`면 무엇이 바뀌었는지(`superseded_reason` 우리말) + 「다시 만들기」 | writer |

교수/검토자에게는 생성·수정·승인 버튼이 없고(403이 아니라 아예 표시하지 않음), 미리보기·장 구성·내려받기는 가능하다(01 §5의 「사람 검수」는 P2의 채점 화면이며, 리포트 검토는 읽기로 충분).

## e2e (`frontend/tests/report.spec.ts`, PowerShell에서 실행)

1. 운영자 로그인 → 접수 가져오기 → 설문 CSV → 영상 등록 → 8구간 확정 → 시험 서버가 fixture 시트를 `POST /sheets`로 저장(화면 밖) → 리포트 메뉴에서 상태 「생성 가능」. 시트 없는 참가자는 「채점 화면에서 사람 검수를 확정하세요」.
2. 「리포트 만들기」 → 「생성 중」 → 「초안」. 미리보기 iframe에 `h2` 「오늘의 흐름」 존재. 장 구성에 제외 장과 이유·근거 항목 표시. 참가자 두 명 선택 → 「선택 2명 리포트 만들기」 → 둘 다 초안.
3. 서술 문장에 「불안정 애착」 입력 → 저장 시 위반 표시, 저장 안 됨. 정상 문장 → 새 판 생성.
4. 승인 → 목록 상태 「승인」. 설문 CSV 재가져오기(값 변경) → 상태 「이전 입력 기준」, 승인 판은 여전히 열림.
5. 교수/검토자 로그인 → 같은 화면, 버튼 없음, 미리보기·내려받기 가능. 직접 `POST` 시 403(백엔드 시험이 담당).
6. 768px: 목록·상세가 가로 넘침 없이 읽힘(기존 `intake.spec` 방식).
7. 미저장 서술 수정 상태에서 메뉴 이동 시 경고(`mayLeave`).

## 완료 조건

1. 위 e2e 7개와 기존 e2e 전부 통과, `npm run build` 통과.
2. 화면 어디에도 점수 숫자·유형 이름·총점이 없다(리포트 본문은 R03이 보장, 화면의 장 구성·상태 문구는 이 PR이 보장). 채점 시트 목록은 「채점 41 · 미판독 n」 같은 개수만 보인다.
3. 생성·수정·승인은 모두 사용자가 눌러야 일어나고, 메뉴 이동·시트 확정·구간 확정이 리포트를 자동 생성하지 않는다. 일괄 동작은 「선택한 참가자의 생성」 하나뿐이며 일괄 승인은 없다.
4. A05가 먼저 병합됐다면 참가자·회차 맥락을 그 방식대로 이어받고, 아니면 이 메뉴도 자체 선택을 갖되 A05가 병합될 때 교체된다는 점을 PR 본문에 적는다.
