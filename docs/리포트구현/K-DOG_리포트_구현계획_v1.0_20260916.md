## 0. 이 폴더가 다루는 것

P0·P1(PR #1~#12)로 접수·설문·촬영·전처리는 42항목 판으로 바뀌었지만, **리포트를 만드는 부분은 아직 옛 55항목 판 코드(`backend/app/reporting.py`·`report_models.py`·`exports.py`의 PDF, `resources/report-presentation-v1.json`)가 worker 참조용으로만 남아 있고 화면·라우트는 없다.** 이 폴더는 `docs/최종 고객 문서/06b_리포트_6쌍/`의 HTML 6개를 템플릿으로 삼아 42항목 판 리포트를 만드는 작업을 PR 단위로 나눈 상세 구현 계획이다.

`06b`는 예시다. 고객이 9월 13일 6쌍의 영상을 사람이 보고 손으로 만든 것이며, 본촬영에서는 프로그램이 같은 모양의 리포트를 **채점 시트·설문·확정 8구간**에서 생성해야 한다. 따라서 이 계획의 기준은 「06b와 같은 데이터가 들어오면 같은 장 구성이 나온다」(변경검토 §6 P3 완료 기준)이다.

## 1. 원칙 (고객 문서에서 그대로 가져온 것)

1. **총점·등수·판정·다른 개와의 비교·공격성 없음**(01 §6). 유형 이름(안정·불안·거리 둠·일관되지 않음, 편안·우호 …, 설문 분리 유형 4종)은 **연구 데이터에는 남기되 리포트에는 쓰지 않는다.** 06b 어디에도 유형 이름이 없다.
2. **점수 숫자는 관찰 척도에 쓰지 않는다.** 1~5 척도는 「가운데를 기준으로 한 눈금에 점 하나」로만 그린다. 다만 06b가 실제로 숫자로 쓴 것은 그대로 허용한다: 설문 영역 평균(채우기 막대, 소수 1자리), 동조율(백분율), 지표 변화량(+1·−2), 몸 털기 횟수(0회), 구간 길이(초).
3. **Ainsworth 용어 금지**(01 §4). 문헌 인용(Topál 1998, Horn 2013, Duranton 2017)은 06b가 각주로 쓰므로 허용하되 유형 명칭(Secure·Avoidant·Ambivalent·Disorganized, 안정형·회피형·양가형·혼란형)은 문장에서 차단한다.
4. **장(章)은 실제로 본 것만 넣는다.** 06b `00_읽어주세요` 표처럼 쌍마다 장 수가 다르다(12·5·6·8·9·9). 없는 장은 빼고, 왜 빼는지는 「이 리포트가 말할 수 없는 것」에 적는다. 억지로 채우지 않는다.
5. **사람 검수를 거친 채점만 리포트에 쓴다**(01 §5 「사람 검수가 반드시 들어갑니다」). AI 채점 시트는 리포트의 직접 입력이 아니다. 서술(AI 생성)도 운영자 승인 전에는 「초안」이다.
6. **그래픽은 데이터 바인딩, 서술만 AI**(변경검토 N9). 렌더러는 결정적이며 같은 입력이면 같은 HTML(해시 동일)을 낸다.
7. **불변 산출물·해시·revision 고정·삭제 상태 재확인**(AGENTS.md 「established safeguards」). 리포트도 `clips.json`처럼 파일 + 감사 기록 + `maintenance.MANAGED`에 포함한다.
8. **외부 접속 없음.** 06b는 Google Fonts를 링크하지만 운영 PC는 오프라인일 수 있고 `resources/fonts/README.md`가 「실행 시 외부 글꼴 서버에 접속하지 않는다」고 정했다. 앱 안에서는 동봉 폰트(`NanumGothic`)를 `/fonts/`로 제공하고, 내려받은 단독 HTML은 시스템 글꼴 스택(Malgun Gothic 등)으로 대체한다. 스크립트는 넣지 않는다.
9. **미정 규칙은 데이터로 둔다.** 장 포함 문턱·눈금 라벨·설문 하위영역·금칙어 목록·보호자용 구간 이름은 `resources/rules/report-v2.json`에 두고 코드에 박지 않는다(P0 §0 원칙과 같음).

## 2. 데이터 흐름

```
접수(cases) ─┐
설문(intake-2.0 survey) ─┤  survey_scores() ──► SurveyResult ─┐
촬영(segments 확정) ─────┤                                    │
채점 시트(R01, 사람 최종) ┤  behavior_scores() ─► ScoreResult ─┼─► ReportInput(R02) ─► chapters(R02)
전처리(clips.json 오디오 유무) ┘                              │        │
                                                              │        ├─► render(R03) ─► report.html (불변, R04)
서술 초안(R05, Gemini) ── 원칙 검사 ── 운영자 수정 ────────────┘        │
                                                                       └─► 승인(R04·R06) ─► 인쇄·전달(R08)
```

리포트는 **한 쌍 · 한 촬영 세션 · 한 입력 revision · 한 채점 시트(해시) · 한 규칙 버전**에 묶인다. 입력이 바뀌면(설문 재가져오기, 구간 재확정, 시트 수정) 승인본은 「이전 입력 기준」이 되고 새로 만들어야 한다. `storage.Store.save()`가 모든 입력 변경에서 `display_run_id`를 비우는 기존 동작을 그대로 이 목적에 쓴다(R04).

## 4. 이 계획이 P2(AI 채점·검수·내보내기)와 겹치는 곳

- **채점 시트 저장(R01)** 은 P2 검수 화면·AI 채점이 함께 쓰는 구조다. 여기서 먼저 정의하고, P2는 같은 `ScoreSheet` 파일·표에 `kind=ai` 시트를 쓰고 사람이 검수 화면에서 `final` 시트를 확정한다. **채점은 자동(AI)과 검수 화면으로만 들어오며 운영자가 파일로 옮겨 넣는 수동 경로는 만들지 않는다.** 리포트 PR들의 시험은 05 예비촬영 엑셀에서 만든 fixture를 R01 API로 넣어 P2 없이도 검증한다. 문항별 화면 입력·AI 값 나란히 보기·ICC는 P2다.
- **관찰 원장 v2(N5)** 가 생기면 09장 「가까이 있던 비율」, 국면별 동조 여부, 02장 장면 시각의 정밀도가 좋아진다. 이 계획은 원장 없이도 동작하도록 42항목·구간·설문만으로 장을 구성한다.
- **연구용 내보내기(N10)** 는 `exports.py` 기계를 재사용하는 별도 PR이다. R04는 `exports.py`의 `reporting` import만 끊고 파일은 남긴다.
- **worker 재구성.** 현재 `worker.py`는 55항목 단계만 안다. R04가 실행 종류(`kind`) 분기를 넣고 `report-v2`만 처리한다. P2 채점 파이프라인이 들어오면 같은 분기에 `scoring-v2`를 추가하고 그때 55항목 단계 코드를 삭제한다(P1 계획 §0 「대체물이 들어오는 PR에서 지운다」).

## 6. 검증 명령과 PR 절차

P0 계획 §0과 같다: 브랜치 → 구현 → 검증 → 리뷰 → 수용 여부 기록 → 반영 → 재검증 → 푸시·PR. 프론트 변경이 있는 PR(R06·R08)은 `npm run build`·`npm run test:e2e`를 PowerShell에서 추가로 통과한다.

```powershell
# backend/에서
uv run --locked python -X utf8 -m unittest discover -s tests
uv run --locked python -X utf8 -m app.import_catalogs --check
git diff --check
```

리포트 계획의 공통 완료 기준: **05 예비촬영 6쌍의 채점값 + 05b 구간 시각 + 06b에 실린 설문 값을 fixture로 넣으면, 프로그램이 만든 리포트의 장 목록이 06b `00_읽어주세요` 표의 장별 ○/— 표시와 일치**하고(모집단 장·AI 서술 장·「가까이 있던 비율」은 예외로 명시; 표의 「장 수」 숫자는 기준이 아님), 원칙 검사기가 06b 6개 HTML 본문을 통과시키며(허용 예시), 유형 이름·Ainsworth 용어를 넣은 합성 문장은 거절한다.
