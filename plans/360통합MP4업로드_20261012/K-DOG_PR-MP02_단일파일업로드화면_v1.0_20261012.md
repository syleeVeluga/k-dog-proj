# PR-MP02 단일 파일 업로드 화면

버전: v1.0 · 2026-10-12 · 상태: 계획, 미구현 · 선행: MP01 · 브랜치 제안: `veluga/mp02-360-upload-ui`

상위: [전체 계획](K-DOG_360통합MP4업로드계획_v1.0_20261012.md). 범위: VM-R01/R03/R04/R07. 제목 제안: `feat: add a single prepared 360 MP4 upload option`.

## 문제와 결과

현재 변환 MP4 화면은 등록된 부모 원본을 요구한다. 새 옵션은 원본 미등록 통합 MP4 한 개로 업로드·등록을 완료하고, 실제 카메라 기기 연결로 오해할 수 있는 입력을 요구하지 않는다.

새 옵션 「360 통합 MP4 (Studio 등에서 내보낸 파일)」를 영상 파일 구분에 추가한다. 기존 촬영 원본/실제 부모 등록 변환 MP4를 유지하고, 새 옵션에서는 부모 원본·원본 번호·촬영 카메라 번호 강제 입력을 숨긴다. 저장 후 표시를 「360 통합 영상」으로 한다.

## 사용자 흐름

1. 「영상 파일 업로드」 → 「영상 파일 구분」에서 새 옵션을 선택한다. 안내: ‘Studio 등에서 내보낸 통합 MP4를 올립니다. 원본 INSV를 먼저 올릴 필요가 없습니다.’
2. 파일을 하나 선택한다. 원본/다중 카메라 업로드도 그대로 사용할 수 있으며 이 종류에 한해서 단일 선택을 기본으로 한다. 브라우저 accept 외에 서버의 실제 입력 검사를 유지한다.
3. 영상 배치 선택: ‘일반 화면으로 내보냄 / 360 펼침 영상 / 잘 모름’. 시각 선택: ‘촬영 시간의 순서·속도 유지 / 구간 편집·속도 변경 있음 / 잘 모름’. 기본은 잘 모름이며 아무 선택 없이도 업로드·보관할 수 있다. tool/version/note는 접힌 선택 정보로 제공하고, 모르는 값은 비워 둘 수 있다. JSON 설정 편집기는 없다.
4. 「업로드 시작·재시도」 → 완료 파일별 참가자·촬영 회차를 확인 → 「영상 정보 저장」. UI가 EXT360/null 원본 번호를 전달하며 내부 코드는 기본 화면에서 숨긴다. 파일명 원본1/2/3의 기존 카메라 번호 제안을 새 통합본에는 적용하지 않는다.
5. 성공 표시와 별도로 원본 미등록·사용자 제공 외부 처리 정보 및 해당 파일의 전처리 조건을 짧게 표시한다. 일반 화면·시간 유지도 업로드 직후 분석 완료가 아니다. 360 펼침이면 ‘일반 화면으로 재구도한 MP4가 필요합니다’, 시각 미확인이면 ‘촬영 시각 대응을 확인해야 합니다’로 표시한다.
6. 촬영 8구간의 실제 시각은 시간 유지가 확인된 기준 MP4의 재생 시각에 맞춰 기록한다. 시간을 잘라 붙였거나 속도 변경한 파일에 단일 offset을 자동 적용하지 않는다. edited/unknown 통합본을 기준 영상이나 사건/관찰 시각의 앵커로 확정할 수 없다는 사유와, 정상 근거로 바꿔 재확정하는 동작을 안내한다. 360 펼침+시간 유지의 시간 근거 이용과 영상 클립 제한은 구분한다.
7. 등록한 파일 카드에 「처리 정보 확인·정정」을 제공한다. 잘 모름→실제 확인 값으로 저장하면 MP01의 metadata PATCH만 호출하고 파일을 다시 올리지 않는다. 업로드 당시 정보와 현재 입력 판본의 정보를 구분하고 새 revision/이전 판본 보존·기존 전처리가 이전 입력 기준이라는 점을 표시한다. bytes/kind/부모/camera 변경은 이 동작으로 제공하지 않는다. 시각 근거에 영향이 있으면 촬영 기록 확인과 새 전처리를 명시 실행하도록 안내한다.

## 대기 목록·재시도 규칙

옵션을 바꾸었다고 이미 선택한 파일/출처 metadata를 자동 재분류하거나 완료 업로드를 다시 전송하지 않는다. 요청이 시작되면 request ID와 요청 내용을 고정하며 실패 재시도도 원래 출처 내용을 쓴다. 출처를 바꾸려면 아직 미시작인 대기 항목을 명시 취소/재선택하거나 새 요청으로 등록한다. 한 파일의 진행 중 다른 파일/대상을 바꿔도 해당 업로드의 case/session·종류·metadata가 섞이지 않아야 한다. UI 상태만 바꾸어 MP01 서버 제한을 우회할 수 없다.

## 검증과 완료 조건

- VM-T01: 원본 목록이 비어 있어도 MP4 한 개 선택→업로드→참가자/회차 저장→새로고침→보관 파일 제공을 실제 API로 확인한다.
- VM-T03: 카메라 1/2/3 세 칸·실제 장치 연결·원본 부모 선택이 새 옵션의 필수 항목으로 나오지 않는다. 기존 세 파일/번호 1→CAM1·2→CAM2·3→CAM3와 원본 번호 대응은 유지한다.
- VM-T04: 모든 projection/timeline 조합은 업로드를 허용하고, 전처리 조건/파일별 사유를 정확히 표시한다. 모름을 flat/preserved로 바꾸지 않는다. 미지원 파일의 재사용/분석 버튼만 켜진다고 서버가 영상을 전송하지 않는다. 편집 기준 또는 편집 파일의 사건창을 사용한 확정은 실패하며 정상 시간 근거의 재확정은 성공한다.
- VM-T07: operator/reviewer/admin/developer의 같은 업무, 미로그인/개발자 설정 경계, 360/390/768/1440px, 포커스/미저장·옵션 전환·재접속·실패 재시도·409 저장 재시도를 확인한다. unknown 등록 후 실제 확인 값 저장은 파일 전송0·동일 video/hash·새 input revision이며 옛 결과를 소급 활성화하지 않는다.
- 촬영 원본·INSV 보관·실제 부모를 가진 변환 MP4 경로, 완료 파일 재전송 없음과 파일명 자동 번호 제안 회귀를 유지한다. 새 selector의 표시만 변경해 기존 fixture 검증을 삭제하지 않는다.

```powershell
# frontend/
npm run build
npm run test:e2e -- tests/uploads-v4.spec.ts tests/recording-split-v4.spec.ts tests/preprocess-v4.spec.ts tests/navigation.spec.ts tests/intake.spec.ts tests/copy-guard.spec.ts
```

새 시험 파일이 필요한 경우 실제 파일 생성 뒤 실행 명령을 추가한다. 합성 screenshot을 ignored test-results에 저장하고 시각 검수한다. 실제 참가자 영상/프레임은 PR에 넣지 않는다. 기본 화면·파일 입력 완료·통합 영상 저장·전처리 제한·모바일 screenshot으로 MP03에 인계한다. 버전 확인은 상위 §7을 적용한다.
