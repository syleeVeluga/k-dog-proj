# K-DOG PR-AR02 조회·수정·실행 기록

버전: v1.0 · 2026-10-11 · 상태: 상세 계획 / 제품 구현 미착수 · 선행: AR01
상위: [업무 권한 단순화 계획](K-DOG_업무권한단순화계획_v1.0_20261011.md). 조사 기준 `d6dd58a`; 진행 중인 로컬 U08 수정은 제외한다. 실제 착수 시 최신 병합 코드의 호출 관계를 다시 확인한다.

## 1 목표·현재 근거

[changes 테이블](../backend/app/storage.py#L77-L82), [Store.audit](../backend/app/storage.py#L330-L332)는 actor/시각/대상/action/detail을 이미 저장한다. 주요 수정은 기록하지만 모든 열람을 기록하지 않는다. [일반 자료 조회](../backend/app/api.py#L313-L339), [영상](../backend/app/api.py#L453-L480), [시트 조회](../backend/app/sheets_v4.py#L238-L264), [리포트 download](../backend/app/report_runs_v4.py), [export](../backend/app/exports_v4.py), [참고자료](../backend/app/validation_data_v4.py)를 대상으로 한다. U08의 report.s1.open이 이후 병합되어 있으면 재사용하고 같은 동작을 중복 기록하지 않는다.

## 2 최소 기록 계약

changes와 작은 공통 helper를 재사용한다. 별도 메시지 브로커·범용 이벤트 플랫폼·새 DB는 도입하지 않는다.

| 행위 | 필수 기록 |
| --- | --- |
| 명시 상세 열람/원자료·영상 열기 | actor, 서버 시각, 대상 case/session/sheet/run/export/reference, 정확한 revision/ref/hash, action |
| 수정 저장/제출/최종 구성 | 실제 편집 actor, 대상, before/after revision·참조, 변경 필드명/짧은 요약, 입력한 사유가 있으면 사유 |
| 실행·중지·재시도 | 요청 actor, run/request ID, 입력·설정 판본, action, 결과 상태의 서버 이벤트 |
| 발급·다운로드·인쇄용 열기 | actor, 발급 run/출력 hash, html/pdf/csv/xlsx, 열기/다운로드 구분 |
| 시스템 완료·전환·복원 | 요청 actor와 실제 시스템 처리의 구분, 실행 식별자, 이전/이후 판본 |

키·비밀번호·세션 token·공급자 비밀·영상 bytes는 기록하지 않는다. 변경 전후는 불변 문서 참조로 추적하고 설문/참가자 원문 전체를 로그에 중복 복제하지 않는다. 실제 DOM 읽기·사용자 인쇄 완료를 증명한다고 표시하지 않고 서버가 제공한 열기/출력 준비 요청만 기록한다.

## 3 상세 구현

1. 업무 변경과 해당 audit를 같은 DB transaction에 저장한다. 불변 파일 생성 후 DB 채택 실패 시 기존 고아파일 정리 계약을 사용한다. 감사 실패를 무시한 성공 응답은 금지하며 저장/기록 불능은 기술 오류로 반환한다.
2. 명시 상세 열람은 서버에서 actor와 자료를 검증한 후 기록한다. frontend는 실제 사용자 열기와 백그라운드 갱신을 구분하는 작은 요청 표식을 전달하고, 서버는 표식의 username/시각/판본을 신뢰하지 않는다. 네트워크 재전송과 중복 버튼 요청은 기존 request ID로 중복 방지한다.
3. 목록 자동 갱신·worker heartbeat·실행 진행 폴링·manifest 자동 조회는 명시 열람으로 누적하지 않는다. 사용자 검색/목록 열기와 자료 본문 열기를 구분해 action을 정한다. 다운로드는 각 사용자 요청을 기록한다.
4. 열람 audit 때문에 score sheet/document revision, independent 목적, result hash를 변경하지 않는다. 타 결과 노출은 AR03의 별도 사실 기록에 정확히 연결한다.
5. 전역/참가자별 기록 조회 API와 화면을 제공한다. 모든 업무 계정이 actor·기간·대상·action으로 검색하고 고정 정렬/페이지 단위로 조회한다. 조회 API가 자기 조회로 재귀 로그를 만들지 않는다.
6. 기록은 현재 대상의 DB/FK가 사라지더라도 읽을 수 있게 기존 target 문자열을 사용한다. 정리·복원에서 업무 이력을 삭제하지 않도록 AR04와 연결한다. 일반 사용자에게 감사 event 수정/삭제 UI는 만들지 않는다.
   복원 시 백업 이후 원 DB에 남은 audit는 별도 검증 파일로 먼저 보관하고 event ID를 기준으로 백업 audit와 중복 없이 보존한다. 복원한 자료 상태와 과거/후행 사건의 출처를 구분한다. 백업에 없는 actor 참조는 로그인 권한을 새로 부여하지 않는 역사 식별로 보존하는 최소 DB 전환을 AR04와 함께 정한다. 로그를 보존하려고 옛 삭제 정책 event를 다시 실행해서는 안 된다.
7. 접수·Forms commit·촬영·설문·영상·전처리·AI·채점·의견·최종·리포트·비교·검수·export·계정·백업·복원 전체 action 목록을 파일별로 작성하고 누락을 cold review한다.

조회 로그는 작업이 성공적으로 자료 제공을 결정한 사실이다. 전송 후 브라우저 표시 실패까지 열람 완료로 단정하지 않는다. 임의 필수 변경 사유/승인 서명 화면은 추가하지 않는다.

## 4 검증과 인수

합성 A 수정→B 상세/영상/시트 열람→C 실행→D 발급/download를 실제 API로 연결하여 actor·시각·전후 참조를 조회 API에서 확인한다. 재전송 중복, 폴링 10회에도 명시 open 증가 없음, 실패한 save에 성공 audit 없음, audit insert 실패에 자료 채택 없음, 다른 사람이 만든 자료 actor 유지/실제 편집자 분리, 과거 판본·유실 target 로그 조회를 검증한다.

신규 `tests.test_activity_v4`와 변경된 해당 API/Forms/sheets/run/report/export tests를 필요한 범위만 실행한다. AR06의 기록 UI E2E와 AR07 종단/복원에서 기록 보존을 다시 확인한다. 이 신규 모듈명은 구현 때 작성하는 계획이며 현재 존재·통과를 뜻하지 않는다.

완료: 열람/수정/실행/출력의 주요 사용자 동작이 모두 기록되고 다른 계정이 조회 가능. 비밀 노출·허가 단계·문서 revision 오염 없음.

## 5 실패·복구

기존 changes event는 소급 변환·삭제하지 않는다. 새 상세 필드는 선택적이며 옛 event는 당시 정보만 표시한다. 실사용 로그를 fixture나 공개 저장소에 넣지 않는다.
