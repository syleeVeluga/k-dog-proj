# K-DOG 업무 권한 단순화 및 기록 중심 전환 계획

버전: v1.0 · 2026-10-11 · 조사 기준: `d6dd58a` · 문서 작업 기준: `origin/main / f2b79d9`
상태: 계획 수립·문서 검증·독립 cold review·수용 수정·재검토 완료. AR01~AR07 제품 구현은 미착수이며 이 계획 PR의 병합은 제품 변경 완료가 아니다.

## 1 확정 방향과 적용 우선순위

2026-10-11 사용자 후속 지시: 본인 소유·배정 제한과 일반 역할 구분은 전혀 필요하지 않다. 동의 거절·철회·삭제 요청 절차와 그에 따른 접근/실행 차단도 제거한다. 운영자와 교수진이 모든 업무 자료를 조회·편집·실행하고 실제 행위자·시각·대상·판본을 기록하는 구조로 바꾼다. 개발자는 설정 기능을 유지하고 다른 모든 업무 권한도 갖는다. 관리자/교수/운영자 사이의 승인·공개 허가 절차를 만들지 않는다.

이는 종전 S06/S09/S14/S15 및 리포트 계획의 자기 시트·명시 공개·동의/삭제 재검사 요구를 대체하는 운영 결정이다. S1 산식·문항·관찰 근거·결측 규칙을 새로 확정하는 결정은 아니다. 평가 내용 원본과 기존 S1 결과를 초기화하거나 삭제하지 않는다.

인증은 행위자 식별을 위해 유지한다. 로그인·계정 활성 상태·세션 만료는 남기고 업무 권한의 단계는 없앤다. 개발자 설정만 별도로 보호한다. 일반 계정이 웹 계정 관리로 자신을 개발자로 승격하는 경로는 제공하지 않는다. 개발자 발급은 기존 로컬 관리 경로를 유지한다.

진행 중인 로컬 U08 교수 리포트 권한 작업은 이 계획 작성·리뷰·병합 대상에서 제외한다. 그 변경을 가져오거나 수정하지 않는다. 실제 구현 착수 시 최신 병합 코드에서 겹치는 부분만 재대조하고 최종 상태는 본 계획으로 통일한다. U08의 승인/완료가 이 계획의 선행 조건은 아니다.

## 2 목표와 제거/유지 경계

| 구분 | 결정 | 검증 가능한 최종 상태 |
| --- | --- | --- |

| 독립 평가 | 접근 차단 대신 사실 분류 | 원평가자 사전 노출·후속 편집 판본을 구분, 제3자의 후행 열람으로 최초 독립본을 소급 변경하지 않음 |

계정 비활성화는 로그인 중단만 의미한다. 평가 자료 배정의 active나 소유자 계정 비활성화가 다른 사용자의 자료 접근을 막아서는 안 된다. 중단·폐기된 의견의 의미, 손상·유실 파일, 미완성 계산, 실제 외부 기준 부재는 유효 자료로 꾸미지 않는다. 이들의 기술 상태·출처 분류는 유지하며 참가자 동의/삭제 정책과 혼동하지 않는다.

조회 기록 때문에 채점 문서 revision을 올리지 않는다. 공개 허용/제출 완료를 조회의 선행으로 요구하지 않는다. 보관 자료를 읽을 때도 이전 허가·활성화 기록을 재승인해야 하는 조건을 두지 않는다.

## 5 기존 자료·보관 전환

기존 role 문자열, assigned_username/rater_id, score_grants, consent/deletion 필드와 대장은 이미 저장된 문서·DB의 출처 정보다. 새로운 접근 조건으로 사용하지 않되 과거 bytes/hash를 일괄 변경하지 않는다. DB/입력의 물리 필드 제거가 불변 파일 재작성이나 전체 점수 폐기로 이어지면 하지 않는다. 현재 조회/쓰기 계약에서 제거하고 기존 자료 parser는 선택적 과거 metadata 읽기만 지원한다.

AR04는 offline 백업 → DB/참조 사전 검사 → 정책 전환 marker와 기존 상태 요약 기록 → 검사 → 반복 실행 무변경 순서로 한다. 삭제 요청 플래그와 tombstone을 confirmed/false로 일괄 덮어쓰지 않고 런타임 판정 자체에서 무효화한다. 원파일이 이미 실제 삭제되었거나 purge된 산출물은 되살아났다고 표시하지 않는다. 읽을 수 있는 백업에서의 수동 자료 복원은 별도 실제 복구 작업이며 이번 계획·이력 전환은 데이터를 복원하지 않는다.

restore는 검증된 S1 백업을 정확히 복원하고 새 정책을 적용한다. 삭제대장 재적용·참가자/공유 산출물 purge를 하지 않는다. 운영 변경 후 이전 정책 앱으로 동일 DB를 다시 실행하면 purge가 재발할 수 있어 자동 다운그레이드는 지원하지 않는다. 실패 복구는 전환 전 백업과 해당 앱의 별도 격리 경로에서 한다. 기존 S1 초기화 이전 백업 거절은 유지한다.

## 6 검증·리뷰·문서 상태

[검증 대장](K-DOG_업무권한계획검증_v1.0_20261011.md)과 [Cold Review](K-DOG_업무권한계획ColdReview_v1.0_20261011.md)에 이 계획 자체의 실행 결과를 적는다. 문서 링크는 작업 파일과 committed tree에서 검사한다. 제품 인수 시나리오는 AR01~AR07의 미래 실행 항목이며 계획 검증 통과와 구분한다.

새 의존성 도입은 계획하지 않는다. 현재 작업은 Markdown 계획 작성/검증이며 앱 라이브러리를 설치·실행하거나 새 API 사용을 구현하지 않는다. 실제 구현 시 공식 릴리스/registry/API 문서로 최신 안정판·선택판·호환 이유·확인일·출처를 해당 PR 기록에 남기고 기존 lockfile을 유지한다.

기존 개발 기준/실행 기록/고객 원본은 역사 사실을 소급 바꾸지 않는다. AR06/AR07에서 현행 운영 안내·요구사항 추적표·AGENTS의 삭제 재검사/배정 보호 지침을 이 사용자 결정과 맞춰 갱신하고 이전 검증은 당시 이력으로 남긴다. 미수령 평가 기준·실자료·공급자 품질을 이 운영 단순화 계획의 승인이나 완료로 간주하지 않는다.
