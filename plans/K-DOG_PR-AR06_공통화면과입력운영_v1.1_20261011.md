## 1. 목적과 확정 범위

운영자·교수/검토자·운영 관리자의 업무 권한 차이를 없앤다. 활성 로그인 계정은 접수·설문·영상·촬영 기록·전처리·AI 실행·채점·의견·최종 결과·리포트·비교·검수 자료·내보내기·기존 계정/백업 기능을 동일하게 사용한다. 기록은 해당 자료의 최근 이력 접기에서 본다. 개발자는 설정 화면을 기본 진입점으로 유지하면서 모든 일반 업무 메뉴에도 접근한다. 계정 이름은 실제 사용자 식별자다.

본인 소유 시트, 배정 계정, 관리자 공개 허용, 본인 독립 제출, 관리자 재개방을 업무 접근 전제에서 제거한다. 동의 확인·거절·철회·참가자 삭제 요청 UI와 관련 상태 필터를 제거한다. 다른 자료를 보거나 고치는 데 승인·공개 사유를 먼저 입력하게 하지 않는다. 열람·편집·실행·다운로드 기록은 AR02의 공통 감사 기록에 자동으로 남긴다.

새로운 승인·보관·삭제 대체 업무를 만들지 않는다. 동의/삭제 플래그 처리, 과거 파일의 무결성 확인, 실제로 폐기된 파일의 복원 불가능 상태는 AR04가 담당한다. 이 PR에서는 AR04의 결과를 사실대로 표시한다. 개인정보·영상·API 키를 계획이나 시험 산출물에 넣지 않는다.

독립성·출처의 역사 기록과 원본·이전 판본 보존을 제거하지 않는다. 현재 업무에서는 열람 사실만 기록하고, 본인 제출·명시 공개를 새 접근 조건이나 자동 목적 변경 조건으로 사용하지 않는다. 점수 규칙, 설문 원척도, 관찰 기회, 실제 근거, 유효 n, hash 검증, 충돌 방지 조건은 변경하지 않는다.

## 3. 상세 변경

### 3.1 메뉴·직접 주소·개발자 진입

1. `navigation.ts`의 일반 업무 항목에서 역할 목록과 역할별 문구를 제거한다. AR01의 개발자 설정 구분만 사용한다. 알려지지 않은 hash 처리는 유지한다.
2. `App.tsx`의 개발자 일반 데이터 로딩 차단과 일반 화면을 막는 삼항 분기를 제거한다. 개발자 기본 진입은 설정, 일반 계정 기본 진입은 접수로 한다. 개발자도 일반 메뉴·직접 주소·페이지 재진입을 사용할 수 있다.
3. 접수·설문·촬영·전처리의 `writable`을 역할에서 계산하지 않는다. 로그인 상태와 실제 작업 상태(저장 중, 미저장 충돌, 파일 손상 등)만 조작 가능 여부에 사용한다. 불필요해진 props/import는 호출처 확인 후 이 변경에서 만든 것만 제거한다.
4. 계정 표시에는 이름과 필요한 개발자 설정 구분만 둔다. 과거 역할이 남은 이력은 역사 값으로 열람하고, 현행 권한 등급으로 설명하지 않는다.
5. AR02의 대상별 최근 「열람·수정 기록」 접기를 필요한 자료 상세에 연결한다. 시각·로그인 사용자·행위·필요한 판본만 표시하고 제한된 더 보기만 둔다. U08 접기와 기록을 재사용한다. 새 전역 감사 메뉴/검색·로그 export·읽음 확인·감사 역할을 만들지 않는다.

### 3.2 공유 채점·해석·산출물

1. 「평가자 배정」을 「채점 시트 만들기」로 바꾼다. 평가자 이름/ID는 원자료의 작성 대상 정보로 남기되 계정 배정을 요구하지 않는다. 사용자가 타인의 시트를 열고 수정해도 원래 평가자 이름을 현재 계정으로 바꾸지 않는다. 실제 편집자는 감사 이력에 별도로 기록한다.
2. 모든 시트·보존 판본을 같은 목록에서 열 수 있게 한다. 「내 시트」·「배정 활성/취소」·grant 대상 선택·공개 허용 UI를 제거한다. 기존 비활성 배정이 접근/편집을 막지 않도록 선행 API 응답과 화면 분기를 함께 확인한다.
3. 제출 상태는 기록의 완료 상태로 표시한다. 제출 뒤 수정 버튼은 AR03의 새 판본 정정 경로를 호출한다. 관리자 재개방 요청이나 공개 허용을 선행시킬 수 없다. 보존 판본을 직접 덮어쓰지 않고 현재 작업본에서 새 판본을 만든다.
4. `FinalResultsV4`에서 본인 제출 시트·`viewer_sheet_id`·공개 사유·`requires_reveal` 기반 숨김을 제거한다. 기본 결과의 정확한 원자료 판본 선택과 근거 연결은 유지한다. 의견 저장/완료/정정과 최종 결과 생성은 같은 화면에서 모두에게 제공한다.
5. 리포트·연구 내보내기·검수 자료는 작성자와 무관하게 조회한다. 내보내기 선택은 전체 유효 원자료 판본이다. 리포트의 개발자 제외·본인 제출 시트·공개 사유·requires_reveal·독립 채점 중 차단 안내·동의 기반 생성 disabled를 제거한다. 「권한 확인된 리포트 발급본」을 「리포트 발급본」으로 표시하고 U08의 발급/열람 기록은 중복 작성하지 않는다.
6. 원본 AI 결과와 보존 산출물은 출처 증거로 유지한다. 사람의 정정은 새 사람 원자료/판정 판본으로 보존하며 원본 공급자 응답을 수동으로 덮어쓰지 않는다. 이 조건을 사람 역할별 제한으로 구현하지 않는다.
7. 본인 할 일 필터·배정 전제 체크리스트·「운영자에게 요청」 문구를 제거한다. 공통 진행 단계와 실제 미완료 작업을 표시한다. 단계·출처·비용의 기술 상세는 접기에 두고 공통 접근으로 제공한다. 개발자 비밀키·설정 변경은 설정 권한 경계 안에 둔다.

### 3.3 동의·삭제 입력 제거와 CSV/Excel

1. `ParticipantFields`·`participantValue`·`types.ts`·접수 목록/상세에서 동의 확인 입력·열·배지·필터를 제거한다. 참가자 수정 시 삭제된 UI의 기본값을 새로 전송해 과거 사실을 덮어쓰면 안 된다.
2. `CaseDetail` 삭제 요청 폼을 제거한다. Recovery의 삭제 건수, 삭제 처리 안내, 실행 화면의 동의/삭제 차단 안내를 제거한다. 기존 파일이 없거나 손상되어 사용할 수 없는 경우에는 AR04의 실제 기술 실패 이유를 표시한다.
3. 신규 명단·명단+28문항 CSV/Excel 양식에서 `consent_confirmed`, `consent_analysis_feedback`, `consent_stranger_contact` 열을 제거한다. `intake.headers`, Forms 필드/별칭/자동 연결/검증 결과, `formsCsv.ts`, `FormsImporter.tsx`와 해당 타입을 동일 계약으로 수정한다.
4. 기존 CSV/Excel 파일에 위 동의 열이 있으면 입력 오류·필수 매핑·분석 차단을 만들지 않는다. 원본 workbook/CSV와 raw cell은 기존 불변 원본으로 보존하고, 현재 업무 참가자 입력에서는 해당 열을 사용하지 않는다. 과거 「거절」·미확인·빈칸을 「확인」으로 바꾸어 저장하지 않는다.
5. 저장된 과거 열 대응 템플릿은 동의 열을 제외한 유효 대응을 재사용한다. 동의 열만 남은 무효 대응 때문에 전체 미리보기를 실패시키지 않는다. 고유 참가자 ID·회차 선택·중복 방지·부분 등록·Q01–Q28 원척도·0/빈칸·CSV 수식 안전 처리와 손상 workbook 거절은 유지한다.
6. Forms 미리보기와 커밋의 활성 계정 확인은 AR01로 통일한다. AR04가 삭제 플래그를 접근 판정에서 제거한 결과를 사용하고, `forms_v4._live_state`의 삭제 상태를 계속 키/차단 조건으로 쓰지 않는다. 기존 preview/receipt의 정합성 및 idempotency는 보존한다.
7. 실제 S1 점수 Excel 가져오기의 G01/G04 원자료·양식 검증 미완료와 검수 참고 workbook 등록을 구분한다. 업무 권한 제거를 미확정 점수 규칙이나 존재하지 않는 기능의 완료로 표시하지 않는다.

### 3.4 비교 적용 화면

1. 외부 기준표 등록·적용·대상 선택은 모두에게 제공한다. 연구 확인 승인·관리자 기술 활성화·approved만 선택 가능한 흐름을 제거한다.
2. AR05가 제공하는 기준표 실제 존재·source hash·문항/척도 일치·필수 통계·대상 범위 검증 결과를 표시한다. 자료가 없거나 검증에 실패하면 원인과 해당 셀/척도 정보를 보여준다. 합성 fixture로 실제 기준표 사용을 승인한 것으로 표시하지 않는다.
3. 기준 저장·변경은 기존 업무 event, 실제 적용 판본은 기존 report/export 입력 참조로 연결한다. 같은 기준 사용을 새 감사 사건으로 다시 기록하지 않는다. 승인 대기·두 사람 결재는 없으며 자체 비교집단 구성·수정·해제도 공통 업무다.

### 3.5 계정·발행·운영 문서

1. `Users.tsx`에서 operator/reviewer/admin 선택과 차등 권한 설명을 제거한다. AR01의 일반 계정 계약으로 계정을 만들고 활성 여부를 관리한다. 개발자 설정 권한 부여/변경은 AR01의 경계를 따른다. 일반 업무 사용자가 개발자 설정 권한을 임의 획득하는 UI를 만들지 않는다.
2. CLI·설치·발행 안내를 「초기 업무 계정」으로 맞춘다. `--admin`/exactly-one-admin bootstrap·기존 패키지 저장값은 호환 내부 계약으로 유지 가능하며 공통 업무 접근을 검증한다. 포맷 재설계는 필수가 아니다. `manage.py` 백업 actor의 업무 역할 제한은 AR01로 제거하고 기존 백업 화면/상태에서 삭제 건수 안내만 정리한다. 새 복원 UI·로그 추출/병합 도구는 만들지 않는다.
3. [DEVELOPMENT.md](../docs/DEVELOPMENT.md)·[PILOT_OPERATIONS.md](../docs/PILOT_OPERATIONS.md)에서 계정 준비·일일 운영·비교 적용·백업/복원 절을 현행 절차로 다시 쓴다. `clean --purge-deleted`, 최신 삭제 대장 재적용, 교수 읽기 전용, 운영자 배정/공개/재개방 안내는 AR04/AR03 종착 계약으로 대체한다.
4. `AGENTS.md`의 현재 권한·삭제 재검사 요구와 현행 개발 기준 안내에 이 계획의 사용자 결정·대체 관계를 반영한다. 과거 실행/인수 대장의 통과 기록을 현재 통과로 다시 쓰지 않는다. AR07에서 새 인수 기대값과 실제 검증 결과를 별도 기록한다.
5. 현재 계획/안내의 권한·독립성·동의·삭제 요구는 새로운 결정으로 대체된 범위를 표시하고 이 계획에 연결한다. 고객 원문·과거 평가 규칙·과거 cold review 사실은 수정하지 않는다. U08/U09 병합 기능은 재사용하며 이번 개정은 제품 파일을 변경하지 않는다.
6. 공급자 파일 수명 정리, 실패한 임시 파일 정리, 계정 로그인 만료는 참가자 동의 철회/삭제 요청 절차와 구분한다. 불변 원본/감사 기록을 지우는 보관 명령으로 되돌리지 않는다.

## 4. 실행 순서와 변경 소유

1. AR01–AR05 API·타입 계약을 확정하고 실제 caller graph를 확인한다. 메뉴·직접 주소·개발자 공통 업무 진입과 계정 화면을 먼저 변경한다.
2. 채점·해석·산출물에서 배정·소유·공개·제출 후 승인 전제를 제거한다. 이전 판본 및 충돌 UI를 연결한다.
3. 동의·삭제 UI와 CSV/Excel 신규 양식을 함께 바꾼다. 구 양식 및 저장된 매핑의 원본 보존·재사용을 확인한다.
4. 비교 적용·감사 기록·수신 취소를 공통 업무에 연결한다. 리포트와 내보내기 다운로드는 AR02 사건 계약으로 기록한다.
5. 설치·CLI 안내·발행 입력·운영 문서와 시험 fixture를 갱신한다. 제품 코드 변경 PR과 연관 API PR이 함께 배포될 수 있도록 AR07 릴리스 범위를 고정한다.
6. 아래 대상 검증 후 cold review를 받고 수용한 지적만 수정한다. 수정 이유/근거/재검증을 PR에 기록하고 상위 계획의 병합 절차를 따른다.

AR06은 실데이터 migration과 복원·clean 삭제연쇄를 구현하지 않는다(AR04). 공통 감사 저장/조회 API는 AR02, 채점/해석 접근 계약은 AR03, 비교·리포트·내보내기 접근 계약은 AR05가 소유한다. UI만 임의로 서버 차단을 우회하거나 기존 backend 함수를 복제하지 않는다.

## 5. 검증 명령과 사례

계획 작성 단계에서는 패키지를 설치하거나 아래 시험을 실행하지 않는다. 구현 시 기존 잠금 의존성을 유지한다. 새 의존성은 필요 없다. 설치/라이브러리 API 사용 전에 프로젝트 규정대로 공식 문서·레지스트리의 최신 안정판 및 선택 버전 호환성을 확인하고 날짜·링크·기존 버전 유지 이유를 PR에 남긴다. 무관한 패키지 업그레이드는 하지 않는다.

frontend 작업 디렉터리:

```powershell
npm run build
npm run test:e2e -- tests/navigation.spec.ts tests/scenario-professor.spec.ts tests/scenario-staff.spec.ts tests/scoring-v4.spec.ts tests/opinions-v4.spec.ts tests/scoring-ai-v4.spec.ts tests/exports-v4.spec.ts tests/forms-auto-map.spec.ts tests/importer-upload-v4.spec.ts tests/importer-existing-v4.spec.ts
```

backend 작업 디렉터리:

```powershell
uv run --locked python -X utf8 -m unittest tests.test_forms_import_v4 tests.test_forms_api_v4 tests.test_intake_v3 -v
```

저장소 루트:

```powershell
git diff --check
git diff -- plans docs AGENTS.md
graft check
```

`test_intake_v3`는 현재 남아 있는 원입력 기반 fixture의 새 입력 호환·원본 보존 검증에 한정한다. 과거 점수 실행/이전 권한 정책을 다시 제품 경로로 활성화하지 않는다. 새 테스트 파일/이름이 필요하면 PR에서 확정하고 위 명령에 갱신한다. 전 범위 회귀 및 새 ZIP 검증은 AR07에서 수행한다.

| 실제 파일이 이미 없거나 hash가 불일치하는 전환 fixture | 업무 권한 오류로 오표시하지 않음, 자료 없음/무결성 실패 안내, 임의 복원·ready 표시 없음 |

## 6. 인수 기준

- 모든 활성 일반 계정과 개발자가 동일 업무 기능을 사용한다. 개발자만 설정을 변경할 수 있고 개발자에게 업무 메뉴가 빠지지 않는다.
- 본인 소유/배정, 공개 허용, 본인 제출, 관리자 재개방, 동의 상태, 삭제 요청이 화면·직접 주소·CSV/Excel 입력·다운로드를 차단하지 않는다.
- 일반 계정 역할 선택, 동의/삭제 절차 UI, 운영자 승인 요청 문구와 본인 자료만 보이는 필터가 없다. 임의 새 승인/삭제 대체 업무도 없다.
- 조회·수정·실행·다운로드는 실제 로그인 계정과 대상 판본으로 감사 기록에 남고 모든 업무 계정이 이력을 조회할 수 있다.
- 과거 원본·작성 대상·이전 판본·hash·변경 이력은 보존된다. 과거 사실을 현재 계정/가짜 확인 동의로 바꾸지 않는다. 미저장 입력 및 충돌 방지가 유지된다.
- 새 명단/설문 양식에는 동의 필드가 없고 기존 양식/매핑은 원본을 보존하며 등록할 수 있다. 미확정 산식·실물 미확보 기능을 권한 제거를 이유로 확정하지 않는다.
- 문서·CLI·설치 문구가 같은 공통 업무 절차를 설명한다. 병합된 U08 기능에서 남은 제한도 같은 계약으로 제거한다.
- U08 리포트 기록과 U09 자연스러운 이름·짧은 ID·중간 폭 표시를 유지한다. 새 감사 메뉴/복원 로그 병합/계정 이름·타인 비밀번호 편집 기능은 없다.
- 위 계획 검증 결과와 AR07의 통합 인수는 구분해 기록한다. 실제 제품 구현·시험·실데이터 전환이 계획 문서 통과만으로 완료 처리되지 않는다.

## 7. 실패·복구

선행 API와 타입이 불일치하면 AR06만 배포하지 않는다. 깨진 API에 역할 우회 UI를 덧붙이지 않고 해당 PR에서 계약을 고친 뒤 재검증한다. U08/U09의 병합된 기능을 대조하며 이번 계획 개정에서는 제품 파일을 수정하지 않는다.

UI 변경 전 합성 fixture를 보존한다. 실패 시 해당 PR 코드/정적 번들을 되돌릴 수 있으나 AR04의 정책 전환 완료 DB를 구 권한·동의·삭제 프로그램으로 실행하지 않는다. 릴리스·DB 호환 경계와 전환 백업은 AR04/AR07 기준을 따른다. 과거 권한으로 감사 흔적을 삭제하거나 old `clean --purge-deleted`를 실행하는 복구 절차는 없다.

CSV/Excel 변환 실패는 저장된 원본과 preview/receipt를 유지하고 원인 행을 안내한다. 승인/동의 필드를 복구해 다시 강제하지 않는다. 실제 없어졌던 파일은 복원 성공으로 표시하지 않고 AR04의 확인 결과에 연결한다.
